# 报告、问题清单与编制说明（dd-report-issue-list）

> **前置**：
> 1. 读取 `shared/references/due-diligence-playbook.md` 第 4–8 节与 `shared/references/document-delivery-qa.md` 第 2、4、5 节；
> 2. 读取 `commercial-legal/CLAUDE.md` → `## 输出` 取工作产物标题；
> 3. 前三个子技能输出已落盘。
>
> 可被 `equity-transaction-dd/SKILL.md` 编排入口调用，也可通过 `/commercial-legal:dd-report-issue-list` 单独触发。

---

## 目的

交付三件而不是一件：报告给结论，问题清单给动作，编制说明给可信度。律师据编制说明判断哪些数字可以直接用、哪些要再查。

---

## 详细步骤

### 步骤 1：报告正文

- 章节与版式沿用参考稿；参考稿中被排除（标黄）的段落不得参考；沿用的既有表格在问题清单说明「系律师此前检索结果，本次未独立核验」；
- 每章结构：事实（引用 `fact_id`）→ 法律评析 → 风险等级 → 建议；
- 交易结构未知的章节开头注明「按一般情形」；
- 条件句与【待核实】用于未回原件核对或单一来源的事实；
- 释义表以 `chapter-fact-memos` 定稿的主体全称为准。

### 步骤 2：管理层摘要

从正文倒推，按风险等级排序，每行注明正文位置。经营资源依赖控股股东体系的提示合并为一行。摘要不得出现正文没有的结论。

### 步骤 3：问题清单三分类

| 分类 | 条目来源 |
|---|---|
| 补充资料 | `data-room-inventory` 的 `unreadable` 与缺失文件；底稿「需补」 |
| 待说明（事实矛盾） | 底稿 `conflicts_with`；访谈口径与文件不一致 |
| 需律师决定 / 复核 | 交易结构、联网检索许可、按通行文本引用未下载原文的条文、测算假设 |

每项：编号 / 事项 / 来源章节 / 影响 / 建议动作。

### 步骤 4：编制说明

1. 工作流程（清点 → 底稿 → 程序核查 → 装配，含子代理分工与规则）；
2. 资料来源对照表（章节 ↔ 主要 `file_id`）；
3. 计算方法（每个测算的公式、假设、来源）；
4. 已纠正错误清单（发现方式：回原件 / 重算 / 交叉比对）；
5. 法条核验表（法规 / 条文 / 版本 / 核验来源 / 状态）；
6. 覆盖审计结果（`referenced / unique_files`，未引用文件及解释）；
7. 未执行事项（外部检索、独立复核）。

### 步骤 5：成稿与 QA

按 `document-delivery-qa.md`：参考稿 DOCX 作包模板 + DSL 生成正文；渲染两次回填目录页码；逐页检查表格与分页；OOXML 校验；发送包正则检查身份证号；内部底稿分目录。

### 步骤 6：交付说明与复核状态

交付说明：占位符（出具日期、尽调期间）、三件文件清单与指纹、外部检索声明、结构指标（仅作解释）。随后按 `shared/legal-document-intake/SKILL.md` 输出 `REVIEW_STATUS`；未做独立复核写 `skipped` 与原因。

### 步骤 7：补充资料第二版

补充资料到达时：单独清点 → 逐份写「对报告的影响」→ 更新受影响 `fact_id` 与章节 → 输出「补充资料核查及修订说明」+ 问题清单第二版；文件名带版本号，不覆盖第一版。

## 检查清单

- [ ] 标黄段落未复用；沿用表格已声明
- [ ] 摘要每行可回溯正文位置
- [ ] 问题清单三分类完整，每项有来源与动作
- [ ] 编制说明七项齐全
- [ ] 目录页码已回填；渲染逐页检查完成
- [ ] 发送包无身份证号；内部目录分开
- [ ] 交付说明与 `REVIEW_STATUS` 已输出

## 边界条件

| 情形 | 处理 |
|---|---|
| 无参考稿 | 用 `shared/references/document-structures.md` 的报告结构 + 中文 reference.docx |
| 律师要求只出问题清单 | 仍需底稿支撑，每项注明 `fact_id` |
| 上下文压缩 | 从分章底稿与 DSL 源文件续写 |
