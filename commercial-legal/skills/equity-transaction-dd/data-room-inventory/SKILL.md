# 资料室清点与覆盖审计（data-room-inventory）

> **前置**：读取 `shared/references/due-diligence-playbook.md` 第 2、4 节，按其 schema 输出。
> 可被 `equity-transaction-dd/SKILL.md` 编排入口调用，也可通过 `/commercial-legal:data-room-inventory` 单独触发。

---

## 目的

资料室常见 300–500 个文件，重复、多版本、扫描件混杂。没有清单就没有覆盖审计，没有覆盖审计就不能说「资料已全部审阅」。LWC-2026-0005 的覆盖审计发现 6 份未引用的资质证照，补写后暴露了许可证延续申请的时效问题。

---

## 详细步骤

### 步骤 1：递归清点与去重

- 递归遍历全部子目录；每个文件计算 sha256 与大小；
- sha256 相同 → `duplicates_of`；同名不同哈希 → **两个版本**，都保留并在步骤 3 标记版本关系；
- 聚合指纹 = 各文件 sha256 排序后清单的 sha256（供案例库，不入库原文）。

### 步骤 2：提取路径与个人信息

| 类型 | 提取 | 备注 |
|---|---|---|
| docx / xlsx / pptx | 直接读取 | doc / xls 先转换 |
| 有文本层 PDF | pdftotext | — |
| 扫描 PDF / 图片 | OCR，后台任务 | 只用于定位；影响结论的内容由主笔回原件 |
| 加密 / 损坏 | `unreadable` | 进问题清单「补充资料」 |

含身份证号、住址、银行账号的文件标 `contains_pii: true`，其底稿与文本镜像放内部目录。

### 步骤 3：分章映射

默认章节（按目标公司情况增删）：

| 章节 | 典型文件 |
|---|---|
| 01 主体与历史沿革 | 营业执照、登记档案、历次变更、批准证书 |
| 02 股权与出资 | 出资证明、验资 / 审计、股东名册、股权质押 |
| 03 章程与治理 | 历版章程、合资合同、股东会 / 董事会决议、委派函 |
| 04 资质与许可 | 行业许可、特许经营、经营权合同、认证 |
| 05 资产与租赁 | 不动产权证、租赁合同、租金支付凭证、设备清单 |
| 06 重大合同 | 客户、供应商、框架协议、关联交易合同 |
| 07 融资与担保 | 借款 / 委贷合同、征信报告、担保、还款计划 |
| 08 劳动用工 | 花名册、社保、外包 / 派遣合同（交叉引用 employment 对照表） |
| 09 税务与财务 | 审计报告、月报、纳税证明、处罚 |
| 10 诉讼仲裁与处罚 | 判决、裁决、调解书、处罚决定、信用报告 |
| 11 关联交易 | 关联方清单、交易合同、定价依据 |
| 12 其他（环保 / 安全 / 保险 / 知识产权） | 按行业 |

同一文件可映射多章；版本关系（如章程 2019 版 / 2023 版）在章节内并列记录。

### 步骤 4：清单输出

按 playbook 第 2 节 schema 输出 YAML / 表格，并给统计：文件总数、去重后数、按类型与章节分布、OCR 文件数与页数、`unreadable` 数。

### 步骤 5：覆盖审计（装配前复跑）

1. 取底稿全部 `sources.file_id`，与清单比对；
2. 未引用文件逐个标注：无关（写原因）/ 漏读（补底稿）/ 需补章节（补报告）；
3. 输出 `referenced / unique_files` 与未引用清单，交 `dd-report-issue-list` 写入编制说明。

---

## 检查清单

- [ ] 全部子目录已遍历；`skipped` / `unreadable` 有原因
- [ ] 同名不同哈希文件按版本并列，未被当作重复删除
- [ ] 每个文件有章节映射；多章文件已交叉标注
- [ ] OCR 文件已标记并后台处理
- [ ] `contains_pii` 文件已隔离
- [ ] 聚合指纹与统计已输出
- [ ] 覆盖审计在装配前复跑并记录比例

---

## 边界条件

| 情形 | 处理 |
|---|---|
| 资料分批到达（补充资料包） | 新批次单独清点并合并，版本号 v2；修订说明列每份新文件对报告的影响 |
| 文件名含客户名 | 清单 `label` 用脱敏标签，原文件名只留内部目录 |
| 超 1,000 份 | 清点交子代理并行，去重与映射规则由主笔定稿 |
