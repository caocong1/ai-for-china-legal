# 检索升级路由（C1 / C2 / C3）

> 研究闸门的常规五步足够处理结构清楚的单一法律问题。复杂、跨领域或穷尽式问题需要加宽检索，而不是把主会话写成一篇更长的散文。
> 路由结构改编自 claude-for-legal-ZH `references/agentic-search-routing.md`（SOURCE_INDEX S2，Apache-2.0）。检索源顺序已改为本仓库连接器：法规 `law-database` 优先，案例 `rmfyalk` / `wenshu`，`yuandian` 兜底。

本文件不要求特定 Agent 产品实现 subagent。若当前环境不能开隔离检索，改为**在同一会话按维度分批检索**，每批写进研究底稿，避免把未核验摘要直接写进文书。

---

## 三层路由

```
用户法律问题
    → 轻量拆维
         ├─ 常规研究闸门五步（默认）
         └─ 加宽检索（C1 直接 / C2 五步后升级 / C3 用户要求）
```

常规管线：法条确认、单份合同审查、单一概念解释、用户已提供充分依据。
加宽检索：多个独立法律维度需要并行查不同源。

---

## 触发

### C1 直接加宽

满足任一即跳过「只跑一遍常规五步就起草」：

1. 要回答清楚需要 **≥3 个独立检索方向**（不同法域、不同源类型、或正/反/程序同时深挖）
2. 同时涉及 **≥2 个本仓库插件领域**（例如知产 + 劳动，公司 + 税务）
3. 用户明确要「全面 / 穷尽 / 所有 / 系统性」梳理

拿不准时不走 C1，先跑常规五步。

### C2 五步之后升级

常规研究底稿出现任一情形则加宽，不得直接起草：

1. 关键依据缺失，无法合理推断
2. 产出中 **≥2 处**仍是 `[模型知识 — 需验证]` 或 `[搜索摘要-未抓全文]`
3. L1/L2 源覆盖完后，核心争点仍无可靠依据

升级时把**已经用过的关键词、已查过的库、已排除的版本**写入下一轮检索说明，避免重复。

### C3 用户指令

用户要求「深入查 / 全面检索 / 穷尽检索 / 系统研究」时直接加宽。

---

## 不触发

| 情形 | 原因 |
|------|------|
| 单一法条或单一条款核对 | 常规闸门足够 |
| 纯概念解释、不依赖现行条文 | 不启动法规穷尽 |
| 本会话刚完成同一问题的加宽检索 | 不重复 |
| 非法律问题 | 不走研究闸门 |

---

## 加宽时的源顺序

必须遵守 `official-source-routing.md` 与 `authoritative-sources.md`：

1. 法规：`law-database` → 规章库 / 行政法规库 / 专项官方库（税务、条约、生态环境等）
2. 权威案例：`rmfyalk`；指导/典型也可 WebFetch court.gov.cn
3. 普通文书：`wenshu`
4. 监管网站与部门公告
5. `yuandian` 仅官方源与 wenshu 不可用时
6. L5 律所文章只发现案号与争点，不绑定性

每个维度输出：检索词、源、是否现行效力已由官方字段确认、正向/反向依据。全部维度汇总进研究闸门底稿后再进入专项文书 skill。

---

## 约束

- 加宽检索是常规闸门的补充，不是替代。多数问题仍走五步。
- 加宽结果仍须律师审查；不确定项标 `待律师复核`。
- 核心涵摄与策略判断留在主工作流，检索通道只负责把依据找全。
