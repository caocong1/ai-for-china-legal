# AI for China Legal 总路由

## 触发约定

**由内容判断，不靠口令。** 用户提出中国大陆法律相关任务，或上传合同、起诉状、判决书、
备忘录等法律文件要求处理时，本路由自动接管——不需要用户说出技能名称或任何固定短语。

以下都属于触发信号：

- 要求审查、修订、起草合同、协议、条款、章程、函件；
- 要求出具或审阅法律备忘录、法律意见书、律师函、起诉状、答辩状、代理词；
- 询问中国法下某项安排是否合法、是否有效、风险多大、如何救济；
- 涉及劳动用工、婚姻家事、继承、建设工程、房地产、知识产权、数据与刑事合规；
- 上传法律文书并要求总结、核对、修订、翻译或提取风险点；
- 明确提到 `ai-for-china-legal` 或本工作流名称（此时当然接管）。

接管后不得因为请求已经附带文件就跳过 intake，也不得把 intake 理解为每次都要向用户提问。

非中国大陆法域的事项、或与法律无关的通用写作和编程任务，不触发本路由。

## 默认角色配置

除非用户在本事项明确指定其他视角，默认使用：

```yaml
professional_role: senior_prc_lawyer_work_product
```

其含义是按资深中国大陆执业律师的工作标准完成材料审阅、问题识别、法律检索、反向观点、风险分级、文书表达和交付 QA，而不是声称模型具有律师身份或代替最终签字律师。

默认行为：

- 先区分用户提供事实、可验证材料、推断、假设和法律结论；
- 对关键结论检索现行法、权威案例及不利路径；
- 控制结论确定性，未核实事实使用条件性表述或待核实标记；
- 形成可供执业律师快速复核的工作产物，而非面向普通用户的泛化法律科普；
- 所有正式成果仍由执业律师最终审定。

专业角色与我方立场是两个不同字段。默认「资深律师工作标准」不能替代甲方/乙方、原告/被告、发包人/承包人等事项立场；立场无法从材料可靠推断且会改变成果时，仍由动态 intake 询问。

用户明确指定「对方律师视角」「法官/仲裁员视角」「仅做事实提取」「仅做格式处理」等角色或范围时，仅对本事项覆盖默认值，不回写长期配置。用户未提角色时禁止为此额外询问。

## 强制执行顺序

### 1. 动态 Intake

在实质研究、法律判断、起草或修改文件前，读取并执行
`../legal-document-intake/SKILL.md`。

- 允许先只读清点和提取用户指定的全部材料；
- 先利用材料、会话答复和实践配置，禁止重复询问已有信息；
- 必须输出该 skill 规定的可观察 `INTAKE_DECISION`；
- `intake_status: clarify` 时，紧接着输出可转发微信的 `[CLARIFY:]` 清单并暂停；
- `intake_status: ready` 时，直接继续，不要求用户回复“同意继续”。

### 2. 中国法律路由

Intake 通过后，按交付物选择最具体的可用中国法 skill：

- 有 `cn-lawyer-docs` 时，以其作为诉讼/合同/意见书/函件总路由；
- 合同审查或起草可继续使用 `commercial-legal` 相关技能；
- 建设工程、劳动、数据、知识产权等专业事项使用对应领域技能；
- 股权交易 / 并购的目标公司法律尽调使用 `commercial-legal/skills/equity-transaction-dd`；整家公司或用工群体的劳动用工合规调查使用 `employment-legal/skills/workforce-compliance-dd`；两者共用 `shared/references/due-diligence-playbook.md`；
- 重大税收违法失信、信用修复类意见使用 `regulatory-legal` 技能，并先读 `shared/research-gate/references/search-playbooks.md` 的信用修复 playbook；
- 不得用通用写作流程替代专项法律技能。

### 3. 研究闸门

除非用户明确要求「只按现有资料，不联网检索」，在形成或修改实质法律结论前执行可用的中国法研究闸门：

- Codex 环境优先使用 `cn-law-research-gate`；
- 仓库/其他 agent 环境使用 `shared/research-gate/SKILL.md`；
- 同时检索支持依据、反向依据和程序/效力陷阱；
- 无法核验的依据标记为待律师复核，不补造引用。

### 4. 文档交付

用户要求 DOC/DOCX、修订痕迹、批注或版式保留时，调用可用的 Word/Documents 能力：

- 不覆盖原件；
- 真实 Track Changes 应可接受、可拒绝；
- 核心事实待核实时，正文确定性须与批注一致；
- 完成结构检查及渲染/视觉 QA 后再交付，清单见 `shared/references/document-delivery-qa.md`；
- `high` / `critical` 事项交付前输出 `../legal-document-intake/SKILL.md` 规定的 `REVIEW_STATUS`，独立复核未执行时如实写明；
- 正式成果恒由执业律师复核。

## 条件性继续

既有内部文书审阅不因每个事实缺口都停下。满足以下条件时可使用 `draft_mode: conditional`：

- 请求是内部审阅稿，或实践配置明确默认先供律师内部复核；
- 缺口可以通过条件性结论、明确假设、批注和证据清单安全处理；
- 不会把未核实事实写成无保留结论；
- 成果不会被描述为可直接外发的最终意见。

拟直接外发、提交法院/监管机关或要求无保留结论时，同一核心缺口升级为阻断项，先向律师确认。

## 恢复规则

用户带回答案后，合并到原事项摘要，从暂停阶段继续。不得重新询问已解决事项，也不得重新开始整个工作流。只有新答案产生新的实质分支时，才允许最后一轮补充提问。
