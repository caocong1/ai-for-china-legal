# 中国法法律推理调度

**本 skill 不替代领域插件，也不提供法律结论。** 它只决定先做什么、调用哪套已有技能，以及哪些推理在中国大陆成文法下必须收紧。

调度思路参考 Legal-Skills-Chinese 的七类能力划分（SOURCE_INDEX S7）。该库许可为 CC BY-NC-ND 4.0：**禁止复制其 SKILL.md 原文、检查清单或输入输出模板。** 下文步骤与表均为本仓库自写，并接到本仓库插件路径。

除非用户明确豁免联网检索，任何会写出法律结论的路径仍须先满足 `shared/research-gate/SKILL.md`。

---

## 何时使用

- 用户任务跨越「查法 / 认事 / 解释 / 出文书」多段，不知从哪个插件起
- 领域技能已经触发，但论证跳过了争议焦点或效力核验
- 需要在刑法、税法等**禁止或严格限制类推**的领域提醒推理边界

单一、已定位的任务（例如「只改这份买卖合同的违约金」）直接走对应插件，不必完整跑本表。

---

## 调度主线

默认顺序。能跳过的只有「本步输入已由用户或上一 skill 完整提供」的情形，并在输出里写明跳过原因。

```
清点材料与争议
  → 规范检索与效力核验（研究闸门 + 十库路由）
  → 事实与构成要件/请求权要素
  → 解释争议条文（有歧义时）
  → 涵摄与推理（演绎为主；类推须过界）
  → 论证组织与反方攻击
  → 风险与程序后果
  → 文书结构与术语
```

对应复合任务的常见落地：诉讼方案、代理意见、合规备忘录、合同审查备忘录。

## 中国法硬边界（调度层）

1. **成文法优先**。指导性案例可作参照，普通判决只作地方实务参考，均须标明来源层级。
2. **效力先于解释**。未核验现行有效（见十库效力纪律）不得进入涵摄。
3. **类推限制**。刑法定罪量刑、税法构成要件：不得用「类似案件」补足缺失要件。民事漏洞填补须明示方法与反向依据。
4. **程序与实体分开**。管辖、时效、主体资格、举证责任在进入实体胜负评估之前单独列出。
5. **刑事材料**。先适用 `criminal-compliance` 脱敏与强制库核，再谈构成要件。

## 与领域插件的衔接

1. 识别领域 → 打开对应插件 `CLAUDE.md` 与顶层 skill。
2. 用本表检查是否跳步；缺的步骤补做或标明「用户已提供」。
3. 检索与效力一律回研究闸门，不在领域 skill 里另造一套源等级。
4. 输出阶段用该插件的格式 skill + `document-structures.md`。

跨领域（C1，见 `agentic-search-routing.md`）时：每个领域各走一遍「检索→要素→推理」，再在论证层合并，禁止把两个领域的法条混在一个三段论里。

## 输出

调度本身只追加一段**推理路径说明**（可并入研究底稿或备忘录审查者注）：

- 已执行的步骤 / 跳过的步骤及原因
- 关键规范是否已官方库核验
- 用了哪种推理（演绎 / 类案参照 / 解释选择），以及是否触及类推限制
- 下一步应进入的插件命令（例如 `/litigation-legal:defense-drafting`）
