# 法律文书 Word / PDF 交付 QA 清单

适用于三类交付：① 对既有 DOCX 的修订稿（Track Changes + 批注）；② 以律所 / 客户模板包成稿的报告；③ Markdown → DOCX 的意见书 / 备忘录。来源：案例库 LWC-2026-0001 至 0007 的文档工程观察。

通用前提：永不覆盖原件；输出到源文件同目录或指定目录，并使用新后缀。所有成果都须经执业律师复核，但人审标记放在哪里取决于交付模式：

- **律师工作稿**（内部审阅稿、批注稿、修订稿）：在正文或批注中标注；
- **客户成稿**（律师拟原样转发客户）：正文不放任何内部标记，人审要求由给律师的《成稿说明》、`REVIEW_STATUS` 与宿主 App 的人审标识承担，见第 5 节。

## 1. 修订稿（Track Changes）

| 检查项 | 方法 | 不通过的处理 |
|---|---|---|
| 真实修订 | OOXML 中为 `w:ins` / `w:del`，不是直接改文本 | 重做；不得把净稿当修订稿交付 |
| 可逆性 | 接受全部修订应得到目标稿；**拒绝全部修订后的规范化文本应与源稿一致** | 列出不可追踪的结构变更：编号、样式、列表属性的直接改动会绕过修订记录（LWC-2026-0002） |
| 批注锚点 | 批注范围不得跨越修订边界；批注关系文件完整 | 改用兼容锚点 |
| 批注与正文一致 | 批注写「待核实」的核心前提，正文不得写成确定结论 | 正文改条件句 |
| 外部版本净化 | 拟外发稿去除内部评级、谈判底线、特权标题 | 另存外部版 |
| 结构指标只作解释 | `w:ins` / `w:del` 数量受 run 拆分影响，不用于排名 | — |

## 2. 模板包成稿（律所 / 客户模板）

- 以模板 DOCX 为**包模板**：删除旧正文，保留封面、前言、释义、页眉页脚、编号与脚注样式；
- **以另一事项的成稿作模板**（律师要求「框架和格式按某稿，内容不参考」）：
  - 只沿用版式与固定条款：信笺页眉（含首页不同）、页脚页码域、页边距、字体字号与行距、自动编号、确认与保证条款、结语与落款格式；正文、脚注、附件全部替换；
  - 交付前全文检索模板事项的标志词（客户名、项目名、地名、金额），结果应为 0；
  - 重置 `docProps/core.xml` 的作者、最后修改人与时间；
  - 模板信笺中的错字不擅改，写入《成稿说明》由律师决定（LWC-2026-0007）；
- **直接格式模板**：律所模板常用直接格式而非样式。按段落角色（致函对象、标题、称谓、事实段、分析段、小标题、落款、附件）复制模板中对应段落的 `pPr` / `rPr`，编号沿用模板的 `numId`，不新建样式；
- **脚注**：每个引用位置一个独立脚注，同一来源再次引用时写「同前注 N。」（多个引用共用同一脚注 id，部分渲染器会显示空脚注）；删除模板原有脚注，保留分隔符脚注（id -1、0）；
- 样式克隆：标题层级、编号、表格样式从模板读取后复用（python-docx 或 DSL 生成器），不手写新样式；
- 正文用标记语言 / DSL 生成（如 `@H` / `@P` / `@N` / `@TABLE` / `@ROW`，脚注用 `[^key]` 引用、`@FN key 文本` 定义），源文件、构建脚本与底稿一起落盘，便于上下文压缩后续写与律师回查；律师要求修改时改源文件重新生成，不直接改 DOCX；
- 参考稿中被排除的段落（如标黄）不得复用；沿用的表格须在问题清单说明「系律师此前检索结果，本次未独立核验」；
- 目录：保留模板 TOC 域。律师工作稿可设 `updateFields`（Word 打开时刷新）；**客户成稿不要设**，否则客户打开时会弹出更新域提示。客户成稿改为渲染后回填页码，并在《成稿说明》中请律师发送前在 Word 中「更新域 → 只更新页码」；
- 表格：不用固定行高（长单元格会被截断）；列宽按内容比例设定（如 38 / 62）；行不可跨页造成的空白属已知代价，不要为此拆表；
- 组织架构图等整页元素另起一页，留白属已知代价。

## 3. Markdown → pandoc → DOCX

- 自备中文 `reference.docx`：正文宋体、标题黑体、表格全边框。首版出现「表格无边框 / 目录标题为英文」即属此项缺失（LWC-2026-0004）；
- 命令要点：`pandoc --reference-doc=<中文模板> --toc -M toc-title=目录`；
- 管道表分隔线的短横数量控制列宽；
- 用律所既有 DOCX 作 reference-doc 时，`styles.xml` 表格样式中 `w:tblPr` 的子元素顺序可能不合 schema（`w:tblInd` 须在 `w:tblBorders` 之前）。`officecli validate` 报错时，重排后重新打包（2026-10-16、2026-10-22 两次出现）；
- 含脚注或多张宽表的文档必须逐页渲染检查。

## 4. 渲染与结构校验

1. LibreOffice headless → PDF → 逐页缩略图，检查分页、表格截断与边框、编号连续、页眉页脚、批注锚点、异常空白页。macOS 上 LibreOffice 不认 Windows 中文字体名（宋体、仿宋、黑体、楷体_GB2312），每次回退的字体不同，页数会波动。渲染前在 QA 副本中把字体名换成本地化名称（宋体→宋体-简、仿宋→华文仿宋、黑体→黑体-简、楷体_GB2312→华文楷体）；页数以 Word / WPS 为准，LibreOffice 页数只作参考；
2. 结构校验链：`officecli validate` → outline → issues → 域代码与模板占位符泄漏检查（LWC-2026-0003）；OOXML 包有效性；
3. 【待核实】/【待律师复核】/【HUMAN_REVIEW】计数与附录清单条目数核对；客户成稿中这些标记的计数应为 0，并按第 2 节检索模板残留词；
4. 外部版与内部版分目录；发送包正则检查身份证号、手机号、银行账号。

## 5. 客户成稿模式与《成稿说明》

### 5.1 何时按客户成稿交付

律师说「可以直接给客户」「出一份正式的」「出给客户的……」，或要求用律所模板出具时，按客户成稿交付：

- 律所口吻、律所模板，正文没有内部标记，律师可以原样转发；
- 未核实的事实用来源句（「根据《X》记载」「截至……尚未向我们提供……」）和条件句处理，把关键文件列为实施前提；
- 写给律师的内容（问题、取舍、核验状态、待填项、敏感点）另出一份《成稿说明（致承办律师）》，不随成稿发给客户；
- 是否向客户说明使用了 AI 辅助，由律师决定；拟提交法院、仲裁机构的文书仍按 5.3 随附说明。

依据：同一律师曾把带【待核实】标记和「工作草稿」封面的报告退回为半成品（2026-10-16，另一事项）；按本节交付的 LWC-2026-0007 获「很满意」评价。

律师要求内部工作稿、批注稿或修订稿时，仍按第 1 节在正文或批注中标注。

### 5.2 《成稿说明》九节结构

| 节 | 内容 |
|---|---|
| 一、形成方式 | 「您的要求 → 本稿的落实方式」对照表：模板沿用范围、哪些内容未参考、问题如何分节、口吻与未核实事实的处理 |
| 二、核心结论 | 供律师快速把握的结论要点；对客户价值大、但措辞须律师把握分寸的点单独说明（如价款可能多算、依据敏感） |
| 三、客户材料中的问题及本稿处理 | 表：客户表述｜问题（错引、失效、适用对象错误、数字口径不一）｜本稿处理 |
| 四、发送前请您关注或确认 | 结论强度能否加强或减弱、方案选择、出具日期、落款与签章、附件取舍、篇幅、模板残留（如信笺错字）、目录页码刷新 |
| 五、法律依据核验情况 | 表：依据｜核验来源（官方网站、数据库、转载本）｜日期。取不到官方网页、改经浏览器或官方附件核对的，单独说明 |
| 六、检索到但未采用的依据 | 表：依据｜未采用原因（失效、无法核验、不相关、为控制篇幅） |
| 七、建议客户补充的材料 | 编号清单，措辞可直接转给客户 |
| 八、复核情况 | 复核方式（不同模型、新上下文、传了哪些材料）；「复核意见｜处理」表；是否做了第二轮复核 |
| 九、源文件与重建方式 | 源文件位置与构建命令；以后修改改源文件、重新生成 |

### 5.3 其他交付事项

- 占位符清单：出具日期、尽调期间、释义表待填简称、落款；
- 目录域刷新（见第 2 节）；
- 未执行事项：外部检索、独立模型复核（引用 `REVIEW_STATUS`）；
- 拟提交法庭 / 仲裁机构的诉讼文书、案例检索报告、代理词：随附《AI 辅助使用情况说明》，交付说明列出逐条引用核验状态（最高法法发〔2026〕10号第 19 条，2026-09-07）；任一引用为未核验时，不得标为可提交；
- 律师工作稿，或律师明确要求在对外文书中保留人审标记的，可按上海律协《律师企业法律顾问服务 AI 应用操作指引（2026）（试行）》的惯例呈现为「【需律师核查】」。去 AI 腔润色不得删除人审标记与 AI 使用说明；客户成稿模式下，这两项保留在《成稿说明》中；
- 结构指标（页数、表格数、待核实数）仅作解释，不作质量评分。
