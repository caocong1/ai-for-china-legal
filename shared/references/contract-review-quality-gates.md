# 合同审查质量门禁

> 供 `commercial-legal` 合同审查编排入口及子技能使用。定义审查顺序与交付纪律，不替代研究闸门。
> 门禁结构改编自 claude-for-legal-ZH `references/contract-review-quality-gates.md`（SOURCE_INDEX S2，Apache-2.0），已改写为本仓库口径：效力优先之后才进入已有的双重严重性、违约金四维与最小修改粒度。

涉及实质性法律判断时，先跑 `shared/research-gate/SKILL.md`，依据走 `official-source-routing.md`。

---

## 1. 效力优先

在优化商务条款之前，先处理可能让合同不成立、无效、可撤销或无法履行的问题：

1. 名实不符：循环买卖、合作开发、投资、委托贷款等是否实为借贷或其他关系
2. 关联交易与明显不合理对价、恶意串通风险
3. 格式条款：免除己方责任、排除对方主要权利、提示说明义务是否履行
4. 审批 / 登记：区分合同效力、报批义务与物权变动；未登记不等于合同无效
5. 成立要素：当事人、标的、数量是否确定；鉴于条款中的事实陈述是否构成不利自认

**发现效力风险：先处理效力，再谈条款优化。** 效力未决时，在风险清单顶部标记，并告知律师后续修改建议参考意义有限。

与 `shared/references/subject-qualification-traps.md` 一并使用。

---

## 2. 主体与授权

必须核对：

- 签约主体名称与证照、信用公示信息是否一致
- 法定代表人签字是否配合公章；非法定代表人是否有授权委托
- 项目部章、合同专用章、业务章、个人签字是否可能引发代理争议
- 一人公司、关联担保、减资、对外担保是否需要公司决议及决议留存
- 上市公司、国企、外商投资企业、银行分支机构等特殊主体见主体资格陷阱清单

---

## 3. 条款八维（逐条至少扫过）

| 维度 | 核对要点 |
|------|----------|
| 价款与支付 | 节点、发票、结算依据、唯一收款账户、付错账户的后果 |
| 交付与验收 | 标准、程序、异议期、逾期未异议是否视为合格 |
| 违约责任 | 是否覆盖关键风险；违约金是否过低/过高；实现债权费用由谁承担 |
| 解除与清算 | 解除权触发、解除后返还/结算/赔偿是否可执行 |
| 担保与保险 | 登记义务、保证期间、最高额范围、解除条件 |
| 送达与争议解决 | 送达地址、电子送达、管辖/仲裁是否明确且可执行 |
| 定义与附件 | 定义不偷偷加义务；内部制度须转化为合同附件才约束对方 |
| 内部一致性 | 正文与附件、通用与特别约定、金额期限、定义用法不得冲突 |

本表是底线。违约金仍按本仓库已有四维分析；管辖法律差异仍按 legal-basis 子技能。

## 4. 修订方式：直接改还是批注

在写出替换语言之前，先决定这一条是**直接修订**还是**批注请律师/客户拍板**。本仓库 `clause-revision` 的最小粒度（词 < 短语 < 句子 < 条款）仍然适用；本门禁只决定「改不改、谁拍板」。

**倾向直接修订**（仍须在备忘录中告知律师）：

- 错别字、过时法规名称、明显笔误
- 对我方有利且通常可落地的缺失条款（送达确认、唯一收款账户、实现债权费用、签章要件等）——以实践配置中的审查立场为准
- 明显单向义务、退出权不对等，且对称化不改变交易结构

**必须批注、不得静默改掉对方交易结构**：

- 验收标准重构、付款比例、违约金数额、知识产权归属等商业取舍
- 条款矛盾但存在多种合理解释
- 事实尚未核对
- 有多个合理方案需要客户选择

### 每条意见四问

1. 律师能否替客户直接改？能 → 直接修订
2. 是否涉及商业判断？是 → 批注
3. 对方大概率接受？是 → 直接修订并告知客户
4. 是否有多个合理方案？是 → 批注并列方案

与实践配置冲突时，以 `commercial-legal/CLAUDE.md` 的审查立场和升级矩阵为准。

## 5. 风险提示四要素

每个写入备忘录的风险块必须能回答：

1. 风险点是什么
2. 在什么条件下会变成实际损失
3. 可能后果（法律 + 商业摩擦，即双重严重性）
4. 建议怎么改（给出替换语言或明确「待客户选择的方案」，禁止只写「建议修改」）

---

## 6. 终稿三件套（映射到本仓库输出格式）

完整审查结束时，默认仍由 `output-formatting` 组装。三件套对应关系：

| 用途 | 本仓库输出 | 受众 |
|------|------------|------|
| 带痕迹的文本 | 修订文档（可选） | 内部或向对方传递的条款层面 |
| 给业务/客户看的结论 | 完整备忘录中的底线 + 风险分级；若用户要「法律意见书」则按意见书结构再出一版 | 客户/业务 |
| 律师存档的依据 | 备忘录中的法律依据段 + 研究闸门底稿 | 律师内部 |

微信群摘要不是三件套之一，只作同步。特权圈外目的地仍须脱敏版。

## 7. 类型加码（提示，不替代专项插件）

| 类型 | 额外关注 | 优先插件 |
|------|----------|----------|
| 建设工程 | 工期顺延、变更、竣工验收、结算审计、优先受偿 | `construction-legal` |
| 房地产/商品房 | 产权与土地性质、规划、交付、面积差异 | `construction-legal` 商品房审查 |
| 劳动 | 合同期限、试用、竞业、解除 | `employment-legal` |
| 数据/技术 | 个人信息、出境、知识产权归属、二次开发 | `data-compliance` / `ip-legal` |
| 融资/担保 | 利率合规、担保决议、独立保函主体 | 研究闸门保函 playbook + 主体资格陷阱 |

专项插件与本门禁同时适用时，专项规则优先，本文件作总检。
