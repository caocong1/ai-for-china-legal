# 动态问题路由

本参考供 `legal-document-intake` 在第二步列候选问题时读取。问题是候选路由，不是每次必问清单。

## 0. 问题来源与典型问题

| 来源 | 典型问题 | 常见档 |
|---|---|---|
| 指令有两种读法 | 「10 月份的租金标准」指原合同单价，还是 10 月实际应付额？附两种读法的金额 | 必须确认或建议确认（看差额） |
| 模板或格式指令冲突 | 律师要求「格式与上一份备忘录一致」，操作员又给了另一份旧模板：版式按哪份，结构是否借鉴另一份？ | 建议确认（操作员通常能答） |
| 底稿与版本 | 律师是否已有自己的草稿或修改稿？本次以哪份为底稿？上一轮成果律师改过没有？ | 建议确认；临近提交的诉讼文书为必须确认 |
| 程序状态 | 原仲裁是否已出裁决、是否已撤回？举证期限何时届满，是否反诉？ | 必须确认 |
| 谈判、审批与政府口径 | 对方已拒绝哪些条款？内部是否已决策？政府是否有书面或口头意见？ | 建议确认 |
| 整体前提 | 方案假定某事实成立；不成立则结论和建议都要改 | 必须确认 |
| 客户目标与取舍 | 两条路径客户倾向哪条？能接受多大风险？措辞是否按政府主导项目处理？ | 建议确认 |
| 受众与交付 | 直接发客户还是先内部审阅？出具日期与落款？ | 可按默认或建议确认 |
| 只有客户掌握的事实 | 结婚登记日、某笔款项的去向、某份文件是否存在 | 建议确认；拟提交法院的核心事实为必须确认 |
| 材料缺口 | 规划条件、评估报告、举证通知书、递增通知等 | 材料请求 |

## 1. 提问判定

对每个候选问题依次判断：

1. 材料或既有答复能否直接回答？能则不问。
2. 实践配置是否给出具体稳定值？有则使用；值为「视情况而定」时进入下一判断。
3. 不同答案是否会改变法律路径、正文措辞、数字、风险等级、谈判力度或交付版本？不会则不问。
4. 按 `../SKILL.md` 第二步的分档表归档：必须确认 / 建议确认 / 可按默认 / 材料请求。有安全默认值不等于不问：答案会改变正文的，列为「建议确认」并给出推荐答案。

「视情况而定」表示事项级路由信号，不等于配置缺失，也不得直接写入成稿。

## 2. 通用问题候选

| 触发条件 | 候选问题 | 通常级别 |
|---|---|---|
| 无法识别任务 | 这次需要审查、起草、出意见、发函还是纯检索？ | 必须 |
| 我方身份不清 | 我方是哪一方、代表谁、希望保护谁？ | 必须 |
| 版本混乱 | 哪个文件是本轮基准稿，是否要保留已有修订/批注？ | 必须 |
| 受众不清且影响内容 | 先供律师内部复核，还是拟直接发送对方/法院/监管机关？ | 必须 |
| 范围不清 | 全文审查还是只处理指定章节/问题？ | 必须 |
| 格式未说明 | 需要 Word 修订稿、净稿、备忘录、清单还是聊天答复？ | 可默认/必须 |
| 保存位置未知 | 是否采用实践配置默认目录或源文件同目录新建文件？ | 可默认 |
| 有截止期限 | 最迟何时交付，是否存在法定/谈判时限？ | 必须或风险预警 |

不要仅因用户没有提供公司规模、所有审批人、全部背景或精确金额，就机械阻断与这些信息无关的任务。

## 3. 合同审查/修订

优先从合同正文推断合同类型、当事人、金额、期限、争议解决和已有修订。仅在相关时从下列问题中选择：

| 触发条件 | 向律师确认 | 影响 |
|---|---|---|
| 我方立场可能混淆 | 我方是甲/乙方以及实际交易角色（出租/承租、采购/供应等） | 风险方向 |
| 修改力度未知且配置为事项决定 | 本轮采用强势乙方/平衡/仅改硬伤哪一级？ | 修订深度、谈判摩擦 |
| 已进入谈判 | 当前是首轮、回合稿还是临签最后一轮？哪些条款对方已拒绝？ | 是否保留中低风险修改 |
| 商务条件可能已锁定 | 租金、价格、期限、免租、交付等哪些商业条款不得改？ | 避免破坏交易 |
| 关键附件缺失 | 是否有权属/抵押、授权、技术规格、交付标准、报价/付款表等附件？ | 效力和可执行性 |
| 特殊主体或行业 | 是否存在国资、上市公司、担保、许可、数据、律所保密等特别要求？ | 强制规则与升级 |
| 输出拟外发 | 是否保留批注/法条依据，是否去除内部评级和特权说明？ | 外部版本净化 |
| 多稿比较 | 哪一稿是基准；输出合并稿、差异说明还是择优建议？ | 版本控制 |

### 租赁合同条件触发

出现抵押、定制装修、提前交付、物业费单方调整、自力救济、客户资料或关联机构共用等词时，按需确认：

- 是否已取得产权、抵押登记和抵押权人不干扰文件；
- 装修预算、方案、验收、工期和超支机制是否已经商务确认；
- 是否要求禁止停水停电、锁门、强制腾退和自行处置物品；
- 承租人为律师事务所、医疗机构等保密主体时，是否需要专门的文件/数据保护；
- 是否需要分所、关联机构或项目团队共同使用。

## 4. 合同起草

起草通常比审查需要更多事实，但仍应先使用用户材料。关键候选包括：

- 合同类型和交易目的；
- 双方身份、授权与实际履行角色；
- 标的、交付物、数量/范围和验收标准；
- 价格、税费、付款节点和发票；
- 期限、续约、变更、暂停和退出；
- 知识产权、数据、保密和担保（仅在涉及时）；
- 争议解决和特殊监管要求。

律师允许使用占位符或指定「先出框架」时，不必等待所有商务数字；应在草案中显著标记待填项。

补充协议、变更协议：律师给出商务条件清单的，逐个数字与原合同对账（`../SKILL.md` 第一步）；再看原合同中可能被对方援引来对抗新约定的条款（提前解除、免租补足、递增通知等），需要律师取舍的列为建议确认。起草方法见 `commercial-legal/skills/contract-drafting/framework-design`。

## 5. 诉讼/仲裁

优先确认会改变程序和请求的事实：

- 我方诉讼地位、程序阶段、法院/仲裁机构、案号；
- 送达日、起算日和最近期限；
- 请求/抗辩目标、已作出的程序决定；
- 证据清单、证据缺口、原件和保全状态；
- 是否已完成利益冲突与授权检查；
- 文书拟提交版本还是内部策略稿。

拟提交的文书，以下几类常被漏问：

- 举证期限、答辩期、是否反诉：必须确认。答案决定答辩状能否承载积极请求，或须另出反诉状（LWC-2026-0009：继承份额、多分等积极请求只写在答辩状里，法院可能不处理）；
- 律师是否已有自改稿：建议确认（0009 中律师稿在开工约 68 分钟后到达，第一轮初稿作废）；
- 只有客户掌握的身份与财产事实（结婚登记日、未成年期间是否共同生活、款项去向）：建议确认，标「客户」；作为答辩核心事实的，升为必须确认；
- 原案的程序结果（是否已裁决、撤回、和解）：方案以此为前提的，必须确认。

无关紧要的背景不得阻断紧急期限处理；先提示时限并处理保全动作。

## 6. 法律意见书/备忘录

通常必须明确：委托问题、事实截止日、适用地域/行业、结论用途、受众、需要何种确定程度、是否包含建议方案。若事实与假设可分离，可先形成假设清单并请律师确认。

这些项通常能从指令推出，推出了就不问：

- 「可以直接给客户」：受众是客户，律所口吻，按客户成稿模式交付；
- 事实截止日即出具日；
- 咨询型备忘录默认包含建议方案；
- 律师给出模板（包括另一事项的旧稿）时，模板只决定版式与固定条款。

只有推不出、且会改变成稿时才问。咨询型备忘录的事实缺口不阻断，用条件式结论与实施前提处理；但会改变正文的缺口仍列为建议确认、起草前问，截止紧迫时问卷与起草并行（`intake-examples.md` 示例 8）。拟向第三方出具、供其依赖的法律意见书，事实与假设须先确认。

律师给了一份模板、操作员又指定另一份，或律师要求「格式与上一份一致」而上一份已被律师改过的，问一句版式与结构各按哪份（示例 12）；默认以律师最近返回的文件为版式底稿。

## 7. 律师函/通知

通常必须明确：发函主体与授权、收件人、事实时间线、诉求、付款/整改期限、是否已准备诉讼、语气、送达方式和附件。不得自行编造金额、日期或威胁措施。

## 8. 纯法律检索

检索问题、法域、时间点和用途已明确时直接检索。只有关键词过宽、事实分支会改变检索方向或用户要求可直接用于文书时才追问。

## 9. 不应询问

- 文件中明确写明的当事人、金额、期限、管辖、输出格式；
- 用户刚在上一条消息回答的内容；
- 不会改变成果的偏好（例如纯提取任务中的风险偏好）；
- 为满足固定题数而添加的「还有其他要求吗」；
- 能用安全默认值解决、且实践配置已授权默认的事项。

## 10. 输出/路径推断

| 已知条件 | 可采用的默认 |
|---|---|
| 用户要求“保留 Word 修订痕迹”并提供 DOCX | 输出 DOCX 修订稿 |
| 配置为“源文件同目录、新建后缀” | 在同目录生成，不覆盖原件 |
| 用户要求仅分析/报告 | 不修改源文件 |
| 目标可能是对方当事人 | 生成外部净化版，内部评级另存或留在对话 |
| 目标仍有歧义或可能覆盖文件 | 必须确认 |

## 11. 尽职调查 / 合规调查

详细判定见 `shared/references/due-diligence-playbook.md` 第 1 节。候选问题：

| 触发条件 | 向律师确认 | 级别 |
|---|---|---|
| 委托方 / 受众不明 | 报告面向投资方、目标公司自查还是贷款人 / 监管提交？ | 必须 |
| 参考稿或模板的使用规则不明 | 哪些段落不得参考（如标黄）、版式沿用到什么范围？ | 必须 |
| 交易结构未知（股权尽调） | 受让哪一方股权、比例、是否增资、是否取得控制权？ | 必须或授权「按一般情形」 |
| 基准日 / 尽调期间 / 出具日期缺 | 是否先占位、交付时填？ | 可默认（占位） |
| 外部检索许可未说明 | 是否允许联网核验企业信用、裁判文书、执行信息？ | 可默认（不联网并声明） |
| 重点关注事项未列 | 是否有优先核查项（如外包 / 派遣、社保代缴、关联交易）？ | 可默认（领域技能默认清单） |
| 问题清单形式未说明 | 单独成文三分类，还是并入报告附录？ | 可默认（单独成文） |

不要因为资料包很大就先问一套背景问卷；先清点资料再决定剩余问题。
