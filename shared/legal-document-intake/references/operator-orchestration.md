# 多模型操作员执行建议

当用户像项目经理一样在多个 LLM/agent 间分配任务时使用。本参考只给能力与角色建议，不绑定模型品牌或额度。

## 1. 先分阶段，不先分模型

建议把法律任务拆为：

1. 材料清点与事实提取；
2. 动态 intake 与律师补充；
3. 权威法源与反向依据检索；
4. 主成果起草/修订；
5. 独立法律审查；
6. Word/PDF 结构和视觉 QA；
7. 律师人审与反馈记录。

先确定每阶段产物和门槛，再把角色映射到当时有额度的模型。

## 2. 复杂度分级

| 等级 | 典型任务 | 建议执行 |
|---|---|---|
| `standard` | 机械整理、低风险摘要、明确模板的简单文件 | 一个合适模型完成并自检 |
| `high` | 合同全文审查、重要律师函、一般诉讼文书 | 强主模型 + 不同模型独立复核 |
| `critical` | 重大交易、时效紧急、陌生法域、关键法律意见 | 提取/检索/起草/复核分工，最强模型做最终综合，律师硬门槛 |

存在大额、特殊主体、担保、在先抵押、客户敏感数据、不可逆外部发送或重大期限时，不低于 `high`。

以下任务默认 `critical`，无需逐案判断：正式法律意见书；对外尽调报告 / 合规调查报告；拟提交法院、仲裁机构或监管机关的文书；涉及行刑衔接、上市公司或国资主体的事项。案例库 LWC-2026-0004 / 0005 / 0006 三件 `critical` 任务均以单模型 + 自检完成，独立复核缺失是目前最常见的流程缺口，因此交付前必须输出 `REVIEW_STATUS`（见第 7 节）。

## 3. 额度使用策略

- 快速/低成本模型：材料目录、事实表、条款定位、格式检查；
- 强推理模型：问题识别、反例、策略、正文起草与综合；
- 有可靠检索能力的模型：权威源全文和引用核验；
- 不同强模型：盲审主稿，重点找遗漏、错误法条、立场偏移和不可执行措辞。

若只有一次高端模型额度，优先留给「基于已整理材料和检索底稿的最终综合」，不要消耗在原始文件摘录。

## 4. 不要把同一提示词盲发给所有模型

并行生成多份完整稿会增加比较成本，且难以判断谁遗漏了什么。更高效的分工：

- Agent A：事实与缺口；
- Agent B：法源、反例和程序陷阱；
- Agent C：按明确立场起草；
- Agent D：以对方律师/审判者视角质检；
- 主模型：综合修正并生成最终文件。

只有在建立基准评测时，才给不同模型同一任务；必须共享相同输入、实践配置、输出要求和评分维度。

## 5. 推荐的中间交付契约

每个 agent 交付以下最小结构，便于换模型继续：

```yaml
task_stage: extract | research | draft | review | document_qa
source_version: "hash-or-label"
party_role: "..."
confirmed_facts: []
assumptions: []
open_questions: []
findings: []
citations: []
artifact_path: "optional"
requires_human_review: true
```

不得在中间产物中复制不必要的客户全文。优先保存引用位置、文件哈希和脱敏摘要。

## 6. 律师反馈闭环

记录：任务类型、输入指纹、模型/推理档、结构指标、律师定性评价、被接受/拒绝原因和可复用规则。结构指标不能替代律师评价；律师评价是成果质量的最高权重标签。

将单次反馈转为窄规则。例如「乙方立场不够强」应落到具体触发项（在先抵押、自力救济、保证金重复受偿等），而不是把所有合同一律改成极端强硬。

## 7. 复核状态可观察

`high` / `critical` 事项交付前，主会话按 `../SKILL.md` 输出 `REVIEW_STATUS`。操作员据此决定是否补做复核再发律师。

独立复核的输入契约（与新鲜上下文原则一致）：

- 只传：源材料或其脱敏摘要、已确认事项、候选成果、本次立场与交付用途；
- 不传：起草者的推理过程、自评分数、模型名称；
- 复核者使用 `operator-quickstart.md` 第 6 节的独立复核提示词，按「严重程度—位置—问题—影响—建议修改—依据状态」输出；
- 主模型综合时逐条处理分歧，未消解的写入成果并标 `[HUMAN_REVIEW]`；不得把复核原文直接抄给律师。

宿主内置复核子代理（如墨律桌面端的复核 / 对抗工具）时，同一契约由工具参数承载；本文件不绑定具体宿主。

## 8. 子代理与底稿规则

- 适合子代理：OCR、分章摘录、清单比对、覆盖审计；不适合：结论性事实、法条核对、数字定稿。
- 统一规则文件先于任务下发：禁止联网（除明确授权）、禁止修改原始资料、只补缺口、更正须在原处注明、输出按约定 schema。
- 子代理产出一律视为「摘要」级证据，影响结论的事实由主笔回原件核对（`shared/research-gate/references/source-policy.md`「原件、摘要与占位规则」）。
- 接口限流或中断时按章节重派，不重做已落盘章节；并发上限由操作员设定。
- 分章内容先落盘再综合，防止上下文压缩丢失（LWC-2026-0005 / 0006 各经历一次压缩）。
