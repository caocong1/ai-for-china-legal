# 墨律 `ask_user` 澄清问题协议

> **消费者**：墨律桌面端（`lawyer-desktop`）通过 `ask_user` 工具渲染可点击澄清卡片。  
> **维护**：与 `src-tauri/src/skills/router.rs` 中工具 schema 保持同步。

---

## 何时调用

- 正式起草或案情分析前，存在会改变成果的问题：`legal-document-intake` 第二步归为「必须确认」或「建议确认」的题（立场、标的、程序阶段、指令的两种读法、底稿版本、客户取舍等）。
- 先执行 `shared/legal-document-intake/SKILL.md` 的材料读取和分档；不是固定问卷。
- 每轮优先 2–5 题，调用后宿主暂停等待用户提交。
- 用户消息或「以下是补充信息」答复已覆盖全部要点时，**禁止重复提问**。

## 单选 vs 多选

| 场景 | `allow_multiple` | 示例 |
|------|------------------|------|
| 互斥事实、唯一立场 | `false`（默认） | 代理原告/被告、是否已起诉、金额区间 |
| 可同时成立的类型/范围/关切 | `true` | 业务领域、已接入系统、关切重点、文书风格偏好 |

**规则**：按每题语义单独配置，不要全局强制多选。题干可写「（可多选）」以提示用户，但 UI 是否多选以 `allow_multiple` 为准。

## 工具参数示例

```json
{
  "intro": "起草前需确认以下要点，以便选用合适模板与检索策略。",
  "questions": [
    {
      "id": "party_role",
      "question": "贵方在本交易中是甲方还是乙方？",
      "allow_multiple": false,
      "options": [
        { "label": "甲方", "value": "party_a" },
        { "label": "乙方", "value": "party_b" }
      ]
    },
    {
      "id": "contract_types",
      "question": "本次涉及哪类合同？",
      "allow_multiple": true,
      "options": [
        { "label": "租赁合同", "value": "lease" },
        { "label": "买卖合同", "value": "sale" },
        { "label": "服务合同", "value": "service" }
      ]
    }
  ]
}
```

## 用户答复格式（宿主 → 模型）

用户提交后，宿主以隐藏消息发送：

```
以下是补充信息，请基于这些答案继续推进起草：

1. 贵方在本交易中是甲方还是乙方？
回答：甲方

2. 本次涉及哪类合同？
回答：租赁合同、买卖合同
```

- 单选：`answer` 为单个 `value`。
- 多选：`answer` 为多个 `value` 以 `|` 拼接（如 `lease|sale`）；展示文案为中文标签以 `、` 连接。

## 与各 cold-start skill 的关系

各 plugin 的 cold-start 访谈 SKILL 中「可多选」类问题，在通过 `ask_user` 落地时应设 `allow_multiple: true`；单选题保持默认或显式 `false`。

## 人工微信中继模式

操作员需要把问题复制到微信、等待律师答复时，不调用不可用的 UI 工具，改为输出 `[CLARIFY:]` 文本清单，格式以 `shared/legal-document-intake/SKILL.md` 第四步为准（必须确认 / 建议确认 / 可按默认 / 请提供的材料 / 我们对材料的理解）。

操作员带回答案后，模型应按原问题 id/序号合并，继续未完成流程；禁止重新开始材料清点或重复问题。律师对某一题回复「按推荐」即选了该题的推荐项；笼统的「其余按默认」「都按建议」不覆盖必须确认项。

## 其他宿主的直接问

Claude Code 的 `AskUserQuestion` 与 `ask_user` 语义相同，限制不同：

| 项 | `AskUserQuestion` |
|---|---|
| 每次题数 | 1—4，超过时分两次调用 |
| 每题选项 | 2—4 个；「其他」自由填写由工具自动提供，不要自己加 |
| 推荐项 | 放第一个，标签末尾加「（推荐）」 |
| 多选 | `multiSelect: true`（同上表的多选场景） |
| `header` | 不超过 12 个字符的短标签，如「减租基数」 |
| 题干 | 自足：写清所依据的材料事实，用户可能只看到提问框 |

操作员未指定提问方式、且多数问题需律师回答时，先用一道单选题让操作员选「生成问卷文档」「直接问我」或「不问，按推荐先写」。

## 问卷文档模式

操作员需要把全部问题一次发给律师时，不逐题调用工具，改为生成问卷文档：见 `shared/legal-document-intake/references/questionnaire-mode.md`。律师答复粘贴回来后按题号合并，与本协议「用户答复格式」同样处理。

## 输出格式与保存位置

用户请求和实践配置已明确格式、目录及不覆盖原件规则时，不使用 `ask_user` 重复确认。只有目标存在实质歧义、可能覆盖文件或涉及内外部版本净化时才提问。
