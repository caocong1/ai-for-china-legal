01概要

通过四轮结构化访谈初始化或更新 construction-legal/CLAUDE.md 实践配置文件：主体画像与项目组合、审查与争议立场、风险校准与升级矩阵、文书风格与地方规定。访谈答案覆盖配置文件中的 [PLACEHOLDER] 占位符，跳过的问题保留占位符，涉及司法解释条号或法律事实的字段保留 [待验证] 标注；配置文件是散文模板、唯一真相来源，不另存 YAML，律师可直接编辑或用 git 追踪变更。四轮可完整运行，也可用各自的命令单独更新某一章节；不想访谈时可只告知代理立场进入临时模式。README 估计完整访谈约 10-15 分钟。

02适用与边界

适用场景

  • 首次使用建设工程流程，配置文件尚全是 [PLACEHOLDER]
  • 代理立场变化（如从承包人侧转为发包人侧、新增商品房业务）需要只更新「审查与争议立场」
  • 团队权限、金额升级阈值或自动升级清单调整，需要只更新「风险校准」与「升级矩阵」
  • 更换文书风格、造价鉴定机构或主要业务省市，需要只更新「文书风格」与地方规定
  • 任一流程读取配置时发现「建设工程角色」或「整体代理立场」含 [PLACEHOLDER]

不做什么

  • 不处理具体案件或文书，只采集并写入配置
  • 不替代直接编辑 construction-legal/CLAUDE.md（律师可直接改文件，无需重跑访谈）
  • 不把用户口述的司法解释条号、期限、金额标准写成确定结论，一律保留 [待验证] 标注
  • 不创建独立的 practice-profile.yaml 或 JSON 配置文件

03输入与产出

需要律师提供

  • 访谈回答必需
    每题可填「不确定/暂不填写」跳过，字段保留 [PLACEHOLDER]
  • 只需更新某部分的说明（如「只更新审查立场」）可选
    也可直接用对应步骤的命令单独触发

    访谈结果写入该文件对应章节；重跑时覆盖

    进入临时模式，其余字段用默认值并标 [临时模式]

产出

  • 填充后的 construction-legal/CLAUDE.md给律师内部
    我们是谁（建设工程角色、项目类型组合）/ 谁在使用 / 可用集成 / 审查与争议立场（合同审查严格度、争议处理倾向、商品房审查立场）/ 风险校准 / 升级矩阵（角色权限表、自动升级触发条件、诉讼仲裁优先受偿权触发）/ 文书风格 / 输出 / 共享护栏（地方性规定提示、项目类型识别）

04开始前

前置条件

  • 读取引用规范 construction-legal/skills/_shared/legal-basis-conventions.md（用于法律事实合理性检查）
  • 读取配置契约 construction-legal/skills/_shared/practice-profile-schema.md（字段映射表、临时模式默认值）
  • construction-legal/CLAUDE.md 模板存在；访谈结果填充其对应章节

硬性规则

写入原则
采集的答案覆盖 CLAUDE.md 对应章节的 [PLACEHOLDER]；用户跳过的问题保留 [PLACEHOLDER]；涉及司法解释具体条号或法律事实的字段保留 [待验证] 标注，不因用户口述而移除。
唯一真相来源
访谈结果写入 construction-legal/CLAUDE.md（散文模板），不写入独立 YAML 或 JSON 文件；访谈完成后该文件即成为所有建设工程流程的唯一配置来源。
法律事实合理性检查
用户口述条款号、期限、赔偿数额、规模标准时，写入前复述确认：「你提到 [X]；我的理解是 [Y]。建设工程司法解释修订频繁，请确认是否要按此填入配置？[前提 flagged — 需验证]」；口述的司法解释条号标 [待验证 — 司法解释条号易变，须核实现行版本]。
临时模式默认值
不访谈时只需告知代理立场，其余按默认值并标 [临时模式]：审查立场中立审查（双向呈现风险）；合同审查严格度保守型；商品房审查立场双向提示；风险校准标准四级（建设工程默认触发情形）；文书风格结构化分析（含风险等级清单与修改建议）；地方性规定每次触发地方相关问题时主动提醒核实。
四种运行方式
完整访谈 /construction-legal:cold-start-interview；单独更新用各步骤命令；直接编辑 CLAUDE.md；git log construction-legal/CLAUDE.md 追踪变更历史。

05执行步骤

共 4 步，按执行顺序。每步旁边（窄屏在步骤说明之后）是请律师核对的内置假设，可逐条复制。页面里的英文标记见首页「标记与术语」。

  1. 主体画像与项目组合

    /construction-legal:identity-project可单独运行

    采集组织、建设工程角色、项目类型组合、使用者角色与可用集成，填充「我们是谁」「谁在使用」「可用集成」三章，作为工作产物标题、项目类型识别与资质要求判断的基础。

    请律师核对

    • 核对 1.1实体类型 6 项、代理角色 8 项、对手方 7 项是否覆盖贵所业务（EPC 总承包商、代建单位、政府平台公司、实际施工人未单列）
    • 核对 1.2非律师使用者一律降级为「研究笔记」标题是否符合贵所内部法务的使用习惯
    • 核对 1.3平台清单 8 项是否要加入地方公共资源交易平台、信用中国、裁判文书以外的案例库

    做法

    1. 开场说明每个问题都可跳过（填「不确定/暂不填写」），稍后可直接编辑配置文件更新。
    2. Q1.1 组织/律所/企业名称；Q1.2 实体类型六选一：A 律所建设工程部门 / B 发包人（建设单位）法务部 / C 承包人（施工方）法务部 / D 房地产开发商法务部 / E 造价咨询机构 / F 其他。
    3. Q2.1 主要代理角色（可多选）：A 发包人 / B 承包人（施工总承包）/ C 承包人（专业分包）/ D 监理单位 / E 造价咨询方 / F 房地产开发商 / G 购房人代理 / H 多角色混合（说明主要比例）；说明这是审查立场默认值的核心输入，后续在第二步细化。Q2.2 典型合同对手方：政府/国企发包人、民营发包人、大型施工总包、中小施工企业、专业分包、购房人、混合。
    4. Q3.1 主要项目类型（可多选按比例）：房屋建筑、市政基础设施、装饰装修、机电安装、公路、水利、电力、商品房买卖（含预售合同审查）、其他专业工程、多类型混合；Q3.2 典型项目规模与造价区间（示例：单项目 500 万至 5000 万；商品房项目 1 亿以上）；Q3.3 主要痛点（示例：工程款拖欠/工期索赔/黑白合同/转包分包/商品房逾期交付/资质核查）；Q3.4 团队规模；Q3.5 负责人/联系人。
    5. Q4.1 使用角色六选一：A 建设工程律师（有执照）/ B 发包人内部法务（有律师可咨询）/ C 承包人内部法务（有律师可咨询）/ D 监理人员 / E 造价咨询人员 / F 非律师且无律师可咨询（须明确提示）；说明角色决定工作产物标题。Q4.2 非律师角色的律师联系人。
    6. Q5.1 工程造价咨询/鉴定机构：已委托（机构名）/ 未委托可委托 / 不适用（影响工程款争议流程的结算/鉴定路由）。Q5.2 八个平台逐项确认可用/不可用/需配置：全国建筑市场监管公共服务平台（资质/业绩）、中国招标投标公共服务平台、企业信用信息系统（失信核查）、网签备案系统、中国裁判文书网、项目管理/OA、文档存储、企业微信/钉钉。
    7. 访谈中口述法律事实时触发合理性检查：引用建设工程合同条号标 [待验证] 并提示官方数据库核实；口述项目规模阈值提示必须招标规模标准因项目类型与地方有差异 [前提 flagged — 需验证]；口述商品房预售条件提示受地方规定影响 [地方 flagged]。
    8. 按写入映射表把 Q1.1–Q5.2 共 13 组字段写入 CLAUDE.md 对应位置，覆盖 [PLACEHOLDER]；填「不确定/暂不填写」的保留占位符；不另存 YAML。

    内置规则

    • 使用角色决定工作产物标题：律师用「律师工作产物 — 受律师-当事人特权保护 / 保密」；非律师用「研究笔记 — 非法律建议，供律师审查」。
    • 用户选「多角色混合」→追问主要比例，提示在第二步逐项设定立场。
    • 用户为非律师且无律师可咨询→明确提醒所有输出为研究笔记，须律师审查方可作出法律结论。
    • 实体类型与角色不一致（如律所选「购房人代理」）→无冲突，保留双重描述。
    • 项目类型含商品房买卖→提示还需在第二步设定商品房审查立场（购房人侧/开发商侧）。
    • 集成未连接时核心功能仍可工作，造价鉴定数据、资质信息需手动提供。

    产出

    CLAUDE.md「我们是谁」（含建设工程角色、项目类型组合小节）、「谁在使用」、「可用集成」三章填充完毕。

  2. 审查与争议立场

    /construction-legal:review-stance可单独运行

    采集整体代理立场、合同审查严格度、争议处理倾向与商品房审查立场，填充「审查与争议立场」章及其三个小节；立场是建设工程审查最核心的变量，同一份合同不同立场结论可能截然相反。

    请律师核对

    • 核对 2.1五种立场各自预设的关注清单（如发包人侧「结算高估冒算防控」、承包人侧「无效合同折价补偿」）是否贴合贵所实践
    • 核对 2.2三档严格度的定义，尤其是「保守型＝任何可能不利条款均标红」是否会产生过多标记
    • 核对 2.3面积误差 3% 作为购房人侧与开发商侧的处理分界，以及「双倍返还超出部分」的表述是否需按现行司法解释复核
    • 核对 2.4仲裁机构偏好清单只列北仲、贸仲、当地仲裁、法院四类，是否需加入上海、深圳等常用仲裁机构

    做法

    1. Q1.1 整体代理立场五选一，每项附关注清单：A 发包人侧（承包人资质核查 / 工期质量违约追责 / 结算高估冒算防控 / 合同无效风险防控）；B 承包人侧（足额结算保障 / 工期顺延签证 / 无效合同折价补偿 / 优先受偿权行使时机）；C 中立审查（识别显失公平条款 / 双向争议点 / 合同缺口）；D 购房人侧（预售资质五证 / 逾期交房违约救济 / 面积误差处理 / 贷款不成解除 / 网签保护）；E 多场景混合（说明主要组合及比例）。Q1.2 立场补充说明（如「绝大多数为承包人侧，偶尔承接发包人方尽职调查」）。
    2. Q2.1 审查严格度三选一：A 保守型——任何可能对代理方不利的条款均标红，优先识别风险；B 平衡型——重大风险标红、一般风险标橙，优先商务对话；C 进取型——仅拦截明显不利条款，一般条款尽量放行。Q2.2 各立场保守重点（供参考）：发包人侧——承包人资质核查要求、价款调整封口条款、结算逾期答复条款、违约金基数与上限；承包人侧——签证权限与期限、工期顺延事由完整性、变更程序（口头指令书面确认）、进度款支付条件、质保金返还期限与条件；购房人侧——逾期交房/办证违约金封顶条款、面积误差条款是否排除法定规则、预售资质核查。
    3. Q3.1 争议处理优先级：A 协商优先 / B 造价鉴定优先（争议金额大或结算依据不足）/ C 仲裁优先（有仲裁条款且倾向非公开）/ D 诉讼优先 / E 视情况。Q3.2 承包人优先受偿权（民法典第807条，建议复核）行使倾向：A 积极行使——拖欠即评估启动 / B 仅在金额重大时 / C 以启动作为催款手段 / D 不适用（我方通常发包人侧）；提示行使期限须核实现行司法解释版本 [待验证 — 司法解释条号易变，须核实现行版本]。Q3.3 争议解决机构偏好：北京仲裁委（BAC/BIAC）/ 贸仲（CIETAC）/ 当地仲裁机构（注明地区）/ 人民法院 / 视合同约定。
    4. Q4 商品房审查立场仅在项目类型含商品房买卖时生效：Q4.1 代理方向——A 购房人侧（预售资质五证合规 / 逾期违约金不被封顶 / 面积误差超 3% 退款解除 / 按揭不成无责解除）/ B 开发商侧（确认五证合规 / 限制过高违约金 / 面积误差据实结算 / 约定贷款不成可归责情形）/ C 中立；Q4.2 逾期违约金容忍度——购房人侧严格任何封顶条款均标红 / 开发商侧宽松可接受约定上限 / 视约定数额；Q4.3 面积误差处理——购房人侧超 3% 即评估追究（解除或双倍返还超出部分）/ 开发商侧尽量在误差范围内解决（3% 以内据实结算）/ 中立按面积误差比实际数值分析；Q4.4 退房条件容忍度（口头描述）。
    5. 合理性检查：口述优先受偿权行使期限→[前提 flagged — 须核实现行司法解释版本]；口述仲裁时效→[前提 flagged — 须核实现行规定]；口述商品房违约金比率或上限→提示须与合同约定及司法解释调整规则对照 [前提 flagged — 需验证]；违约金率明显偏高或偏低→参照民法典第585条第2款调整规则（建议复核）提示核实。
    6. 写入「审查与争议立场」及「合同审查严格度」「争议处理倾向」「商品房审查立场」三个小节，覆盖占位符；写入后提示可用 git 追踪配置变更。

    内置规则

    • 用户选「多场景混合」→记录比例描述，并提示临时模式下须每次明确告知代理立场。
    • 用户不确定审查严格度→默认保守型并标 [临时模式]，提示这是稳健做法。
    • 用户无商品房业务→Q4 全部跳过，商品房审查立场保留 [PLACEHOLDER]。
    • 面积误差 3% 是购房人侧「评估追究」与开发商侧「据实结算」的分界。
    • 不应把「中立」当作未经思考的默认值：真正的中立审查是双方风险均衡呈现，而非不设立场。

    法律依据

    • 《民法典》第807条 — 承包人工程价款优先受偿权（建议复核；行使期限须核实现行司法解释版本 [待验证]）
    • 《民法典》第585条第2款 — 违约金过高或过低的调整规则（建议复核），用于口述违约金率的合理性检查

    产出

    CLAUDE.md「审查与争议立场」章（整体代理立场、立场说明）及「合同审查严格度」「争议处理倾向」「商品房审查立场」三个小节填充完毕。

  3. 风险校准与升级矩阵

    /construction-legal:risk-escalation可单独运行

    采集四级风险定义、角色权限、自动升级触发条件与诉讼/仲裁/优先受偿权行使触发规则，填充「风险校准」与「升级矩阵」章，在正确时点把事务升级给有资质的律师。

    请律师核对

    • 核对 3.1优先受偿权期限「30 天内升级」与「60 天以上低风险」之间 30–60 天区间未定义等级，是否需补中等或高风险
    • 核对 3.2工程款升级阈值示例 500 万 / 2000 万是否贴近贵所案件规模
    • 核对 3.3面积误差 ±2%~3% 定为中等风险、超 3% 由第二步立场决定追究，分级是否合理
    • 核对 3.4高风险清单中「进度款长期拖欠超过 3 个月」「变更签证超出约定期限」的默认示例

    做法

    1. Q1.1 关键风险（须立即处理）默认触发情形供勾选或修改：A 合同因转包/违法分包/必须招标但未招标/黑白合同可能无效（须律师出具效力意见）；B 工程款优先受偿权期限临近（期限须核实现行司法解释 [待验证]）；C 收到合同解除通知或起诉/仲裁申请；D 工程质量存在重大安全隐患；E 商品房群体性退房风险（多户同时主张）；F 其他。
    2. Q1.2 高风险（须采取行动但不需立即升级）：A 承包人资质存在问题（证书不全/超范围施工）；B 结算依据不足或结算金额重大争议；C 变更签证未按时确认（超出约定期限 [待验证]）；D 进度款长期拖欠（超过 [PLACEHOLDER — 如 3 个月]）；E 逾期交房/办证违约金数额较大；F 商品房预售手续不完整（五证缺失之一）；G 其他。
    3. Q1.3 中等风险：A 合同约定不明确可能引发纠纷；B 工期顺延条件限制较多；C 面积误差接近 3% 临界值（±2%~3% 范围）；D 造价鉴定申请条件存在争议；E 保修条款不完整或质保金返还期限不明确；F 其他。Q1.4 低风险：A 主体资质核查无问题（资质等级符合/无失信记录）；B 合同条款约定明确公平；C 商品房五证齐全且预售许可在效期内；D 优先受偿权期限尚早（离截止日 60 天以上 [待验证期限]）；E 其他。
    4. Q2.1 初级角色（内部法务/助理律师）可独立处理事项：合同初步审查（资质查询、条款对比、标准条款分析）、招标文件合规初步审核、逾期通知/催款函草稿、工程款主张材料整理、商品房审查信息收集（五证核查、备案查询）。Q2.2 初级角色需升级条件（可多选）：合同可能无效；工程款重大争议（超过 [PLACEHOLDER — 如 500 万]）；作出解除判断或发送解除通知；行使优先受偿权；重大索赔诉讼/仲裁策略决策；商品房群体性退房。Q2.3 工程款/索赔金额升级阈值（示例：单项争议超过 500 万须升级；超过 2000 万须合伙人介入）。
    5. Q3.1 自动升级清单默认全选、可调整：A 合同可能无效；B 工程款数额重大（超过 Q2.3 阈值）；C 拟行使优先受偿权（启动前须律师确认期限与程序 [待验证]）；D 收到解除通知或起诉/仲裁申请；E 商品房群体性退房；F 优先受偿权期限临近（离截止日 30 天内 [待验证]）须主动提示并升级；可新增。
    6. Q4.1 工程款拖欠触发仲裁/诉讼的时机（催款函发送后 [PLACEHOLDER — 如 30 天] 无回应 / 明确拒绝支付 / 优先受偿权期限临近 / 金额超过阈值 / 其他）。Q4.2 优先受偿权行使决策因素：期限（首要，须核实 [待验证]）、是否已进入诉讼仲裁、金额大小、发包人资产状况、项目是否已竣工交付（影响行使条件 [待验证]）。Q4.3 收到对方解除通知的标准程序：立即升级主办律师、评估解除条件是否成就、准备已完工程验收与结算证据、视情况发异议函。Q4.4 商品房违约/退房触发升级：逾期交房/办证累计超过 [PLACEHOLDER — 如 6 个月] 且购房人发解除通知、一房二卖或房屋被查封抵押、群体性退房、贷款不成后购房人主张无责解除。
    7. 合理性检查：口述优先受偿权期限（如「6 个月」「18 个月」）→[前提 flagged — 须核实现行司法解释版本]；口述工程款诉讼时效（如「3 年」）→提示适用民法典通则规定、计算起点须确认 [待验证]；口述仲裁时效→[前提 flagged — 须核实仲裁时效与诉讼时效区别]；口述必须招标金额标准（如「200 万以上」）→提示因项目类型与地方有差异 [前提 flagged — 需核实现行规定]。
    8. 按写入映射把 Q1.1–Q4.4 写入「风险校准」四级表与「升级矩阵」三个小节；用户选「视情况/不确定」保留占位符；司法解释期限字段保留 [待验证]。

    内置规则

    • 四级风险：关键（明显违法或重大权益受损、极可能影响合同效力或工程款回收、须立即处理）/ 高（须采取行动）/ 中等（建议进一步核实或预防）/ 低（正常推进、备案记录）；配置文件中以红、橙、黄、绿四色图标标记。
    • 自动升级优先于角色权限划分，六项默认清单无论风险等级一旦触发即升级。
    • 优先受偿权期限阈值：离截止日 30 天内升级；60 天以上为低风险；具体期限一律 [待验证]。
    • 角色权限三级：内部法务/助理律师、主办律师/合伙人、法务总监/高级合伙人（无上限）；团队很小的简化为两级（本人 vs 须转委托）。
    • 用户无商品房业务→Q4.4 跳过，商品房条目保留但标「不适用」；用户主要为开发商侧→优先受偿权相关问题标「不适用」，商品房升级触发调整为开发商侧视角。
    • 用户不确定工程款升级阈值→保留 [PLACEHOLDER]，提示后续直接编辑配置文件设定。

    法律依据

    • 建设工程施工合同司法解释关于优先受偿权行使期限的规定 — 具体期限 [待验证 — 司法解释条号与期限易变，须核实]

  4. 文书风格与地方规定

    /construction-legal:style-local-rules可单独运行

    采集四类文书的风格、存放与交付方式、造价鉴定资源与地方造价定额、主要业务省市与地方建设主管部门重点关注事项，填充「文书风格」「输出」「共享护栏」章，使各流程能自动触发 [地方 flagged] 提示。

    请律师核对

    • 核对 4.1主要业务省市清单只列 9 个地区，其他须填「其他」
    • 核对 4.2地方造价定额清单只列全国、北京、广东、上海四种具名定额
    • 核对 4.3地方规定重点关注 8 项是否遗漏贵所所在地的特殊规定（如地方工程担保、保证金比例）

    做法

    1. Q1.1 合同审查意见书结构：A 结构化分析（主体资质→工期质量→价款结算→违约解除 + 风险等级清单 + 修改建议）/ B 摘要式（仅列重要风险项）/ C 对照表式（合同原文 vs 建议修改，谈判阶段）/ D 简报式（3-5 个要点 + 风险结论，领导汇报）/ E 其他。Q1.2 风险标注方式：A 颜色图标四级 + 文字 / B 纯文字四级 / C 仅标关键和高风险 / D 视输出目的地。
    2. Q2.1 工程款主张函件语气：A 正式强硬（不留协商空间）/ B 正式但留余地（长期合作方）/ C 阶梯式（友好提醒→正式催告→法律声明）/ D 视关系与金额。Q2.2 优先受偿权行使通知的格式与律师签署要求；提示行使有期限要求 [待验证 — 须核实现行司法解释版本]，送达方式与时间均有法律意义。
    3. Q3.1 争议分析意见书结构：A 分析框架式（事实→争议焦点→法律依据→胜诉概率→策略建议）/ B 问题回答式 / C 诉讼仲裁预案式（请求草案 + 证据清单 + 抗辩预案）/ D 结算鉴定前置式 / E 其他。
    4. Q4.1 商品房审查报告（仅含商品房业务时）：A 购房人侧风险清单 + 修改建议 / B 开发商侧合规核查报告 + 问题清单 / C 双向风险评估 / D 五证资质核查摘要（购房前尽调）/ E 其他。
    5. Q5.1 工作产物存放位置：内部系统路径 / 共享文件夹 / 项目管理系统 / 不设固定位置。Q5.2 交付方式：电子邮件 PDF / 企业微信钉钉 / 内部系统提交 / 纸质打印盖章 / 其他。
    6. Q6.1 造价咨询/鉴定机构再确认（已在第一步填写的显示已采集值快速确认）：已委托固定机构 / 有意向未委托 / 未委托可委托（倾向国有/私营/官方名册机构）/ 不适用。Q6.2 地方造价计价定额：全国统一（住建部）/ 北京市建设工程费用定额 / 广东省建设工程计价依据 / 上海市建设工程预算定额 / 其他省市定额 / 视项目所在地每次确认。
    7. Q7.1 主要业务省市（最多三个）：北京 / 上海 / 广东（含深圳）/ 江苏 / 浙江 / 四川 / 湖北 / 重庆 / 山东 / 其他。Q7.2 地方规定重点关注事项（可多选）：A 地方必须招标规模标准（是否高于国家标准 [待验证]）；B 农民工工资保障专项规定（工资专用账户/保证金）；C 地方造价定额与调价规则；D 地方施工许可条件与期限；E 地方商品房预售条件；F 地方限购限贷政策；G 建筑企业资质互认 [待验证]；H 其他。Q7.3 跨类型项目识别偏好：A 按主体工程类型（合同总价值最大）/ B 按资质要求 / C 按法律适用分别识别 / D 每次由用户说明。
    8. 合理性检查：口述地方必须招标规模标准（如「200 万以上」）→[地方 flagged — 须核实该省市现行标准 [待验证]]；口述定额版本（如「2018 年版」）→提示定额定期修订确认现行版本 [待验证]；口述地方预售许可条件→[地方 flagged — 须核实住建/房产主管部门现行规定 [待验证]]；口述限购限贷条件→提示政策频繁调整 [时效性 flagged]。
