01概要

对案件中每一项请求权做诉讼时效深度分析并建立持续监控台账：识别适用的时效期间（一般 3 年 / 特殊时效 / 最长 20 年保护期）、精确判定起算点并算出初步届满日、分析中止与中断事由并重算届满日、按剩余天数分级预警并给出催款函 / 起诉 / 仲裁等中断手段建议。它承接案件录入阶段的时效初判结果加以深化，读取实践配置文件中的重大性阈值做预警联动，法律引用全部来自诉讼仲裁引用库并遵守「已核实锚点 / [待验证]」纪律。四个步骤可按顺序完整执行，也可单独运行其中一步，例如只确认时效期间或只更新台账。全程贯穿一条护栏：时效届满不消灭实体权利，时效抗辩须由义务人主动提出、法院不主动适用。

02适用与边界

适用场景

  • 案件录入阶段的时效初判标记为临近届满、存在中断事由或案由复杂，需要深度分析时
  • 需要跨案件汇总所有请求权的时效届满日，建立或更新监控台账时
  • 发出催款函、提起诉讼或仲裁、对方书面确认债务等中断事由发生后，需要重算届满日并更新台账时
  • 定期（正常档按季度）刷新剩余天数与预警等级时
  • 只需确认某一请求权适用的时效期间，或只需更新台账时（单独运行对应步骤）

不做什么

  • 不替代案件录入阶段的时效初判（matter-intake/key-dates-limitation），而是在初判基础上深化，不重复初判工作
  • 不处理境外法律的时效规则，标注「超出中国大陆法律范围，需专门分析」
  • 不下「时效已届满」的定论，疑似届满只做标记，最终认定由律师作出
  • 不代替律师起草或发出催款函、起诉状，只给出行动建议
  • 不是法律意见：输出附执业提示，时效届满日的最终结论须由执业律师确认

03输入与产出

需要律师提供

  • 案件标识（slug）或「全部案件」必需
    单独运行台账步骤时可填「更新全部」
  • 案件类型 / 案由、逐项列出的请求权、当事人身份、法律关系成立时间必需
    可从事项工作区读取
  • 权利受损事件日、我方知悉日、义务人身份已知日、合同约定履行期限、分期履行情况及最后一期日期、催告记录及最后一次日期必需
    起算点判定所需
  • 催款函及送达证明、义务人书面确认、此前诉讼或仲裁记录、不可抗力等中止事由及证据可选
    中止中断分析所需；没有则届满日不作调整
  • 请求权金额可选
    用于与风险校准的重大性阈值联动
  • litigation-legal/CLAUDE.md（重大性阈值、事项工作区、工作产物存放位置）可选
  • matter-intake/key-dates-limitation 的初判结果（时效期间 / 起算点 / 预警标记）可选
    作为各步骤的起点输入

产出

  • 诉讼时效期间识别报告给律师内部
    时效期间识别表（序号 / 请求权 / 案由类型 / 适用时效期间 / 法律依据 / 待验证）+ 最长权利保护期间评估 + 待律师确认事项
  • 诉讼时效起算点判定报告给律师内部
    起算点判定表（请求权 / 起算情形 / 起算事实 / 起算日 / 初步届满日 / 时效状态）+ 每项请求权的「应当知道」分析 + 待律师确认事项
  • 诉讼时效中止/中断事由分析报告给律师内部
    中止与中断区别提示表 + 本案事由分析表（事由 / 类型 / 发生日 / 证据 / 对届满日的影响 / 证据风险）+ 调整后届满日表 + 举证风险提示
  • 诉讼时效监控台账给律师内部
    生成日期与负责律师 + 台账使用说明 + 汇总预警表（案件 / 请求权 / 届满日 / 剩余天数 / 预警等级）+ 每案详细台账（金额、届满日、预警等级、时效依据与最后中断、起算点确定性、行动建议）+ 预警行动清单（优先级 / 须在某日前完成的行动）；写入事项工作区 matter.md 或独立台账文件
  • 行动建议清单给律师内部
    对黄色 / 红色预警请求权按情形给出催款函、起诉或仲裁、取得义务人书面确认等中断手段及所需证据

04开始前

前置条件

  • 读取 litigation-legal/CLAUDE.md，加载风险校准的重大性阈值，用于预警与重大性联动
  • 加载指定案件的事项工作区（如有）
  • 加载 matter-intake/key-dates-limitation 的初判结果（如有），作为各步骤的起点
  • 读取 civil-procedure-citations.md D 节（民法典诉讼时效）与 legal-basis-conventions.md（待验证标记规则）
  • 按 shared/legal-document-intake/SKILL.md 做动态 intake：格式、保存位置和立场已由请求、文件或配置明确时直接执行，不重复询问

硬性规则

时效抗辩核心护栏
诉讼时效届满不消灭实体权利，义务人可主动提出时效抗辩拒绝履行；法院不主动适用——只有义务人主动提出，才发生丧失胜诉权的法律效果；义务人主动履行的，不得以时效为由请求返还。即使时效可能已届满，仍应评估义务人是否会提出抗辩。
中止与中断不可混淆
中止 = 障碍消除后继续计算剩余期间（不归零），依据《民法典》第194条 [待验证]，触发条件为时效最后六个月内的不可抗力等法定障碍；中断 = 重新起算（归零），依据《民法典》第195条 [待验证]，触发事由为主张权利 / 同意履行 / 提起诉讼仲裁等。
引用纪律
已核实锚点（《民法典》第188条）正确使用，不滥标待验证；不确信条号一律标 [待验证]，不臆造；特殊时效的条号和年限一律标 [待验证]；案例引用默认标 [待验证]。
执业提示
完成深度时效分析后始终附：「本时效分析为辅助工具，不替代律师的专业判断。时效届满日的认定涉及起算点、中断事由等复杂法律问题，最终结论须由执业律师确认。」
动态 intake 与输出确认
只有影响成果的必须项未解决，或写入目标不明、可能覆盖原件、涉及外部发送时，才输出 [CLARIFY:] 并暂停；有不覆盖原件的安全默认值时采用默认并简短说明；永远不覆盖原件，除非用户明确指定。
先检索、后结论
给出任何法律结论前优先用检索工具核对现行有效的法律法规、司法解释及指导性案例；无法核实时标注「未经检索核实，请以现行有效文本为准」；禁止凭记忆断言法条编号、发文文号或生效日期。
与初判的分工
案件录入阶段的 key-dates-limitation 做快速初判（每案一次）；本流程做深度分析，以初判结果为起点深化而非重复。

05执行步骤

共 4 步，按执行顺序。每步旁边（窄屏在步骤说明之后）是请律师核对的内置假设，可逐条复制。页面里的英文标记见首页「标记与术语」。

  1. 时效期间识别

    /litigation-legal:limitation-period-identification可单独运行

    为案件中每一项独立请求权确定适用的时效期间——一般 3 年、特殊时效或最长 20 年保护期——多个请求权逐一识别、不合并

    请律师核对

    • 核对 1.1特殊时效表只列五行（国际货物买卖、票据、海事、寿险、其他单行法），没有劳动争议等常见特殊期间情形，是否需要补充？
    • 核对 1.2特殊时效年限全部标 [待验证]，流程只提示核验、不自行核验，律师是否接受每次手动核验？
    • 核对 1.3输出模板中的「距2024年年数（估算）」写死了 2024 年，须按当前日期理解；是否要求改为动态日期？

    做法

    1. 读取引用库 D 节（D.1 一般时效 / D.2 起算点 / D.5 最长期间 / D.6 特殊时效）、引用规范、配置文件中的案件信息和已有的初判结果。
    2. 向律师确认或从事项工作区读取四项信息：案件类型与案由（合同 / 侵权 / 劳动 / 知识产权 / 国际货物买卖 / 票据 / 海事 / 其他）、逐项请求权（返还货款 / 赔偿损失 / 支付违约金 / 确认合同无效 / 侵权赔偿等）、当事人身份（如外贸企业可能涉及国际货物买卖特殊时效）、法律关系成立时间。
    3. 列出请求权分项表：序号 / 请求权名称 / 简要描述 / 初步案由判断。
    4. 按案由对照特殊时效表判断是否落入特殊情形：国际货物买卖 4 年、票据汇票本票 2 年 / 支票 1 年、海事 1 年、寿险给付 5 年、其他单行法，全部标 [待验证]。
    5. 存在特殊时效可能：标「[特殊时效适用 — 具体年限须核验]」并提示律师通过国家法律法规数据库（flk.npc.gov.cn）或北大法宝核验；不存在：适用一般 3 年时效（《民法典》第188条第1款，已核实）；不确定：标「[时效期间待律师确认 — 需核查是否有特殊时效适用]」。
    6. 计算自「权利受到损害之日」起的年数，接近或超过 20 年的显著标记「[最长期间预警 — 需核查是否超过20年保护期]」，并注明最长期间从权利受损日起算、不受知情日影响。
    7. 多个请求权逐一填入时效期间识别表（请求权 / 适用时效期间 / 时效期间来源 / 待验证标记），不合并。
    8. 按检查清单核对（锚点未被误标待验证、表格列数一致）后输出识别报告，并提示下一步运行 /litigation-legal:accrual-determination。

    内置规则

    • 一般诉讼时效 3 年：向人民法院请求保护民事权利的诉讼时效期间为三年，法律另有规定的依照其规定（《民法典》第188条第1款，已核实锚点）。
    • 特殊时效对照表（全部 [待验证]）：国际货物买卖合同纠纷 4 年；票据纠纷汇票、本票 2 年 / 支票 1 年；海事物件赔偿请求 1 年；寿险给付请求 5 年；其他单行法特殊时效依各专门法律确定。
    • 最长权利保护期间 20 年：自权利受到损害之日起超过二十年的不予保护，有特殊情况可申请延长（规则已核实，条款款号 [待验证]）。
    • 案由不明时不假设适用一般时效：先完成请求权基础识别，标「[案由待定 — 时效期间需在请求权基础确认后判断]」。
    • 涉及境外法律：标「[境外时效规则 — 超出中国大陆法律范围，需专门分析]」。
    • 律师声称非常规特殊时效（如 1 年合同时效）：触发合理性检查，说明一般合同纠纷适用 3 年时效，要求说明特殊法律依据并标 [前提 flagged — 需验证]。
    • 最长保护期已接近或超过 20 年：显著标记，建议立即进行起算点和中止中断的深度分析。

    法律依据

    • 《民法典》（2020年）第188条第1款 — 一般诉讼时效三年（已核实锚点，建议复核）
    • 《民法典》（2020年）第188条 — 最长权利保护期间二十年，特殊情况可申请延长（规则已核实，条款款号 [待验证]）
    • 《票据法》关于票据请求权时效 [条号待验证] — 汇票 / 本票 2 年、支票 1 年 [待验证]
    • 《海商法》关于海事请求权时效 [条号待验证] — 货物运输请求权 1 年 [待验证]
    • 《联合国国际货物销售合同公约》及相关规定 [条号待验证] — 国际货物买卖特殊时效 4 年 [待验证]
    • 《保险法》相关条款 [条号待验证] — 寿险给付请求 5 年 [待验证]

    产出

    「诉讼时效期间识别报告」：时效期间识别表、最长权利保护期间评估（权利受损大致日期 / 年数估算 / 安全、接近 20 年需关注或已超过）、待律师确认事项清单

  2. 起算点判定

    /litigation-legal:accrual-determination可单独运行

    为每项请求权精确判定起算日并算出初步届满日；起算点不清时不推断，而是列出待查事实请律师确认

    请律师核对

    • 核对 2.1分期履行债务「整体以最后一期届满日为基准」只是文件采用的一种口径且标 [待验证]，贵所是否按此处理？
    • 核对 2.2持续侵权起算点被写为「侵权终止日与知悉日以较早者为准」并注明有争议，请确认贵所采用的立场。
    • 核对 2.3「应当知道」的举证责任被分配给主张时效已过的义务人，是否与贵所的实务经验一致？
    • 核对 2.4对方提前违约时取「实际违约日与期满日较早者」的处理是否接受？

    做法

    1. 读取引用库 D.2 / D.3 / D.4 节、引用规范、配置文件中的案件信息、上一步确认的时效期间和初判起算点。
    2. 向律师确认六项起算基础信息：权利受损事件（违约发生日 / 侵权行为日 / 债务到期日 / 通知到达日）、我方实际知悉日、义务人身份已知日、合同约定履行期限、分期履行情况及最后一期日期、书面催告记录及最后一次日期。
    3. 套用一般起算规则：自权利人知道或者应当知道权利受到损害以及义务人之日起算（《民法典》第188条，已核实）；取「知道」与「应当知道」中较早者，且须同时知悉义务人身份，缺一不可。
    4. 按六种情形对照分情形判定表确定起算点规则：有明确约定履行期限 / 未约定履行期限 / 分期履行 / 持续侵权 / 连带债务 / 合同解除后的返还请求。
    5. 分析「应当知道」的拟制知悉情形——权利受损事实已公开（诉讼立案、行政处罚公告）、关联方已知悉（代理人、法定代表人）、合理审查可知悉、对方已书面通知（送达日为知悉日）——并标注举证方向；我方主张知悉日较晚时需证明在更早时间无法合理知悉或无法确认义务人。
    6. 填起算点汇总表（请求权 / 起算情形 / 起算事实 / 起算日 / 确定性），存疑的标 [需律师确认]。
    7. 计算初步届满日 = 起算日 + 时效期间（来自上一步），并按剩余时间打时效状态标记。
    8. 起算点有双方争议或知悉日举证困难时，列出双方可能的起算点或建议收集的证据，不单方面裁断。
    9. 输出判定报告并提示下一步运行 /litigation-legal:tolling-interruption。

    内置规则

    • 分情形起算点（除一般规则外全部 [待验证]）：有约定履行期限 → 期限届满之日；未约定期限 → 催告后合理期限届满之日，无催告则自知悉权利受损之日；分期履行 → 各期分别起算，整体请求权以最后一期届满为基准；持续侵权 → 侵权终止之日与知悉之日以较早者为准，有争议 [待律师确认]；连带债务 → 对每个义务人分别计算，以知悉该义务人之日为各自起算点；合同解除后返还 → 自解除生效之日起算。
    • 「应当知道」的举证责任通常在主张时效已过的义务人，对方须举证权利人应当知道的时间节点。
    • 时效状态标记：剩余 >1 年「常规监控」；6 个月～1 年「[时效预警 — 距届满不足1年]」；<6 个月「[时效紧急 — 距届满不足6个月，需评估起诉/仲裁必要性]」；<30 天「[时效极度紧急 — 距届满不足30天，需立即行动]」；已届满（疑似）「[时效疑似届满 — 需检查中止/中断事由]」；起算点不清「[起算点不确定 — 不计算届满日，需律师确认以下事实]」。
    • 双方各主张不同起算点：列出两种可能，标「[起算点有争议 — 双方各主张不同时点，需律师评估有利立场]」。
    • 有约定履行期限但对方提前违约：实际违约日（知悉违约之日）与合同期满日取较早者，标「[提前违约起算点有争议]」[待验证]。
    • 律师口述起算日与已有证据不一致：列出两个版本，标「[起算日有矛盾：用户口述为X，现有证据显示Y — 请确认]」。
    • 无法判断是否属于持续侵权：标「[持续侵权认定存在争议，起算点待律师确认]」，并提示检索相关司法解释和案例。

    法律依据

  3. 中止与中断事由分析

    /litigation-legal:tolling-interruption可单独运行

    识别本案全部中止与中断事由、评估证据、算出调整后届满日，并把两种制度的法律后果区分清楚

    请律师核对

    • 核对 3.1中止后届满日的计算，文件同时写了「原届满日 + 中止期间」和「剩余不足六个月的延长至六个月」两种口径，请确认采用哪一种。
    • 核对 3.2中断证据强度排序把公证送达评为强、微信无回复评为弱，是否与贵所经办法院的认定口径一致？
    • 核对 3.3「提起诉讼或仲裁即发生中断、无需等待判决」之后撤诉、驳回起诉等情形如何处理，文件未展开，请律师补充立场。

    做法

    1. 读取引用库 D.3（中止）/ D.4（中断）节、引用规范，以及前两步确认的时效期间、起算点和初步届满日。
    2. 先明确区别：中止（《民法典》第194条 [待验证]）须发生在时效最后六个月内，障碍消除后继续计算剩余期间；中断（《民法典》第195条 [待验证]）从中断事由发生时重新起算、归零。
    3. 按五类逐一询问事由：催款类（书面催款函 / 律师函 / 要求履行通知，最近一次日期与送达证明）、对方确认类（书面承认债务 / 还款承诺，日期与形式）、诉讼仲裁类（此前是否就同一权利起诉或仲裁，日期与撤案 / 判决 / 未结结果）、其他同等效力行为（公证发函等）[待验证]、不可抗力等中止事由（是否在最后六个月内）。
    4. 对每个事由按证据要求表评估证据状态（有 / 无 / 不完整）并归类为中止或中断，填事由分析表（序号 / 类型 / 描述 / 发生日 / 证据状态 / 中止或中断）。
    5. 中断：以最后一次有效中断事由发生日为新起算日，调整后届满日 = 最后中断日 + 时效期间；多次中断的逐一列出并评估证据强度（公证送达强 / 微信无回复弱），有效性存疑的标「[有效性存疑 — 需律师评估]」。
    6. 中止：确认障碍发生在时效最后六个月内，调整后届满日 = 原届满日 + 中止期间；不在最后六个月内的说明「不产生中止效力」。
    7. 对送达证明缺失、电子催告无回复等情形标注有效性存疑并给出补证建议（如公证保全）。
    8. 按起算点判定步骤的时效状态标记体系更新状态，输出分析报告，提示下一步运行 /litigation-legal:monitoring-ledger。

    内置规则

    • 中止触发条件（须在时效最后六个月内）：不可抗力；权利人为无或限制民事行为能力人且无法定代理人；继承开始后未确定继承人或遗产管理人；权利人被义务人控制；其他障碍 [待验证]。后果：继续计算不归零，剩余时间不足六个月的延长至六个月；计算方式写为「时效届满日 = 原届满日 + 中止期间」。
    • 中断触发事由：权利人向义务人提出履行请求；义务人同意履行义务；权利人提起诉讼或申请仲裁；与起诉仲裁具有同等效力的其他情形 [待验证]。后果：重新起算归零，新届满日 = 中断事由发生日 + 适用时效期间；多次中断以最后一次中断事由发生日为起算点。
    • 中断证据要求：催款函须函件原件 + 送达证明（快递面单 / 签收回执 / 公证送达），电子催告须证明对方收到；义务人书面承诺须明确确认债务存在及义务人身份；起诉或仲裁以起诉状副本 + 法院受理通知或仲裁申请书 + 受案通知为证，提起本身即中断、无需等待判决；双方签署的对账单以签署日为中断日；微信 / 邮件催款须完整电子数据（时间戳 + 对方已读或回复记录），公证保全更有力。
    • 中断证据形式有争议（如微信催款）：评估可信度等级，标「[证据效力存疑 — 建议补充公证保全]」。
    • 义务人否认收到催款函：标注争议，提示我方须举证送达事实。
    • 时效可能已届满但存在中断事由：重点核查中断事由有效性，标「[时效疑似届满，但存在中断事由——需律师紧急核查]」[紧急]。
    • 律师混淆中止和中断（说「中断了但不用从头算」）：予以纠正，说明中断是归零重算、中止是继续计算剩余时间，请确认指哪种情形。
    • 无法提供催款函送达证明：标「[中断事由有效性存疑 — 无送达证明：催款函是否实际到达对方无法证明，存在时效届满风险]」。

    法律依据

    • 《民法典》（2020年）第194条 — 诉讼时效中止：最后六个月内因不可抗力等法定障碍不能行使权利，障碍消除后继续计算 [待验证]
    • 《民法典》（2020年）第195条 — 诉讼时效中断：主张权利 / 同意履行 / 提起诉讼仲裁等，重新起算 [待验证]
    • 《最高人民法院关于民事诉讼证据的若干规定》（2020修正）关于电子数据 [条号待验证] — 微信 / 邮件须证明真实性与完整性，公证保全具有优先认定效力 [待验证]

    产出

    「诉讼时效中止/中断事由分析报告」：中止与中断区别提示表、本案事由分析表、调整后届满日表（请求权 / 原始届满日 / 调整事由 / 调整后届满日 / 时效状态）、举证风险提示与补证建议

  4. 监控台账与预警

    /litigation-legal:monitoring-ledger可单独运行

    把全部案件、全部请求权的届满日汇总成一张持续更新的台账，按剩余天数分七级预警，对黄色与红色预警给出具体中断行动

    请律师核对

    • 核对 4.1七级预警的天数边界（180 / 90 / 30 / 7 天）是否符合贵所的时效管理节奏？剩余恰为 30 天时同时落入行动建议的「≥30 天」黄色情形和等级表的「1–30 天」红色档，须确认按哪一档处理。
    • 核对 4.2红色预警的优先方案是「立即起诉或申请仲裁」而非先发函，是否符合贵所策略？
    • 核对 4.3「负责律师（读自配置文件）」在配置模板中没有对应字段，需明确读取哪一项（律师联系人还是升级联系人）。

    做法

    1. 读取引用库 D 节、引用规范、配置文件「## 风险校准 → 重大性阈值」，以及前三步产出的时效期间、起算点、调整后届满日。
    2. 按「事项（案件）→ 请求权」两级组织台账，对每项请求权收集九个字段：名称 / 当事人（义务人）/ 案件类型 / 金额 / 时效期间 / 起算日 / 调整后届满日 / 最近中断事由日期 / 起算点确定性。
    3. 计算剩余天数 = 届满日 − 今日，用实际日历天数（含节假日），不用工作日。
    4. 按预警等级表分配等级：正常 / 关注 / 黄色预警 / 红色预警 / 极度紧急 / 起算不确定 / 疑似届满。
    5. 请求权金额超过配置的重大性阈值时，在预警等级后加注「[重大性标记：请求权金额 ¥X 超过已披露阈值 ¥Y，须同步通知 升级联系人]」。
    6. 对每项黄色 / 红色预警请求权按三种情形生成行动建议：剩余 ≥30 天（黄色区间）给出三选项——(A) 发出书面催款函并备送达证明、(B) 提起诉讼或申请仲裁、(C) 取得义务人书面确认；剩余 <30 天（红色区间）优先方案立即起诉或申请仲裁、备选同日公证催款函，并提醒时效届满后义务人可主动抗辩、法院不主动适用；起算点不确定的建议立即发催款函保守保全权利并尽快确认起算点。
    7. 按触发事件更新台账：新案件录入后新增行（来自初判、本步骤完善）；中断事由发生后更新届满日 = 中断日 + 时效期间；案件已解决（判决 / 和解 / 撤案）标记「已解决」并移出预警列表；时效期间或起算点确认后更新对应字段。
    8. 台账写入案件事项工作区（matter.md 或独立台账文件），配置文件指定了工作产物位置的写入对应文件夹。
    9. 案件超过 10 个时优先显示黄色 / 红色预警案件，绿色 / 蓝色折叠至附录；输出带台账使用说明的台账与预警行动清单。

    内置规则

    • 预警等级：正常 >180 天（绿色，常规监控、按季度更新）；关注 91–180 天（蓝色，开始准备中断措施、下季度前行动）；黄色预警 31–90 天（本月内采取中断时效措施）；红色预警 1–30 天（紧急、立即行动）；极度紧急 ≤7 天（今日或明日必须行动）；起算不确定（橙色，需紧急确认起算点、不得拖延）；疑似届满 <0 天（灰色，立即核查中断事由）。
    • 剩余天数用实际日历天数（含节假日），不用工作日。
    • 优先中断方式排序：提起诉讼 / 申请仲裁（效力最强、立案回执证据最强、操作较复杂）> 公证发函（效力强、公证书证据强、需联系公证处）> 挂号信或快递函有签收回执（中）> 电子邮件催告且对方已回复（中等，证明较难）> 普通邮件 / 微信对方无回复（效力存疑、证据弱）。
    • 剩余天数 <0 且无中断记录：标灰色「疑似届满」，提示紧急核查中断事由；不得定论时效已届满，由律师最终判断。
    • 仲裁案件：向仲裁机构申请仲裁同样产生中断效力，与诉讼等同处理。
    • 台账与事项工作区数据不一致：列出两个版本，请律师确认后更新。
    • 台账必须包含「不替代律师判断」的使用说明，并说明时效届满使义务人获得须主动提出的抗辩权。

    法律依据

    • 《民法典》（2020年）第188条 — 一般诉讼时效三年及起算点（已核实锚点，建议复核）
    • 《民法典》（2020年）第195条 — 时效中断，重新起算 [待验证]
    • 《民法典》（2020年）第194条 — 时效中止，障碍消除后继续计算 [待验证]

09何时暂停或升级

  • 起算点不确定：不计算届满日，橙色标注并列出需律师确认的事实，建议先发催款函保守保全权利
  • 时效疑似届满（剩余 <0 天）：不下定论，标灰色，紧急核查全部中止 / 中断记录（律师函 / 对账单 / 诉讼记录）
  • 时效疑似届满但存在中断事由：标 [紧急]，请律师紧急核查中断事由有效性
  • 最长保护期接近或超过 20 年：显著标记，建议立即进行起算点和中止中断深度分析
  • 请求权金额超过已披露阈值：加重大性标记并同步通知配置中的升级联系人
  • 律师声称非常规特殊时效，或口述起算日与证据矛盾：标 [前提 flagged — 需验证] 或列出两个版本请确认

  • 写入目标不明、可能覆盖原件或涉及外部发送：输出 [CLARIFY:] 并暂停
