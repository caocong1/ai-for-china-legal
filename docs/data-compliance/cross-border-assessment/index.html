01概要

面向拟将个人信息或重要数据提供至境外的企业及其律师/DPO，完成从出境数据识别到最终评估报告的全流程合规评估：先依《个人信息保护法》第38条三路径决策树判定应走安全评估申报、保护认证还是标准合同，再按选定路径分别完成出境风险自评估与申报材料准备、或标准合同必备条款审查与省级备案、或保护认证路径说明，最后做境外接收方综合评估、核对三路径合规清单、建立出境记录台账并组装《数据出境合规评估报告》。流程开始前读取 data-compliance/CLAUDE.md 中的 CIIO 身份、处理规模、跨境政策、重要数据出境立场、文书风格与使用者角色；配置为占位符时进入临时模式，按最保守口径（CIIO 不确定按 CIIO、规模不确定按须申报）判定。所有网信办办法的数量门槛、评估有效期、备案时限一律只描述规则并标 [待验证]，由律师核实最新版办法后填入。法条引用来自 data-compliance/skills/_shared/data-protection-citations.md，核心锚点（第38/39/40/55/56条、DSL 第21/31条）标「已核实锚点，建议复核」。

02适用与边界

适用场景

  • 拟向境外母公司或集团关联方传输员工信息（如薪酬、考勤）或业务数据
  • 拟向境外 SaaS 服务商、业务合作方共享用户行为数据等个人信息
  • 需要判断本次出境应走路径①安全评估申报、路径②保护认证还是路径③标准合同
  • 已确定路径①，需要完成出境风险自评估并备齐申报书、自评估报告、法律文件
  • 已确定路径③，需要审查标准合同必备条款、在签约前完成 PIA 并向省级网信部门备案
  • 路径工作完成后，需要做境外接收方综合评估、逐项核对合规清单、建立出境记录台账并出具最终评估报告
  • 出境数据可能包含重要数据，需要与重要数据识别联合评估后再定路径

不做什么

  • 不替代重要数据的认定：重要数据是否成立须对照行业主管部门目录，由「重要数据识别与处理」步骤（/data-compliance:important-data-handling）联合评估，本流程只做初步排查与保守推定
  • 不替代有资质团队实际操办安全评估申报；文件明确「安全评估申报须由有资质团队操作」，用户无资源完成时提示升级处理
  • 不提供《数据出境安全评估办法》《个人信息出境标准合同办法》的具体数量门槛、评估有效期、受理/评估期限、备案时限数值——一律描述规则并标 [待验证]
  • 不生成面向监管的对外沟通稿：向网信部门提交的申报/备案材料不受律师-当事人特权保护，须单独处理
  • 不提供处罚案例与学说检索：各步骤的案例、学说部分均为占位（文号待填入）
  • 不处理前序步骤未完成的报告组装：路径判定或路径对应的申报/备案未完成时，装配步骤暂停并提示先完成，不可跳过

03输入与产出

需要律师提供

  • 出境业务场景描述（数据类型、境外接收方、出境目的与方式）必需
    如：向境外母公司传输员工薪酬数据 / 向境外 SaaS 服务商共享用户行为数据
  • data-compliance/CLAUDE.md 实践配置（是否为 CIIO、处理者类型/规模、跨境政策与首选路径、重要数据出境立场、文书风格与工作产物标题、使用者角色）必需
    关键字段为占位符时进入临时模式，并建议先运行 /data-compliance:cold-start-interview
  • 数据地图或处理活动记录可选
    数据类型识别不完整时，路径判定暂停并列出待补充信息清单，要求补充数据地图或处理活动记录
  • 境外接收方资料（安全问卷、认证证书、合规报告、隐私政策、内部管理制度证明）可选
    接收方信息不完整时暂停材料准备并向接收方索取；接收方拒绝提供安全能力证明时视为评估未通过（[橙]/[红]）
  • 出境路径判定结论（单独触发申报、备案或装配步骤时）可选
    各路径步骤均「建议已完成路径判定」后再触发
  • 前序成果文件：PIA 报告、自评估报告、合同草案或已签合同、评估通过结论、备案确认、认证证书可选
    装配步骤组装最终报告时逐项引用
  • 使用者角色（律师 / DPO / 法务）可选
    角色未配置时，临时模式先询问用户角色后再输出；非律师角色的输出标为「研究笔记 — 非法律建议，供律师审查」

产出

  • 出境路径判定报告给律师内部 / 客户
    五部分：一、出境数据识别表（类型/数量级/敏感程度/重要数据）；二、处理者身份（CIIO 认定来源、规模评估）；三、路径判定结论（选定路径、判定依据、临时模式标注、下一步命令）；四、跨境单独同意与影响评估状态（含 PIA 留存 3 年安排）；五、待验证事项表（规模门槛、标准合同门槛、重要数据目录）
  • 数据出境安全评估申报工作底稿给律师内部（申报材料本身面向网信部门，不受特权保护）
    五部分：一、申报情形判断表与申报结论；二、出境风险自评估摘要（综合风险等级 [红]/[橙]/[黄]/[绿]、五维度结论、总结论三选一）；三、申报材料清单与准备状态；四、时间安排（提交日期、评估期 [待验证]、有效期到期日 [待验证]）；五、待验证事项表
  • 个人信息出境标准合同备案工作底稿给律师内部 / 客户
    五部分：一、适用条件确认表与适用结论（适用 / 不适用转路径① / 临时模式）；二、标准合同审查摘要（范本版本 [待验证]、必备条款审查结果、附加条款、签订日期）；三、PIA 摘要（完成日期、风险等级、主要结论、存放位置）；四、备案情况（提交日期、受理省份、确认情况）；五、待验证事项表
  • 出境记录台账给客户内部存档
    八项记录：出境场景、出境数据量、适用路径、单独同意记录、PIA 报告、安全评估/备案/认证状态、接收方信息变更、数据安全事件；区分首次出境时记录与每次/定期更新；建议至少保存三年
  • 数据出境合规评估报告给律师内部 / 客户（出具前须做特权圈检查）
    封面载实践配置中的工作产物标题；正文十部分：一、评估概述；二、法律依据；三、出境数据识别；四、路径合规结论（选择理由 + 合规状态）；五、接收方评估结论；六、跨境单独同意与 PIA 结论；七、合规清单通过情况；八、待验证事项；九、审查者注释（按配置格式）；十、结论与建议。多路径并存时分路径分别记录合规状态并给出整体结论

04开始前

前置条件

  • 读取 data-compliance/CLAUDE.md 六项配置：是否为 CIIO（驱动决策树）、数据处理者类型/规模（驱动路径①适用性，规模门槛 [待验证]）、跨境政策与首选路径（路径偏好）、重要数据出境立场（触发重要数据联合评估）、文书风格/工作产物标题（最终报告格式）、角色（输出特权标头与审查者注释块）
  • 关键配置为占位符时进入临时模式 [临时模式]：采用平衡偏好并标注待验证项；输出标「律师工作产物」，角色未配置则先询问；按门槛逐案判定、不预设首选路径；CIIO 身份不确定按 CIIO 处理，规模门槛不确定按须申报处理；所有不确定项同时标 [待验证] 与 [临时模式]；建议先运行 /data-compliance:cold-start-interview
  • 出境数据可能包含重要数据时，先确认重要数据认定（联合触发 /data-compliance:important-data-handling），再判断出境路径
  • 读取「所属行业」字段，识别金融、医疗健康、汽车、互联网/平台、能源/交通的行业特殊规定
  • 使用前确认所引用的《数据出境安全评估办法》（2022年）与《个人信息出境标准合同办法》（2023年）是否为当前施行版本
  • 单独触发某一步骤时，该步骤的前置部分自行读取配置，不必运行整个流程
  • 使用者为非律师角色时，所有输出作为供律师审查的研究，在对处理活动作出合规结论、决定出境路径或建议启动申报前暂停并建议升级律师确认（来自实践配置文件「谁在使用」）

硬性规则

数据处理者身份与 CIIO 立场确认
如为 CIIO → 强制路径①安全评估申报，直接跳至申报步骤，路径③标准合同不适用；如不确定 CIIO 身份 → 临时模式按 CIIO 处理，并建议向行业主管部门确认认定情况；如非 CIIO → 在路径判定步骤中继续决策树
重要数据识别提示
重要数据出境一律走路径①安全评估申报（DSL 第31条，已核实）；重要数据识别须对照行业主管部门目录 [行业监管 flagged — 需核实主管部门规定]；建议同步触发重要数据识别与处理步骤做联合评估；行业目录尚未公布时按保守标准推定，标 [行业监管 flagged — 目录待公布]
单独同意与影响评估两项强制项
无论哪条路径均须满足：（1）跨境单独同意（PIPL 第39条）——取得个人对境外提供的单独同意，并告知境外接收方名称/联系方式、目的/方式、信息种类、保存期限、权利行使途径，出境前完成；（2）跨境前 PIA（PIPL 第55条第(四)项+第56条）——评估接收方保护水平及个人权益影响，报告留存至少三年，出境前完成，路径③须在签订合同前完成
第40条的适用边界
PIPL 第40条的数据本地化+强制安全评估义务仅适用于 CIIO 及处理个人信息达到网信部门规定数量的处理者，不是「无论路径均须满足」的普遍义务；该义务连同 DSL 第31条由路径判定的处理者身份判断处理
行业监管识别
读取「所属行业」：金融（个人金融信息出境特别规定，人民银行/金融监管总局）、医疗健康（健康医疗数据、基因数据，国家卫健委）、汽车（汽车数据安全管理规定 [待验证]，工信部/网信办）、互联网/平台（超规模平台境外上市须经网络安全审查，门槛 [待验证]）、能源/交通（关基认定与重要数据出境风险高）；不确定时标 [行业监管 flagged — 需核实主管部门规定] 并建议向主管部门确认
目的地与特权检查
评估报告须核查目的地是否在律师-当事人特权圈内；境外接收方所在国/地区对中国企业数据的法律取用风险须在接收方评估中记录；向网信部门提交的申报/备案材料不受律师-当事人特权保护，对外监管沟通稿件须单独处理
时效性提示
网信办出境评估办法（2022年）与标准合同办法（2023年）的具体条款、门槛数值一律描述规则并标 [待验证]；个人信息处理规模门槛、出境数量门槛、敏感个人信息门槛、评估有效期年限、备案时限、重新评估情形均须核实最新版办法
流程顺序
步骤 1 路径判定 → 步骤 2a 安全评估申报 / 2b 标准合同备案 / 2c 保护认证（按路径结论选一；同时含重要数据和个人信息时可并行）→ 步骤 3 出境合规装配；各步骤可单独触发
来源标签与验证状态
法条引用一律标来源标签（本流程全部为 [模型知识 — 需验证]），PIPL 第38/39/40/55/56条与 DSL 第21/31条标「已核实锚点，建议复核」，部门规章标 [待验证]；引用规范见 data-compliance/skills/_shared/legal-basis-conventions.md

05执行步骤

共 4 步，按执行顺序。每步旁边（窄屏在步骤说明之后）是请律师核对的内置假设，可逐条复制。页面里的英文标记见首页「标记与术语」。

  1. 出境路径判定

    /data-compliance:pathway-determination可单独运行

    识别拟出境的全部数据类型并判断处理者身份，依 PIPL 第38条三路径决策树给出明确的路径结论，同时确认跨境单独同意与跨境前 PIA 两项无论路径均须完成的义务。

    请律师核对

    • 核对 1.1决策树把「集团内部数据流转」作为优先考虑保护认证（路径②）的触发条件，是否符合贵所对认证路径适用性的实务判断？
    • 核对 1.2识别表把员工「薪酬」标为「否/是」可能构成敏感个人信息，而 PIPL 第28条列举的是金融账户等类别，是否接受这一倾向？
    • 核对 1.3「CIIO 身份不确定按 CIIO 处理」「规模门槛不确定按须申报处理」两条保守默认会把大量中小处理者推向路径①，是否会导致过度申报？
    • 核对 1.4对匿名化数据的排除要求（提供匿名化技术说明及标准对照）在实务中是否可行？
    • 核对 1.5文件对三路径之间是否存在强制顺序未作结论，仅在学说占位中标「有争议」，贵所是否有明确立场可写入？

    做法

    1. 读取实践配置中的 CIIO 身份、处理者类型、跨境政策、首选出境路径、重要数据出境立场；「是否为 CIIO」「跨境政策」为占位符时进入临时模式——凡不确定是否触发强制安全评估，一律建议申报，并建议运行冷启动访谈完善配置
    2. 步骤一：把出境场景涉及的全部数据填入识别表（数据类型 / 示例 / 是否个人信息 / 是否敏感个人信息 / 是否重要数据 / 数据量级），表中预置六类：员工信息（姓名、工号、职位、薪酬）、用户行为数据（浏览、消费记录）、生物识别数据（人脸、指纹）、行踪轨迹数据（GPS、出行记录）、运营/业务数据（交易量、订单）、技术数据（代码、算法参数）；运营数据与技术数据标「重点排查」是否为重要数据
    3. 重要数据排查对照行业主管部门目录 [行业监管 flagged]；目录未公布或不确定时按保守标准推定——可能对国家安全、公共利益有影响的数据先纳入重要数据范围排查再确认，并转入重要数据识别与处理步骤联合评估
    4. 步骤二：判断三项处理者身份——是否 CIIO（公共通信/能源/交通/水利/金融/公共服务/电子政务等领域，来源为配置或行业认定）、是否为处理个人信息达到规定数量规模的处理者（门槛数值 [待验证 — 数值随办法修订变动]）、是否处理重要数据；归入情形 A（强制安全评估）、情形 B（三路径可选）或情形 C（重要数据部分强制评估、个人信息部分另判）
    5. 步骤三：对照四种路径的适用条件、主要场景、核心要求与下游步骤——①安全评估（强制情形，向网信办申报）、②保护认证（非强制情形，集团内部流转，经国家认监委认可机构认证 [待验证]）、③标准合同（非 CIIO、未达申报门槛、出境数量未超门槛 [待验证]，签网信办范本+备案+PIA）、④其他法律行政法规或网信办规定的条件；逐条选定或排除
    6. 走路径选择决策树：是否 CIIO → 是否包含重要数据 → 处理个人信息是否达到规定数量门槛 [待验证] → 出境个人信息数量是否超过标准合同适用门槛 [待验证] → 是否集团内部数据流转；输出路径结论并指向对应的下一步命令
    7. 步骤四：逐项核对 PIPL 第39条五项告知事项（境外接收方名称/联系方式、提供目的/方式、个人信息种类、境外保存期限、向接收方行使权利的方式途径）是否落实到隐私政策或单独同意书，并按四项设计要点检查单独同意机制
    8. 步骤五：按五个维度列出跨境前 PIA 评估要点——处理目的/方式是否合法正当必要、境外接收方保护水平、再转移风险、对个人权益的影响、保护措施是否与风险相适应；确认报告与处理情况记录留存至少三年，并说明 PIA 与三条路径的衔接（路径①并轨自评估报告、路径③签约前完成并作备案材料、路径②建议另做独立 PIA 文档）
    9. 对照十项检查清单（数据分类完成、身份判断完成、三路径逐条对照、决策树走完、告知事项清单确认、PIA 列入计划、留存 3 年、重要数据联合评估、门槛标注 [待验证]、临时模式标注），按模板生成五部分《出境路径判定报告》

    内置规则

    • 决策树第一问是 CIIO：是 → 路径①强制申报；CIIO 身份不确定 → 按 CIIO 处理，同时建议向行业主管部门确认关基认定情况
    • 本次出境包含重要数据 → 路径①强制申报，先通过重要数据识别与处理步骤确认重要数据范围，再转申报步骤

    • 生物识别数据、行踪轨迹数据直接标为敏感个人信息（PIPL 第28条）；员工薪酬在识别表中标「否/是（薪酬）」，须逐案判断

    • 不确定是否为个人信息的数据（如匿名化是否满足 PIPL 匿名化标准存疑）按个人信息处理；确需排除须提供匿名化技术说明及标准对照
    • 多次分批出境须评估累计出境数量，不得通过分批规避强制申报门槛，标 [红] 违规风险

    • 同一场景同时含重要数据和个人信息 → 重要数据部分强制路径①，个人信息部分单独判断路径，分开处理或合并申报

  2. 安全评估申报（路径①）

    /data-compliance:security-assessment-filing可单独运行

    对须走路径①的场景，判断是否属强制申报情形，完成五维度出境风险自评估，准备申报材料包，并掌握申报流程、评估有效期与须重新评估的情形。

    请律师核对

    • 核对 2.1情形 D「出境敏感个人信息达到规定数量」被标为「须申报（待验证）」，请按现行办法确认该情形是否成立及门槛
    • 核对 2.2接收方评估中「所在国政府是否有大规模数据获取行为的法律依据」这一维度的措辞，是否适合写入提交监管的自评估报告？
    • 核对 2.3「存在不确定项按须申报对待」是否会使门槛以下的客户也被建议申报，贵所是否希望改为「先核实再定」？
    • 核对 2.4申报材料框架仅列四类，临时模式下「按最全集合准备」缺少现行申报指引的细目，是否补充？
    • 核对 2.5「向省级以上网信部门提交、国家网信部门组织评估」标 [待验证]，请核对现行受理层级与申报系统

    做法

    1. 读取实践配置中的 CIIO 身份、处理者类型、跨境政策、重要数据出境立场、文书风格；CIIO 身份或跨境政策为占位符时进入临时模式——假设须强制申报，申报材料清单按最全集合准备，所有门槛数值按 [待验证] 处理；建议已完成路径判定并确认须走路径①
    2. 步骤一：对照五种申报情形——A 出境重要数据（依 DSL 第21条认定）、B CIIO 出境个人信息或重要数据、C 处理个人信息累计超过规定数量门槛 [待验证]、D 出境敏感个人信息人数超过规定门槛 [待验证]、E 其他网信部门认定情形 [待验证]；填写四项判断工作表（含重要数据 / 已认定 CIIO / 处理规模达门槛 / 出境数量达门槛）
    3. 判断结论：任一项为「是」→ 须强制申报，继续自评估；全部为「否」→ 可考虑标准合同路径或保护认证路径；存在「不确定」→ 保守按须申报对待，建议专业机构确认
    4. 步骤二 2.1：评估出境活动合法正当必要性四项（目的合法正当、数据范围最小化、传输渠道安全、频率与规模符合业务需求），各给 [绿]/[黄]/[橙]/[红] 风险等级
    5. 步骤二 2.2：填写数据规模、范围与敏感程度（出境个人信息总人数、敏感个人信息类型与规模、是否含重要数据及类型、数据最近更新时间）
    6. 步骤二 2.3：评估境外接收方保护能力四维度——所在国/地区数据保护法律环境及与中国的互认机制、内部安全管理措施、合规记录（是否受罚或发生重大事件）、所在国政府是否有大规模数据获取行为的法律依据
    7. 步骤二 2.4–2.5：评估再转移风险（是否可能向第三方再提供、约束机制是否落地、对数据主体权利的影响）并核对已采取的四类保护措施（技术：加密传输/访问控制；合同：接收方承担与境内相当的保护义务；单独同意已取得；组织：专人负责跨境合规）
    8. 给出自评估结论三选一：可以出境（风险可控、接收方能力满足、措施充分）/ 须整改后出境（列出整改项）/ 暂不具备出境条件（存在重大合规风险）
    9. 步骤三：按参考性材料框架准备申报书（处理者基本信息、出境数据概况、路径选择理由、申报事由）、出境风险自评估报告（覆盖步骤二全部维度及整改计划）、与境外接收方拟订立的法律文件（须含数据保护义务条款、个人权利保障机制、违约责任）、其他证明性材料 [待验证]，并核对三项质量要点
    10. 步骤四：说明申报路径——向省级以上网信部门提交申报材料，由国家网信部门组织安全评估 [待验证]；按六阶段安排时间（准备、申报提交、受理确认 [受理期限待验证]、安全评估 [评估期限待验证]、结果出具、整改补充）
    11. 步骤五：登记评估有效期 [待验证] 与五种重新评估触发情形，纳入内部变更管理流程，安排到期前续评提醒
    12. 对照十一项检查清单（含「数据出境已暂停，等待评估结果」「跨境单独同意已完成」「跨境 PIA 已完成并留存 3 年」），按模板输出五部分《数据出境安全评估申报工作底稿》

    内置规则

    • 安全评估须在数据出境之前完成；评估通过前出境活动须暂停，不得在未通过评估的情况下启动出境
    • 评估申报未通过 → 禁止出境（[红] 强制要求）；针对评估意见整改，整改完成后重新申报
    • 评估有效期届满但尚未续评 → 暂停出境活动，立即启动续评申请，标 [红]
    • 出境活动发生变化须重新评估但企业未识别 → 合规缺口 [红]；识别后立即启动重新评估并暂停超出原评估范围的出境活动
    • 申报材料与实际情况不符 → 属违规申报 [红]，须整改材料；自评估报告须客观反映风险、不得刻意回避高风险项；法律文件须体现接收方承担与境内相当的保护义务；材料不得伪造或误导
    • 紧急业务需求须立即出境 → 无例外，安全评估审批不可绕过；可临时暂缓业务，优先推进申报
    • 五种须重新申报的情形：评估有效期届满（届满前须提前申请续评）、出境目的/方式/数据种类变化、境外接收方数据保护政策或法律环境重大变化、发生数据安全事件、其他办法规定情形 [待验证]
    • 申报情形判断关键信息（数据量、CIIO 身份）缺失 → 暂停申报，列出待确认项，保守按须申报对待
    • 自评估报告遗漏重要维度或结论不支持实际风险水平 → 退回完善，不得以不完整报告申报
    • 监管部门要求补充材料 → 按要求时限积极配合，视补充内容决定是否暂停出境；网信办规章已修订与本指引不符 → 以最新版为准并重新核实相应条目；申报系统或流程不明 → 联系省级网信部门或通过行业协会了解最新实践

    做法

    1. 读取实践配置中的 CIIO 身份、处理者类型、跨境政策、首选出境路径、文书风格；跨境政策为占位符时进入临时模式——适用条件按最保守处理，规模门槛不确定时提示核实或升级路径①；建议已完成路径判定并确认须走路径③
    2. 步骤一：逐项核对四项适用条件——非 CIIO（来源：配置或行业主管部门认定）、处理个人信息总量未超安全评估强制申报门槛 [待验证]、本次及历史出境个人信息累计数量未超标准合同适用门槛 [待验证]、出境敏感个人信息人数未超规定门槛 [待验证]
    3. 适用判断结论：全部满足 → 继续审查合同；任一条件不满足（尤其 CIIO 身份或规模超门槛）→ 本路径不适用，转路径①安全评估申报；规模门槛不确定 → 临时模式保守处理，建议咨询监管机构或直接申报路径①
    4. 步骤二：以网信办发布的标准合同范本为基准（不得随意修改必备条款，范本版本 [待验证]），对照八类必备条款逐条审查——处理者义务（是否保留对接收方的监督权）、接收方义务（是否覆盖全部处理活动）、个人作为第三方受益人（权利行使渠道、联系方式、响应时限是否明确）、接收方所在地数据保护情况（是否客观披露）、违约责任（是否可执行）、争议解决（适用法律与解决方式）、数据安全事件处理（通知时限、协助义务）、合同终止后数据处理（删除/退回时限）
    5. 在范本框架内评估四类可附加的协商条款：数据转移限制（不得转移第三方或须书面同意）、再转移条件（须满足同等保护水平）、安全审计权（处理者可合规审查或要求第三方审计）、境外数据存储时限（仅在必要期限内存储）
    6. 步骤三：签约前完成六项内容的 PIA——出境处理活动目的/方式合法正当必要、对个人权益的影响及安全风险（含敏感个人信息）、接收方所在地法律政策对履约的影响、接收方承担合同义务的技术与法律能力、数据主体权利在境外的可执行性、保护措施与风险程度相适应；结论三选一（风险可控继续 / 可整改整改后继续 / 风险较高升级或暂停），报告留存至少三年
    7. 步骤四：按严格顺序执行——完成 PIA 并形成评估报告 → 与境外接收方签订标准合同（必备条款 + 可选附加条款）→ 向省级网信部门提交备案（备案时限 [待验证]）；按备案材料框架准备备案申请材料、签订的标准合同、PIA 报告全文、其他材料 [待验证 — 以最新版办法及省级网信部门要求为准]
    8. 对照十一项检查清单（含「未发现累计出境规避门槛的行为」「签订顺序正确：PIA → 合同 → 备案」「备案后变更情形纳入内部变更管理」），按模板输出五部分《个人信息出境标准合同备案工作底稿》

    内置规则

    • 不得通过拆分业务或分批出境规避数量门槛；累计计算超过适用门槛须升级至路径①安全评估申报；蓄意拆分规避属违规行为（[红]）
    • 必备条款不可协商删除（[红]）；接收方不接受必备条款时可通过附加条款协商其他事项，必备条款缺失则不得以标准合同路径出境
    • 争议解决条款建议约定适用中国法律、在中国解决争议，以保障个人权利的可执行性
    • 接收方所在国/地区数据保护法律情况须在合同中客观说明，不得虚假陈述法律环境
    • PIA 未在签约前完成属程序违规，须补开 PIA；如发现高风险问题须重新评估合同或暂停出境
    • 备案须在合同签订后按规定时限完成 [待验证]，不得无限期拖延；备案超时属合规缺口（[橙]/[红]），立即提交并说明延迟原因，视程度决定是否暂停出境
    • 使用的范本非最新版 → 以网信办官网最新版为准，已签旧版合同须评估是否更新
    • 合同签订后出境情况重大变化或超出原备案范围 → 重新评估是否仍满足适用条件，更新合同并重新/补充备案，不得默许超范围出境；备案遭拒或要求整改 → 暂停出境，整改后重新提交
    • 目的地国/地区数据保护法律重大变化 → 重新开展 PIA，评估原合同义务是否仍可执行；接收方发生数据安全事件 → 立即启动合同约定的处置流程，评估是否影响出境合规性，必要时暂停
    • 适用门槛因数据量难以统计而不确定 → 临时模式按超门槛处理，建议专业机构协助数据盘点，同时保守准备路径①材料

    做法

    1. 读取实践配置中的出境路径立场、文书风格、工作产物标题与审查者注释块格式；文书风格为占位符时默认使用「结构化合规清单 + 正式评估报告格式」并建议完善配置
    2. 检查前序工作是否完成（路径判定，以及路径对应的申报或备案）；未完成即触发本步骤的，暂停并提示先完成前序步骤，不可跳过合规步骤
    3. 步骤一（路径②）1.1：对照保护认证适用场景——集团内部跨境数据流转（境内子公司向境外母公司传输员工或业务数据，主要场景 [待验证]）、同一集团境内外关联主体之间 [待验证]、其他网信办认可情形 [待验证 — 须核实认证规定最新版]
    4. 步骤一 1.2：说明五阶段认证流程及责任方——认证申请（向国家认监委认可机构）、初审、审核评估、认证证书颁发（有效期 [待验证]）、持续监督（频率 [待验证]）；核心纪律：认证机构须为国家认监委认可，不得使用未经认可的机构（名录 [待验证]）
    5. 步骤一 1.3：提示认证路径下仍须独立完成的三项义务——跨境单独同意（PIPL 第39条）、跨境前 PIA（第55条第(四)项+第56条）、保障境外个人的权利行使渠道
    6. 步骤二：填写接收方基本信息（法律全称、注册地/主营业务地、类型：集团内部/第三方服务商/业务合作方、数据保护负责人），按五个维度评估保护能力——所在国/地区法律环境及是否被网信办列为特别关注目的地 [待验证]、内部合规体系（索取隐私政策/安全认证/制度证明）、技术安全措施（加密、访问控制、隔离、应急响应）、历史合规记录（处罚、重大泄露）、对数据主体权利的保障机制
    7. 步骤二 2.3：评估再转移风险（向子公司/合作方再提供是否有合同约束及第三方保护水平；多国存储是否有明确声明），给 [绿]/[黄]/[橙]/[红] 等级并形成再转移约束结论（充分约束 / 存在缺口）
    8. 步骤三：按选定路径逐项确认出境前合规清单——九项通用项（数据类型范围识别与数据地图更新、目的合法正当必要、单独同意完整、PIA 完成且风险可控、PIA 留存 3 年、接收方评估完成、接收方能力满足、加密传输渠道确认、境外权利行使渠道落实），加路径①两项（评估通过结论、有效期与续评计划 [待验证]）、路径③两项（含全部必备条款的合同已签、省级备案已提交 [时限待验证]）、路径②两项（证书有效 [待验证]、认证范围与本次出境一致）；全部「已完成」方可启动出境
    9. 步骤四：建立八项出境记录台账（出境场景描述、出境数据量、适用路径、单独同意记录、PIA 报告、安全评估/备案/认证状态、接收方信息变更、数据安全事件），区分首次出境时记录与每次/定期更新，由指定人员维护，建议至少保存三年
    10. 步骤五：读取工作产物标题与审查者注释块，生成报告封面（标题、出境场景、评估日期、评估人/律所），按十部分结构组装《数据出境合规评估报告》；多路径并存（如重要数据走路径①、部分个人信息走路径③）时分路径分别记录合规状态并说明整体结论
    11. 对照十项检查清单（含「特权检查已完成：确认报告目的地是否在律师-当事人特权圈内」「所有待验证事项已在报告中明确标注」「台账保存安排至少 3 年」）后出具

    内置规则

    • 路径①申报结果尚未出具而业务有紧迫需求 → 禁止在评估结果出具前启动出境（[红] 强制要求），业务团队须等待
    • 路径变更（如从路径③变为路径①）→ 须重新走变更后路径的合规流程，不可沿用旧路径的合规文件
    • 保护认证届期未续认 → 认证失效后出境无合规路径（[红]），暂停出境直至续认完成
    • 接收方拒绝提供安全能力证明 → 视为接收方评估未通过（[橙]/[红]），建议更换接收方或缩小出境数据范围
    • 合规清单存在未完成项即要求出具报告 → 报告须明确标注未完成项为待解决风险，不得出具「合规通过」结论
    • 接收方发生重大数据泄露 → 立即暂停出境，启动合同约定的应急处置，通知数据主体（条件 [待验证]）、报告主管部门（条件 [待验证]）
    • 出境目的地国/地区爆发数据保护危机 → 重新开展接收方评估，视情况暂停出境，并在报告中记录事件
    • 多路径并存时报告须分路径记录，重要数据路径①的合规状态须独立确认
    • 出境记录台账与 PIA 报告留存期一致，建议至少保存三年

  • 路径③：四项适用条件全部满足；未发现累计出境规避门槛；必备条款无缺漏，个人权利行使渠道与争议解决条款已审查；签订顺序 PIA → 合同 → 备案正确；备案后变更纳入变更管理

  • 多路径并存时报告分路径记录合规状态并给出整体结论

09何时暂停或升级

  • 数据类型识别不完整 → 暂停路径判定，列出待补充信息清单，要求补充数据地图或处理活动记录
  • CIIO 身份与处理规模均不确定（配置为占位符）→ 临时模式，按最保守路径①判定并明确标注，建议完善配置
  • 用户无资源完成后续申报操作 → 提示升级处理；安全评估申报须由有资质团队操作
  • 评估申报未通过 / 评估有效期届满未续评 / 认证届期未续认 → 禁止或暂停出境（[红]），整改或续评后方可恢复
  • 紧急业务需求须立即出境 → 无例外，不可绕过安全评估审批，建议临时暂缓业务
  • 累计出境数量超过标准合同适用门槛或发现分批拆分规避 → [红]，升级至路径①安全评估申报
  • 接收方拒绝提供安全能力证明 → 视为接收方评估未通过（[橙]/[红]），建议更换接收方或缩小出境范围
  • 接收方发生重大数据泄露或目的地爆发数据保护危机 → 立即暂停出境，重新评估接收方，通知与报告条件 [待验证]
  • 前序步骤未完成即要求组装最终报告 → 暂停，提示先完成前序步骤
  • 网信办规章已修订与本流程指引不符 → 以最新版办法为准，重新核实相应条目
  • 出境数据含法律规定须境内存储的数据（金融、健康等）→ 境内存储义务优先，标 [红] [行业监管 flagged]
  • 使用者为非律师角色 → 在作出合规结论、决定出境路径或建议启动监管申报前暂停并升级律师；涉及重要数据出境、大规模敏感个人信息、监管问询等情形触发实践配置文件的自动升级
