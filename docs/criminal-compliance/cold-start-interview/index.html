01概要

通过四段结构化访谈，把执业角色与企业画像、服务立场与是否已涉案、风险等级与升级规则、文书风格与地方试点口径写入 criminal-compliance/CLAUDE.md 的对应散文章节，完成刑事合规实践档案初始化；之后刑事风险评估、合规不起诉、单位犯罪预防、合规体系建设四条流程都从这份文件读取立场与护栏。访谈按「身份与企业画像 → 合规立场与服务范围 → 风险与升级矩阵 → 文书风格与监管资源」顺序进行，共 43 问；每步先读取现有配置判断目标章节是 [PLACEHOLDER] 还是已有内容（已有则询问是否覆盖），再按实践配置契约的字段映射表逐题提问，写入前回显预览并经确认。每步访谈开始前都先确认企业或相关人员是否已被立案、被采取强制措施或收到侦查传唤，有则立即标 [强制升级 — 涉刑情形] 提示联系执业刑事辩护律师。对用户口述的具体罪名条号、定罪量刑数额、规范性文件文号做合理性检查：条号改为构成要件描述、数额改为规则描述、文号不写入，均标 [待验证]。四步各可单独触发用于只更新某一章节；律师/合规官/法务也可直接编辑配置文件（保持 ## 标题不变），文件纳入 git 版本控制可回滚。

02适用与边界

适用场景

  • 首次使用刑事合规插件，criminal-compliance/CLAUDE.md 仍是带 [PLACEHOLDER] 的模板
  • 其他刑事合规流程检测到配置缺失或关键字段（执业角色、整体服务立场、是否已涉案、角色）含占位符，提示「运行冷启动访谈或以临时模式继续」时
  • 服务事项从事前预防转为涉案应对，或企业涉案状态变化（出现监管苗头、被立案）时，优先单独重跑第 2 步更新「合规与服务立场」与「是否已涉案」
  • 新增经营地区需要补充地方涉案企业合规试点口径时，单独重跑第 4 步
  • 风险等级定义或角色权限需要调整（如合规官独立处理范围变化）时，单独重跑第 3 步

不做什么

  • 不做任何具体事项的刑事风险评估、合规整改方案、不起诉申请或辩护研究，只采集并写入配置
  • 不另存独立 YAML 或 JSON 配置文件；criminal-compliance/CLAUDE.md 是唯一真相来源
  • 不替代律师核实口述的具体罪名条号、定罪量刑数额、规范性文件文号，只做合理性检查并改为构成要件/规则描述加 [待验证]
  • 不接受降低强制升级门槛或修改合规边界护栏的请求；这两项是系统固定护栏，访谈只做回显确认
  • 「事项工作区」「审查过的种子文档」两章不由访谈填充，由律师/合规官/法务直接编辑
  • 小改动（更新联系人、调整某项风格措辞）不需要重跑访谈，直接编辑配置文件即可

04开始前

前置条件

  • 每步开始先读取或创建 criminal-compliance/CLAUDE.md，检查目标章节是否含 [PLACEHOLDER]（需更新）或已有内容（询问是否覆盖）
  • 每步访谈第一个问题前先做涉案情形识别（已被立案 / 被采取强制措施 / 收到侦查传唤或询问通知）
  • 第 2 步读「我们是谁」的执业角色与服务事项做一致性检查；第 3 步读「是否已涉案」与执业角色（角色权限表须匹配实际角色）；第 4 步读执业角色（决定标题）、整体服务立场（决定文书侧重）、可用集成（本步补充）与是否已涉案（已涉案则优先采集合规不起诉申请风格与检察机关本地口径）
  • 按实践配置契约对应章节确认采集范围：第 1 步第二节字段映射表、第 2 步第四节服务立场选择、第 3 步第五节涉案情形与强制升级契约
  • criminal-compliance/CLAUDE.md 已纳入 git 版本控制：git log 查看历史、git diff HEAD~1 HEAD 对比变更、git checkout <commit-hash> 回滚

硬性规则

唯一真相来源
访谈结果填充 criminal-compliance/CLAUDE.md 的散文章节（## 标题锚点），不创建独立 YAML 文件；写入保持章节结构不变，避免破坏其他流程按章节定位读取
写入前确认
每步在写入 CLAUDE.md 前向用户回显将写入的内容并请求确认，避免误写
用户陈述法律事实合理性检查
访谈中用户提供具体罪名条号 → 标 [待验证]，以构成要件描述记录，不写裸条号；定罪量刑数额 → 描述规则并标 [待验证]，不写裸数额（数额依司法解释，快速变化）；涉案企业合规规范性文件文号 → 描述规则并标 [待验证 — 规范性文件快速演进]，不写具体文号。检查提示：「你提到 [X]；具体罪名条号/数额/文号须以现行法律/司法解释/规范性文件核实，建议以构成要件描述/规则描述方式记录，标 [待验证]」
涉案情形优先识别
每步访谈前先确认是否已被立案、被采取强制措施、收到侦查传唤；有则立即提示 [强制升级 — 涉刑情形] 并建议联系执业刑事辩护律师；第 1 步中止画像采集，第 2–4 步可继续采集供律师参考
合规预防与辩护立场
所有输出立足于帮助企业事前预防刑事风险、涉案后依法合规整改争取从宽，不作有罪无罪的最终结论
系统固定护栏不可修改
六条强制升级触发条件与六条合规边界写入后凌驾于服务立场与合规严格度配置之上；用户要求去除合规边界限制一律拒绝；强制升级条件仅接受提高警惕（扩大范围），不接受降低门槛；用户不愿确认合规边界时说明这是运行前提条件
法律引用说明
刑法总则中度把握锚点（第30/31条等）标「建议复核」；各具体罪名条号一律 [条号待验证]，以构成要件描述呈现；涉案企业合规规范性文件描述规则并标 [待验证 — 规范性文件快速演进，须核实现行版本]；案例案号一律 [待验证]，不具判例法约束力；验证资源为国家法律法规数据库与最高人民检察院官网
部分更新互不干扰
单独触发某一步时只更新该步对应章节；完整访谈推荐首次使用时依次运行 1→2→3→4

05执行步骤

共 4 步，按执行顺序。每步旁边（窄屏在步骤说明之后）是请律师核对的内置假设，可逐条复制。页面里的英文标记见首页「标记与术语」。

  1. 身份与企业画像访谈

    /criminal-compliance:identity-enterprise-profile可单独运行

    采集执业角色、服务事项、企业画像（行业、规模、业务模式、是否涉外、历史涉案、重点刑事风险领域）及检察/公安/监管/第三方监督评估资源，写入「我们是谁」「谁在使用」「可用集成」三章，使后续流程能按执业角色选择工作产物标题与升级路由、按行业识别高发罪名范围、按资源情况选择合规不起诉与监管对接路径。

    请律师核对

    • 核对 1.1执业角色未回答时默认「律师」即最高权限：后续输出将带律师工作产物标题且不触发非律师暂停升级；是否接受这一默认，还是应默认按非律师处理？
    • 核对 1.2执业角色七选项是否覆盖贵所实际使用者（如外聘合规顾问、独立董事、财务负责人以外的高管）？
    • 核对 1.3规模分档以 50/500 人与 1 亿/10 亿元营业额为界，SKILL.md 未规定分档如何影响后续流程；是否需要与地方涉案企业合规试点的企业规模口径对齐？
    • 核对 1.4行业清单把「国有企业」「政府相关单位（事业单位）」与制造、金融等行业并列为选项，侧重职务犯罪合规风险；是否合理？
    • 核对 1.5B7 重点刑事风险领域八类清单未含走私类与反洗钱（引用库 C7 有走私类罪名，2026 年更新表有金融机构客户尽职调查办法）；是否补充？

    做法

    1. 检查 criminal-compliance/CLAUDE.md 是否存在：存在则读取「我们是谁」章节，确认是否含 [PLACEHOLDER]（需要更新）或已有内容（询问是否覆盖）；不存在则告知将创建文件并填充章节；参照实践配置契约第二节字段映射表确认本步采集范围对应「我们是谁」「谁在使用」「可用集成」。
    2. 访谈第一个问题前先做涉案情形识别：询问企业或相关人员是否已被立案、被采取强制措施（拘留/逮捕/取保候审/监视居住）、已收到侦查传唤/询问通知；若有，立即提示升级至执业刑事辩护律师并暂停访谈。
    3. A 组执业角色：A1 主要角色七选一（刑事合规律师 / 企业合规官 / 企业法务 / 当事人本人（有执业律师可咨询）/ 当事人本人（目前无执业律师，寻求初步了解）/ 非律师但有律师联系人（如财务总监、CEO）/ 其他），未提供时默认「律师」（最高权限，降低误升级风险）；A2 主要服务事项可多选（事前刑事风险评估 / 事前合规体系建设 / 涉案企业合规不起诉 / 单位犯罪预防 / 单位犯罪辩护研究 / 混合多类型）；A3 律所名称或业务部门（选填，用于输出标题与特权标注）。
    4. B 组企业画像：B1 企业/组织名称（可匿名，如「某制造企业」）；B2 行业十选一（制造业 / 金融投资（含银行、证券、私募、P2P）/ 医药健康 / 房地产与建设工程 / 能源化工 / 互联网与数据 / 贸易与物流 / 国有企业（涉职务犯罪合规风险）/ 政府相关单位 / 其他）；B3 规模按员工人数加年营业额分档（小型 50 人以下、1 亿元以下；中型 50–500 人、1–10 亿元；大型 500 人以上、10 亿元以上；上市公司注明 A股/港股/美股；国有企业注明央企/地方国企）；B4 主要业务模式（如制造+出口 / 金融理财产品销售 / 工程建设承包 / 医药代表+医院渠道 / 互联网平台数据业务）。
    5. B5 是否涉外（是：跨境贸易/境外投资/外资股东 / 否 / 部分涉外）；B6 历史涉案记录（无 / 曾受行政处罚并说明领域：税务/市场监管/环保/安全生产/其他 / 曾有刑事案件并说明情况 / 不确定待评估）；B7 已知重点刑事风险领域可多选十项（税收合规——虚开增值税专用发票/逃税 / 反商业贿赂——采购销售回扣、行贿政府官员 / 金融融资合规——非法集资、非法吸收公众存款 / 数据与个人信息合规——侵犯公民个人信息 / 安全生产合规——重大责任事故 / 环境合规——污染环境 / 反垄断与招投标合规——串通投标、垄断 / 单位职务类风险——职务侵占、挪用资金 / 暂不清楚需要全面梳理 / 其他），选「暂不清楚」则建议画像完成后运行 /criminal-compliance:compliance-risk-identification；B8 主要合规痛点（简述）；B9 刑事合规团队规模。
    6. C 组可用集成：C1 当地人民检察院（已确认联系并填写检察院与联系人 / 未确认需要建立联系 / 暂不适用——纯预防立场）；C2 公安经济犯罪侦查部门（已确认并填写经侦支队/总队 / 未确认 / 不适用）；C3 行业监管部门可多选（税务机关 / 市场监督管理局 / 中国证监会 / 国家药品监督管理局 / 生态环境局 / 应急管理局 / 国家互联网信息办公室 / 其他，均注明行刑衔接领域）；C4 当地第三方监督评估机制管理委员会（已知联系方式 / 尚未接触可能需要 / 不适用——纯预防尚未涉案）；C5 司法鉴定/会计审计机构（已委托并填写机构 / 未委托可根据需要委托 / 不适用）。

    /criminal-compliance:compliance-stance-scope可单独运行

    1. 读取 criminal-compliance/CLAUDE.md「合规与服务立场」（已有配置则询问是否覆盖）与「我们是谁」（执业角色与服务事项，与本步立场采集做一致性检查）；参照实践配置契约第四节「服务立场选择」确认采集范围。

    10. 按写入映射：D1 → 整体服务立场；D2 → 主要服务事项（补充）；E1 → 是否已涉案；E2 → 苗头描述；E3 → 已涉案情形描述；F1 → 合规严格度；F2 → 各领域保守重点。

    /criminal-compliance:risk-escalation可单独运行
