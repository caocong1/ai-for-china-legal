01概要

用四段结构化访谈把法援工作者的身份、服务立场、质量与升级规则、文书风格和本地资源写进 legal-aid/CLAUDE.md 的七个章节，其余四条法援流程都从这个文件读取个性化设置。访谈按「身份与角色画像 → 服务立场与范围 → 质量标准与升级 → 文书风格与本地资源」顺序进行，共 47 个问题（10 + 9 + 10 + 18），多数给出选项、均可跳过，跳过的字段保留 [PLACEHOLDER]，由后续流程触发临时模式。完整访谈约 5–10 分钟，单独一步约 2–3 分钟；每步都可单独触发、只更新对应章节，也可直接编辑配置文件，并用 git 查看历史和回滚。字段去向按 practice-profile-schema.md 的映射表；写入本地经济困难标准前，模型会用训练知识交叉核对，明显不一致时请用户确认写入哪个数字，并标 [前提 flagged — 需验证]。

02适用与边界

适用场景

  • 第一次使用法援流程前，初始化 legal-aid/CLAUDE.md
  • 其他流程提示「还没有配置你的实践档案」，不想长期以临时模式运行时
  • 角色、机构、所在地区或服务范围有变化，只需单独重跑对应一步
  • 本地低保标准或法援经济困难标准调整，或配置被标 [时效性 flagged] 时，重跑文书风格与本地资源一步

不做什么

  • 只配置法律工作者本人的身份、立场、质量标准与本地资源，不收集当事人或具体案件信息
  • 不生成独立的 YAML/JSON 配置：legal-aid/CLAUDE.md 是唯一真相来源，访谈只替换其中的占位符
  • 不替用户填推测值：用户跳过的问题保留 [PLACEHOLDER]
  • 不自行认定本地经济困难标准：用户不知道时标注待查，建议查询民政部门或司法局官网

03输入与产出

需要律师提供

  • legal-aid/CLAUDE.md 模板（含 [PLACEHOLDER] 占位符）必需
    访谈逐章替换占位符；律师也可直接编辑，编辑后即时生效
  • practice-profile-schema.md 第 2.1–2.4 节字段映射表必需
    规定每一步收集的字段写入哪一章、由哪些流程读取
  • 法律工作者对 47 个访谈问题的回答必需
    身份 10 问、服务立场 9 问、质量与升级 10 问、文书风格与本地资源 18 问；部分为开放题，均可跳过
  • 本地最低生活保障标准、法律援助经济困难标准、免予核查的本地扩大规定可选
    第 4 步 Q13–Q15；低保金额按 ¥[金额]/月 填写并标 [待验证 — 需查询当地民政部门最新公布数据]；不知道的标注待查
  • 常用法院 1–3 个，以及法援中心、民政局、劳动仲裁委、公证处、鉴定机构的名称与联系方式可选
    第 4 步 Q6–Q12、Q16–Q18；不常用的资源可跳过
  • 要单独更新的部分可选
    完整访谈不需要参数；只更新某一章时直接运行该步命令，如 /legal-aid:quality-escalation

产出

  • 更新后的 legal-aid/CLAUDE.md给律师内部
    访谈填充七章：我是谁、谁在使用、可用集成（第 1 步）；服务立场（第 2 步）；质量标准（第 3 步）；文书风格、本地资源（第 4 步）。「输出」「共享护栏」「审查过的种子案件」三章不在访谈写入范围内，保持模板预设
  • 每步完成提示块给律师内部
    引用块：本步已配置的四个要点（如第 1 步为角色、机构、服务领域、所在地区；第 4 步为文书格式、法援中心、常用法院、经济困难标准 ¥/月）、「配置已写入 legal-aid/CLAUDE.md」、下一步应运行的命令；第 4 步末尾宣布冷启动访谈完成，提示可重跑整个访谈或单独触发任一步

04开始前

前置条件

  • 推荐顺序：身份在前（建立基础上下文）→ 服务立场（核心配置）→ 质量标准（依赖前两步）→ 文书风格与本地资源（补充信息）
  • 写入目标固定为 legal-aid/CLAUDE.md，各步字段去向见 practice-profile-schema.md 第 2.1–2.4 节
  • 单独触发某一步时只更新该步对应章节，其他章节不动

硬性规则

唯一真相来源
legal-aid/CLAUDE.md 是唯一真相来源；不引入与现有体系冲突的新配置文件格式，访谈产出的配置只用于填充该文件的占位符字段
跳过即保留占位符
用户跳过某问题时保留 [PLACEHOLDER]，后续流程据此进入临时模式；不常用的本地资源可跳过
非律师角色标注
第 1 步 Q1 选法援中心工作人员或志愿者时，追问「你是否可以随时咨询执业律师？」；非律师角色的所有输出标注「工作辅助—非法律建议，供律师审查」，志愿者输出另附「供执业律师审查」
经济困难标准合理性检查
用户口述经济困难标准时与训练知识交叉核对；明显不一致时询问「你提到的经济困难标准是 X；我的理解是 Y。请确认哪个写入配置文件？」，并标 [前提 flagged — 需验证]
时效性标记
低保标准金额一律附 [待验证 — 需查询当地民政部门最新公布数据]；标准已过期（>6个月）标 [时效性 flagged — 需验证最新标准]
缺省口径
无特殊质量标准时使用办理法律援助案件程序规定的基本要求；群体性案件标准不确定时使用 10 人以上的常见标准并标 [待验证]；独立执业无团队时简化升级矩阵并标「独立执业」

05执行步骤

共 4 步，按执行顺序。每步旁边（窄屏在步骤说明之后）是请律师核对的内置假设，可逐条复制。页面里的英文标记见首页「标记与术语」。

  1. 身份与角色画像

    /legal-aid:identity-role-profile可单独运行

    确定使用者角色（决定工作产物标题、是否须律师审查）、所属机构（决定文书抬头和落款）、服务领域（决定案件分流）和所在地区（决定适用哪里的经济困难标准和地方特别规定），写入「我是谁」「谁在使用」「可用集成」三章。

    请律师核对

    • 核对 1.110 个问题都没有问「姓名/工号」，非律师角色也不问律师联系人，但配置模板这两项都有，各流程输出模板的经办人一栏写的也是「[你的名字/工号]」——要不要补问？
    • 核对 1.2角色只分法援律师、法援中心工作人员、志愿者、其他四类；引用库写明法援机构也指派基层法律服务工作者办案——这类人员归入哪一类、用哪种输出标题？
    • 核对 1.3配置模板「谁在使用」有五个选项（含「非律师但有律师可咨询」「非律师且无律师可咨询」），Q1 追问的答案如何对应这五项、两种非律师的处理有何不同，SKILL.md 未规定。
    • 核对 1.4「可用集成」中的「文档存储」「政务系统对接」没有对应问题，访谈后仍会保留占位符。

    做法

    1. Q1 角色类型四选一：法援律师（持律师执业证，在法援中心或指派律所执业）/ 法援中心工作人员（可能不持律师证）/ 法律援助志愿者（可能是律师或其他专业人员）/ 其他。
    2. Q1 选工作人员或志愿者时追问「你是否可以随时咨询执业律师？」；凡非律师角色，后续所有输出标注「工作辅助—非法律建议，供律师审查」。
    3. Q2 所属机构五选一：法律援助中心（政府设立）/ 律师事务所（受指派承办法律援助案件）/ 社会组织（如公益法律服务中心）/ 高校法律诊所 / 其他，并追问机构全称。
    4. Q3 律师执业证号（法援律师填写，其他角色可跳过）；Q4 从事法援工作的年限；Q5 所在省/市（影响地方性经济困难标准和特别规定）。
    5. Q6 主要服务领域（可多选）：民事法援（劳动争议、赡养、交通事故等）/ 刑事法援（辩护、代理）/ 行政法援 / 综合；Q7 每月大约处理的法援案件数；Q8 目前最大的痛点（开放题）。
    6. Q9 是否使用法律援助管理系统（已连接 / 未连接 / 不适用）；Q10 主要通过哪个工具接收工作产物（企业微信 / 钉钉 / 飞书 / 邮件 / 其他）。
    7. 写入：Q1–Q8 → 「我是谁」；Q1 → 「谁在使用」的角色字段；Q9、Q10 → 「可用集成」。
    8. 输出完成提示块（角色、机构、服务领域、所在地区），提示下一步运行 /legal-aid:service-stance-scope。

    内置规则

    • 志愿者身份：标注「志愿者」，输出附加「供执业律师审查」
    • 多机构兼职：按最主要的机构填写
    • 用户跳过某问题：保留 [PLACEHOLDER]，后续流程触发临时模式
    • 角色类型影响工作产物标题；所属机构影响文书抬头和落款；执业领域影响案件分流；所在地区影响地方性规定适用

    产出

    「我是谁」（角色、机构及全称、执业证号、年限、所在地区、服务领域、月均案件量、最大痛点）、「谁在使用」（角色）、「可用集成」（法援管理系统、通讯工具）写入 legal-aid/CLAUDE.md，附完成提示块

  2. 服务立场与范围

    /legal-aid:service-stance-scope可单独运行

    确定服务类型、刑事法援中的角色、法援类型、优先受理和暂不受理的案件、群体性案件处理规则以及与受援人的沟通安排，写入「服务立场」一章。

    请律师核对

    • 核对 2.1Q2 刑事角色只有辩护人、被害人代理人、视案件而定，配置模板写的是「代理人」，而事实收集一步另有「自诉案件代理」、Q3 另有「值班律师」——角色选项是否补齐？
    • 核对 2.2「通用默认值」具体是什么 SKILL.md 未写；实践配置契约的临时模式默认为「民事法援为主」——无偏好时是否就按这一口径？
    • 核对 2.3群体性案件处理规则在本步 Q6 和第 3 步 Q5、Q6 各问一次，两处答案冲突时以哪处为准 SKILL.md 未规定。
    • 核对 2.4Q5「暂不受理的案件类型」会进入接待分流决策树（不属于受理偏好即转介）——是否同意让这项偏好决定转介？

    做法

    1. Q1 主要服务类型四选一：民事法律援助 / 刑事法律援助 / 行政法律援助 / 综合（各类都有）。
    2. Q2（仅刑事法援时）在刑事法援案件中通常担任的角色：辩护人 / 被害人代理人 / 视案件而定；不主要做刑事法援的跳过本题。
    3. Q3 法援类型（可多选）：法律咨询 / 代理（民事/行政）/ 刑事辩护 / 值班律师 / 综合。
    4. Q4 优先受理的案件类型（开放题，常见：劳动争议、赡养纠纷、工伤赔偿、交通事故）；Q5 通常不受理的案件类型（开放题，常见：商事合同纠纷、知识产权案件）。
    5. Q6 群体性案件（同一事实涉及多人）处理规则：须报告主任审批后受理 / 可以单独受理但须通报 / 不单独受理、统一安排 / 其他；规则复杂的详细记录，留到第 3 步完善。
    6. Q7 与受援人沟通的主要方式（面对面 / 电话 / 线上（微信/短信等）/ 混合）；Q8 工作语言（普通话 / 方言（请注明）/ 双语）；Q9 对残疾人、老年人、未成年人的特殊沟通安排（开放题）。
    7. 替换「服务立场」中的占位符；没有特殊偏好的使用通用默认值。
    8. 输出完成提示块（服务类型、法援类型、优先受理、沟通方式），提示下一步运行 /legal-aid:quality-escalation。

    内置规则

    • 不主要做刑事法援：跳过 Q2
    • 无特殊偏好：使用通用默认值
    • 群体性案件规则复杂：详细记录，后续在质量标准与升级一步完善
    • 按实践配置契约：服务类型由客户接待、案件管理、法援申请三条流程读取；法援类型由登记指派和委托代理协议/指定辩护函读取；受理优先级由登记指派和质量审查读取；沟通偏好由身份核实和事实收集读取

    产出

    「服务立场」三小节（服务类型、案件受理偏好、受援人沟通）写入 legal-aid/CLAUDE.md，附完成提示块

  3. 质量标准与升级

    /legal-aid:quality-escalation可单独运行

    确定质量标准依据、归档期限、是否做满意度回访，以及重大案件和群体性案件的定义、升级矩阵、审批层级和自动升级触发条件，写入「质量标准」一章，供接待、登记指派和质量审查判断何时升级。

    请律师核对

    • 核对 3.1群体性案件人数只给 5 人 / 10 人两档，不确定时默认「10人以上」并标 [待验证]——贵中心或本省的口径是多少？
    • 核对 3.2Q2 归档期限以「30日内」为常见示例，结案归档一步却写「结案后 [期限待验证] 内」——默认期限是否需要定下来？
    • 核对 3.3Q10 的自动升级清单（群体性、重大社会影响、受援人投诉、超期）没有配置模板「共享护栏」列出的涉访涉诉和跨地区案件——访谈是否应一并确认？

    做法

    1. Q1 质量标准依据：办理法律援助案件程序规定（司法部）/ 省级法律援助质量标准 / 本中心内部质量标准 / 其他。
    2. Q2 结案后多长时间内完成归档、有什么要求（开放题，常见：30日内归档）；Q3 是否对每件案件做受援人满意度评估（是 / 否）。
    3. Q4 什么情况算「重大案件」（开放题，常见：涉及10人以上群体性纠纷、社会影响较大、涉访涉诉）。
    4. Q5 涉及多少人算「群体性案件」：5人以上 / 10人以上 / 其他标准。
    5. Q6 重大案件处理规则：须报告主任审批 / 须集体讨论 / 须报司法行政机关 / 以上全部 / 其他。
    6. Q7 可以独立决定、不需请示的事项（常见：常规法援案件）；Q8 需要升级给上级的情况（常见：重大案件、群体性案件、超期案件）；Q9 审批层级（示例：法援律师 → 法援中心主任 → 司法行政机关）。
    7. Q10 逐项确认是否必须自动升级：群体性案件 / 涉及重大社会影响 / 受援人投诉 / 案件超过办理期限 / 其他（请说明）。
    8. 替换「质量标准」中的占位符（案件质量标准、重大案件与群体性案件、升级矩阵、自动升级触发条件），输出完成提示块，提示下一步运行 /legal-aid:style-local-resources。

    内置规则

    • 无特殊质量标准：使用办理法律援助案件程序规定的基本要求
    • 群体性案件标准不确定：使用 10 人以上的常见标准，标注 [待验证]
    • 独立执业无团队：升级矩阵简化，标注「独立执业」
    • 配置模板的升级矩阵为三层：法援律师/工作人员独立处理常规法援案件，重大案件、群体性案件、超期案件需升级；法援中心主任审批重大案件，特别重大案件需报司法行政机关；司法行政机关负责监督指导

    法律依据

    • 《办理法律援助案件程序规定》（司法部）— 质量标准依据的选项之一，也是没有特殊质量标准时的默认要求

    产出

    「质量标准」四小节（案件质量标准、重大案件与群体性案件、升级矩阵、自动升级触发条件）写入 legal-aid/CLAUDE.md，附完成提示块

  4. 文书风格与本地资源

    /legal-aid:style-local-resources可单独运行

    确定文书格式、语气和法条/案例引用偏好，并收集法援中心、常用法院、民政部门、劳动仲裁委、公证处、鉴定机构和本地经济困难标准，写入「文书风格」「本地资源」两章；其中经济困难标准是资格初评的比对基准。

    请律师核对

    • 核对 4.1法援经济困难标准举例「低保标准的1.5倍或2倍」，配置模板示例为2倍——贵省实际倍数是多少？按家庭收入还是人均收入计算？
