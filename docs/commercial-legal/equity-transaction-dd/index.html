01概要

面向投资方 / 受让方对目标公司的资料室法律尽调，产出沿用律所参考稿版式的尽调报告（律师复核稿）、三分类问题清单和编制说明，每一处重大发现都能回到文件与页码，交易结构未知造成的局限被显式标注而不是被通用措辞掩盖。做法是四步：先递归清点资料室并去重、识别版本、映射章节；再按章写可溯源的事实底稿，金额用两个以上来源勾稽，影响结论的事实由主笔回原件核对；然后按主体属性矩阵核查国资、外资过渡、负面清单、经营者集中、优先购买权、认缴出资、上市公司、控制权变更触发条款九条程序路线；最后装配报告、问题清单与编制说明，装配前复跑覆盖审计，交付前做渲染 QA 与发送包隐私检查并输出 REVIEW_STATUS。流程读取 commercial-legal/CLAUDE.md 取工作产物标题，法条经研究闸门核对现行原文，程序法锚点来自 transaction-procedure-citations.md。流程固化自案例库 LWC-2026-0005（国有控股中外合资企业股权交易尽调，354 份资料，125 页报告），只固化流程与检查清单，不固化该案结论。

02适用与边界

适用场景

  • 投资方 / 受让方（或贷款人）委托对目标公司做股权交易法律尽调，资料以资料室目录形式提供。
  • 资料量大（常见 300–500 个文件，超过 1,000 份时并行清点），存在重复、多版本、扫描件混杂。
  • 目标公司或其股东涉及国资、外商投资企业、上市公司，报告需要交易程序专章。
  • 律所要求沿用参考稿 / 模板的章节与版式成稿。
  • 补充资料包到达，需要出报告与问题清单的第二版。

不做什么

  • 单份合同的审查（用合同审查流程 /commercial-legal:contract-review）；本流程面向整个目标公司的资料室。
  • 不固化 LWC-2026-0005 案的具体结论，只固化流程与检查清单。
  • 默认不联网做企业信用公示、裁判文书、执行信息、信用中国核验；未经律师授权时在报告中声明未执行并进问题清单。
  • 不替代律师的最终判断：成稿恒标「律师复核稿」，所有法律评析为草案。
  • 不替代不同模型的独立盲审；未做时在 REVIEW_STATUS 中如实写 skipped。

03输入与产出

需要律师提供

  • 资料室目录必需
    递归清点全部子目录；分批到达的补充资料包单独清点并合并为 v2
  • 委托方身份与报告受众必需
    投资方 / 受让方 / 贷款人；阻断项，决定立场、措辞确定性与问题清单口径，无法安全假设
  • 参考稿 / 模板的使用规则必需
    哪些段落（标黄）不得参考、版式沿用范围；阻断项，写错会污染成果
  • 参考稿 / 模板 DOCX可选
    无参考稿时用 shared/references/document-structures.md 的报告结构 + 中文 reference.docx
  • 输出目录必需
    已明确时直接执行；写入目标可能覆盖参考稿或资料原件时暂停确认
  • 交易结构（受让哪一方股权、比例、是否增资、是否取得控制权）可选
    首要澄清项，可用一个问题开工前澄清；未答时按「一般情形」继续，列 deferred_items 首项，受影响章节逐章注明
  • 基准日 / 尽调期间 / 出具日期可选
    可占位【 】，交付说明逐项点名
  • 联网外部检索许可可选
    默认不联网并在报告中声明；律师可授权
  • 实践配置文件 commercial-legal/CLAUDE.md可选
    取工作产物标题；缺失或含 [PLACEHOLDER] 时按临时模式默认（律师角色、平衡型、中国法律体系）

产出

  • 尽调报告（律师复核稿）给律师内部复核后交委托方
    沿用参考稿章节与版式；管理层摘要从正文倒推、按风险等级排序、每行注明正文位置；释义表；每章「事实（引 fact_id）→ 法律评析 → 风险等级 → 建议」；特殊主体时设交易程序章节；结构未知章节标「按一般情形」；成稿恒标「律师复核稿」
  • 问题清单给律师；补充资料部分转目标公司
    三分类：补充资料 / 待说明（事实矛盾）/ 需律师决定或复核；每项编号 / 事项 / 来源章节 / 影响 / 建议动作
  • 编制说明给律师内部
    七项：工作流程、资料来源对照表、计算方法、已纠正错误清单、法条核验表、覆盖审计结果、未执行事项
  • 交付说明与 REVIEW_STATUS给律师内部
    占位符清单、三件文件清单与指纹、外部检索声明、结构指标（仅作解释）、独立复核执行情况（未做写 skipped 与原因）
  • 中间工作底稿给律师内部
    资料清单与聚合指纹、分章事实底稿（每章一文件）、交易程序路线表、控制权变更触发条款表、合资合同与章程对照表；均放仓库外内部目录

04开始前

前置条件

  • 读取 commercial-legal/CLAUDE.md；配置缺失或含 [PLACEHOLDER] 时按合同审查流程的「临时模式」处理，默认律师角色、平衡型、中国法律体系。
  • 报告立场由委托方身份（投资方 / 受让方 / 贷款人）决定，来自本次指令而非实践配置。
  • 执行 shared/legal-document-intake/SKILL.md，并按 shared/references/due-diligence-playbook.md 第 1 节判定：阻断项（委托方身份与报告受众、参考稿使用规则）、交易结构（可按一般情形继续）、可后置项（基准日 / 出具日期占位、联网检索许可）。
  • 本类任务为正式对外报告，execution_profile 默认 critical，开工前必须输出 INTAKE_DECISION；LWC-2026-0005 读取了 intake 却未输出决策，是已记录的流程缺口。
  • 资料目录、参考稿、输出目录已明确时直接执行，不重复询问。
  • 四步顺序不可颠倒：先盘清资料（否则覆盖审计无基准）→ 底稿（报告唯一事实来源）→ 程序核查（依赖股权、章程、合资合同底稿）→ 装配；覆盖审计在装配前由第一步的清单复跑。

硬性规则

特殊主体即专章
目标公司或股东为国资、外商投资企业、上市公司时，报告必须有交易程序章节，依据见 transaction-procedure-citations.md。
核心经营资源依赖提示
经营权 / 特许、核心资产租赁、融资三者中两项以上来自同一控股股东体系时，摘要合并提示「控制权变更后可能同时失去支撑」，不得分散在三章各说一句。
原件核对
辅助模型 / OCR 底稿只用于定位；章程条文、决议版本、委派日期、文号、金额由主笔回原件核对后才进报告。
数字勾稽
金额用两个以上独立来源；只有一个来源时写明；假设性测算（如滞纳金）列假设与敏感性。
条号来源
合资合同条号与章程条号不得混用；取不到原文的地方规定与部门文件不写条号。
外部检索声明
未做企业信用、裁判文书、执行、信用中国核验时，在方法说明中声明并进问题清单。
个人信息
含身份证号的底稿留内部目录；发送包正则检查。
动态确认与输出确认
资料目录、参考稿、输出目录已明确时直接执行；委托方身份、参考稿排除规则等阻断项缺失，或写入目标可能覆盖参考稿时，才输出 [CLARIFY:] 并暂停。参考稿与资料原件永不覆盖。
先检索、后结论
每一处法条写入前经 shared/research-gate/SKILL.md 取官方原文核对现行版本；按通行文本引用而未下载原文的条文在问题清单「需律师复核」中列明。
独立复核可观察
交付前按 shared/legal-document-intake/SKILL.md 输出 REVIEW_STATUS；未做不同模型独立复核时写 skipped 与原因。

05执行步骤

共 4 步，按执行顺序。每步旁边（窄屏在步骤说明之后）是请律师核对的内置假设，可逐条复制。页面里的英文标记见首页「标记与术语」。

  1. 资料室清点与覆盖审计

    /commercial-legal:data-room-inventory可单独运行

    把资料室（常见 300–500 个文件，重复、多版本、扫描件混杂）盘清：去重、识别版本、映射到报告章节、登记提取路径与个人信息，形成资料清单与聚合指纹；报告装配前复跑覆盖审计，使「资料已全部审阅」有依据。

    请律师核对

    • 核对 1.1默认 12 章结构是否符合贵所尽调报告的章节习惯，例如知识产权、环保安全、保险是否应从「12 其他」中单列。
    • 核对 1.2个人信息标记只列身份证号、住址、银行账号三类，是否要加手机号、家庭成员等。
    • 核对 1.3OCR 结果只用于定位、不直接采信，影响结论的内容必须主笔回原件，这一口径是否接受。
    • 核对 1.4聚合指纹与覆盖率记入案例库（不入库原文），是否符合贵所保密要求。

    做法

    1. 先读 shared/references/due-diligence-playbook.md 第 2、4 节，按其资料清单 schema 输出（file_id 稳定编号、脱敏 label、chapter、type、sha256、size、pages、extraction、status、duplicates_of、contains_pii）。
    2. 递归遍历资料室全部子目录，为每个文件计算内容哈希（sha256）与大小。
    3. 哈希相同的文件标 duplicates_of 视为重复；同名但哈希不同的文件视为两个版本，都保留，并在分章映射时标记版本关系，不得当作重复删除。
    4. 生成聚合指纹：各文件 sha256 排序后清单的 sha256，供案例库记录，不入库原文。
    5. 按文件类型登记提取路径：docx / xlsx / pptx 直接读取（doc / xls 先转换）；有文本层的 PDF 用 pdftotext；扫描 PDF 与图片走 OCR 后台任务，结果只用于定位，影响结论的内容由主笔回原件；加密或损坏文件标 unreadable，进问题清单「补充资料」。
    6. 含身份证号、住址、银行账号的文件标 contains_pii: true，其底稿与文本镜像放内部目录。
    7. 按默认 12 章把每个文件映射到报告章节（按目标公司情况增删）；同一文件可映射多章；版本关系（如章程 2019 版 / 2023 版）在章节内并列记录。
    8. 输出 YAML 或表格清单，并给统计：文件总数、去重后数、按类型与章节分布、OCR 文件数与页数、unreadable 数。
    9. 报告装配前复跑覆盖审计：取分章底稿全部 sources.file_id 与清单比对；未被引用的文件逐个标注为「无关（写原因）」「漏读（补底稿）」或「需补章节（补报告）」；输出 referenced / unique_files 比例与未引用清单，交报告装配步骤写入编制说明。

    内置规则

    • 去重以 sha256 为准；文件名归一只作提示；同名不同哈希是两个版本，不是重复（LWC-2026-0005 中同一编号的董事会决议实为两份落款日期、内容不同的文件）。
    • 默认 12 章：01 主体与历史沿革（营业执照、登记档案、历次变更、批准证书）；02 股权与出资（出资证明、验资 / 审计、股东名册、股权质押）；03 章程与治理（历版章程、合资合同、股东会 / 董事会决议、委派函）；04 资质与许可（行业许可、特许经营、经营权合同、认证）；05 资产与租赁（不动产权证、租赁合同、租金支付凭证、设备清单）；06 重大合同（客户、供应商、框架协议、关联交易合同）。
    • 默认 12 章（续）：07 融资与担保（借款 / 委贷合同、征信报告、担保、还款计划）；08 劳动用工（花名册、社保、外包 / 派遣合同，交叉引用劳动人事插件的外包 / 派遣对照表）；09 税务与财务（审计报告、月报、纳税证明、处罚）；10 诉讼仲裁与处罚（判决、裁决、调解书、处罚决定、信用报告）；11 关联交易（关联方清单、交易合同、定价依据）；12 其他（环保 / 安全 / 保险 / 知识产权，按行业）。
    • OCR 默认后台执行、不阻塞主线；OCR 结果只用于定位，不直接采信。
    • 没有清单就没有覆盖审计；没有覆盖审计就不能说「资料已全部审阅」。LWC-2026-0005 覆盖审计为 348 / 354，未引用的 6 份全部是资质证照，补写后暴露了许可证延续申请截止日早于报告出具日的问题。
    • 资料分批到达（补充资料包）：新批次单独清点并合并，版本号 v2；修订说明列每份新文件对报告的影响。
    • 文件名含客户名：清单 label 用脱敏标签，原文件名只留内部目录。
    • 超过 1,000 份文件：清点交辅助模型并行，去重与映射规则由主笔定稿。

    产出

    资料清单（YAML / 表格，每份文件一条，含 file_id、脱敏标签、章节、类型、sha256、页数、提取路径、状态、重复关系、个人信息标记）+ 统计 + 聚合指纹；装配前的覆盖审计结果（referenced / unique_files 比例、未引用文件清单及逐个解释）。清单与指纹留在仓库外工作目录。

  2. 分章事实底稿

    /commercial-legal:chapter-fact-memos可单独运行

    为每章提取可溯源的事实（文件 + 页码 / 条号 / 单元格），区分原件目视、OCR、摘要与访谈口径，用两个以上来源勾稽金额，记录版本差异与矛盾，由主笔回原件核对影响结论的事实后才进入报告。底稿是报告唯一的事实来源，按章落盘供上下文压缩后续写与律师回查。

    请律师核对

    • 核对 2.1「访谈口径与文件不一致时以文件为准、访谈口径只作待说明」的立场是否符合贵所做法。
    • 核对 2.2日期取证顺序（台账 / 原始凭证 > 决议 > 备案材料）是否接受。
    • 核对 2.3金额至少两个独立来源、否则写「仅据 X」的要求，以及表中列出的勾稽来源组合是否完整。
    • 核对 2.4滞纳金、违约金等假设性测算按合同条款与访谈口径测算并列敏感性后进入报告，还是应只列公式交律师。
    • 核对 2.5各章「必须提取的事实」清单只覆盖 11 章，第 12 章其他（环保 / 安全 / 保险 / 知识产权）未列事实清单，需律师补充。

    做法

    1. 先读 shared/references/due-diligence-playbook.md 第 3 节底稿 schema，读取资料清单与章节映射；有辅助模型（并行处理 OCR、摘录等机械工作的模型实例）参与时，先下发统一规则文件。
    2. 按各章「必须提取的事实」清单提取：主体与沿革（设立日期、历次名称 / 住所 / 法定代表人 / 经营范围变更、登记机关）；股权与出资（各股东持股、出资方式与实缴、出资期限、质押 / 冻结）；章程与治理（现行章程的表决、转让、优先购买、委派条文，历版差异处数，决议清单与版本）；资质与许可（许可名称、编号脱敏、有效期、延续申请截止日）。
    3. 继续提取：资产与租赁（权属、租赁期限、租金标准、实际支付记录、欠付与滞纳金计算口径）；重大合同（相对方、期限、金额、控制权变更 / 转让限制条款、是否届满未续）；融资与担保（本金、利率、到期日、担保、12 个月内到期金额）；劳动用工（人数口径、外包 / 派遣比例、所属单位，用劳动人事插件的外包 / 派遣对照表定性）；税务与财务（净资产、营收、处罚、补税）；诉讼仲裁与处罚（案件、金额、状态、原告主体是公司还是工会）；关联交易（关联方、交易类型、金额、定价）。
    4. 每条事实按 schema 记录，强制字段：sources（file_id + 定位）、evidence_kind、confidence、verified_by_author。
    5. 条号写明出自哪份文件：「合资合同第 X 条」与「章程第 Y 条」分开记录。
    6. 释义表中的主体全称以营业执照 / 批准证书为准，一次定稿全文复用。
    7. 同一事实多个来源不一致时标 conflicts_with，并进问题清单「待说明」。
    8. 日期优先取台账 / 原始凭证，其次决议，最后备案材料。
    9. 数字勾稽：借款余额用借款合同 / 征信报告 / 财务月报三方核对；应收应付用明细表 / 月报 / 审计报告；年度财务数据用当年审计报告与下年审计报告年初数；欠付租金用合同租金标准 × 期间、支付凭证、对账或访谈口径。只有一个来源时在报告中写「仅据 X」；假设性测算（滞纳金、违约金）列假设、公式与敏感性，注明「按合同条款与访谈口径测算」；表格分项加总必须重算。
    10. 辅助模型分工：适合 OCR、分章摘录、清单比对、覆盖审计；统一规则：禁止联网、禁止修改原始资料、只补缺口、更正须在原处注明、输出按 schema；并发上限由操作员设定；接口限流中断时按章节重派，不重做已落盘章节。
    11. 辅助模型写的底稿一律标 evidence_kind: summary；影响结论的事实由主笔回原件核对后改为 original_viewed 并置 verified_by_author: true。
    12. 每章一个文件（如 03-章程与治理.md 或 .yaml），放仓库外内部目录；报告只引用 fact_id；上下文压缩后从底稿续写。

    内置规则

    • 底稿是报告唯一的事实来源。LWC-2026-0005 在撰写与自查阶段共纠正 10 处错误（章程「缺句」误判、同编号决议两个版本、委派函实际日期早一年、文号笔误、释义表主体全称错误、合资合同与章程条号混用、分项加总错误等），全部靠回原件与重算发现，结构指标一个都发现不了。
    • 各章常见陷阱：批准证书与营业执照日期不一致；认缴未届期与国资登记日期；两版章程差异数要逐条数；同编号决议多版本；为备案重新出具的委派函日期不等于实际委派日；许可截止日早于报告出具日；支付凭证只覆盖部分期间、滞纳金为合同约定测算；经营权合同届满未续签；借款需合同 / 征信 / 月报三方勾稽；当年审计数与下年年初数核对；调解结案金额与原告主体识别；与控股股东体系的经营依赖。
    • 证据种类 evidence_kind 五档：original_viewed（主笔目视原件）/ ocr / summary（含辅助模型底稿）/ interview / public_record；置信度 confidence 三档：confirmed / inferred / assumed。
    • evidence_kind 为 ocr 或 summary 的事实，凡影响结论、数字、条号、日期，必须主笔回原件核对；未核对的只能以条件句进入报告。
    • 金额与数量尽量用两个以上独立来源勾稽；同一文件的多个版本须并列记录差异数量与位置，不得只取「最新」。
    • 关键文件只有扫描件且 OCR 不清：主笔目视原件页面；仍不清则标【待核实】并进「补充资料」。
    • 访谈口径与文件不一致：以文件为准，访谈口径作「待说明」。
    • 补充资料包到达：逐份写「对报告的影响」并更新受影响的 fact_id。

    产出

    每章一个底稿文件（.md 或 .yaml），每条含 fact_id、脱敏陈述、sources（file_id + 页码 / 条号 / 单元格）、evidence_kind、confidence、conflicts_with、verified_by_author、used_in；放仓库外内部目录，含个人信息的进「内部」目录。

  3. 交易程序核查

    /commercial-legal:transaction-procedure-check可单独运行

    按目标公司与交易对手的主体属性（国资 / 外商投资 / 上市公司）和交易结构，把「谁转给谁、多少比例、是否取得控制权」拆成可核查的程序路线：国资进场交易与评估、外商投资法过渡期后合资合同与章程的并存与冲突、负面清单与信息报告、经营者集中申报、优先购买权与章程限制、认缴出资期限、控制权变更触发条款、行业许可；结构未知时诚实地按一般情形写。

    请律师核对

    • 核对 3.1交易结构未知时仍输出按「一般情形」的路线表并逐项注明，而不是等结构确认后再写本章，贵所是否接受。
    • 核对 3.2合资合同与章程冲突只用条件句并引实施条例第 46 条标 [待律师复核]，不替律师作取舍，是否符合预期。
    • 核对 3.3九条程序路线是否完整：未列外汇登记（仅境外受让方时作 [待验证] 提示）、股权转让所得税务、经营者集中之外的国家安全审查、不动产 / 土地过户程序。
    • 核对 3.4「经营权合同届满未续 + 租赁欠付 + 委贷 12 个月内到期同时来自控股股东体系」作为典型发现模式，是否反映贵所经验。
    • 核对 3.5上市公司与行业许可路线的锚点仅为 [待验证]，需律师指定贵所常用的披露规则与行业规章。

    做法

    1. 先读上一步的股权、章程、合资合同、重大合同、融资底稿；读 commercial-legal/skills/_shared/transaction-procedure-citations.md 取锚点与验证状态；读 shared/references/subject-qualification-traps.md（国企 / 上市公司 / 外商投资企业主体陷阱）；每处条文经 shared/research-gate/SKILL.md 取官方原文核对现行版本。
    2. 填主体属性矩阵四个维度：转让方属性（国有及国有控股 / 外资 / 民营 / 上市公司，决定国资程序、外资程序、信息披露）；目标公司属性（中外合资 / 内资 / 国有控股，决定合资合同与章程关系、国资登记）；受让方属性（境内 / 境外、是否已持股，决定负面清单、集中申报、优先购买权）；交易结构（受让存量 / 增资 / 混合、比例、是否取得控制权，决定几乎所有程序）。未知项标明。
    3. 交易结构未知时，本章开头写「以下按一般情形分析，待交易结构确认后更新」，并在问题清单「需律师决定」列明。
    4. 逐条核查九条程序路线（国资交易、外商投资过渡、负面清单与信息报告、经营者集中、优先购买权与章程限制、认缴出资、上市公司、控制权变更触发、行业许可），每条写核查点、锚点与验证状态、常见发现。
    5. 合资合同与章程逐条对照股权转让、表决、董事委派、利润分配、终止条款，列表：事项 / 合资合同第 X 条 / 章程第 Y 条 / 冲突 / 现行法处理。
    6. 对照结论用条件句「若按合资合同约定……；若按章程……」，并引《外商投资法实施条例》第 46 条口径说明过渡安排，标 [待律师复核]。
    7. 输出「交易程序路线表」（程序 / 是否适用：是、否、取决于交易结构 / 核查结论 / 依据与验证状态 / 待补）和「控制权变更触发条款表」（合同 / 条款 / 触发条件 / 后果 / 建议）。
    8. 经营资源依赖控股股东体系的目标公司，在管理层摘要中合并提示。

    内置规则

    • 国资交易路线：核查是否属于国有产权转让 / 增资、评估与核准备案、进场交易或非公开协议转让的条件、国资登记状态；常见发现：国资登记日期晚于设立、非公开转让条件不满足。
    • 外商投资过渡路线：核查合资合同是否随《外商投资法》修订、过渡期届满后组织形式与章程调整、原合营合同约定的股权转让办法可否继续适用；常见发现：未修订的合资合同与新章程并存且冲突。
    • 负面清单与信息报告路线：行业是否在负面清单；股权变更后的信息报告义务；清单版本按年度核对。
    • 经营者集中路线：营业额是否达申报标准、是否取得控制权；门槛数值按现行版本核对，不写死。
    • 优先购买权与章程限制路线：有限公司股东优先购买权、章程另有规定、合资合同一致同意条款；常见发现：章程与合资合同口径不一致。
    • 认缴出资路线：认缴期限与过渡期、未届期出资转让的责任；存量公司须在 2027-06-30 前调整。
    • 上市公司路线：转让方 / 受让方为上市公司时的决策与信息披露，关注股东会权限；行业许可路线：控制权变更是否触发许可重新审批或备案，关注许可到期日。
    • 控制权变更触发路线：核查经营权 / 特许合同、核心资产租赁、委贷与担保中的控制权变更、股权变动通知与解除条款；典型发现：经营权合同届满未续 + 租赁欠付 + 委贷 12 个月内到期同时来自控股股东体系。
    • 边界：目标公司为纯内资民营，国资 / 外资路线写「不适用」并说明依据；受让方为境外主体，增加负面清单与信息报告，外汇登记 [待验证] 列为律师决定；转让方为上市公司子公司，核查母公司披露义务与关联交易程序。

    法律依据

    • 《企业国有资产交易监督管理办法》（国资委、财政部令第 32 号）— 国有产权转让 / 增资的评估、进场交易与非公开协议转让条件（步骤原文未写条号；引用库已核实第 3、13、35、39、45、46、48 条）
    • 《外商投资法实施条例》第44条 — 过渡期届满后未调整组织形式等的后果与办理（已核实）
    • 《外商投资法实施条例》第46条 — 原合营合同约定的股权转让办法等可继续按约定办理，用于合资合同与章程冲突的过渡安排说明 [待律师复核]
    • 现行《外商投资准入特别管理措施（负面清单）》— 行业是否限制 / 禁止外资，版本按年度核对 [待验证]
    • 《外商投资信息报告办法》— 股权变更后的信息报告义务 [模型知识 — 需验证]
    • 《国务院关于经营者集中申报标准的规定》第3条 — 全球与中国境内营业额申报门槛，门槛数值按现行版本 [待验证 数值]
    • 《公司法》（2023 修订）股权转让条款 — 有限公司股东优先购买权、章程另有规定优先，具体条号 [待验证]
    • 《公司法》（2023 修订）及过渡期规定 — 认缴出资期限与 2027-06-30 前调整（引用库：国务院令第 784 号第 2 条）
    • 上市公司信息披露规则 — 转让方 / 受让方为上市公司时的决策与披露 [待验证]
    • 行业规章 — 控制权变更是否触发许可重新审批或备案 [待验证]

    产出

    交易程序路线表（九条路线逐项：是否适用 / 核查结论 / 依据与验证状态 / 待补）、合资合同与章程逐条对照表、控制权变更触发条款表；结构未知时章首「按一般情形」声明及问题清单「需律师决定」条目；经营资源依赖控股股东体系时的摘要合并提示。

  4. 报告、问题清单与编制说明装配

    /commercial-legal:dd-report-issue-list可单独运行

    交付三件而不是一件：报告给结论，问题清单给动作，编制说明给可信度，律师据编制说明判断哪些数字可以直接用、哪些要再查。沿用律所参考稿版式成稿，完成覆盖审计、渲染 QA 与发送包隐私检查，输出交付说明与 REVIEW_STATUS。

    请律师核对

    • 核对 4.1参考稿标黄段落一律不参考、沿用表格须声明「本次未独立核验」的处理是否符合律所要求。
    • 核对 4.2每章须给「风险等级」且摘要按风险等级排序，但 SKILL.md 未规定分级口径（几级、各级定义），需律师补充贵所标准。
    • 核对 4.3每章「事实 → 法律评析 → 风险等级 → 建议」的结构是否与贵所模板一致。
    • 核对 4.4问题清单三分类的归类边界，例如测算假设与联网检索许可归入「需律师决定 / 复核」是否合适。
    • 核对 4.5编制说明作为第三件交付物是对外交付给委托方，还是仅供律师内部使用。

    做法

    1. 先读 shared/references/due-diligence-playbook.md 第 4–8 节与 shared/references/document-delivery-qa.md 第 2、4、5 节；读 commercial-legal/CLAUDE.md「输出」章节取工作产物标题；确认前三步输出已落盘。
    2. 报告正文：章节与版式沿用参考稿；参考稿中被排除（标黄）的段落不得参考；沿用的既有表格在问题清单中说明「系律师此前检索结果，本次未独立核验」。
    3. 每章结构：事实（引用 fact_id）→ 法律评析 → 风险等级 → 建议；交易结构未知的章节开头注明「按一般情形」；未回原件核对或单一来源的事实用条件句与【待核实】；释义表以上一步定稿的主体全称为准。
    4. 管理层摘要从正文倒推：按风险等级排序，每行注明正文位置；经营资源依赖控股股东体系的提示合并为一行；摘要不得出现正文没有的结论。
    5. 问题清单三分类：补充资料（来源：清点的 unreadable 与缺失文件、底稿「需补」）；待说明即事实矛盾（来源：底稿 conflicts_with、访谈口径与文件不一致）；需律师决定 / 复核（来源：交易结构、联网检索许可、按通行文本引用而未下载原文的条文、测算假设）。每项写编号 / 事项 / 来源章节 / 影响 / 建议动作。
    6. 编制说明七项：工作流程（清点 → 底稿 → 程序核查 → 装配，含辅助模型分工与规则）；资料来源对照表（章节对应主要 file_id）；计算方法（每个测算的公式、假设、来源）；已纠正错误清单（发现方式：回原件 / 重算 / 交叉比对）；法条核验表（法规 / 条文 / 版本 / 核验来源 / 状态）；覆盖审计结果（referenced / unique_files、未引用文件及解释）；未执行事项（外部检索、独立复核）。
    7. 成稿与 QA：以参考稿 DOCX 作包模板 + DSL 生成正文；渲染两次回填目录页码；逐页检查表格与分页；OOXML 校验；发送包用正则检查身份证号；内部底稿分目录存放。
    8. 交付说明：列占位符（出具日期、尽调期间）、三件文件清单与指纹、外部检索声明、结构指标（仅作解释）；随后按 shared/legal-document-intake/SKILL.md 输出 REVIEW_STATUS，未做不同模型独立复核时写 skipped 与原因。
    9. 补充资料到达时出第二版：单独清点 → 逐份写「对报告的影响」→ 更新受影响 fact_id 与章节 → 输出「补充资料核查及修订说明」+ 问题清单第二版；文件名带版本号，不覆盖第一版。

    内置规则

    • 三件交付各司其职：报告给结论，问题清单给动作，编制说明给可信度；成稿恒标「律师复核稿」。
    • 工作产物标题取自实践配置：律师角色为「律师工作产物 — 受律师-当事人特权保护 / 保密」。
    • 无参考稿时用 shared/references/document-structures.md 的报告结构 + 中文 reference.docx。
    • 律师要求只出问题清单时，仍需底稿支撑，每项注明 fact_id。
    • 上下文压缩后从分章底稿与 DSL 源文件续写，不凭记忆重写。
    • 摘要、正文与批注对核心前提使用同一确定程度（条件句 + 【待核实】），不得出现正文确定、批注待核实。

    产出

    三件 DOCX：尽调报告（律师复核稿，沿用参考稿版式，含管理层摘要、释义表、分章「事实 → 法律评析 → 风险等级 → 建议」）、问题清单（三分类，每项编号 / 事项 / 来源章节 / 影响 / 建议动作）、编制说明（七项）；另附交付说明与 REVIEW_STATUS；补充资料时另出带版本号的修订说明与问题清单第二版。

08交付前检查

  • 覆盖审计在装配前复跑并记录 referenced / unique_files；未引用文件逐个解释；未做覆盖审计不得写「资料已全部审阅」。
  • 每条事实有 file_id + 定位，evidence_kind 与 confidence 已填；影响结论的事实 verified_by_author: true，未核对的只以条件句 + 【待核实】进入报告。
  • 金额有两个以上来源或写明单一来源；表格分项加总已重算；两版章程 / 多版决议差异逐条数清。
  • 条号注明出自合资合同还是章程；释义表主体全称与登记文件一致。
  • 主体属性矩阵四个维度已填、未知项标明；每条程序结论有现行版本锚点或 [待验证]；负面清单、申报标准数值按当年版本核对；控制权变更触发条款逐合同列出。
  • 摘要每行可回溯正文位置，摘要不出现正文没有的结论；交易结构未知的章节已注明「按一般情形」。
  • 问题清单三分类完整、每项有来源与动作；编制说明七项齐全；法条核验表登记每处法条的版本与核验来源。
  • 标黄段落未复用；沿用表格已声明「本次未独立核验」。
  • 目录页码已回填；渲染逐页检查完成；OOXML 校验通过；发送包无身份证号；内部底稿分目录。
  • 成稿恒标「律师复核稿」；交付说明与 REVIEW_STATUS 已输出。

09何时暂停或升级

  • 委托方身份与报告受众、参考稿排除规则等阻断项缺失：输出 [CLARIFY:] 编号清单并暂停。
  • 写入目标可能覆盖参考稿或资料原件：暂停确认；参考稿与原件永不覆盖。
  • 交易结构未答：不阻断，按「一般情形」继续，列 deferred_items 首项，受影响章节逐章注明，并进问题清单「需律师决定」。
  • 关键文件只有扫描件且 OCR 不清、主笔目视仍不清：标【待核实】并进问题清单「补充资料」。
  • 访谈口径与文件不一致：以文件为准，访谈口径进「待说明」。
  • 受让方为境外主体：增加负面清单与信息报告核查，外汇登记 [待验证] 列为律师决定。
  • 按通行文本引用而未下载原文的条文：在问题清单「需律师复核」逐条列出（LWC-2026-0005 有 7 条）。
  • 未获联网检索许可：不做企业信用、裁判文书、执行、信用中国核验，在方法说明中声明并进问题清单。
  • 未做不同模型独立复核：REVIEW_STATUS 写 skipped 与原因，不得省略状态输出。
  • 辅助模型接口限流中断：按章节重派，不重做已落盘章节；上下文压缩后从分章底稿与 DSL 源文件续写。
  • 补充资料包到达：单独清点、逐份写对报告的影响，出带版本号的第二版，不覆盖第一版。
