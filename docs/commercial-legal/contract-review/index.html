01概要

审查对方发来或发回的商事合同（买卖、技术服务、租赁、合作协议等），代表甲方或乙方找出偏离贵所立场的条款，给出可直接粘贴的替换语言、法律依据、谈判路线图和审批路由，组装成完整审查备忘录，可选微信群两行摘要、带修订标记的文档和去除内部评级的外部版。做法是：先读实践配置文件 commercial-legal/CLAUDE.md 的审查立场、交易破坏者、升级矩阵和文书风格（缺失则二选一：跑约 2 分钟访谈或用临时模式），再完整读合同和附件做一轮 2–5 题的事项确认，然后按风险识别 → 法律依据 → 条款修改建议 → 谈判要点 → 输出格式化五步执行。法律依据只从民法典合同编引用库和检索工具取，成文法优先，每条带来源标签，凭记忆的条文一律标待验证。五步各自可单独运行。

02适用与边界

适用场景

  • 收到对方起草的合同或发回的修订版，需要代表甲方（买方/委托方）或乙方（卖方/受托方）审查并回复修改意见。
  • 只需快速风险扫描（/commercial-legal:risk-identification）、只需为某个条款找法律依据（/commercial-legal:legal-basis --issue 违约金条款）、已有风险清单只要修改语言（/commercial-legal:clause-revision）、谈判前准备（/commercial-legal:negotiation-points）。
  • 需要向业务方或微信群同步两行摘要，或向对方发出带修订标记的文档。

不做什么

  • 不从零起草合同（由合同起草流程负责）。
  • 法律依据库只覆盖中国法；合同适用境外法律时只能说明「须咨询当地律师」并标 [管辖 flagged — 不同法域]。
  • 交易破坏者未解决时，后续步骤的结果参考意义有限，不作为签约依据。
  • 不直接向对方当事人输出内部备忘录；外部版必须先去除内部评级、谈判底线和特权标题。
  • 不凭记忆断言法条编号、发文文号或生效日期；无法检索核实的结论必须标注。

03输入与产出

需要律师提供

  • 合同文件（路径或正文）及附件、订单、既有修订必需
    非中文合同也可，结果标注「基于中文翻译，建议对照原文复核」
  • 实践配置文件 commercial-legal/CLAUDE.md必需
    缺失或有占位符时可说「临时模式」用通用默认值继续
  • 我方立场（甲方/乙方）可选
    优先从用户指令和合同角色推断，只在有合理歧义时询问；可用 --party 甲方|乙方 指定
  • 合同金额可选
    先从正文、附件、订单或计价公式归纳；只在影响审批路由/责任上限/修订策略且无法取得时才问
  • 对方当事人类型（大公司 / 中小企业）可选
    影响修改策略和谈判路线；可用 --counterparty 指定
  • 输出目的地（内部复核 / 业务摘要 / 直接发对方）可选
    优先从请求和配置推断，只在内外部版本有实质歧义时询问；默认先供律师内部复核
  • 事项工作区的 matter.md可选
    仅在配置启用事项工作区且有活跃事项时加载，输出写入事项文件夹

产出

  • 完整审查备忘录（默认）给律师内部（受律师-当事人特权保护）
    工作产物标题 → 标题块（对方、合同类型、审查日期、金额/期限、我方立场、管辖法律、应用的审查立场）→ 审查者注（法规来源、阅读范围、四级标记数量、时效性）→ 底线（两句话：能签吗、什么必须先改；法律风险与商业摩擦两组统计；需要谁审批）→ 交易破坏者检查 → 按风险等级分类的问题（每块含等级、原文、偏离类型、替换语言、对方不让步的备选、法律依据）→ 有利条款 → 缺失条款 → 法律依据（法条/案例/学说）→ 谈判要点 → 审批路由 → 修订包 → 下一步决策树
  • 微信群摘要（可选）给律师-当事人工作群
    两行：「[对方] [类型] — 需要修改。[N] 关键（最关键问题 第X.X条），[N] 高。完整审查：[位置]。需要 [审批人姓名] 审批。」；无风险时「可以签，有几个小的跟进事项」
  • 修订文档（可选）给对方
    .docx 修订标记（Track Changes），每处修改附批注引用审查立场 + 法条；无 docx 工具时输出可手动应用的 markdown 修订记录
  • 外部净化版 / 脱敏版给对方 / 公司全员群 / 业务方
    去除特权标题、内部评级、谈判底线和内部风险评估，保留修订建议；面向董事会/业务方的版本简化术语、聚焦商业影响
  • 四份中间结果（可单独交付）给律师内部
    风险识别结果、法律依据清单、条款修改建议（含修改包汇总表）、谈判要点（含谈判路线图与审批路由）

04开始前

前置条件

  • 在阅读合同之前读取 commercial-legal/CLAUDE.md；缺失或仍有占位符时提示二选一：运行 /commercial-legal:cold-start-interview（约 2 分钟），或说「临时模式」。
  • 检查配置的「事项工作区」是否启用（默认未启用，用实践级上下文）；启用但无活跃事项时询问「这个审查属于哪个事项？」，有活跃事项则加载其 matter.md，输出写入事项文件夹。
  • 加载配置后、风险识别前执行 shared/legal-document-intake/SKILL.md：完整读合同、附件、用户文字和既有修订，建立 known / derived / material_missing / optional_missing 四类清单；配置中的具体值作默认，「视情况而定」只在本事项相关时才问；只问会改变甲乙方立场、修订力度、谈判范围、法律路径或内外部版本的问题，每轮优先 2–5 题；操作员需微信沟通时输出可转发的 [CLARIFY:] 清单并暂停；答案带回后合并到事项摘要，从当前阶段继续，不重复提问。候选问题见 question-routing.md，但不得机械全问。
  • 目的地检查：优先从请求和配置推断；仅在内部特权稿、业务摘要、拟直接发对方的外部修订稿之间有实质歧义时才问。
  • 进入各步骤前加载五份共享资源：主体资格陷阱清单、搜索策略、研究质量闸门、法律引用规范、民法典合同编引用库。

硬性规则

临时模式
用户说「临时模式」时用通用默认值运行：中等风险偏好、律师角色、中国法律体系、无特定审查立场（标记常见甲乙方风险——无限责任、无数据泄露例外、不明确的违约金、自动续约无通知等）；审阅者注释和每个发现块标 [临时模式]，输出末尾附「运行冷启动访谈约 2 分钟可获定制输出」。
合同金额处理
先从正文、附件、订单或计价公式计算/归纳；只有金额会影响本次审批路由、责任上限或修订策略且无法取得时才询问；金额无实质影响时标「金额未确认，审批路由待律师判断」并继续，不得因固定问卷阻断全文审查。
哪一方
优先从用户指令和合同角色推断我方立场；只在有合理歧义时问「在这个协议中，[机构] 是哪一方、希望保护谁？」；不得重复询问用户已明确的「代表甲方/乙方」。
交易破坏者优先
风险识别发现交易破坏者时，先标记并告知律师再继续后续步骤；此问题不解决则后续结果参考意义有限。
输出与落盘确认
用户已明确 Word/修订稿/备忘录及目标路径时直接执行不反问；配置已有「源文件同目录、新建后缀」安全默认且不覆盖原件时采用默认并简短说明；只有格式或目标不明、可能覆盖原件、涉及外部发送或特权泄露时才阻断确认；永不覆盖原件，除非用户明确指定。
先检索、后结论
给出任何法律结论、条款建议或风险判断前，优先用检索工具核对现行有效的法律法规、司法解释及指导性案例；无法核实时标注「未经检索核实，请以现行有效文本为准」；禁止凭记忆断言法条编号、发文文号或生效日期。
特权保护
备忘录和基础协议可能受律师-当事人特权保护，仅在特权圈内分发；外部版本必须去除内部评级、谈判底线和特权标题，净化由输出格式化步骤执行。

05执行步骤

共 5 步，按执行顺序。每步旁边（窄屏在步骤说明之后）是请律师核对的内置假设，可逐条复制。页面里的英文标记见首页「标记与术语」。

  1. 风险识别

    /commercial-legal:risk-identification可单独运行

    对照实践配置文件，从主体资格、条款偏离、法律强制性、可执行性四个维度逐条识别风险，输出按严重性分级、同时标注法律风险与商业摩擦的风险清单。

    请律师核对

    • 核对 1.1四级风险等级直接绑定审查立场（关键 = 绝不接受、高 = 超出备选、中 = 备选内未达标准、低 = 明确容忍）——与贵所分级口径是否一致。
    • 核对 1.2主体资格预检表只有 5 类情形，法条全部标 [待验证]；其中「银行分支机构为担保方」引用《民法典》第504/506条，而同一文件把第506条定义为免责条款效力——请核对依据，并考虑是否补充其他主体类型。
    • 核对 1.3把竞业限制（《劳动合同法》第23-24条）列入商事合同的管辖差异核查表，是否适用于贵所审查的商事合同（如合作协议、股权文件中的竞业条款）。
    • 核对 1.4合同金额缺失时继续审查、只标「审批路由待律师判断」——是否同意不阻断。

    做法

    1. 读取配置文件（审查立场、交易破坏者、升级矩阵）、shared/references/subject-qualification-traps.md、引用规范与引用库；检查事项工作区是否启用。
    2. 第一步建立定位表 8 项：合同类型（买卖 / 技术服务 / 租赁 / 合作协议 / 其他）、我方立场（甲方买方/委托方或乙方卖方/受托方）、对方当事人名称与类型（大公司 / 中小企业 / 个人）、合同金额（总价/年费）、合同期限与续约机制、是否涉及数据处理（个人信息/重要数据）、是否涉及担保（保证/抵押/质押）、合同约定的适用法律与争议解决方式。
    3. 金额先从订单、附件、计价公式归纳；若只影响审批路由，标「金额未确认，升级路由待律师判断」并继续；只有金额会改变责任限制、修订策略或审批结论且无法推断时才按事项确认规则询问。
    4. 第二步主体资格预检，对照陷阱清单优先核查 5 类情形：有担保/保证条款时核查担保人是否有权出具（融资担保公司、银行分支机构、上市公司等）；上市公司为一方时核查对外担保是否有董事会/股东会决议；国企/事业单位为一方时核查国资委审批或内部决策程序；银行分支机构为担保方时核查总行授权文件；外商投资企业对外担保时核查外汇局备案/登记。发现问题置于风险清单顶部显著标记，并评估对合同效力的影响。
    5. 第三步交易破坏者检查：先扫描配置中「绝不接受」的条款，存在则立即输出「存在交易破坏者」块（条号、名称、建议替代表述、「对方不让步：放弃，不签」），并声明其他识别结果参考意义有限。
    6. 第四步逐条扫描，对每个偏离生成识别块：我方立场（引自配置）/ 合同原文引用 / 偏离类型（缺失条款、弱于标准、弱于备选、非典型结构、不可接受）/ 法律风险等级 / 商业摩擦等级 / 为什么重要（一到两句白话：保持原样业务会出什么问题）/ 法律依据标签。
    7. 第五步责任限制与违约金条款必须完成四维识别，不得只写「检查责任限制」：维度 1 限制适用于所有责任还是仅直接损失；维度 2 逐字引用「限制金额」表述并归为四种基数之一（索赔前 12 个月已付费用 / 当前 12 个月应付费用 / 合同总价 / 其他），不明确则标「基数定义不明确 — [原文] — 可能意味着 [X] 或 [Y]，签署前确认」；维度 3 列出哪些在限制之外（例外）、哪些在内，评估限制是否有实质意义；维度 4 与配置中的直接限制倍数、间接损失处理、例外清单、基数偏好逐项对应。
    8. 第六步管辖法律差异核查 5 项：竞业限制（《劳动合同法》第23-24条，期限≤2年、需支付补偿，各地司法实践有差异）、自动续约格式条款（《民法典》第496条，消费者合同有额外保护）、责任排除（第506条，人身损害/重大过失免责无效，强制性规定）、违约金调整（第585条，各地法院裁量幅度不同）、格式条款（第496-498条）；审查立场与合同适用法律可执行性冲突时标「你的审查立场倾向于 [X]，但合同受 [Y] 法律管辖，在那里 [X] 是 [不可执行/受限制] [管辖法律 — 需验证]」。
    9. 按 9 项检查清单自查（定位表完整、担保情形已预检、交易破坏者已优先标注、每条有偏离类型+两档等级、等级已校准不全是关键、责任限制四维完成、管辖差异已核查、法律依据已按来源标注、金额缺失时未用猜测值做审批或责任结论）后输出。

    内置规则

    • 双重严重性：每个问题同时标法律风险与商业摩擦两档。关键 = 交易破坏者或绝不接受清单条款 / 阻碍交易；高 = 超出备选范围、强烈推动 / 拖慢谈判；中等 = 在备选范围内但未达标准 / 造成日后执行困惑；低 = 明确容忍或纯形式偏离 / 基本无感。
    • 风险等级必须校准，对照配置文件，不得全部标关键。
    • 责任限制基数只归为四类：索赔前 12 个月已付费用、当前 12 个月应付费用、合同总价、其他。
    • 合同非中文：标「合同为 [语言] 版，风险识别基于中文翻译，建议对照原文复核 [用户提供]」。
    • 合同极短（少于 5 条）重点检查「缺失条款」；框架协议注明「具体权利义务由订单/补充协议确定，订单签署前需复核」。
    • 涉经济特区/自贸区标 [管辖 flagged — 需验证特别规定]，提示特别立法权；管辖法律不确定时标 [管辖法律 — 需验证]，不按单一法律做结论性判断。
    • 担保主体资格存疑：识别清单顶部置红，评估合同效力影响，建议出具法律意见。
    • 合同文本明显不完整时标注「识别结果可能有遗漏，建议补充后重新运行」；条款格式特殊无法解析时标「需人工审查」。
    • 法律依据查询无结果时遵循无静默补充原则：报告并询问下一步，不自行填补。

  3. 条款修改建议

    /commercial-legal:clause-revision可单独运行

    把每个偏离条款转成可直接粘贴进修订版的替换语言，用尽可能小的修改粒度保留对方框架，并为每条附上对方不让步时的备选处理。

    请律师核对

    • 核对 3.1默认最小粒度修改、「拿不准时选更小」——是否符合贵所的修订习惯，还是贵所惯用整条替换。
    • 核对 3.2第506条无效免责条款直接标「法定无效，无需谈判」建议删除——是否同意不作谈判处理。
    • 核对 3.3格式条款修改时「提示对方本条按第498条解释对提供方不利」——向对方点明这一点是否符合贵所策略。
    • 核对 3.4最后一轮谈判放弃中等/低风险条款这一默认取舍是否合适。

    做法

    1. 读取配置（审查立场、可接受备选、文书风格中的修订语气）、风险识别结果（没有则先运行风险识别）、引用规范与引用库；检查事项工作区。
    2. 确认修改范围（全部偏离条款，或 --focus 指定的特定条款）、对方当事人类型（大公司 vs 中小企业，影响策略和预期）、当前谈判阶段（首轮 vs 最后一轮，影响粒度选择）。
    3. 应用修改粒度原则：修订是谈判工具不是重写；整体替换发出「我们扔掉了你的草稿」的信号，精细修订发出「我们有具体要求」。粒度层级从小到大：词（单词不准确或有歧义）→ 短语（补充修饰或替换表述）→ 子条款（重组逻辑）→ 句子（整句与立场冲突，需说明理由）→ 整条款（相差太远，须主动说明「我们替换了第X.X条，因为改动范围很大，很高兴带你过一遍差异」）。
    4. 默认选择五条：替换词优先于短语；替换短语优先于句子；重组子条款优先于替换句子；替换句子优先于整条款；仅当对方版本与立场相差太远、精细修改比新草稿更难阅读时才替换整条款。拿不准时选更小的粒度。
    5. 对每条生成修改建议块：风险等级（来自风险识别）/ 修改粒度 / 原文完整引用 / 问题一句话（偏离类型与影响）/ 建议修改（可直接粘贴的替换语言，用删除线和加粗示意修改位置）/ 修改说明（引用法条或审查立场）/ 如果对方不让步（配置中的备选方案；无备选则写「升级到 [人员]」或「可考虑接受，需标注风险」）/ 法律依据（来源标签 + 待验证）。
    6. 特殊条款处理：对方提供标准合同的格式条款，按《民法典》第498条有争议时作不利于提供方解释，修改建议须明确表述，并提示对方「本条按第498条解释对提供方不利，建议明确表述以避免争议」。
    7. 违约金/责任限制按风险识别的四维结果针对性修改；需分别处理直接损失限制与间接损失排除时生成两个独立建议；明确基数定义的替换语言。
    8. 免责条款涉及《民法典》第506条（人身损害或重大过失）时说明「按第506条本条款无效，无需谈判」；仍需明确约定（如限制至法定最低标准）时生成合规替换语言。
    9. 汇总修改包：四列表（条款 / 风险等级 / 修改粒度 / 摘要）按条款顺序排列，供律师统一传递给对方；附按配置修订语气给出的传递说明。
    10. 按 9 项检查清单自查（每条有具体替换语言、粒度最小可行、整条款替换附说明、每条有对方不让步处理、格式条款遵循第498条、违约金/责任限制覆盖四维问题、第506条无效条款已标「法定无效无需谈判」、法律依据有来源标签、汇总表四列一致）后输出。

    内置规则

    • 每个修改建议必须有具体替换语言，不得只写「建议修改」。
    • 修改建议块按关键 → 高 → 中等 → 低排序。
    • 交易破坏者条款不生成「可接受备选」，只生成坚持修改的语言 + 不签的说明。
    • 首轮谈判优先推动所有修改；最后一轮优先保留关键/高风险条款，放弃中等/低风险条款。
    • 只指定特定条款时，其他条款说明「未在本次范围内」。
    • 对方为大公司（标准合同不会改）时，在建议中增加对方不让步时的博弈策略（见谈判要点步骤）。
    • 合同非中文：修改建议提供中文，注明「建议对照原文语言同步修改，本建议为参考」。
    • 配置无该类条款的备选方案时给三个选项：坚持标准立场 / 升级律师决定 / 更新配置文件记录本次决策。
    • 修改语言与对方法律文风差异大时标注「本建议采用 [风格]，对方合同采用 [风格]，传递时建议适应对方格式」。

  4. 谈判要点

    /commercial-legal:negotiation-points可单独运行

    把审查立场与风险识别结果转成可操作的谈判路线图：硬底线、让步空间、交易筹码、对方类型差异策略、谈判顺序和审批路由。

    请律师核对

    • 核对 4.1对方类型只分大公司 / 中小企业两类，且大公司策略为「以法律合规要求包装硬底线」——是否恰当，是否需要政府/事业单位等第三类。
    • 核对 4.2六步谈判顺序，尤其「低风险不花谈判资本」「中等风险最后一轮可接受」是否符合贵所习惯。
    • 核对 4.3业务方与法务冲突时以「业务方书面确认风险接受」作为出口——贵所是否接受这一机制。

    做法

    1. 读取配置（审查立场、交易破坏者、可接受备选、升级矩阵）、风险识别结果（没有则先运行）、条款修改建议（已有则提取「对方不让步」部分）；检查事项工作区。
    2. 层次 1 硬底线：从配置「交易破坏者（The one thing）」提取；策略是坚持不让步，对方坚持则考虑放弃交易；措辞建议「这是我们法务合规方面的硬性要求，不在谈判范围内」。
    3. 层次 2 让步空间：从配置「可接受的备选」提取；先推标准立场，对方反对再退至备选；措辞建议「我们的首选是 [X]，如果这对你有困难，我们可以接受 [备选]」。
    4. 层次 3 交易筹码：从风险识别「优于我方标准」的有利条款提取；不主动提出，留作在其他条款上换取让步；记录「第X.X条对方给了比标准更多的条款，这是谈判资本」。
    5. 对方类型差异化。大公司（标准合同改动空间小）：接受大框架、精准推动核心风险条款；聚焦关键/高风险，中等/低风险非关键时可接受；硬底线以「法律合规要求」包装；对方联系人无权改则请求升级决策层；知会业务方某些条款可能改不了需提前了解风险。中小企业（灵活愿协商）：全面推动所有偏离条款；解释商业逻辑（共赢）；注意对方可能存在主体资格、偿付能力风险；谈判时间较长可能影响交易节奏。
    6. 谈判顺序六步：先解决交易破坏者（否则继续审查意义不大）→ 关键级条款（法定无效或绝不接受清单）→ 高风险条款（超出备选范围）→ 在其他条款上让步换取高风险条款的让步 → 中等风险在最后一轮可接受 → 低风险不花谈判资本。
    7. 审批路由：对照升级矩阵检查合同金额与审批权限阈值、是否存在关键级问题、自动升级触发条件（无限责任、知识产权转让、境外管辖等）；输出勾选清单「[姓名/角色] 审批 — 原因」「业务负责人确认 — 需确认的商业条款」及建议下一步（发送修订给对方 / 升级到合伙人后再回复 / 先获取业务方对 X 条款的意见）。
    8. 汇总谈判路线图三张表：硬底线（条款 / 底线要求 / 谈判措辞建议）、让步区间（条款 / 标准立场 / 可接受底线 / 换取条件）、交易筹码（条款 / 对方给的 / 用途），加「建议升级」。
    9. 按 7 项检查清单自查（硬底线有据可查、让步区间来自配置而非自行判断、有利条款已提取、对方类型已识别、顺序按优先级、升级路由三项检查完成、表格列数一致）后输出。

    内置规则

    • 硬底线与让步区间必须来自配置文件，不得自行判断。
    • 配置无交易破坏者定义：基于关键级风险条款推导硬底线，标「临时底线，建议更新配置文件」。
    • 配置无备选方案：建议律师明确备选，标「本次谈判需律师判断让步下限」。
    • 对方类型不明：询问「对方是大公司（标准合同不灵活）还是中小企业（可以谈）？这影响谈判策略」。
    • 合同金额超过所有审批阈值：升级路由中说明需最高级审批。
    • 所有条款都是交易破坏者：标「本合同大部分条款不符合立场，建议考虑是否要推进这笔交易」。
    • 谈判已进入最后阶段：标「保留关键/高风险，放弃中等/低风险，集中资本在核心条款」。
    • 配置仍有占位符：提示「审查立场未填写，无法准确推导谈判底线，建议运行冷启动访谈或手动填写」。
    • 业务方要签、法务不同意：标注升级信号，提供「业务方确认风险接受」选项（明确写明风险后签字确认）。

    法律依据

    • 《民法典》第585条 — 违约金谈判区间（法院可调整，给谈判空间） [模型知识 — 需验证] [待验证]
    • 《民法典》第497条 — 格式条款无效谈判底线（强制规定） [模型知识 — 需验证] [待验证]

    产出

    Markdown「谈判要点：[对方] [合同类型]」：生成日期、对方类型、我方立场 → 谈判路线图（硬底线 / 让步区间 / 交易筹码三表）→ 对方类型策略 → 审批路由（勾选清单 + 建议下一步）。

  5. 输出格式化

    /commercial-legal:output-formatting可单独运行

    把前四步的结构化结果组装成可交付文件（完整备忘录 / 微信群摘要 / 修订文档），完成目的地与特权检查、交付前质量检查，并以定制的下一步决策树结束。

    请律师核对

    • 核对 5.1五类目的地的特权风险分级（公司全员群与对方 = 特权失效风险；业务部门群 = 中等需询问）是否符合贵所保密实践。
    • 核对 5.2微信群摘要固定两行并点名「需要 [审批人姓名] 审批」——在群里点名审批人是否合适。
    • 核对 5.3外部净化版「去除内部评级与内部风险评估、保留修订建议」——这一边界是否足以防止暴露谈判底线。

    做法

    1. 输出前置判断：读取事项摘要与配置；请求已明确输出格式与路径时直接执行不重复确认；有不会覆盖原件的稳定默认值时采用并简短说明；仅当格式/目标不明、可能覆盖文件、内外部版本有实质歧义时输出 [CLARIFY:] 并暂停；任何写入均新建文件，除非用户明确授权覆盖。
    2. 第一步目的地检查，对照五类表：内部法务文件夹（低风险，直接完整备忘录）/ 律师-当事人工作群仅法务（低风险，完整备忘录）/ 公司全员群（特权失效风险，脱敏版）/ 对方当事人（特权失效风险，净化版，剥离内部评估）/ 业务部门群（中等风险，询问是否在特权圈内）。目的地看起来在特权圈外时提供选项：(a) 仅法务的特权版 (b) 面向更广渠道的脱敏版 (c) 两者。用户已说明「供内部复核」或「直接发对方」时直接应用，不重问。
    3. 第二步读取配置「输出」中的工作产物标题：律师角色「律师工作产物 — 受律师-当事人特权保护 / 保密」；非律师角色「研究笔记 — 非法律建议，供律师审查」；临时模式附加「[临时模式 — 配置你的档案以获得定制输出]」。
    4. 第三步组装完整备忘录：标题前置 → 标题块（对方、合同类型、审查日期、金额/期限、我方立场、管辖法律、应用的审查立场）→ 审查者注（配置模板：法规来源、阅读范围、四级标记数、时效性）→ 底线（两句话：我们能签吗、什么必须先改；法律风险与商业摩擦两组统计；需要审批）→ 交易破坏者检查 → 按风险等级分类的问题（合并风险识别与修改建议，每块含等级、原文、偏离类型、替换语言、对方不让步备选、法律依据）→ 有利条款 → 缺失条款 → 法律依据 → 谈判要点 → 审批路由 → 修订包。
    5. 第四步微信群摘要（用户请求或目的地为工作群时）：两行加链接格式「[对方] [类型] — 需要修改。[N] 关键（[最关键问题] 第X.X条），[N] 高。完整审查：[链接/位置]。需要 [审批人姓名] 审批。」；无风险时「[对方] [类型] — 可以签，有几个小的跟进事项。完整审查：[位置]。」
    6. 第五步修订文档（用户要求 .docx 时）：每处修改用修订标记（Track Changes），每处批注引用审查立场 + 法条；无 docx 工具时输出可粘贴的 markdown 修订记录并说明「无法直接生成 .docx，以下为可手动应用的修订记录」。
    7. 第六步交付前质量检查 10 项：配置已加载并引用（不是通用市场立场）；交易破坏者已优先检查并明确说明；每个问题有具体替换语言；风险等级已校准不全是关键；审批人有具体姓名而非「升级到法务」；对方背景（大公司 vs 中小企业）已考虑；工作产物标题已前置；临时模式已在每个发现块和末尾标注（若适用）；目的地检查已完成、特权风险已处理；法律依据按来源分类并带标签。
    8. 第七步下一步决策树（按配置模板，根据本次结果定制）：1 起草修订版（运行 /commercial-legal:clause-revision）/ 2 升级给 [指定人员]（需要：[问题描述]）/ 3 获取更多事实（列出缺少的信息）/ 4 观望等待（标记风险暂不行动）/ 5 其他。

    内置规则

    • 某一步输出缺失时在对应章节标「[本章节需先运行 X]」，不留空白章节。
    • 面向对方的交付物应用静默模式：净化特权标题与内部风险评估，保留修订建议；面向董事会/业务方的摘要简化法律术语、聚焦商业影响。
    • 目的地明确是对方当事人时停下，提供版本选项，不直接输出内部备忘录。
    • 四步输出均缺失时提示「请先完成合同审查（风险识别 → 法律依据 → 条款修改 → 谈判要点），或运行完整流程 /commercial-legal:contract-review」。
    • 配置中的工作产物标题仍为占位符时使用通用律师标题，标注「[配置文件标题占位符，请运行冷启动访谈]」。
    • 法律依据章节直接引用法律依据步骤的输出，不重新生成；来源标签和待验证标注原样保留，不剥离或折叠。
    • 临时模式：每个发现块标 [临时模式]，输出末尾附冷启动引导。
    • 配置无下一步决策树模板时使用五个默认分支，标注「请在配置文件中自定义决策树」。

    产出

    完整审查备忘录（结构见第三步）；按请求附微信群两行摘要、修订标记文档或 markdown 修订记录、脱敏/净化版；文末为定制的五分支下一步决策树。

08交付前检查

  • 配置文件已加载并引用，不是通用市场立场；临时模式时每个发现块和末尾已标注。
  • 交易破坏者已优先检查并明确说明；主体资格有担保情形时已预检。
  • 每个问题同时有法律风险与商业摩擦两档，等级已校准（不全是关键）。
  • 责任限制/违约金条款已完成四维识别（直接/间接、基数、例外、立场对应）。
  • 每个问题都有具体替换语言，不是「建议修改」；每条有「对方不让步」处理。
  • 法律依据成文法优先，每条含法律名称 + 条号 + 版本年份，行末有且只有一个来源标签，案例标法院层级 + 待验证 + 不具判例法约束力，距最后更新超 6 个月已标时效性。
  • 管辖法律差异已核查（格式条款、违约金、免责条款等）并标注。
  • 审批人有具体姓名而非「升级到法务」；对方类型（大公司 vs 中小企业）已考虑。
  • 工作产物标题已前置；目的地检查已完成，外部版已净化；下一步决策树已按本次结果定制。
  • 合同金额缺失时未用猜测值做审批或责任结论；永不覆盖原件。

09何时暂停或升级

  • 发现交易破坏者：立即标记并告知律师，此问题不解决则后续结果参考意义有限。
  • 担保主体资格存疑：识别清单顶部置红，评估合同效力影响，建议出具法律意见。
  • 法规检索结果很少：不自行填补，报告结果并给四个选项（扩大范围 / 换工具 / 搜网络并标注 / 标未验证并停止）。
  • 管辖法律不确定或合同适用境外法：标 [管辖法律 — 需验证] / [管辖 flagged — 不同法域]，不按单一法律做结论性判断，建议咨询当地律师。
  • 合同金额、我方立场、输出目的地有实质歧义且无法从材料推断：按事项确认规则询问，每轮 2–5 题；操作员需微信中继时输出 [CLARIFY:] 清单并暂停。
  • 按升级矩阵触发（金额超阈值、关键级问题、自动升级条件）：在审批路由中指名审批人；配置无审批人时提示「请升级给 [角色]，联系方式待配置」。
  • 目的地明确是对方当事人或公司全员群：停下，提供特权版 / 脱敏版 / 两者的选项，不直接输出内部备忘录。
  • 业务方要签、法务不同意：标注升级信号，提供业务方书面确认风险接受的选项。
  • 合同文本明显不完整或条款格式无法解析：标注可能遗漏 / 需人工审查。
  • 未先运行风险识别就单独调用修改建议或谈判要点：提示先运行风险识别或提供风险清单。

10请律师重点核对

下面是这个流程内置的法律假设、立场、阈值和清单，每一条都可以同意、反对或补充。条目下的「相关批注」按文字重合自动匹配到步骤旁的核对条目，可能不全。

  1. 四级风险等级与审查立场绑定：关键 = 交易破坏者或绝不接受清单；高 = 超出备选范围；中 = 备选范围内但未达标准；低 = 明确容忍或纯形式偏离。商业摩擦同样四级（阻碍交易 / 拖慢交易 / 造成困惑 / 无感）。这套定义是否与贵所分级口径一致？相关批注：核对 1.1
  2. 主体资格预检表只列 5 类情形（担保条款、上市公司、国企/事业单位、银行分支机构、外商投资企业对外担保），法条全部标 [待验证]；其中「银行分支机构为担保方」引用《民法典》第504/506条，而同一文件把第506条定义为免责条款无效。请核对依据，并考虑是否补充其他主体类型。相关批注：核对 1.2
  3. 责任限制条款强制做四维分析，基数定义只能归为四类（索赔前 12 个月已付费用 / 当前 12 个月应付费用 / 合同总价 / 其他）。这一分类是否覆盖贵所常见的基数写法？
  4. 管辖法律差异核查表把竞业限制（《劳动合同法》第23-24条，期限≤2年、需支付补偿）列入商事合同审查范围。这对贵所审查的商事合同是否适用？相关批注：核对 1.3
  5. 临时模式默认值：中等风险偏好、律师角色、中国法律体系、无特定立场但标记常见风险（无限责任、无数据泄露例外、不明确的违约金、自动续约无通知）。这组默认是否可接受，还是应禁止在无配置时审查？
  6. 法律依据只允许五个来源标签，所有案例（含最高院指导性案例）一律标 [待验证] 并声明「不具判例法约束力」，距最后更新超 6 个月即标时效性 flagged；引用库只覆盖民法典合同编与 2023 年合同编通则解释，专项法规（行业监管、数据、知识产权等）需另行检索，SKILL.md 未规定专项库如何补充。贵所是否接受这些口径，是否需要为常见合同类型增补专项引用库？相关批注：核对 2.4、核对 2.3、核对 2.1
  7. 修改粒度默认最小化（词 < 短语 < 子条款 < 句子 < 整条款，拿不准选更小），只有对方版本相差太远才整条替换；最后一轮谈判放弃中等/低风险条款。是否符合贵所修订与谈判习惯？相关批注：核对 3.4、核对 3.1
  8. 《民法典》第506条免责条款直接按「法定无效，无需谈判」处理并建议删除；格式条款按第498条作不利于提供方解释，并「提示对方」本条对其不利。这两种做法是否符合贵所立场？相关批注：核对 3.2、核对 3.3
  9. 对方类型只分大公司 / 中小企业两类；大公司策略为「接受大框架、硬底线以法律合规要求包装、知会业务方某些条款改不了」。是否需要第三类（政府/事业单位、个人）及对应策略？相关批注：核对 4.1
  10. 合同金额缺失时只标「金额未确认，审批路由待律师判断」并继续审查，不阻断；我方立场优先从合同角色推断、不重复询问。是否同意这种不阻断的处理？相关批注：核对 1.4
  11. 目的地五分类：内部文件夹与仅法务工作群为低风险；公司全员群与对方当事人为特权失效风险；业务部门群为中等风险需询问。外部版去除内部评级、谈判底线、特权标题但保留修订建议。分类与净化边界是否符合贵所保密实践？相关批注：核对 5.1、核对 5.3
