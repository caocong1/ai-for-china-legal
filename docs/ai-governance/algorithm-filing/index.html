01概要

帮助提供算法推荐服务的企业及其律师、合规官、法务完成算法备案：判断企业的算法是否构成算法推荐服务、归入生成合成类、个性化推送类、排序精选类、检索过滤类、调度决策类中的哪几类，分析备案条件、备案门槛、备案机关、安全评估深度与时限，按14项材料清单准备备案材料并起草算法机制说明与算法自评估报告，备案后再建立变更分类、注销备案、定期自查和监管配合机制。流程分「算法类型识别与分类 → 备案要求分析 → 备案材料准备与提交 → 备案后变更管理」四步，可完整运行并汇总为「算法备案全流程报告」，也可单独触发任一步。开始前读取 ai-governance/CLAUDE.md 中的企业画像、服务立场、监管关系、合规严格度、AI 合规风险校准与升级矩阵，配置缺失时以临时模式运行并把依赖企业画像的判断逐项标 [待确认 — 临时模式]；法律依据取自共享引用库 ai-law-citations.md 的 §D.2 算法推荐管理规定条目，并按 legal-basis-conventions.md 标注来源。专项规章一律只描述规则、不写条号并标 [待验证 — AI 治理法规快速演进]，用户规模门槛、各类备案时限、备案机关分工均未给出数值或定论，须律师核实。

02适用与边界

适用场景

  • 企业上线或计划上线推荐、排序、搜索、过滤、派单、定价等算法功能，需要判断是否构成算法推荐服务、是否须做算法备案
  • 同一平台同时运行多种算法（如电商平台的商品推荐、搜索排序、配送调度），需要逐一分类并分别评估备案义务与合规要求
  • 已确定算法类型，需要分析备案条件、触发门槛、向国家还是地方网信部门备案、安全评估深度、时限与特殊要求（舆论属性、未成年人、劳动者、新闻或金融信息服务）
  • 准备备案材料：算法机制说明、训练数据说明、拟公示内容、三类安全管理制度、算法透明度方案、用户权益保护方案、算法自评估报告，并按备案系统的操作顺序提交
  • 已有有效备案，算法类型、应用领域、运营主体、舆论属性、算法安全负责人或主要参数发生变化，或服务终止、算法下线需要注销备案
  • 需要建立备案后的定期自查、监管问询/检查/整改/处罚配合预案和法规跟踪机制

不做什么

  • 不提供规避算法备案义务的方法、虚假安全评估材料、伪造的算法透明度方案或绕过内容安全审查的方案；识别此类需求即拒绝并标 [合规边界 — 拒绝]
  • 不替代刑事辩护：算法服务违规可能升格刑事时立即强制升级执业律师，并提示与 criminal-compliance 插件衔接
  • 不单独完成深度合成备案或生成式 AI 备案：识别到交叉义务时转 /ai-governance:deep-synthesis-filing 或 /ai-governance:generative-ai；数据安全评估、个人信息保护影响评估与 data-compliance 插件衔接
  • 不给出备案用户规模门槛、首次备案与变更备案时限、上线前预留期等具体数值，文件只描述规则并标 [待验证]；不臆造规章文号或备案流程细节
  • 对新型算法不作定论：五类均不完全匹配时标 [新型算法 — 监管规则尚不明确]，建议关注监管动态、必要时咨询监管机关

03输入与产出

需要律师提供

  • 算法服务描述与业务模式（功能、技术实现、是否向用户提供互联网信息服务、用户规模、是否涉及定价、热搜或榜单、是否面向未成年人或平台劳动者）必需
    类型识别步骤的参数为「[算法服务描述] [业务模式]」；信息不足时报告已识别内容并列出待确认事项清单
  • ai-governance/CLAUDE.md 实践配置（企业画像、服务立场、监管关系、合规严格度、AI 合规风险校准、升级矩阵）必需
    文件不存在或关键字段含 [PLACEHOLDER] 时进入临时模式
  • 已识别的算法类型（单独运行备案要求分析时）可选
    参数为「[已识别的算法类型]」，须已有类型识别结果或由用户提供算法类型信息
  • 备案要求分析结果（单独运行材料准备时）可选
    参数为「[算法类型] [备案要求]」
  • 主体资料：营业执照、统一社会信用代码、联系方式、地址、法定代表人、算法安全负责人姓名/职务/联系方式可选
    材料清单要求主体信息与营业执照一致、负责人为实际负责人
  • 算法技术资料：算法原理、模型架构、主要参数、调优方式，训练数据来源/类型/规模/合规性/标注方式可选
    用于起草算法机制说明与训练数据说明；可请技术团队协助，涉及商业秘密的核心参数可概括描述
  • 已有管理制度与方案：算法安全、内容安全、数据安全管理制度，算法透明度方案，用户权益保护方案，算法安全技术措施说明可选
    材料清单要求制度为企业正式发布的文件，草案须先完成审批
  • 备案编号与变更情况（备案后变更管理时）可选
    参数为「[备案编号] [变更情况]」，须已有有效备案
  • 监管问询、检查、整改通知或处罚决定（如有）可选
    收到整改通知即升级为被动应对模式；受到处罚即强制升级律师

产出

  • 算法类型识别与分类报告给律师内部 / 客户
    七部分：一、算法推荐服务识别（技术基础、算法类型、服务性质、用户规模、舆论属性五要素，结论为属于/不属于/待进一步评估）；二、算法类型分类（五类逐一标是否适用、具体场景、监管要点）；三、备案义务判断（是否须算法备案、是否须安全评估、备案机关为国家网信部门/地方网信部门/待确认）；四、交叉义务识别（深度合成备案、生成式AI备案、数据安全评估、个人信息保护影响评估及衔接方式）；五、特殊合规风险（算法歧视、大数据杀熟、舆论属性、未成年人保护、劳动者权益及建议措施）；六、临时模式待确认事项；七、下一步建议
  • 算法备案要求分析报告给律师内部 / 客户
    九部分：一、备案条件逐项分析（五项条件是否满足、判断依据、不满足时的补救建议，总结为满足/部分满足/不满足）；二、备案门槛判断（四项判断，综合结论为须备案/可能须备案/暂不须备案）；三、建议备案机关及依据；四、备案流程及节点注意事项；五、安全评估要求（维度表、风险等级高/中/低、评估深度全面/标准/基础）；六、时限要求与建议行动；七、特殊要求与建议措施；八、临时模式待确认事项；九、下一步建议
  • 算法备案材料准备清单及材料草稿给律师内部 / 客户（材料最终提交网信部门）
    清单六部分：一、14项材料的准备状态（已准备/待准备）与质量检查（通过/待检查）；二、完整性、准确性、一致性检查结果与补救建议；三、待完善事项（高/中/低优先级）；四、常见缺陷自查；五、临时模式待确认事项；六、下一步（提交备案系统 / 补充材料后重新提交）。另按章节要求起草算法机制说明、训练数据说明、管理制度与方案、算法自评估报告
  • 算法备案后变更管理方案给客户内部 / 律师内部
    抬头列备案编号、企业、算法名称与类型；七部分：一、变更分类与处理（重大变更/一般变更/年度更新的类型、触发条件、流程、时限）；二、注销备案流程；三、定期合规自查计划（项目、内容、频次、方法、负责部门）；四、自查结果处理机制及升级条件；五、监管配合预案；六、法规跟踪计划；七、持续合规管理
  • 算法备案全流程报告给律师内部 / 客户
    完整流程运行时汇总上述四步产出；SKILL.md 未另行规定章节结构

04开始前

前置条件

  • 读取 ai-governance/CLAUDE.md 六项配置：执业角色与企业画像（行业、是否提供 AI 相关服务、AI 服务类型描述，驱动算法类型识别范围）、服务立场（算法备案，决定各步骤审查侧重）、监管关系（主动合规/被动应对）、合规严格度（保守/平衡/务实）、AI 合规风险校准（关键/高/中等/低四级）、升级矩阵（强制升级触发条件）
  • 配置文件不存在或关键字段含 [PLACEHOLDER] 时进入临时模式：输出顶部标 [临时模式 — 请运行冷启动访谈完成配置]，以合理默认值继续执行，所有依赖企业画像的判断标 [待确认 — 临时模式]，输出末尾列出「临时模式待确认事项」清单，提示完成冷启动访谈后重新运行
  • 每一步启动前加载 legal-basis-conventions.md（引用格式、来源标签、待验证标记规则）、ai-law-citations.md（§D.2 算法推荐管理规定为核心引用，另含关联法规与刑法罪名）与实践配置
  • 按用户需求分派到对应步骤之前，先完成五项护栏检查（行刑衔接、合规立场、备案时限、算法歧视、舆论属性）
  • 单独运行某一步须具备前序成果：备案要求分析须已有算法类型识别结果；材料准备须已有备案要求分析结果；变更管理须已有有效备案

硬性规则

行刑衔接升级
识别到算法服务违规可能升格刑事（侵犯公民个人信息、帮助信息网络犯罪活动、拒不履行信息网络安全管理义务等）时，立即强制升级执业律师，标 [强制升级 — 行刑衔接]，并提示与 criminal-compliance 插件衔接
AI 治理合规立场
绝不提供规避算法备案义务的方法，绝不提供虚假安全评估材料或伪造算法透明度方案，绝不提供绕过内容安全审查的方案；识别此类需求即拒绝，标 [合规边界 — 拒绝]
备案时限
涉及备案义务或整改期限时强标备案时限提示，不得静默放任时限流逝
算法歧视
算法价格歧视（大数据杀熟：对交易条件相同的消费者实施不合理差别定价）→ 明确提示违反算法推荐管理规定及消费者权益保护法 [待验证]，绝不提供规避方法；算法推荐歧视（基于地域、性别、消费习惯等用户特征实施不公平的个性化推送）→ 提示违反个人信息保护法自动化决策条款 [待验证]；就业、信贷等领域算法歧视 → 提示可能涉及多重法律责任 [待验证]
算法推荐影响舆论
识别到算法推荐服务具有舆论属性或社会动员能力时，提示须在备案前完成安全评估 [待验证]，并提示可能影响公共舆论的特殊合规义务与内容安全管理制度建设要求
核心合规风险提示
未通过算法备案系统完成备案 → 行政处罚、责令改正、罚款 [待验证]；算法歧视（如大数据杀熟）→ 行政处罚、民事赔偿、可能升格刑事 [待验证]；具有舆论属性或社会动员能力但未完成安全评估 → 行政处罚、责令暂停服务 [待验证]；未提供关闭算法推荐选项等侵害用户知情权、选择权 → 行政处罚、责令改正 [待验证]
路由规则
完整算法备案 → 按顺序执行四步并汇总为「算法备案全流程报告」；识别算法类型 → 仅第1步；分析备案要求 → 仅第2步（须已有类型识别结果）；准备备案材料 → 仅第3步（须已有备案要求分析结果）；备案后变更管理 → 仅第4步（须已有有效备案）
法律依据引用规范
AI 治理专项规章一律描述规则并标 [待验证 — AI 治理法规快速演进]，刑法相关罪名条号一律 [条号待验证]；各步骤的依据均附 [模型知识 — 需验证] 来源标签；不臆造任何规章文号或备案流程细节

05执行步骤

共 4 步，按执行顺序。每步旁边（窄屏在步骤说明之后）是请律师核对的内置假设，可逐条复制。页面里的英文标记见首页「标记与术语」。

  1. 算法类型识别与分类

    /ai-governance:algorithm-type-identification可单独运行

    判断企业当前或计划提供的服务是否构成算法推荐服务，按五类逐一归类，初步判断备案义务，识别深度合成、生成式 AI 等交叉义务与算法歧视、大数据杀熟、舆论属性等特殊风险，输出「AI 服务—算法类型—备案义务」映射表。

    请律师核对

    • 核对 1.1决策树按「主要用途」归入单一类型，同时要求多算法系统逐一列示——一个功能兼有推送与排序时如何归类，是否需要贵所明确口径？
    • 核对 1.2「仅内部使用的算法可能不适用备案」「测试阶段可能已有备案义务」均标 [待验证]，请按贵所对「向用户提供互联网信息服务」的理解确认边界
    • 核对 1.3第三方算法、平台内商家自设算法、API 间接提供、技术支持方四种情形的备案义务分配都只写「须具体分析」，是否需要给出默认立场？
    • 核对 1.4《电子商务法》的个性化推荐规范被概括为「搜索结果须同时展示竞价排名与非竞价排名」[待验证]，请核对这一概括是否准确

    做法

    1. 读取实践配置中的「所属行业」「是否提供AI相关服务」「AI服务类型描述」，加载法律依据引用规范与引用库 §D.2 算法推荐管理规定
    2. 对照算法推荐服务定义（利用生成合成类、个性化推送类、排序精选类、检索过滤类等算法技术向用户提供信息服务），逐项判断五个识别要素：技术基础（是否利用算法技术处理信息）、算法类型、服务性质（是否向用户提供互联网信息服务）、用户规模（是否达到备案门槛，须核实具体门槛 [待验证]）、舆论属性（是/否/待评估），得出属于/不属于/待进一步评估的结论
    3. 按五类分类表逐类对照定义、典型场景、典型行业与监管要点：生成合成类（文本生成、图像生成、语音合成、视频生成、虚拟数字人）、个性化推送类（信息流推荐、商品推荐、内容推荐、广告定向推送、短视频推荐）、排序精选类（搜索结果排序、内容排序、热搜榜单、推荐列表、排行榜）、检索过滤类（信息检索、内容过滤、关键词审核、敏感词过滤、信息分类）、调度决策类（网约车派单、外卖配送调度、动态定价、资源调度、信用评估）
    4. 走分类决策树：不利用算法向用户提供互联网信息服务 → 不适用算法推荐管理规定并退出；否则按算法主要用途归类并做附加判断——生成合成类涉及深度合成 → 交叉触发深度合成备案，向公众提供生成式AI服务 → 交叉触发生成式AI备案；个性化推送类涉及商品/服务定价 → 排查大数据杀熟；排序精选类涉及热搜、榜单 → 关注舆论属性评估；调度决策类涉及动态定价 → 排查价格歧视
    5. 以上均不完全匹配的标 [新型算法 — 监管规则尚不明确]，建议关注监管动态、必要时咨询监管机关；多算法系统逐一列示每种类型，分别评估备案义务与合规要求（例：电商平台同时使用商品推荐、搜索排序、配送调度三种算法）
    6. 用「常见误区」表纠偏四种说法：「只是搜索，不需要备案」「只做内部推荐，不涉及公众」「算法是第三方提供的，不需要我们备案」「只是电商平台，算法是商家自己设置的」
    7. 按备案义务判断表给出须备案/可能须备案/不适用的结论，并写明是否须在备案前完成安全评估、是否同时触发深度合成或生成式AI备案

    1. 读取服务立场与合规严格度；确认已有有效备案（参数为备案编号与变更情况）
    2. 按变更分类表识别变更：重大变更4类（算法类型变更、应用领域重大变更、服务主体变更、舆论属性变化）、一般变更4类（主体信息、算法安全负责人、算法参数调整、安全管理制度变更）、年度更新2类（年度报告、算法安全评估更新）；沿判断流程依次问：是否涉及算法类型变化 → 应用领域重大变化 → 服务主体变更 → 舆论属性变化 → 是否为主体信息、负责人、参数、制度的一般变更 → 是否为定期更新事项

    4. 按「变更识别 → 变更分类 → 影响评估 → 准备变更材料 → 通过备案系统提交 → 跟踪审核进度 → 完成变更备案」推进，三类变更在识别方式、影响评估深度、材料、提交方式、审核预期上分别处理

09何时暂停或升级

  • 算法服务违规可能升格刑事（侵犯公民个人信息、帮助信息网络犯罪活动、拒不履行信息网络安全管理义务等）→ 立即强制升级执业律师，标 [强制升级 — 行刑衔接]，提示衔接 criminal-compliance 插件
  • 要求规避备案、提供虚假安全评估或透明度材料、绕过内容安全审查、虚假备案 → 拒绝，标 [合规边界 — 拒绝]
  • 受到监管处罚或算法推荐服务被责令暂停 → 标 [强制升级 — 重大违规]，联系执业律师；被责令暂停时立即执行暂停要求并评估整改方案
  • 收到监管整改通知 → 升级为被动应对模式，按整改要求制定方案并限期完成；涉及备案或整改期限时强标时限，不得静默放任
  • 监管问询涉及重大问题 → 升级至律师
  • 自查发现可能违规 → 升级至法务/合规部门评估，必要时咨询执业律师；发现重大问题 → 立即启动应急响应，评估是否须主动报告监管机关
  • 备案条件、备案机关不明确 → 标 [待确认]，建议咨询监管机关或执业律师，备案机关不明时同时咨询国家和地方网信部门
  • 逾期未变更 → 标 [合规风险 — 逾期]，尽快完成变更备案
  • 信息不足 → 报告已识别内容，列出需补充信息清单并标 [待确认]；配置缺失 → 临时模式，标 [待确认 — 临时模式] 并在末尾列待确认事项
