01概要

帮助拟上线或已上线生成式 AI 服务的企业及其 AI 合规律师、合规官、法务，按《生成式人工智能服务管理暂行办法》等规定完成四件事：判断服务是否落入暂行办法、是否须备案及有无交叉义务；审查训练数据来源合法性与知识产权、个人信息、内容、重要数据风险并给出整改建议；设计禁止内容识别、四层审核、生成内容标识、风险监测、违规处置、应急响应与事件报告机制；搭建用户协议、知情权与选择权、投诉举报、未成年人保护和用户权利机制，并准备备案材料、开展上线前安全评估、跟进备案提交与备案后管理。四个步骤可顺序全流程运行，也可单独触发任一步，每步产出一份带审查者注的报告或方案。开始前读取 ai-governance/CLAUDE.md 中的企业画像、服务立场、监管关系、合规严格度、AI 合规风险校准与升级矩阵，配置缺失或含占位符时进入临时模式，只出初步分析、不出最终合规结论。法律依据取自本插件的 AI 治理法律引用库（以 §D.3 生成式 AI 暂行办法为核心）并按引用规范标来源标签；暂行办法一律只描述规则、不写文号和条款编号，标 [待验证 — AI 治理法规快速演进，须核实现行版本]，刑法罪名条号一律标 [条号待验证]。

02适用与边界

适用场景

  • 企业计划上线或已上线生成式 AI 服务（AI 对话、AI 写作、AI 翻译、AI 绘图、语音合成、声音克隆、AI 视频、虚拟数字人、代码生成、多模态），需要判断是否落入暂行办法适用范围、是否须备案
  • 服务形态是面向企业客户的 API、B2B2C、ToG、仅内部使用、公测/内测或邀请制测试，需要判断是否构成「向公众提供」
  • 模型为自研、开源模型微调或调用第三方/境外 API，需要审查训练数据（公开数据集、网络爬取、授权数据、用户生成内容、自有数据、合成数据）的来源合法性
  • 需要为文本、图像、音频、视频或代码生成服务设计内容审核、生成内容标识、风险监测、违规处置、应急响应与监管报告机制
  • 需要起草或核对生成式 AI 用户协议与隐私政策，建立投诉举报和未成年人保护机制，准备备案材料并开展上线前安全评估
  • 需要识别是否同时触发深度合成备案、算法备案、数据出境安全评估、网络安全等级保护或关键信息基础设施保护义务
  • 通过 API 调用境外大语言模型，需要评估用户输入出境与境外模型返回内容的内容安全风险
  • 已被监管机关通知整改（监管关系为被动应对），需要在整改期限内补齐合规

不做什么

  • 不提供规避备案、伪造评估、绕过内容安全审查、隐匿训练数据侵权事实或虚假备案的方法；识别到此类需求即拒绝，标 [合规边界 — 拒绝]
  • 不替代刑事辩护：AI 服务违规可能升格刑事时强制升级执业律师，并提示与 criminal-compliance 插件衔接
  • 不直接办理深度合成备案和算法备案：识别到交叉义务时转 /ai-governance:deep-synthesis-filing、/ai-governance:algorithm-filing
  • 不处理数据出境安全评估、网络安全等级保护、关键信息基础设施保护的具体工作，转 data-compliance 插件
  • 不写暂行办法的文号与具体条款编号，不臆造规章文号或备案流程细节；备案系统操作与材料清单以备案系统要求为准 [待验证]
  • 临时模式（实践配置缺失或含 [PLACEHOLDER]）下不输出最终合规结论，只出初步分析供参考
  • 各步骤只处理本步范围：服务识别不做训练数据审查和内容安全机制建设；训练数据步骤不做内容安全机制和用户保护；内容安全步骤不做训练数据审查和备案管理；用户保护与备案步骤不做训练数据审查和内容安全机制建设

03输入与产出

需要律师提供

  • 生成式 AI 服务描述：服务形态、内容生成类型（文本/图像/音频/视频/代码/多模态）、是否已上线及计划上线日期必需
    驱动服务类型识别与备案紧迫性判断；备案时限护栏据上线日期倒推备案准备时间。单独触发服务识别步骤时参数为「[生成式AI服务描述] [业务模式]」
  • 服务对象与业务模式：ToC / ToB / ToG / 仅内部使用，是否 B2B2C，是否公测、内测或邀请制测试必需
    驱动备案义务是否触发与「向公众提供」的认定
  • 模型来源与技术架构：自研 / 开源模型微调 / 调用第三方 API / 混合，是否使用境外模型必需
    驱动训练数据审查范围与深度，以及数据出境和境外大语言模型风险判断
  • ai-governance/CLAUDE.md 实践配置：执业角色与企业画像、服务立场、监管关系、合规严格度、AI 合规风险校准、升级矩阵可选
    不存在或关键字段含 [PLACEHOLDER] 时进入临时模式，建议运行 /ai-governance:cold-start-interview 完成配置后重新运行
  • 训练数据概况：来源及各类占比、类型、规模、清洗/标注/去重/脱敏/过滤流程、跨境情况、存储可选
    训练数据步骤参数为「[训练数据概况] [数据来源]」；来源不明确时标 [数据来源不明 — 合规风险高]
  • 数据授权文件：数据集许可与使用条款、授权协议及授权链条、含训练授权条款的用户协议、开源模型许可与训练数据清单（data sheet）可选
    用于来源合法性与知识产权审查；数据提供方声称已脱敏的，须独立验证脱敏效果
  • 现有内容安全机制：审核规则与敏感词库、标识做法、监测与应急预案、人工审核团队可选
    内容安全步骤参数为「[生成式AI服务类型] [现有安全机制]」
  • 现有用户协议、隐私政策、投诉渠道、未成年人保护措施与备案状态可选
    用户保护与备案步骤参数为「[生成式AI服务类型] [备案状态]」
  • 已有合规基础：是否已完成算法备案、深度合成备案、安全评估可选
    驱动合规差距分析
  • 监管通知、整改通知或处罚决定及其送达日期可选
    已被通知整改时驱动合规严格度与时限紧迫性；未备案且已被通知整改或处罚属强制升级情形

    抬头载企业/组织、服务类型、分析日期、执业角色与审查者注；八部分：用户协议条款核对、用户保护（知情权/选择权/投诉权/撤回同意权/注销权）、投诉举报机制、未成年人保护、用户权利实现、备案情况（材料准备/安全评估/律师审核/备案提交/备案结果）、风险标记、下一步建议

04开始前

前置条件

  • 明确七项事项上下文：企业 AI 服务现状（是否已上线、计划上线时间、服务形态 → 服务类型识别与备案紧迫性）、模型来源（自研/开源微调/第三方 API → 训练数据审查范围与深度）、服务对象（ToC/ToB/内部 → 备案义务是否触发）、内容生成类型（文本/图像/音频/视频/多模态 → 内容安全机制设计）、是否涉外（境外模型、数据出境 → 出境安全评估与境外大语言模型风险）、已有合规基础（算法备案、深度合成备案、安全评估 → 合规差距分析）、监管关系（主动合规/已被监管通知整改 → 合规严格度与时限紧迫性）
  • 启动任何步骤前读取 ai-governance/CLAUDE.md 六项配置：执业角色与企业画像（行业、是否提供 AI 相关服务、AI 服务类型描述 → 服务识别范围）、服务立场（生成式 AI 合规 → 各步骤审查侧重）、监管关系（主动合规/被动应对）、合规严格度（保守/平衡/务实）、AI 合规风险校准、升级矩阵（强制升级触发条件）
  • AI 合规风险校准的典型触发情形（来自实践配置）：红级——未备案且已被监管机关通知整改，涉及侵犯公民个人信息、帮助信息网络犯罪活动等刑事风险，被责令下架或关停服务；橙级——应当备案而未备案，训练数据来源合法性存疑，内容安全机制缺失；黄级——备案信息未及时更新，AI 使用案例分类未完成，合规自查未开展；绿级——已完成备案且信息准确，训练数据合规审查已完成，内容安全机制运行有效
  • 临时模式：实践配置不存在或关键字段含 [PLACEHOLDER] 时，标 [临时模式 — 请运行冷启动访谈完成配置]，以默认保守参数运行，在输出中提示企业画像未完成配置、当前分析基于临时假设、建议完成冷启动访谈后重新运行；不得输出最终合规结论，只出初步分析供参考
  • 加载共享资源：ai-governance/skills/_shared/legal-basis-conventions.md（引用格式、来源标签、待验证标记）与 ai-governance/skills/_shared/ai-law-citations.md（§D.3 生成式 AI 暂行办法为核心；训练数据步骤另读 §B 数据安全法、§C 个人信息保护法，用户保护与备案步骤另读 §C）
  • 步骤间前提：训练数据步骤以服务类型识别已完成为前提；内容安全步骤以服务识别与训练数据评估已完成为前提；用户保护与备案步骤以前三步均已完成为前提
  • 单独触发某一步时，该步自行读取实践配置中的相应字段：服务识别读「所属行业」「是否提供AI相关服务」「AI服务类型描述」「业务模式」；训练数据读「所属行业」「AI服务类型描述」「模型来源」；内容安全读「所属行业」「AI服务类型描述」「内容生成类型」；用户保护与备案读「执业角色」「企业画像」「已完成备案情况」

硬性规则

行刑衔接升级
识别到 AI 服务违规可能升格刑事时，立即强制升级执业律师，标 [强制升级 — 行刑衔接]，并提示与 criminal-compliance 插件衔接；典型情形为侵犯公民个人信息罪、帮助信息网络犯罪活动罪、拒不履行信息网络安全管理义务罪，罪名条号一律标 [条号待验证]，绝不臆造
AI 治理合规立场
绝不提供规避备案、伪造评估、绕过内容安全审查的方法，绝不提供隐匿训练数据侵权事实的操作；识别到此类需求即拒绝，标 [合规边界 — 拒绝]
备案时限
涉及备案义务或整改期限时强标备案时限提示；识别服务上线日期，倒推备案准备时间；不得静默放任时限流逝
训练数据著作权侵权风险提示
须提示：训练数据中使用他人作品可能构成著作权侵权，须评估是否属于合理使用或已取得授权；中国司法实践中已出现涉及 AI 训练数据的著作权纠纷案例 [待验证]；服务提供者对训练数据合法性承担举证责任 [待验证]
生成禁止内容风险提示
须提示：暂行办法明确列举了不得生成的内容类别（危害国家安全、煽动颠覆政权、宣扬恐怖主义、淫秽色情、虚假有害信息等）[待验证 — AI 治理法规快速演进]；服务提供者对生成内容承担内容安全主体责任 [待验证]；生成违法内容可能同时触发行政处罚与刑事追诉
深度合成相关刑事风险提示
涉及图像、音频、视频生成时须提示：利用深度合成技术实施诈骗、侵犯肖像权、制作虚假信息等可能构成刑事犯罪 [待验证]；未添加深度合成标识可能导致行政处罚 [待验证 — AI 治理法规快速演进]；须评估是否同时触发深度合成备案义务
境外大语言模型数据出境风险提示
通过 API 调用境外模型服务时须提示：用户输入可能包含个人信息或重要数据，传输至境外模型服务器构成数据出境 [待验证]；须满足个人信息保护法、数据安全法的跨境传输要求 [待验证]；须评估是否须进行数据出境安全评估 [待验证]；境外模型生成的内容返回境内，仍须满足中国内容安全要求 [待验证]
暂行办法引用纪律
一律描述规则并标 [待验证 — AI 治理法规快速演进，须核实现行版本]，不硬写文号与具体条款编号；七项核心义务均标 [待验证]：服务提供者承担内容安全主体责任；训练数据不得侵犯知识产权、不得含有违法不良信息；按规定对生成内容添加标识；建立投诉举报机制、及时处理用户投诉；向公众提供须依法备案；服务上线前开展安全评估；涉及个人信息处理时遵守个人信息保护法
来源标签
每条引用须附来源标签：[模型知识 — 需验证] / [法宝] / [法规网站] / [网络搜索 — 需验证] / [用户提供]；四个步骤列出的法律依据目前均标 [模型知识 — 需验证]
工作产物定性
律师角色的输出标「律师工作产物 — 受律师-当事人特权保护 / 保密」；合规官、法务、当事人本人的输出标「研究笔记 — 合规研究与初步分析，非法律建议，供律师审查」；各步骤检查清单均要求向非律师角色提示须律师审核

05执行步骤

    请律师核对

    • 核对 2.4影响评估的触发情形只列四项（敏感个人信息、自动化决策、对外提供/公开/向境外提供、其他重大影响）——是否完整？

    做法

    1. 读取实践配置「所属行业」「AI服务类型描述」「模型来源」，读取引用规范与引用库 §D.3、§B 数据安全法、§C 个人信息保护法；以服务类型识别已完成为前提；单独触发时参数为「[训练数据概况] [数据来源]」
    2. 按七个维度梳理训练数据概况：来源（公开数据集、自有数据、授权数据、网络爬取数据、用户生成内容、合成数据，须逐一列明各类来源占比）、类型（文本、图像、音频、视频、代码、个人信息、地理信息）、规模（GB/TB/PB、样本数量，规模影响风险评估等级）、处理（清洗、标注、去重、脱敏、过滤）、跨境（是否跨境、数据来源国/地区，触发数据出境安全评估）、存储（位置、期限、访问控制）、模型来源（自研/开源微调/第三方 API，决定审查范围）
    3. 按来源逐类审查合法性：公开数据集看发布者与使用条款、许可是否允许用于 AI 训练（商业/非商业）、合规声明、是否存在已知合规问题；网络爬取看是否违反目标网站 robots.txt 与服务条款、著作权与合理使用、个人信息、反不正当竞争、是否规避技术保护措施；授权数据看授权范围是否明确涵盖 AI 训练、授权期限、转授权、授权链条是否完整；用户生成内容看用户协议是否含 AI 训练授权条款、用户是否被告知、撤回机制、是否含违法不良信息或他人个人信息；自有数据看产生过程是否合法、员工数据是否取得同意、客户数据使用是否超出原始收集目的
    4. 做知识产权审查七项（著作权、合理使用、授权使用或法定例外、开源协议如 GPL/Apache/MIT、数据库权利、商标权、专利权），并输出著作权侵权风险特别提示
    5. 做个人信息审查：识别个人信息（姓名、身份证号、手机号、生物识别、行踪轨迹等）与敏感个人信息（生物识别、宗教信仰、特定身份、医疗健康、金融账户、行踪轨迹、14岁以下未成年人信息）及涉及的主体数量；按六项合法性基础逐项判断在训练场景的适用性
    6. 对训练后用于自动化决策的情形检查《个人信息保护法》第24条三项要求，对照第55-56条判断是否须事前开展个人信息保护影响评估及评估内容
    7. 区分匿名化（不可复原）与去标识化（需额外信息方可识别），评估模型记忆、成员推断攻击等再识别风险；检查跨境传输是否通过安全评估/专业机构认证/标准合同等合法路径并取得单独同意
    8. 做内容合规审查七项（违法不良信息、淫秽色情、暴力恐怖、虚假有害信息、歧视性内容、侵权内容、数据清洗措施）与重要数据和国家安全审查五项（按国家数据分类分级保护制度识别重要数据、国家安全影响、重要数据出境限制、国家核心数据、涉密地理信息数据）
    9. 做特殊场景审查：境外数据来源（是否符合来源国/地区法律如 GDPR、数据入境要求、出口管制与制裁名单）、开源模型训练数据（许可是否允许再训练/微调、是否披露数据清单 data sheet、微调模型是否继承基础模型的合规风险）、合成数据（原始模型训练数据是否合法、是否模拟真实个人信息及再识别风险）
    10. 按六类风险输出分级整改建议（著作权、个人信息、违法不良信息、重要数据、数据跨境、开源协议），附优先级与时限说明
    11. 处理边界情形：来源不明确标 [数据来源不明 — 合规风险高] 并建议清理或补充合法性证明；大规模个人信息重点审查合法性基础，可能须补充同意、开展影响评估；开源模型训练数据不透明标 [开源模型训练数据不透明 — 继承风险] 并建议独立评估微调数据；多语言/多法域数据评估 GDPR、CCPA 等来源地法律；数据提供方声称已脱敏的，须独立验证脱敏效果并评估再识别风险
    12. 按十一项检查清单自查（所有审查结论标 [待验证]、非律师角色已提示须律师审核）后出具评估报告，下一步建议衔接内容安全机制建设

    内置规则

    3. 设计第一层模型层面安全：训练数据清洗（从源头减少模型学习违法内容）、RLHF 等对齐训练（使模型学会拒绝生成违法内容）、安全微调（增强对特定风险类别的识别与拒绝）、安全系统提示（在系统层面设置安全约束）
    4. 设计第二层输入审核与第三层输出审核：输入端用持续更新的敏感词库做关键词过滤、用分类模型识别越狱攻击等恶意意图、分析多轮对话上下文识别逐步引导、监控异常输入频率识别自动化攻击或批量恶意请求；输出端在返回用户前用内容安全分类模型自动审核、做敏感词匹配、对生成内容做风险分级（高风险触发人工审核）、检测与已知违法内容的相似度
    5. 设计第四层人工审核：用户举报复核、高风险类别定期抽审（评估自动审核准确率与漏检率）、边界案例研判并建立边界案例库、人工审核结果质量检查
    6. 设计内容标识：显式标识按文本、图像、音频、视频给出措辞与位置；隐式标识用元数据（EXIF、XMP 等）、不可见数字水印（图像、视频、音频，用于溯源与鉴定）、内容指纹；涉及深度合成时另满足深度合成管理规定的标识要求
    7. 规划风险监测六个维度（内容违规、用户行为、模型安全、内容传播、趋势分析、审核效能），分别配监测频次与告警条件
    8. 建立违规处置：内容处置五档（拦截、过滤、替换、标注、删除）、用户处置五档（提示警告、限制功能、暂停服务、封禁账号、保存证据），并规定四类记录的保存内容与期限
    9. 制定应急响应预案：事件分 I/II/III 三级并配响应时间与响应层级；按事件发现 → 紧急处置 → 上报决策 → 根因分析 → 修复整改 → 复盘总结六个阶段明确责任主体（安全运营团队、技术团队、合规/法务团队、全团队）
    10. 设计人工审核机制（团队规模、人员资质、统一审核标准与操作手册、轮班制度；任务分配、内容研判、处置执行、结果记录、质量复核五个环节）与内容安全事件报告机制（向网信办等监管机关报告的三种情形与内部逐级报告）
    11. 处理边界情形：新型内容风险标 [新型风险 — 须持续监测] 并建议建立风险快速识别机制；审核能力不足建议引入第三方安全评估机构、增加审核团队投入；多语言内容建立多语言审核能力并配置相应语言审核人员；实时性要求极高时在审核效率与精度之间平衡并建立快速审核通道；越狱攻击建立持续安全对抗机制、定期红队测试、更新安全策略
    12. 按十一项检查清单自查后出具建设方案，下一步建议衔接用户保护与备案管理

    内置规则

    • 风险矩阵（文本 / 图像 / 音频 / 视频 / 代码）：危害国家安全 高/中/中/高/低；宣扬恐怖、极端 高/高/中/高/低；淫秽色情 中/极高/中/极高/低；虚假信息 极高/高/高/极高/中；侵犯名誉/隐私 高/高/中/高/低；侵犯知识产权 高/极高/高/极高/高；歧视性内容 高/中/中/中/低。极高=该服务类型的主要风险场景，须重点防控；高=常见风险场景；中=可能出现的风险场景；低=较少出现但须关注
    • 显式标识：文本在生成内容显著位置标注「本内容由AI生成」；图像在显著位置添加「AI生成图像」水印或角标；音频在开头或结尾以语音提示「本内容由AI生成」；视频在显著位置持续展示「本视频包含AI生成内容」字幕或角标

    • 监测频次与告警：内容违规、用户行为、模型安全为实时（单次/累计超阈值告警、异常行为模式告警、攻击尝试即时告警）；内容传播每小时（传播范围超阈值告警）；趋势分析每周/每月（趋势异常告警）；审核效能（准确率、漏检率、误检率）每日/每周（效能下降告警）
    • 处置阶梯：实时检测到违规 → 返回前拦截；部分违规 → 过滤违规部分、保留合规部分；有风险但可直接替换 → 用安全内容替换；有争议或需提示 → 添加风险提示标注；已发布 → 从平台删除。用户首次轻微违规 → 提示警告；多次或中度违规 → 限制特定功能（如图像生成）；严重或累计多次违规 → 暂停服务；极端违规或恶意攻击 → 永久封禁账号；涉嫌违法的严重违规 → 保存违规记录与证据
    • 记录保存：违规内容记录（原文、生成时间、用户信息）、处置记录（措施、时间、人员）、用户举报记录（举报内容、处理结果、反馈信息）、审核日志（操作、结果、人员）均不少于6个月 [待验证]
    • 应急分级：I 级（特别重大：大规模违法内容生成并传播、被监管机关通报、引发重大舆情）立即（30分钟内）响应，公司级并报告监管机关；II 级（重大：较大范围违法内容生成、模型被大规模攻击、被用户大量举报）2小时内，部门级并评估报告义务；III 级（一般：个别违规内容生成、单点安全事件）24小时内，团队级常规处置。I 级须立即暂停相关功能、拦截违法内容、保存证据，并立即报告管理层与监管机关 [待验证]
    • 人工审核：人员具备法律、内容安全、AI 技术相关知识，定期培训、考核上岗；确保 7×24 小时审核覆盖（如适用）；内容研判 I 级事件30分钟内、一般事件24小时内；审核完成后立即执行处置并即时记录；质量复核每周不低于5%抽样
    • 事件报告：发现严重违法内容 → 发现后立即报网信办等监管机关 [待验证]（违法内容描述、影响范围、已采取措施）；被监管机关通报 → 按要求时限向通报机关报整改方案、进度、结果；发生内容安全事件 → 事件发现后 [待验证] 报事件描述、影响评估、处置措施、后续防控。内部报告：I 级30分钟内报公司管理层、法务、合规；II 级2小时内报部门负责人、合规；III 级24小时内报团队负责人；监管通报或约谈收到后立即报公司管理层、法务、合规

  • 出现大规模违规内容 → 标 [强制升级 — 重大违规]，立即启动应急预案；被监管机关通报或处罚 → 标 [强制升级 — 重大违规]，立即响应整改
  • 实践配置升级矩阵的强制升级触发条件（凌驾于服务立场与合规严格度之上）：被责令下架、关停服务；未备案且已被通知整改或处罚；行刑衔接风险；AI 服务导致用户人身、财产、隐私重大损害；责任人可能被采取刑事强制措施
  • 升级矩阵角色权限：当事人本人（无律师）在全部实质性法律行动前须找律师；企业合规官/法务在备案材料定稿提交前（须律师审核）、安全评估报告定稿、监管通知应对、重大违规或行刑衔接时须升级；助理律师在备案材料与安全评估报告定稿、重大违规或行刑衔接决策时须升级；主办 AI 合规律师遇行刑衔接须合伙人或刑事律师确认
  • 规避备案、伪造评估、绕过内容安全审查、隐匿侵权数据或虚假备案需求 → 拒绝并标 [合规边界 — 拒绝]
