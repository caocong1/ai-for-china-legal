01概要

帮团队在技能注册表（本地 / 组织内部 / 公共社区）里找到适合自己法律工作的技能：先按法律领域、能力类型、安全等级、许可证、兼容性五个维度构建筛选条件，再做关键词搜索或分类浏览，按安全评级、功能匹配度、社区评分、更新活跃度加权排序，最后查看候选技能的功能、安全审查、兼容性、社区评价和版本历史，给出四选一的安装建议。流程顺序为「分类·标签·筛选 → 搜索与浏览 → 推荐与排序 → 详情与评价」，也可从任一步开始，四步各可单独触发，均只产出列表或详情、不执行安装。默认筛选条件和排序权重取自 legal-builder-hub/CLAUDE.md 中的关注领域、能力类型、排序偏好、是否接受未审查技能和整体偏好；每个结果都标许可证和安全状态——绿级（已审查通过）、黄级（有条件通过）、红级（未通过）或「未审查」（原文以白色圆点标示）——未配置或配置为「仅展示已审查技能」时，未审查技能直接过滤。推荐算法须向用户公开排序维度与权重并允许调整，原文以《个人信息保护法》第24条（自动化决策透明度）为依据。

02适用与边界

适用场景

  • 需要某类法律工作的现成技能，如数据合规领域的文书审查、法规检索、案例分析
  • 已有几个候选技能，想比较安全审查状态、许可证、兼容性和社区评价后决定装哪个
  • 想按安全评级或社区评分重新排序，或基于已安装技能找相似 / 互补的技能
  • 安装前确认某个技能是否已审查、审查的是哪个版本、报告是否过期

不做什么

  • 不执行安装或修改操作：选定后转安装向导（/legal-builder-hub:installation），未审查的转安全审查（/legal-builder-hub:security-review），注册表信息转 /legal-builder-hub:skill-registry
  • 不做安全审查本身，只展示已有的审查状态、级别和发现数量
  • 不收集或分析用户的具体法律案件内容；搜索记录只存本地，不上报注册表或第三方
  • 不保证第三方技能的质量或安全性，不替代用户对技能适用性的独立判断（README）

03输入与产出

需要律师提供

  • 需求描述或关键词（如：合同审查 / 法规检索 / 案例分析 / 合规检查）必需
    也可直接给出筛选条件、技能名称或搜索结果编号，从任一步开始
  • 可连接的技能注册表及其分类标签体系必需
    注册表类型取自配置（本地 / 组织 / 公共）；不可达时回退到本地缓存
  • legal-builder-hub/CLAUDE.md 的发现偏好与整体偏好可选
    关注的法律领域、关注的能力类型、推荐排序偏好、是否接受未审查技能、整体技能管理偏好、用户角色；缺失或含占位符时走临时模式
  • 已安装或已评估的技能清单可选
    相似推荐模式使用

产出

  • 筛选条件表给团队内部
    构建日期；法律领域 / 能力类型 / 安全等级（最低可接受）/ 许可证 / 兼容性五维条件及各维匹配数；组合筛选结果数；下一步（执行搜索 / 调整筛选 / 清除筛选）
  • 搜索结果列表给团队内部
    搜索条件、注册表（类型与地址）、匹配数量、过滤规则；结果表（编号、技能名称、版本、安全状态、许可证、兼容性）；每条结果另列描述、法律领域与能力类型标签、来源（社区贡献 / 官方 / 组织内部）、独立命令；下一步（查看详情 / 调整筛选 / 直接安装）
  • 推荐列表给团队内部
    排序策略与推荐模式；精选推荐表（排名、名称、版本、综合评分、安全状态、推荐理由）；逐项说明功能匹配度、安全评级、社区口碑；可选的排序调整与下一步
  • 技能详情与决策建议给团队内部
    基本信息、功能说明、安全审查状态（含各级发现数量）、兼容性、社区评价、版本历史六个区块；结论四选一：建议安装 / 建议修复后安装 / 不建议安装 / 须先安全审查；下一步（安装 / 安全审查 / 返回搜索 / 返回列表）

04开始前

前置条件

  • 读取 legal-builder-hub/CLAUDE.md：关注的法律领域、关注的能力类型、推荐排序偏好、是否接受未审查技能、整体技能管理偏好、用户角色
  • 配置缺失或含 PLACEHOLDER 时进入临时模式并标 [临时模式]：推荐按综合评分排序、不预设领域偏好；默认仅展示已审查通过的技能；建议运行 /legal-builder-hub:cold-start-interview 完善配置
  • 连接注册表、确定注册表类型（本地 / 组织 / 公共），读取注册表当前可用的分类标签

硬性规则

安全优先
未经安全审查的技能须明确标注状态：搜索结果中标 [未审查 — 安装前须完成安全审查]；用户配置为「仅展示已审查技能」时从结果中过滤；推荐结果标注每个技能的安全审查状态和等级
数据合规
搜索和推荐不收集或分析用户的具体法律案件内容；推荐算法不依赖用户个人信息的画像分析（原文称符合 PIPL 最小必要原则）；搜索记录仅保存在本地，不上报至注册表或第三方
知识产权提示
搜索结果须展示每个技能的许可证类型；不同许可证对使用场景有不同限制（如 GPL 要求衍生作品同样开源）；技能描述和文档的著作权归属原开发者
自动化决策透明度
依据《个人信息保护法》（2021年）第24条（已核实锚点，建议复核）：向用户说明排序维度和权重；用户可调整排序偏好；不使用用户个人信息进行不透明的画像分析；推荐结果不因用户身份而产生不合理的差异
只读不安装
四步分别只产出筛选条件、搜索结果、推荐列表和技能详情，不执行安装或修改操作；「安装」下一步只对审查通过的技能提供

05执行步骤

共 4 步，按执行顺序。每步旁边（窄屏在步骤说明之后）是请律师核对的内置假设，可逐条复制。页面里的英文标记见首页「标记与术语」。

  1. 分类·标签·筛选

    /legal-builder-hub:category-tag-filtering可单独运行

    根据需求和用户画像，在法律领域、能力类型、安全等级、许可证、兼容性五个维度上构建组合筛选条件，交给搜索步骤执行。

    请律师核对

    • 核对 1.1许可证表把五类许可证各压缩成一句（如 GPL「衍生作品须同样开源」、LGPL「链接使用可不开源」），「自定义」只写「须逐案审查」——作为筛选依据是否足够？贵方是否有需要写入的许可证使用口径？
    • 核对 1.2SKILL.md 只规定了保守型（默认只看已审查通过）和进取型（默认包含未审查）的默认安全等级，平衡型的默认值未规定。
    • 核对 1.3绿级定义为「通过完整安全审查」，但推荐步骤把「标准审查通过」也列为绿级（安全评分 × 0.9）——绿级是否包含标准审查通过，两处口径不一。

    做法

    1. 读取 CLAUDE.md 的关注法律领域、关注能力类型、是否接受未审查技能；读取注册表当前可用的分类标签。
    2. 按用户画像预填默认条件：关注领域和能力类型自动勾选；「是否接受未审查技能」控制安全等级条件；保守型偏好默认安全等级为绿级「已审查通过」，进取型默认包含「未审查」。
    3. 请用户选择维度（可多选）：法律领域（一个或多个）、能力类型（一个或多个）、安全等级（选最低可接受等级）、许可证（选可接受的许可证）、兼容性要求。
    4. 逐维列出条件和匹配技能数，并给出组合筛选结果数。
    5. 调整：结果过多时建议增加维度或缩小范围；结果过少时建议放宽某些条件；结果为空时显示各维度的匹配数量，帮助用户调整。
    6. 用户无法确定条件时，按用户画像智能推荐默认筛选；分类标签中没有用户需要的值时，记录需求标签并建议向注册表提交新分类标签。
    7. 确认后输出筛选条件表，传给搜索与浏览步骤执行。

    内置规则

    • 法律领域十二个一级分类（括号内为二级示例）：商事合同（买卖合同、技术服务合同、租赁合同、特许经营合同）、诉讼仲裁（民事诉讼、商事仲裁、行政复议、执行）、劳动人事（劳动合同、竞业限制、裁员方案、劳动争议）、数据合规（个人信息保护、数据出境、网络安全等保、数据安全）、知识产权（商标、专利、著作权、不正当竞争）、监管合规（行业监管、行政处罚、合规体系建设）、AI 治理（算法备案、深度合成、生成式 AI 合规）、建设工程（施工合同、工程结算、工期索赔、质量保修）、婚姻家事（离婚协议、遗嘱、继承、婚前财产协议）、刑事合规（企业刑事风险、合规不起诉、单位犯罪预防）、法考培训（客观题训练、主观题写作、案例研习）、法律援助（案件 intake、法律咨询、案件转介）
    • 能力类型八类：文书审查（如合同审查）、文书起草（如合同、协议、诉状起草）、法规检索（法条查询、案例检索）、案例分析（案例比对、裁判分析）、合规检查（PIA 生成、等保检查）、期限管理（诉讼时效、履约期限）、风险评估（合规风险、诉讼风险）、培训训练（法考刷题、写作练习）
    • 安全等级四档（原文以绿、黄、红、白色圆点标示）：绿级「已审查通过」——通过完整安全审查、无重大发现，可安全安装；黄级「有条件通过」——存在中等风险，修复后可安装，须确认修复情况；红级「未通过」——存在高 / 关键风险，不建议安装；「未审查」——尚未审查，安装前须审查
    • 许可证五类：MIT（最宽松，几乎无限制，适合所有场景）；Apache 2.0（宽松，含专利授权，所有场景含商业用途）；GPL（衍生作品须同样开源，适合开源项目）；LGPL（链接使用可不开源，适合库类技能）；自定义（须查看具体条款，逐案审查）
    • 兼容性三档：兼容当前平台 / 需确认（与部分环境配置存在兼容性风险）/ 不兼容
    • 本步只构建筛选条件，搜索由下一步执行

    法律依据

    • 《著作权法》（2021年修正）— 许可证类型说明（许可证筛选维度，未写条号）
    • 平台技术规范 — 分类标签规范（分类体系维护）

    产出

    筛选条件表：构建日期、五维条件、匹配技能数，以及下一步（执行搜索 → /legal-builder-hub:skill-search-browse / 调整筛选 / 清除筛选）

  2. 技能搜索与浏览

    /legal-builder-hub:skill-search-browse可单独运行

    在注册表中执行关键词搜索或分类浏览，返回标明安全审查状态、许可证和兼容性的候选技能列表。

    请律师核对

    • 核对 2.1「直接安装」只对「已通过安全审查」的技能开放，而安装流程也接受「有条件通过（已修复）」——黄级技能能否从这里直接进入安装，SKILL.md 未规定。
    • 核对 2.2分类浏览树的二级分类（如数据合规下「PIA 生成 / 出境评估 / 合规检查」）与筛选步骤的二级示例（「个人信息保护、数据出境、网络安全等保、数据安全」）不同——两套分类是否需要统一？

    做法

    1. 读取 CLAUDE.md 的关注法律领域、是否接受未审查技能、推荐排序偏好；读取实践配置契约字段映射；连接注册表并确定类型（本地 / 组织 / 公共）。
    2. 关键词搜索：按权重在五个维度匹配——技能名称（高，精确或模糊匹配）、技能描述（高，匹配 SKILL.md 的 description 字段）、法律领域标签（中）、能力类型标签（中）、功能关键词（低，匹配 SKILL.md 正文）。
    3. 分类浏览：按「法律领域 → 二级分类」逐级浏览，如商事合同（合同审查 / 合同起草 / 履约管理）、诉讼仲裁（案件管理 / 证据整理 / 文书起草）、数据合规（PIA 生成 / 出境评估 / 合规检查）、知识产权（商标查询 / 专利分析 / 著作权）及更多分类。
    4. 按配置过滤安全状态：「仅展示已审查技能」过滤掉所有未审查和未通过的技能；「接受未审查技能」展示全部，未审查技能标 [未审查 — 安装前须完成安全审查]；临时模式（未配置）默认仅展示已审查技能。
    5. 按兼容性过滤：默认隐藏与当前平台版本不兼容的技能；用户选择显示时加标注 [兼容性 — 须确认平台版本]（原文标签含警告符号）。
    6. 每条结果写明名称与版本、描述、法律领域与能力类型标签、安全状态（绿级已审查通过 / 黄级有条件通过 / 红级未通过 / 未审查）、许可证、兼容性（兼容 / 需确认 / 不兼容）、来源（社区贡献 / 官方 / 组织内部）和独立命令。
    7. 处理边界：结果为空时建议更宽泛的关键词或改为浏览分类，并推荐相近领域的技能；搜索词过宽时建议缩小范围、按安全状态或许可证再过滤；结果超过 50 个时分页并建议增加筛选条件。
    8. 处理错误：注册表连接失败时回退到本地缓存并提示检查网络和注册表地址；搜索语法错误时提示支持的语法并自动纠正常见错误；本地索引损坏时建议重建索引。
    9. 输出搜索结果和下一步：查看详情、调整筛选，或对已通过安全审查的技能直接进入安装。

    内置规则

    • 搜索维度权重：技能名称、技能描述为高；法律领域标签、能力类型标签为中；功能关键词为低
    • 安全状态过滤三种情形：仅展示已审查（过滤未审查和未通过）；接受未审查（全部展示并标注）；未配置（默认仅展示已审查）
    • 不兼容技能默认隐藏，用户可选择显示并加标注
    • 结果超过 50 个时分页展示
    • 本步只产出搜索结果列表，不执行安装或修改操作

    法律依据

    • 《个人信息保护法》（2021年）第13条 — 搜索过程不超出必要范围收集信息（搜索记录管理）
    • 《个人信息保护法》（2021年）第24条 — 搜索排序须保证透明度和公平性（搜索排序算法）

    产出

    搜索结果：搜索条件、注册表、匹配数量、过滤规则；结果表与每条结果卡片；下一步操作

  3. 推荐与排序

    /legal-builder-hub:recommendation-ranking可单独运行

    按用户画像、偏好和技能属性对搜索结果加权排序，给出带推荐理由的精选列表，并向用户公开排序维度和权重。

    请律师核对

    • 核对 3.1安全评级排序把「未审查」排在「未通过」之前，未审查技能按 0.2 计分后仍可进入推荐列表（保守模式除外）——是否同意？
    • 核对 3.2第24条被用作「推荐结果不因用户身份产生不合理差异」的依据，而个性化推荐又按「角色适配（开发者 vs 使用者）」给出不同结果——两者如何兼容，SKILL.md 未解释。
    • 核对 3.3趋势推荐和推荐理由依赖社区安装量与评分，SKILL.md 未规定评价条数很少时如何处理（详情步骤只对「无评价」显示「暂无评价」）。

    做法

    1. 读取 CLAUDE.md 的推荐排序偏好、关注法律领域、整体技能管理偏好、是否接受未审查技能；从搜索步骤取得原始结果（或从筛选步骤取得筛选条件）。
    2. 按「推荐排序偏好」选用五套默认权重之一（见规则）；用户无明确偏好时用综合排序。
    3. 按审查状态调整每个技能的安全评分（完整审查通过满分、标准审查通过 × 0.9、有条件通过 × 0.5、未审查 × 0.2 且保守模式下排除、未通过排除出推荐列表），再与功能匹配度、社区评分、更新活跃度合成综合评分。
    4. 选择推荐模式：个性化推荐（优先关注领域；按角色区分开发者与使用者；按安全偏好调整安全权重）；相似推荐（分析已安装技能的功能领域，在同一或互补领域推荐与之兼容的技能）；趋势推荐（近期热门安装、近期高评分、近期更新）。
    5. 输出精选推荐表（排名、名称、版本、综合评分、安全状态、推荐理由），并逐项说明功能匹配度、安全审查状态与等级、社区评分与评价摘要。
    6. 按透明度要求向用户说明当前排序维度与权重，列出可切换的排序方式（安全评级优先 / 社区评分优先 / 最近更新优先 / 综合排序）。
    7. 处理边界：结果少于 3 个时放宽筛选条件后重新推荐，并提示结果有限；全部为未审查时逐一标注并建议先做安全审查；推荐与上次完全相同时提示改用其他排序策略或筛选条件。
    8. 给出下一步：查看详情、调整排序或安装推荐技能。

    内置规则

    • 四个排序维度及权重范围：安全评级 0-40%（审查状态排序为绿级 > 黄级 > 未审查 > 红级；审查深度完整 > 标准 > 快速）；功能匹配度 0-30%（与需求的语义匹配程度）；社区评分 0-20%；更新活跃度 0-10%（最近更新时间、版本发布频率）
    • 五套默认权重（安全 / 功能 / 社区 / 更新）：安全评级优先 40% / 25% / 20% / 15%；社区评分优先 20% / 25% / 40% / 15%；最近更新优先 20% / 25% / 20% / 35%；下载量优先 20% / 30% / 30% / 20%；综合排序（默认）30% / 30% / 25% / 15%
    • 安全加权：绿级完整审查通过 = 安全评分满分；绿级标准审查通过 × 0.9；黄级有条件通过 × 0.5；未审查 × 0.2（保守模式下排除）；红级未通过 = 排除出推荐列表
    • 透明度四项：说明排序维度和权重；用户可调整排序偏好；不使用用户个人信息做不透明的画像分析；推荐结果不因用户身份产生不合理的差异
    • 本步只产出排序后的推荐列表，不执行安装或修改操作

    法律依据

    • 《个人信息保护法》（2021年）第24条（已核实锚点，建议复核）— 自动化决策须保证透明度和公平公正（推荐算法透明度）
    • 《个人信息保护法》（2021年）第13条 — 推荐过程不超出必要范围收集信息（推荐数据使用）

    产出

    推荐列表：排序策略与推荐模式、精选推荐表、推荐理由说明、排序调整选项与下一步

  4. 技能详情与评价

    /legal-builder-hub:skill-detail-evaluation可单独运行

    展示单个候选技能的完整信息——功能、安全审查、兼容性、社区评价、版本历史、许可证——并按审查状态给出安装决策建议。

    请律师核对

    • 核对 4.1本步把《个人信息保护法》第24条用作「评价信息展示须真实」的依据，而入口和推荐步骤把第24条概括为「自动化决策须保证透明度和公平公正」——同一条文两种用途，社区评价展示应引用什么依据？
    • 核对 4.2近期评价直接展示评价人用户名，SKILL.md 未规定是否需要处理评价人的信息。
    • 核对 4.3「有条件通过」只建议「修复指定问题后安装」，由谁确认已修复、是否需要重新审查，SKILL.md 未规定。

    做法

    1. 读取 CLAUDE.md 的安全审查偏好、技术背景、整体技能管理偏好；从技能名称、搜索结果编号或技能路径确定目标技能。
    2. 基本信息：当前版本、开发者 / 组织、许可证类型与简要说明、最后更新日期、首次发布日期。
    3. 功能说明从 SKILL.md 提取：目的、核心工作流程、输出产物、下属步骤清单（如为多步骤流程）、法律领域标签、能力类型标签。
    4. 安全审查区块：审查状态、审查日期、审查时的版本号、审查级别（完整审查 / 标准审查 / 快速检查），以及关键（红级）、高（橙级）、中等（黄级）、低（绿级）各级发现数量，附完整审查报告入口 /legal-builder-hub:review-report-certification；未审查时显示「此技能尚未通过安全审查。安装前须先完成安全审查」并指向 /legal-builder-hub:security-review。
    5. 兼容性区块：最低平台版本、依赖技能 / 库清单及版本要求、操作系统 / 运行时要求、当前环境兼容性（兼容 / 部分兼容 / 不兼容）。
    6. 社区评价区块：综合评分（满分 5.0，注明评价条数）、五个维度评分（功能完整性、易用性、文档质量、响应速度、安全可信度）和近期评价（用户名、评分、日期、摘要）；版本历史表（版本、发布日期、变更摘要）。
    7. 按审查状态给出决策建议：已审查通过 → 建议安装，可直接进入安装流程；有条件通过 → 建议修复指定问题后安装，查看修复清单；未通过 → 不建议安装，存在安全隐患；未审查 → 须先完成安全审查。
    8. 处理边界：详情不完整时展示已有信息、标注缺失项并提示开发者补充；审查版本与当前版本不一致时视为报告过期、建议重新审查；无社区评价时显示「暂无评价」并标为新技能；技能已下架或废弃时显示原因并推荐替代技能。

    内置规则

    • 决策建议四档与审查状态一一对应：通过 → 建议安装；有条件通过 → 建议修复后安装；未通过 → 不建议安装；未审查 → 须先安全审查
    • 「安装」下一步只在审查通过时提供；未审查时提供「安全审查」下一步
    • 审查时的版本号与当前版本不一致，即视为审查报告过期
    • 本步只展示详情，不执行安装或修改操作

    • 《个人信息保护法》（2021年）第24条 — 原文用途为「评价信息展示须真实」（社区评价展示）

08交付前检查

  • 每个结果都标明安全状态、许可证和兼容性；未审查技能带 [未审查 — 安装前须完成安全审查]
  • 过滤与配置一致：配置为仅展示已审查（或未配置）时，结果中没有未审查和未通过的技能
  • 推荐列表写明排序策略和推荐模式，并向用户说明排序维度与权重
  • 未通过的技能不出现在推荐列表；保守模式下未审查技能也不出现
  • 详情中的审查版本与当前版本一致，否则标为过期并建议重新审查
  • 「安装」下一步只对审查通过的技能提供

09何时暂停或升级

  • 目标技能未审查：详情页显示安全提示，转 /legal-builder-hub:security-review
  • 候选技能全部未审查：逐一标注并建议先做安全审查
  • 审查报告过期（审查版本与当前版本不一致）：建议重新审查
  • 技能已下架或废弃：显示原因并推荐替代技能
  • 注册表不可达：回退本地缓存，提示检查网络和注册表地址
  • 配置缺失或含占位符：进入临时模式，建议运行冷启动访谈

10请律师重点核对

下面是这个流程内置的法律假设、立场、阈值和清单，每一条都可以同意、反对或补充。条目下的「相关批注」按文字重合自动匹配到步骤旁的核对条目，可能不全。

  1. 安全状态口径从严：红级「未通过」定义为「存在高 / 关键风险」，黄级「有条件通过」对应「存在中等风险」；而实践配置的风险校准中，橙级（高）只是「需修复后方可安装」——一个只有高风险发现的技能在发现流程中会被标为「未通过」并排除出推荐，是否同意这一口径？
  2. 未配置或临时模式下只展示已审查通过的技能；但配置为「接受未审查技能」后，未审查技能会出现在搜索结果中，并在推荐中按安全评分 × 0.2 参与排序（只有保守模式排除）——是否同意未审查的社区技能进入推荐列表？相关批注：核对 3.1
  3. 默认的综合排序给安全评级 30%、功能匹配度 30%、社区评分 25%、更新活跃度 15%，即使选「安全评级优先」安全也只占 40%——对会接触客户文件的技能，安全评级的权重是否足够？是否应先按安全状态分组再排序？
  4. 五套默认权重与维度表自身的权重上限相矛盾：社区评分上限 20%，但「社区评分优先」给 40%、综合排序给 25%；更新活跃度上限 10%，但五套方案都给 15%–35%；「下载量优先」没有对应的下载量维度，输出模板的排序调整选项也没有它——SKILL.md 内部不一致，需维护者修正后再请律师确认权重。
  5. 入口护栏称推荐算法「不依赖用户个人信息的画像分析（符合 PIPL 最小必要原则）」，推荐步骤却明确「根据用户画像（角色 / 行业 / 关注领域）」做个性化排序，只承诺不做「不透明的」画像分析——两处口径不一：实践配置中的角色、行业、关注领域是否视为个人信息，个性化推荐需要满足什么条件，请律师确定。
  6. 引用条文与用途需逐条核对：原文把「搜索 / 推荐不得超出必要范围收集用户信息」挂在《个人信息保护法》第13条下，而本插件引用库对第13条的概括是「处理个人信息的合法性基础（七类）」；推荐步骤称第24条为「已核实锚点，建议复核」，但引用库的已核实锚点汇总中没有第24条；详情步骤又把第24条用于「评价信息展示须真实」。
  7. 许可证提示只要求展示许可证类型，并举例 GPL「要求衍生作品同样开源」；许可证为「自定义」时只写「须逐案审查」，没有规定由谁审查、审查完成前能否进入安装——是否需要设定律师介入的触发条件？
  8. 审查报告是否过期，详情步骤以「审查版本与当前版本不一致」判断，安装流程以「审查后技能代码未变更」判断——同一版本号下代码被改动时两者结论不同，是否需要统一？SKILL.md 也未设审查的时间有效期。
  9. 数据合规承诺「搜索记录仅保存在本地，不上报至注册表或第三方」「不收集或分析用户的具体法律案件内容」；但连接组织或公共注册表搜索时关键词如何处理，SKILL.md 未说明——用户在搜索框写入案情描述时是否需要提示？
  10. 注册表不可达时回退到本地缓存给出搜索结果，SKILL.md 未要求标注缓存时间或提示缓存中的安全状态可能已过期——是否应要求标注？
