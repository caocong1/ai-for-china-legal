01概要

把选定的技能安全地装进本地环境并管理其后续生命周期：安装前检查平台版本、依赖项、系统资源、安全审查状态和许可证，安装时创建回滚点、校验 SHA-256、登记命令并写安装日志，安装后引导配置 API 密钥与外部集成并做功能验证，日后负责更新（新版本须重新安全审查）、回滚和完全卸载。核心原则是「未经安全审查的技能不得安装」，且不可绕过：审查结论须为「通过」或「有条件通过（已修复）」，报告须在有效期内（审查后技能代码未变更），审查发现红级（关键：存在严重安全隐患，禁止安装）风险即自动终止安装。流程为「兼容性检查 → 安装执行 → 安装后配置」顺序执行，「更新与卸载」单独触发，四步各可单独使用。安装位置、自动更新策略、兼容性检查强度（强制 / 推荐 / 关闭）、是否允许安装未审查技能和审查级别都从 legal-builder-hub/CLAUDE.md 读取，缺失时按临时模式从严默认（强制兼容性检查、强制安全审查、手动确认每次更新）。

02适用与边界

适用场景

  • 已在技能发现或安全审查中选定技能，准备安装（技能名称@版本、本地路径或 Git 仓库）
  • 安装前单独确认目标技能与当前平台、依赖、磁盘空间、许可证是否兼容
  • 安装后首次配置 API 密钥、偏好设置与外部集成，或修改已有配置
  • 检查并执行已安装技能的版本更新、回滚到旧版本，或完全卸载

不做什么

  • 不做安全审查本身：未审查、报告过期或未通过的技能转 /legal-builder-hub:security-review
  • 不自动安装未经用户确认的技能：安装和卸载都须展示确认摘要并取得明确确认，自动更新范围以外的更新也须确认
  • 兼容性检查只出报告、不安装；安装后配置只说明 API 密钥等的获取方式，配置值由用户提供
  • 不保证第三方技能的质量或安全性；安全审查不替代运行时安全监控

03输入与产出

需要律师提供

  • 目标技能：名称@版本（如 contract-review@1.2.0）、本地路径或 Git 仓库必需
  • 目标技能的 SKILL.md 元数据与 plugin.json必需
    平台版本要求、依赖项、许可证；无元数据时无法做兼容性检查
  • 该技能的安全审查结论与报告（编号、日期、审查版本、审查级别）必需
    结论须为「通过」或「有条件通过（已修复）」，且审查后代码未变更
  • 当前环境信息：平台版本、已安装技能列表、系统资源必需
    自动检测；检测失败时请用户手动提供
  • legal-builder-hub/CLAUDE.md 的安装与安全配置可选
    默认安装位置、自动更新策略、安装前兼容性检查、是否允许安装未审查技能、安全审查级别、用户角色与技术背景；缺失时走临时模式
  • 技能的配置说明（SKILL.md 或附带的 CONFIG.md）以及 API 密钥等配置值可选
    安装后配置步骤使用

产出

  • 兼容性检查报告给团队内部
    目标技能与版本、检查日期、检查环境；检查结果表（平台最低版本、API 兼容性、依赖项、版本冲突、磁盘空间、安全审查状态、许可证）；综合结论三选一（兼容 — 可以安装 / 部分兼容 — 需处理后安装 / 不兼容 — 无法安装）；阻塞项、警告项与建议操作
  • 安装确认摘要与安装日志给团队内部（审计留存）
    确认摘要：技能与版本、来源、安装位置、安全审查与兼容性状态、新增依赖、磁盘需要与可用、「安装即接受许可证条款」提示；安装日志：名称、版本、时间、来源、位置、安全审查编号 / 日期 / 结论、兼容性结论、回滚点标识、六步操作记录表与安装结论
  • 配置完成确认给团队内部
    配置摘要（已配置 / 已配置使用默认值 / 已跳过）、集成状态、功能验证是否全部通过、下一步
  • 更新结果、卸载确认与卸载完成记录给团队内部（审计留存）
    更新：版本变更、时间、回滚点、文件完整性 / 功能测试 / 配置兼容性验证与结论；卸载：将删除与将保留的数据（安装审计日志、安全审查报告各保留 2 年，可选的配置备份）、依赖此技能的其他技能、已清理与已保留清单及审计日志位置

04开始前

前置条件

  • 读取 legal-builder-hub/CLAUDE.md：默认安装位置、自动更新策略、安装前兼容性检查、是否允许安装未审查技能、安全审查级别、用户角色 / 技术背景
  • 配置缺失或含 PLACEHOLDER 时进入临时模式并标 [临时模式]：安装位置用户目录 .skills/；兼容性检查强制执行；强制要求通过安全审查；自动更新关闭（手动确认每次更新）；建议运行 /legal-builder-hub:cold-start-interview
  • 安装执行前须已完成兼容性检查（结论为兼容，或部分兼容且用户已确认），并确认安全审查结论为「通过」或「有条件通过（已修复）」
  • 安装和卸载前都须展示确认摘要，取得用户明确确认

硬性规则

安全审查前置（硬性规则）
未经安全审查的技能不得安装，此规则不可绕过：安装执行前必须确认已通过安全审查；审查报告在有效期内（审查后技能代码未变更）；结论为「通过」或「有条件通过（已修复）」方可继续；审查发现红级（关键）风险时安装流程自动终止
兼容性强制检查
配置为「强制」时兼容性未通过即终止安装；配置为「推荐」时警告不阻止安装，但须用户确认；检查须验证平台版本、依赖项版本、系统资源
安装回滚保障
安装前自动创建回滚点；安装过程记录完整日志（步骤 / 时间 / 状态）；安装失败自动回滚到安装前状态；卸载时清理所有安装产物（文件 / 配置 / 注册信息）
数据合规
安装过程不向外部发送技能代码或用户环境信息（从注册表下载除外）；从注册表下载时须告知用户数据传输情况（原文称符合 PIPL 告知义务）；安装日志保存在本地，含完整审计追踪
更新须重新审查
技能更新后原审查报告自动失效：新版本没有审查报告时须先完成安全审查，审查不通过则终止更新
凭证安全
API 密钥等敏感信息不得明文写入日志或明文存储；配置值存于加密的本地配置文件，文件权限仅当前用户可读写；配置变更记审计日志（时间与操作人，不记值本身），变更前自动备份旧配置

05执行步骤

共 4 步，按执行顺序。每步旁边（窄屏在步骤说明之后）是请律师核对的内置假设，可逐条复制。页面里的英文标记见首页「标记与术语」。

  1. 兼容性检查

    /legal-builder-hub:compatibility-check可单独运行

    安装前全面检查目标技能对当前环境的要求——平台版本、依赖项、系统资源、安全审查状态、许可证——输出兼容性报告和能否安装的结论；本步不执行安装。

    请律师核对

    • 核对 1.1判定标准要求「用户接受该许可证」，但实践配置文件没有「可接受的许可证」字段，冷启动访谈也不问——接受范围从哪里来，SKILL.md 未规定；是否应在访谈中增加这一项？
    • 核对 1.2依赖项许可证只判断「与主技能无冲突」，SKILL.md 未给出冲突的判断标准（哪些许可证组合视为冲突）。
    • 核对 1.3环境检测失败时「使用保守默认值」，SKILL.md 未规定默认值是什么。

    做法

    1. 读取 CLAUDE.md 的安装前兼容性检查（强制 / 推荐 / 关闭）、是否允许安装未审查技能、安全审查偏好；获取目标技能名称、版本、SKILL.md 元数据和 plugin.json；检测平台版本、已安装技能列表和系统资源。
    2. 平台版本：当前版本 ≥ 技能要求的最低版本，≤ 技能声明兼容的最高版本；技能使用的 API 在当前版本均可用。
    3. 依赖项：声明依赖的其他技能均已安装且版本满足；依赖项的版本要求与其他技能不冲突；不存在循环依赖。
    4. 系统资源：安装位置剩余磁盘空间 > 技能大小 × 2；可用内存 ≥ 技能要求的内存。
    5. 安全审查状态：已审查通过；报告在有效期内（审查后技能代码未变更）；审查级别 ≥ 用户配置的级别。
    6. 许可证：技能许可证在用户接受范围内；依赖项的许可证与主技能无冲突。
    7. 汇总结论三选一（兼容 — 可以安装 / 部分兼容 — 需处理后安装 / 不兼容 — 无法安装），分列阻塞项（须解决后方可安装）和警告项（不阻止安装但建议处理）。
    8. 按结论给建议：兼容 → 继续安装执行；部分兼容 → 处理阻塞项后重新检查，或确认接受警告项后继续；不兼容 → 升级平台、经依赖解析（/legal-builder-hub:dependency-resolution）安装缺失依赖，或经搜索（/legal-builder-hub:skill-search-browse）换用兼容的替代技能。
    9. 处理边界：无元数据时无法检查，建议开发者补充 SKILL.md；依赖不可用时标注缺失并推荐替代方案或依赖安装步骤；安全审查未通过时阻止安装并转 /legal-builder-hub:security-review；环境检测失败时请用户手动提供环境信息，并使用保守默认值。

    内置规则

    • 三种检查模式：强制——任何不通过项都阻止安装，必须解决所有阻塞项；推荐——不通过项只发警告，用户确认后可继续，阻塞项仍建议解决；关闭——跳过兼容性检查（不推荐），标注 [风险 — 未进行兼容性检查]
    • 磁盘空间判定：剩余空间 > 技能大小 × 2；内存判定：可用内存 ≥ 要求内存
    • 安全审查三项判定：已审查通过；审查后技能代码未变更；审查级别 ≥ 用户配置级别
    • 许可证两项判定：用户接受该许可证；依赖许可证与主技能无冲突
    • 本步只产出兼容性报告，不执行安装

    法律依据

    • 《网络安全法》（2017年）第21条 — 安装的技能须与宿主系统等保要求相适应（平台版本和环境检查）
    • 《著作权法》（2021年修正）— 许可证兼容性（许可证检查，未写条号）

    产出

    《兼容性检查报告》：目标技能与版本、检查日期与环境、逐项检查结果表、综合结论、阻塞项、警告项与建议操作

  2. 安装执行

    /legal-builder-hub:installation-execution可单独运行

    兼容性检查和安全审查都通过后执行实际安装：创建回滚点、获取并校验技能文件、写入安装位置、登记到本地环境、验证安装并留下完整日志；硬性规则：未通过安全审查的技能不得安装，不可绕过。

    请律师核对

    • 核对 2.1确认摘要用「安装即接受许可证条款」提示用户，原文依据为《著作权法》（2021年修正）但未写条号——这一提示语是否准确？是否需要改为请用户阅读许可证全文后确认？
    • 核对 2.2安装日志与环境快照以 PIPL 第13条为「合法性基础」，但 SKILL.md 未说明日志中含哪些个人信息、适用七类合法性基础中的哪一类。
    • 核对 2.3安装后的技能以 /legal-builder-hub:[技能名] 登记命令，安装日志只记安装来源地址，不记搜索结果中的来源类别（社区贡献 / 官方 / 组织内部）——是否需要在日志中保留来源类别，便于事后追溯？

    做法

    1. 核对前置：兼容性检查结论为兼容，或部分兼容且用户已确认；安全审查结论为「通过」或「有条件通过（已修复）」；读取默认安装位置和安装日志风格。
    2. 展示安装确认摘要（技能与版本、来源、安装位置、安全审查状态、兼容性状态、新增依赖数、磁盘需要与可用、「安装即接受许可证条款：[许可证类型]」），取得用户明确确认后才开始。
    3. 创建回滚点：记录时间戳和唯一标识，快照已安装技能清单，备份配置文件和安装目录。
    4. 获取技能文件：远程注册表下载技能包 / 本地路径复制 / Git 仓库克隆或检出指定版本；从注册表下载时验证 SHA-256 校验和，与注册表记录不一致即终止安装并告警。
    5. 安装技能文件：在安装位置下创建技能目录，复制或链接 SKILL.md、下属步骤文件和共享文件，文件权限设为只读，防止意外修改；安装方式为复制 / 符号链接 / 注册引用之一。
    6. 登记到本地环境：在本地技能注册表添加记录，登记名称与路径映射、斜杠命令路由（/legal-builder-hub:[技能名]）和依赖关系。
    7. 验证安装四项：所有必需文件存在；SKILL.md 可正确解析；斜杠命令路由正确；所有依赖可用。
    8. 写安装日志：名称、版本、时间、来源、位置、安全审查编号 / 日期 / 结论、兼容性检查日期 / 结论、回滚点标识，以及六步操作（创建回滚点、获取文件、验证完整性、安装文件、登记、验证安装）的状态与时间；结论为安装成功，或「安装失败 — 已回滚」。
    9. 按失败阶段处理：文件获取失败 → 终止，无需回滚（未修改环境）；完整性验证失败 → 终止、删除已下载文件并告警；文件安装失败 → 自动回滚到回滚点并记录原因；登记失败 → 删除已安装文件并回滚注册表变更；安装验证失败 → 保留文件但标注安装异常，建议排查。

    内置规则

    • 硬性规则：未通过安全审查的技能不得安装，不可绕过；安全审查报告过期即终止安装并建议重新审查
    • 从注册表下载的技能包必须通过 SHA-256 校验，不一致即终止并告警
    • 安装后的技能文件设为只读
    • 安装位置已有同名技能：提示版本冲突，由用户选择覆盖安装 / 取消 / 指定其他位置；安装过程中断：自动回滚并提示重试；权限不足：提示提升权限或更改安装位置
    • 安装前必须展示确认摘要，并提示「安装即接受许可证条款」

    法律依据

    • 《个人信息保护法》（2021年）第13条 — 安装数据处理的合法性基础（安装日志记录）
    • 《著作权法》（2021年修正）— 安装即接受许可证条款（许可证确认，未写条号）
    • 《网络安全法》（2017年）第21条 — 软件安装须与系统等保相适应（安装环境检查）

    产出

    安装确认摘要（安装前）；安装日志（含六步操作记录表与安装结论）；失败时的回滚记录

  3. 安装后配置

    /legal-builder-hub:post-install-configuration可单独运行

    安装成功后引导完成首次配置——必需配置、可选配置、集成连接——并做功能验证，确保技能可以正常调用。

    请律师核对

    • 核对 3.1原文把《网络安全法》第21条用作「凭证信息的加密存储要求」的依据，而本插件引用库对该条的概括是「网络安全等级保护制度」——条文与用途是否对应，请核对。
    • 核对 3.2集成连接会把凭证和数据发往外部服务，入口只对「从注册表下载」规定了告知数据传输情况，集成连接没有同样的告知要求——是否需要补上？
    • 核对 3.3功能验证只有四项技术测试（加载、核心功能、集成、输出格式），不含对法律输出质量的检查——律所环境是否需要增加律师试用环节？

    做法

    1. 确认安装执行已完成且验证通过；从 SKILL.md 或技能附带的 CONFIG.md 读取配置要求；读取 CLAUDE.md 的集成工具状态和技术背景。
    2. 列出配置需求清单，分三类：必需配置（不配置无法运行）、可选配置（影响功能范围，注明默认值）、集成连接（扩展功能）。
    3. 逐项引导：说明这个配置项是什么、为什么需要；说明获取方式（如 API 密钥的申请地址）；接受用户输入；验证是否有效；写入安全存储。
    4. 集成连接测试：逐项列出连接状态和测试结果；失败时按网络连接、凭证有效性、防火墙 / 代理设置、集成服务端状态四项排查。
    5. 功能验证四项：技能能否正确加载、核心功能是否正常运行、集成连接是否正常工作、输出格式是否符合预期。
    6. 输出配置完成确认：配置摘要（已配置 / 已配置使用默认值 / 已跳过可稍后配置）、集成状态、功能验证是否全部通过、下一步（开始使用 / 修改配置 / 查看文档）。
    7. 处理边界：技能无需配置时直接做功能验证；配置值无效时提示原因并引导重新输入；集成连接失败时给排查建议，允许跳过集成但标注功能受限；用户暂时不想配置时保存进度，下次继续。

    内置规则

    • API 密钥等敏感信息不得明文写入日志，也不得明文存储；配置值存于加密的本地配置文件
    • 配置变更记审计日志（变更时间和操作人），不记录值本身；配置变更前自动备份旧配置
    • 配置文件权限设为仅当前用户可读写
    • 跳过集成须标注功能受限

    法律依据

    • 《个人信息保护法》（2021年）第13条 — 配置过程中数据处理的合法性基础（凭证信息收集）
    • 《网络安全法》（2017年）第21条 — 凭证信息的加密存储要求（配置安全）

    产出

    配置完成确认（配置摘要、集成状态、功能验证结果、下一步）；配置审计日志（不含敏感值）

  4. 更新与卸载

    /legal-builder-hub:update-uninstall可单独运行

    管理已安装技能的后续生命周期：按更新策略检查并执行版本更新（新版本须重新安全审查）、在更新失败或主动回退时回滚、完全卸载并保留审计记录；本步会修改和删除文件，须谨慎处理。

    请律师核对

    • 核对 4.1原文以《个人信息保护法》第47条作为卸载时删除用户数据的依据，但该条不在本插件引用库中，原文也未标验证状态——请核对条号与适用。
    • 核对 4.2「卸载即终止许可证授权」是原文的法律判断，依据只写《著作权法》（2021年修正）而未写条号——是否同意？
    • 核对 4.3卸载后保留的安装审计日志和安全审查报告是否含个人信息、保留 2 年与「删除用户数据」如何协调，SKILL.md 未说明。

    做法

    1. 读取 CLAUDE.md 的自动更新策略、安装位置、用户角色；从本地注册表获取已安装技能清单。
    2. 检查可用更新：逐个列出当前版本、最新版本、更新类型（MAJOR / MINOR / PATCH）和安全状态。
    3. 按更新策略决定行为：自动更新（仅补丁版本）——PATCH 自动执行，MINOR / MAJOR 须用户确认；自动更新（所有版本）——全部自动执行，但须通过安全审查；手动确认每次更新——所有更新都须用户明确确认；自动更新策略与用户意见冲突时以用户明确确认为准。
    4. 更新前安全审查：原审查报告随更新自动失效；检查新版本是否已有安全审查报告，没有则先完成安全审查再更新，审查不通过即终止更新。
    5. 创建回滚点（更新前版本、目标版本、唯一标识、配置备份路径），然后执行更新：备份当前文件和配置 → 获取新版本 → 替换技能文件（保留用户自定义配置）→ 更新本地注册表 → 验证完整性 → 运行基础功能测试；输出版本变更、文件完整性 / 功能测试 / 配置兼容性三项验证和结论（更新成功，或更新失败已回滚至旧版本）。
    6. 回滚：停止当前版本运行 → 恢复回滚点备份的文件和配置 → 把本地注册表改回旧版本 → 验证回滚后功能正常 → 记录回滚日志。
    7. 卸载前检查四项：是否有其他已安装技能依赖它；是否正在使用；是否有用户自定义配置需要备份；是否须保留审计日志。随后展示卸载确认：将删除技能文件、本地注册表记录和斜杠命令路由；将保留安装审计日志（2 年）、安全审查报告（2 年）及可选的配置备份；列出依赖它的技能（须先卸载或解除依赖）。
    8. 用户确认后执行卸载：备份用户配置（如选择）→ 删除技能文件和目录 → 移除本地注册表记录 → 移除斜杠命令路由 → 更新依赖关系图 → 记录卸载日志；输出已清理和已保留清单及审计日志位置。
    9. 处理边界：新版本不兼容时终止更新、保持当前版本并建议手动处理；卸载时有其他技能依赖则列出并建议先处理依赖关系；技能正在使用时提示等使用完成后再卸载，或经确认后强制终止；回滚失败时保留当前状态、记录错误并建议手动修复。

    内置规则

    • 三种更新策略：仅补丁版本自动 / 所有版本自动（须通过安全审查）/ 每次手动确认
    • 技能更新后原审查报告自动失效；新版本须先有审查报告，审查不通过即终止更新
    • 卸载后保留安装审计日志和安全审查报告各 2 年；配置模板「共享护栏」也要求安全审查报告保留至少 2 年备查
    • 仍有其他技能依赖时，须先卸载或解除依赖
    • 强制终止正在使用的技能须用户确认；自动更新策略与用户冲突时以用户明确确认为准

    法律依据

    • 《个人信息保护法》（2021年）第47条 — 卸载时用户数据的处理（用户配置和数据的删除）
    • 《著作权法》（2021年修正）— 卸载即终止许可证授权（许可证管理，未写条号）

    产出

    更新检查表；更新结果（含回滚点和验证结论）；回滚日志；卸载确认与卸载完成记录（已清理 / 已保留清单、审计日志位置）

08交付前检查

  • 安装前已确认安全审查结论为「通过」或「有条件通过（已修复）」，且审查后代码未变更
  • 兼容性结论与检查模式一致：强制模式下无未解决的阻塞项；推荐模式下的警告已经用户确认
  • 已展示安装确认摘要（含许可证提示）并取得用户明确确认
  • 已创建回滚点；从注册表下载的技能包已通过 SHA-256 校验
  • 安装验证四项（文件完整性、元数据可读、命令注册、依赖满足）均通过，安装日志六步状态完整
  • 日志和审计记录中没有明文 API 密钥等敏感值
  • 卸载后文件、注册表记录、命令路由已清理，依赖关系已更新，审计日志和安全审查报告已保留

09何时暂停或升级

  • 安全审查未通过、报告过期或发现红级风险：终止安装，转 /legal-builder-hub:security-review
  • SHA-256 校验和与注册表记录不一致：终止安装、删除已下载文件并告警
  • 兼容性不通过：强制模式终止；推荐模式须用户确认后才能继续
  • 安装位置已有同名技能、权限不足、卸载时有依赖或技能正在使用：暂停，请用户选择处理方式
  • 更新时新版本不兼容或审查不通过：终止更新，保持当前版本
  • 回滚失败：保留当前状态、记录错误，建议手动修复
  • 配置缺失或含占位符：进入临时模式（从严默认），建议运行冷启动访谈

  7. 引用条文与用途需核对：PIPL 第13条（引用库概括为合法性基础）被用于安装日志、环境信息和凭证收集；《网络安全法》第21条（引用库概括为等级保护制度）被用于「凭证信息的加密存储要求」；PIPL 第47条用于卸载时删除用户数据，但不在引用库中、未标验证状态。相关批注：核对 3.1、核对 4.1
