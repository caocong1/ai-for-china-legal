01概要

把选定的技能安全地装进本机，并管好之后的更新和撤下。分四步（前三步依次进行，第 4 步随时单独用）：安装前查平台版本、依赖、系统资源、安全审查和许可证；安装时先建还原点、核对下载文件未被篡改、写安装日志；装好后引导配置 API 密钥和外部连接并试运行；日后更新（新版本须重审）、还原旧版本或彻底卸载。核心原则「未经安全审查的技能不得安装」不能绕过：结论须为「通过」或「有条件通过（已修复）」且审查后代码未改动，发现红级（关键）风险即终止安装。各项设置按实践配置执行，未配置时从严默认：强制兼容性检查、强制安全审查、每次更新手动确认。

02适用与边界

适用场景

  • 已在技能发现或安全审查中选定技能，准备安装（技能名称和版本、本机位置或代码托管平台上的地址）
  • 安装前单独确认目标技能与当前平台、依赖、磁盘空间、许可证是否兼容
  • 装好后第一次配置 API 密钥、偏好设置和外部连接，或修改已有配置
  • 检查并更新已安装的技能、还原到旧版本，或彻底卸载

不做什么

  • 不做安全审查本身：未审查、报告过期或未通过的技能，转安全审查流程
  • 不自动安装未经使用者确认的技能：安装和卸载都须先列出确认摘要并取得明确确认，自动更新范围以外的更新也须确认
  • 兼容性检查只出报告、不安装；安装后配置只说明 API 密钥等怎么取得，配置值由使用者提供
  • 不保证第三方技能的质量或安全性；安全审查不替代运行中的安全监控

03输入与产出

需要提供

  • 要安装的技能：名称和版本（如合同审查技能 1.2.0 版）、本机位置或代码托管平台上的地址必需
  • 技能自带的说明信息（平台版本要求、依赖、许可证）必需
    没有这些信息就无法做兼容性检查
  • 该技能的安全审查结论和报告（编号、日期、审查时的版本、审查级别）必需
    结论须为「通过」或「有条件通过（已修复）」，且审查后代码未改动
  • 当前环境信息：平台版本、已安装的技能、系统资源必需
    自动检测；检测不到时请使用者提供
  • 实践配置中的安装与安全设置可选
    安装位置、更新策略、兼容性检查、审查级别、角色与技术背景等；未填按临时模式
  • 技能的配置说明和 API 密钥等配置值可选
    第 3 步「安装后配置」使用

产出

  • 兼容性检查报告读者：团队内部
    目标技能与版本、检查日期与环境；逐项结果（平台版本、接口、依赖、版本冲突、磁盘空间、安全审查、许可证）；结论三选一（兼容、部分兼容、不兼容）；必须解决的问题与警告
  • 安装确认摘要与安装日志读者：团队内部（审计留存）
    确认摘要：技能与版本、来源、位置、审查与兼容性状态、新增依赖、磁盘空间、「安装即接受许可证条款」提示；安装日志：审查编号与结论、兼容性结论、还原点、各环节的结果
  • 配置完成确认读者：团队内部
    配置摘要（已配置、使用默认值、已跳过）、外部连接状态、试运行是否全部通过、下一步
  • 更新结果、卸载确认与卸载记录读者：团队内部（审计留存）
    更新：版本变化、还原点、三项验证与结论；卸载：将删除和将保留的内容（安装审计日志、安全审查报告各保留 2 年，可选的配置备份）、依赖它的技能、已清理与已保留清单

04开始前

前置条件

  • 读取实践配置：默认安装位置、自动更新策略、安装前兼容性检查、是否允许安装未审查技能、安全审查级别、用户角色与技术背景
  • 配置缺失或有未填写的配置项时按临时模式办理并标 [临时模式]：装在个人目录；兼容性检查强制执行；强制要求通过安全审查；不自动更新（每次手动确认）；建议先做冷启动访谈
  • 安装前须已完成兼容性检查（结论为兼容，或部分兼容且使用者已确认），并确认安全审查结论为「通过」或「有条件通过（已修复）」
  • 安装和卸载前都须列出确认摘要，取得使用者明确确认

硬性规则

安全审查前置
未经安全审查的技能不得安装，不能绕过：须已通过审查、审查后代码未改动、结论为「通过」或「有条件通过（已修复）」；审查发现红级（关键）风险的，安装自动终止
兼容性检查
配置为「强制」的，兼容性不通过即终止安装；配置为「推荐」的，只警告不阻止，但须使用者确认；须检查平台版本、依赖版本、系统资源
安装可还原
安装前自动建还原点；全程记录每个环节、时间和结果；安装失败自动还原到安装前状态；卸载时清理全部安装内容（文件、配置、登记信息）
数据合规
安装过程不向外发送技能代码或本机环境信息（从注册表下载除外），下载时须告知使用者数据传输情况（原文称符合《个人信息保护法》告知义务）；安装日志存本机，可完整追溯
更新须重审
技能更新后原审查报告自动失效：新版本没有审查报告的须先做安全审查，审查不通过即终止更新
凭证安全
API 密钥等敏感信息不得明文写进日志或明文保存；配置值加密存在本机，只有当前用户能读写；配置变更留审计记录（时间和操作人，不记值本身），改前自动备份旧配置

05执行步骤

共 4 步，按执行顺序。每步旁边（窄屏在步骤说明之后）是请律师核对的内置判断，可逐条复制。

  1. 兼容性检查

    可单独使用

    安装前逐项检查平台版本、依赖、系统资源、安全审查和许可证，出兼容性报告和能否安装的结论；本步不安装

    请律师核对

    • 核对 1.1判定标准要求「使用者接受该许可证」，但实践配置里没有「可接受的许可证」这一项，冷启动访谈也不问——接受范围从哪里来，本流程没有规定；是否应在访谈中增加这一项？
    • 核对 1.2依赖组件的许可证只判断「与主技能无冲突」，本流程没有给出冲突的判断标准（哪些许可证组合算冲突）。
    • 核对 1.3检测不到环境时「按保守默认值处理」，本流程没有规定默认值是什么。

    做法

    1. 读取配置中的兼容性检查强度（强制、推荐、关闭）、是否允许安装未审查技能和安全审查偏好，取得目标技能的说明信息，检测当前平台、已安装的技能和系统资源。
    2. 平台与依赖：当前平台版本在技能声明的兼容范围内，技能要用的功能都可用；依赖的其他技能都已装好、版本满足且互不冲突；磁盘空间和内存够用。
    3. 安全审查与许可证：已审查通过、审查后技能代码未改动、审查级别不低于配置的级别；技能的许可证在可接受范围内，依赖组件的许可证与主技能不冲突。
    4. 汇总结论三选一（兼容 — 可以安装；部分兼容 — 处理后安装；不兼容 — 无法安装），分列必须解决的问题（解决后才能装）和警告（不阻止安装，但建议处理）。
    5. 按结论给建议：兼容的，进入第 2 步「安装执行」；部分兼容的，处理完必须解决的问题后重新检查，或确认接受警告后继续；不兼容的，升级平台、通过技能注册表流程的依赖解析补装缺失依赖，或回到技能发现换用兼容的替代技能。
    6. 没有说明信息的无法检查，建议开发者补充；依赖不可用的，标明缺失并推荐替代方案或补装步骤；安全审查未通过的，阻止安装并转安全审查流程；检测不到环境的，请使用者手动提供，并按保守默认值处理。

    内置规则

    • 三种检查强度：强制——任何一项不通过都阻止安装，必须解决全部问题；推荐——不通过的项只发警告，使用者确认后可以继续，必须解决的问题仍建议解决；关闭——跳过兼容性检查（不推荐），标 [风险 — 未进行兼容性检查]
    • 安全审查三项都须满足：已审查通过；审查后技能代码未改动；审查级别不低于配置的级别
    • 许可证两项：使用者接受该许可证；依赖组件的许可证与主技能不冲突
    • 本步只出兼容性报告，不安装

    法律依据

    • 《网络安全法》（2017年）第21条 — 安装的技能须与所在系统的等级保护要求相适应（平台版本和环境检查）
    • 《著作权法》（2021年修正）— 许可证兼容（许可证检查，未写条号）

    产出

    《兼容性检查报告》：目标技能与版本、检查日期与环境、逐项结果、结论、必须解决的问题、警告与建议

  2. 安装执行

    可单独使用

    兼容性检查和安全审查都通过后实际安装：先建还原点，取得并核对文件，装好、登记、验证，全程留日志；未通过审查的不得安装

    请律师核对

    • 核对 2.1确认摘要以「安装即接受许可证条款」提示使用者，原文依据为《著作权法》（2021年修正）但没写条号——这句提示语是否准确？是否应改为请使用者读完许可证全文后确认？
    • 核对 2.2安装日志和环境备份以《个人信息保护法》第13条为「合法性基础」，但本流程没有说明日志里含哪些个人信息、适用七类合法性基础中的哪一类。
    • 核对 2.3安装日志只记安装来源地址，不记搜索结果中的来源类别（社区贡献、官方、组织内部）——是否需要在日志中保留来源类别，便于事后追溯？

    做法

    1. 核对前提：兼容性检查结论为兼容，或部分兼容且使用者已确认；安全审查结论为「通过」或「有条件通过（已修复）」。
    2. 列出安装确认摘要（技能与版本、来源、安装位置、安全审查与兼容性状态、新增依赖数、所需与可用磁盘空间，以及「安装即接受许可证条款：许可证类型」提示），使用者明确确认后才开始。
    3. 先建还原点（备份安装前的技能清单、配置和安装目录），再取得技能文件（从注册表下载、从本机复制，或从代码托管平台取得指定版本）；从注册表下载的，核对文件与注册表登记的一致、未被篡改，不一致即终止并告警。
    4. 装到配置的位置并在本机登记（技能文件设为只读，防止被意外改动），再验证文件齐全、能正确读取、调用入口和依赖都可用。
    5. 写安装日志：技能名称与版本、时间、来源地址、安装位置、安全审查编号与结论、兼容性检查结论、还原点，以及每个环节的结果和时间；结论为安装成功，或安装失败、已还原。

    内置规则

    • 硬性规则：未通过安全审查的技能不得安装，不能绕过；安全审查报告过期的，终止安装并建议重新审查
    • 从注册表下载的文件必须核对，与注册表登记的不一致即终止并告警
    • 失败的处理：没取到文件的终止（本机未改动，无需还原）；核对不一致的终止，删除已下载文件并告警；装到一半或登记失败的，撤销已装内容、还原到安装前并记录原因；验证不通过的，只保留文件、标为安装异常，建议排查（不还原）
    • 安装位置已有同名技能的，提示版本冲突，由使用者选择覆盖、取消或换位置；安装中断的，自动还原并提示重试；权限不足的，提示提升权限或换安装位置
    • 安装前必须列出确认摘要，并提示「安装即接受许可证条款」

    法律依据

    • 《个人信息保护法》（2021年）第13条 — 安装中处理数据的合法性基础（安装日志记录）
    • 《著作权法》（2021年修正）— 安装即接受许可证条款（许可证确认，未写条号）
    • 《网络安全法》（2017年）第21条 — 软件安装须与系统的等级保护要求相适应（安装环境检查）

    产出

    安装确认摘要（安装前）；安装日志（每个环节的结果与结论）；失败时的还原记录

  3. 安装后配置

    可单独使用

    装好后引导完成首次配置——必需项、可选项、外部连接——并试运行，确保技能能正常使用

    请律师核对

    • 核对 3.1原文把《网络安全法》第21条用作「凭证信息加密保存」的依据，而本领域引用库对该条的概括是「网络安全等级保护制度」——条文与用途是否对应，请核对。
    • 核对 3.2外部连接会把凭证和数据发往外部服务，本流程总说明只对「从注册表下载」规定了告知数据传输情况，外部连接没有同样的告知要求——是否需要补上？
    • 核对 3.3试运行只有四项技术测试（加载、核心功能、外部连接、输出格式），不检查法律输出的质量——律所环境是否需要增加律师试用环节？

    做法

    1. 确认第 2 步已完成且验证通过；从该技能的规则文件或附带的配置说明读取配置要求；读取实践配置中的已接入系统和技术背景。
    2. 列出配置清单，分三类：必需配置（不配就无法运行）、可选配置（影响功能范围，注明默认值）、外部连接（扩展功能）。
    3. 逐项引导：说明这一项是什么、为什么需要、怎么取得（如 API 密钥到哪里申请），接受使用者输入、检验是否有效，再加密保存。
    4. 测试外部连接，逐项列出结果，失败的给出排查建议。
    5. 试运行四项：能否正确加载、核心功能是否正常、外部连接是否正常、输出格式是否符合预期；最后出配置完成确认（哪些已配置、用了默认值或已跳过，外部连接状态，试运行是否全部通过，下一步）。
    6. 不需要配置的，直接试运行；配置值无效的，说明原因并引导重新输入；外部连接失败的，给出排查建议，允许跳过但标明功能受限；使用者暂时不想配的，保存进度下次继续。

    内置规则

    • API 密钥等敏感信息不得明文写进日志，也不得明文保存；配置值加密保存在本机，只允许当前用户读写
    • 配置变更留审计记录（变更时间和操作人），不记值本身；变更前自动备份旧配置
    • 跳过外部连接的须标明功能受限

    法律依据

    • 《个人信息保护法》（2021年）第13条 — 配置中处理数据的合法性基础（收集凭证信息）
    • 《网络安全法》（2017年）第21条 — 凭证信息加密保存的要求（配置安全）

    产出

    配置完成确认（配置摘要、外部连接状态、试运行结果、下一步）；不含敏感值的配置审计记录

  4. 更新与卸载

    可单独使用

    管好已装技能的后续：按更新策略更新（新版本须重审），失败或主动退回时还原旧版本，彻底卸载并保留审计记录

    请律师核对

    • 核对 4.1原文以《个人信息保护法》第47条作为卸载时删除使用者数据的依据，但该条不在本领域引用库中，原文也没标核实状态——请核对条号与适用。
    • 核对 4.2「卸载即终止许可证授权」是原文的法律判断，依据只写《著作权法》（2021年修正）而没写条号——是否同意？
    • 核对 4.3卸载后保留的安装审计日志和安全审查报告是否含个人信息、保留 2 年与「删除使用者数据」如何协调，本流程没有说明。

    做法

    1. 读取配置中的自动更新策略、安装位置和用户角色，取得已安装技能清单；逐个列出当前版本、最新版本、更新类型（主版本、次版本或修订号更新）和安全状态。
    2. 按更新策略处理：只自动更新修订号的，修订号更新自动执行，次版本、主版本更新须使用者确认；所有版本都自动更新的，全部自动执行，但须通过安全审查；每次手动确认的，所有更新都须使用者明确确认；策略与使用者意见冲突时，以使用者明确确认为准。
    3. 更新前重审：原审查报告随更新自动失效；新版本没有审查报告的，先做安全审查再更新，审查不通过即终止更新。
    4. 更新：先建还原点、备份配置，再换上新版本（保留使用者自己的配置），核对完整性并试运行，列出版本变化、文件完整、功能正常、配置兼容三项验证和结论（更新成功，或更新失败、已还原到旧版本）；需要退回旧版本时，恢复还原点的文件和配置，确认功能正常并留记录。
    5. 卸载前查四项：是否有其他技能依赖它、是否正在使用、是否有使用者自己的配置要备份、是否须保留审计日志；再列出卸载确认：将删除技能文件、本机登记和调用入口，将保留安装审计日志（2 年）、安全审查报告（2 年）和可选的配置备份，依赖它的技能须先卸载或解除依赖。
    6. 使用者确认后卸载：按选择备份配置，删除技能文件，撤销本机登记和调用入口，更新依赖关系，留卸载记录，并列出已清理和已保留的清单及审计日志位置；新版本不兼容的终止更新、保持当前版本，正在使用的提示用完再卸或经确认后强制停止，还原失败的保持现状、记录错误并建议手动修复。

    内置规则

    • 版本号分三段（主版本.次版本.修订号）：主版本变化表示可能不兼容，次版本表示新增功能，修订号表示问题修复（技能注册表流程的版本规则）。三种更新策略：只自动更新修订号、所有版本都自动更新（须通过安全审查）、每次手动确认
    • 技能更新后原审查报告自动失效；新版本须先有审查报告，审查不通过即终止更新
    • 卸载后保留安装审计日志和安全审查报告各 2 年；配置模板「共享护栏」也要求安全审查报告至少保留 2 年备查
    • 仍有其他技能依赖的，须先卸载或解除依赖
    • 强制停止正在使用的技能须使用者确认；自动更新策略与使用者意见冲突时，以使用者明确确认为准

    法律依据

    • 《个人信息保护法》（2021年）第47条 — 卸载时对使用者数据的处理（删除使用者配置和数据）
    • 《著作权法》（2021年修正）— 卸载即终止许可证授权（许可证管理，未写条号）

    产出

    更新检查表；更新结果（含还原点和验证结论）；还原记录；卸载确认与卸载记录（已清理和已保留清单、审计日志位置）

06主要法律依据

  • 《个人信息保护法》（2021年）第13条 — 安装中处理数据的合法性基础（安装日志、环境信息、凭证信息的收集；引用库标「已核实，建议复核」）
  • 《个人信息保护法》（2021年）第47条 — 卸载时对使用者数据的处理（删除使用者配置和数据；不在引用库中，原文未标核实状态）
  • 《网络安全法》（2017年）第21条 — 安装的技能须与所在系统的等级保护要求相适应（兼容性检查、安装环境检查；原文另用于凭证加密保存；引用库标「已核实，建议复核」）
  • 《著作权法》（2021年修正）— 安装即接受许可证条款；卸载即终止许可证授权（许可证合规，未写条号；引用库标 [条号待验证]）
  • 《个人信息保护法》告知义务（未写条号）— 从注册表下载时告知使用者数据传输情况

带「待验证」「待律师复核」标记的，是 skill 原文自己标出的未核验引用。

08交付前检查

  • 安装前已确认安全审查结论为「通过」或「有条件通过（已修复）」，且审查后代码未改动
  • 兼容性结论与检查强度一致：强制时没有未解决的问题；推荐时的警告已经使用者确认
  • 已列出安装确认摘要（含许可证提示）并取得使用者明确确认；已先建还原点，从注册表下载的文件已核对校验值
  • 安装验证（文件齐全、能正确读取、调用入口和依赖可用）全部通过，安装日志各环节完整
  • 日志和审计记录里没有明文的 API 密钥等敏感值
  • 卸载后文件、登记和调用入口已清理，依赖关系已更新，审计日志和安全审查报告已保留

09何时暂停或升级

  • 安全审查未通过、报告过期或发现红级风险：终止安装，转安全审查流程
  • 下载的文件与注册表登记的校验值不一致：终止安装、删除已下载文件并告警
  • 兼容性不通过：强制时终止，推荐时须使用者确认后才能继续；更新时新版本不兼容或审查不通过：终止更新，保持当前版本
  • 安装位置已有同名技能、权限不足、卸载时有依赖或技能正在使用：暂停，请使用者选择处理方式；还原失败：保持现状、记录错误，建议手动修复
  • 安装失败或触发实践配置「升级矩阵」的自动升级条件（实践配置说明把安装失败列为升级情形）：暂停操作，等人工确认
  • 配置缺失或有未填写的配置项：按临时模式从严办理，建议先做冷启动访谈

10审阅清单

请律师重点核对：下面是这个流程内置的法律判断、立场、阈值和清单，每一条都可以同意、反对或补充。条目里「供核对」之后的内容是本站整理时对照现行条文补充的提示，不是 skill 原文。条目下的「相关批注」按文字重合自动匹配到步骤旁的核对条目，可能不全。

  1. 核心规则「未经安全审查的技能不得安装，不能绕过」与配置选项冲突：冷启动访谈允许把「是否允许安装未经安全审查的技能」设为「是（标注风险后允许）」或「仅开发环境允许」，本流程总说明也把这一项列为决定「安装前提」的配置——两者冲突时以哪个为准，请律师确定。
  2. 放行标准是安全审查结论为「通过」或「有条件通过（已修复）」，但本流程没有规定由谁确认「已修复」、确认后是否要重新审查。是否应明确由安全审核员或平台管理员确认？
  3. 审查有效期只看「审查后技能代码有无改动」，没有时间上限；技能发现流程则以「审查时的版本与当前版本不一致」判断过期——两种口径是否统一？是否需要规定审查满一定期限即须重审？
  4. 兼容性口径三处不一：插件说明的核心护栏写「技能版本与当前环境不兼容 → 阻止安装」；兼容性检查却允许「推荐」强度下经使用者确认带着不通过项安装，「关闭」时直接跳过（只标 [风险 — 未进行兼容性检查]）；安装执行又要求先取得兼容或部分兼容的结论。是否允许关闭兼容性检查？
  5. 安装确认摘要提示「安装即接受许可证条款」，卸载写「卸载即终止许可证授权」，两处都以《著作权法》（2021年修正）为依据而没写条号，本领域引用库对著作权法条文也标 [条号待验证]——这两项法律判断是否成立，能否直接用作提示语？相关批注：核对 4.2、核对 2.1
  6. 卸载后保留安装审计日志和安全审查报告各 2 年（配置模板「共享护栏」写安全审查报告至少保留 2 年）；而本领域引用库记载《个人信息保护法》第56条要求个人信息保护影响评估报告和处理情况记录至少保存三年。审查报告含数据隐私影响评估内容的，2 年是否足够？相关批注：核对 4.3
  7. 引用条文与用途需核对：《个人信息保护法》第13条（引用库概括为合法性基础）被用于安装日志、环境信息和凭证的收集；《网络安全法》第21条（引用库概括为等级保护制度）被用于「凭证信息加密保存的要求」；《个人信息保护法》第47条用于卸载时删除使用者数据，但不在引用库中、没标核实状态。相关批注：核对 4.1、核对 3.1
  8. 本领域统一引用《网络安全法》（2017年）第21条（等级保护）；同一套工具中数据合规领域的引用库记载，《网络安全法》2025 年修正、自 2026-01-01 起施行，条号整体后移（原第21条改为第23条，条号对应关系标为二手资料）——请核实后统一本领域的条号与版本年份。
  9. 数据合规护栏只要求从注册表下载时「告知使用者数据传输情况」，本流程没有规定告知什么（传哪些数据、发给谁、是否出境）；安装后配置中的外部连接会把凭证发往外部服务，却没有同样的告知要求。是否需要补充？相关批注：核对 3.2
  10. 「所有版本都自动更新」的策略下，主版本更新（可能不兼容）也会在通过安全审查后自动执行、不再征求确认；临时模式默认不自动更新。律所环境是否应禁止主版本自动更新？
  11. 安装验证不通过时「保留文件、标为安装异常」而不还原，与本流程总说明「安装失败自动还原到安装前状态」的护栏不一致——验证不通过的技能是否应一律还原？
