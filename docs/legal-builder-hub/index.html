02概要

面向律所、企业法务和技能开发者，管理社区法律技能从发现到卸载的全过程：按法律领域和能力类型搜索、筛选和推荐技能，安装前从静态分析、权限范围、数据隐私三方面做安全审查并出具报告与认证结论（通过 / 有条件通过 / 未通过），经兼容性检查后安装、配置、更新或卸载；开发者还可以校验技能清单（SKILL.md / plugin.json）、管理语义化版本和依赖并发布到注册表。五个流程（冷启动访谈、技能发现、安装向导、安全审查、技能注册表）下共 20 个可单独触发的步骤。核心规则是「未经安全审查的技能不得安装」，审查发现红级（关键风险，禁止安装）问题即终止安装；所有流程从实践配置文件 legal-builder-hub/CLAUDE.md 读取角色、安全偏好、零容忍权限和报告风格，涉及个人信息保护法、数据安全法、网络安全法和著作权法的依据按插件引用规范标注来源标签与验证状态。

03实践配置

实践配置文件 <a href="https://github.com/caocong1/ai-for-china-legal/blob/master/legal-builder-hub/CLAUDE.md">legal-builder-hub/CLAUDE.md</a> 记录贵所的立场与习惯；所有流程开始前先读它。

配置哪些内容

  • 我们是谁
  • 谁在使用
  • 可用集成
  • 技能偏好（含 技能发现偏好 / 安全审查偏好 / 安装与部署偏好）
  • 风险校准
  • 升级矩阵（含 角色权限表 / 自动升级触发条件）
  • 文书风格
  • 输出（含 工作产物标题 / 审查者注释块）
  • 共享护栏（含 安全优先原则 / 数据合规要求 / 来源标签规范 / 知识产权提示）
  • 技能注册表
  • 事项工作区
  • 审查过的技能

会怎样改变输出

  • 「我们是谁 → 用户角色」供所有流程做权限判断与功能路由，「谁在使用 → 角色」决定工作产物标题：技术角色（开发者 / 管理员）用「技能安全审查报告 — 技术审查文档」，法律角色（律师 / 法务）用「技能合规评估笔记 — 非技术结论，供技术人员审查」；角色为非技术人员时，安装和安全审查给出详细步骤指导，涉及安全审查结论时建议升级给技术人员或安全专家确认；「技术背景」决定安装指导的详细程度和审查报告的深度。
  • 「技能偏好 → 整体技能管理偏好」三档校准所有流程的安全口径：保守型只装经过完整安全审查的技能，筛选默认只看已审查通过的技能，推荐中排除未审查技能；平衡型兼顾审查与效率；进取型可快速试用社区技能，筛选默认包含未审查技能，但关键场景仍要求审查。
  • 「安全审查偏好」决定审查深度与安装拦截：审查级别分完整审查（静态分析 + 权限审查 + 隐私评估）/ 标准审查（权限 + 隐私）/ 快速检查（仅权限范围）；「是否允许安装未经安全审查的技能」可选否（强制审查）/ 是（标注风险后允许）/ 仅开发环境允许；敏感权限零容忍列表和数据隐私要求分别交给权限范围审查和数据隐私评估执行。
  • 「技能发现偏好」决定搜索过滤与排序（是否接受未审查技能出现在结果中；推荐排序偏好对应五套权重之一）；「安装与部署偏好」决定默认安装位置、自动更新策略（仅补丁版本自动 / 所有版本自动 / 每次手动确认）和安装前兼容性检查强度（强制：任何不通过项都阻止安装；推荐：警告后由用户确认；关闭：跳过并标 [风险 — 未进行兼容性检查]）。
  • 「风险校准」四级表决定每个审查发现的标注（原文以红、橙、黄、绿色圆点标示）：红级 = 关键，存在严重安全隐患或违规风险，禁止安装（如恶意代码或后门、未经授权收集用户数据、读取全部文件系统等过度权限、违反 PIPL 收集个人信息）；橙级 = 高，需修复后方可安装（如权限超出声明功能所需、未提供隐私政策或数据处理说明、依赖项有已知漏洞）；黄级 = 中等，风险可控但建议优化（如缺少安全文档）；绿级 = 低，风险可接受。「升级矩阵」的五项自动升级条件（审查发现红级风险、请求访问法律文件 / 客户信息 / 案件数据等敏感数据、网络外传能力、依赖项严重漏洞、违反平台安全策略）不论角色一律升级。
  • 「共享护栏」规定未经安全审查的技能不得安装、即使开发者声明安全也须独立审查、安全审查报告保留至少 2 年；涉及数据处理的技能须同时符合《个人信息保护法》第13条（合法性基础）与第29条（敏感个人信息单独同意）、《数据安全法》第21条（数据分类分级）、《网络安全法》第21条（等级保护），四条均标「已核实」；「技能注册表」章的类型、地址和发布审核流程（自动审核 / 人工审核 / 社区审核）驱动注册表流程。

  • 法律依据引用规范（法律技能中心版） legal-builder-hub/skills/_shared/legal-basis-conventions.md
    规定本插件技术与法律交叉领域的引用写法，按六类来源组织：一、法律——《个人信息保护法》（2021年11月1日施行）、《数据安全法》（2021年9月1日施行）、《网络安全法》（2017年6月1日施行）、《著作权法》（2021年6月1日修正施行）、《民法典》（2021年1月1日施行），最小格式为《法律全名》（年份）第X条第X款 + 来源标签 + 验证状态；二、行政法规——《关键信息基础设施安全保护条例》（2021年9月1日施行）、《网络数据安全管理条例》（施行状态须核实 [待验证]）、《计算机信息网络国际联网安全保护管理办法》（公安部）；三、部门规章与规范性文件——网信办、工信部、公安部、市场监管总局相关规定，只描述规则、不写条号，标 [模型知识 — 需验证] [待验证]；四、国家标准——GB/T 35273、GB/T 22239 等，编号、发布年份、推荐性 / 强制性一律标 [待验证]；五、平台技术规范——SKILL.md、plugin.json、安全审查标准、语义化版本、marketplace.json；六、案例与学说一律标 [待验证]。五个来源标签（[平台规范] [安全标准] [网络搜索 — 需验证] [模型知识 — 需验证] [用户提供]），每条引用必须且只能附一个，[模型知识 — 需验证] 在依赖前须对照原始来源。成文法优先：不得以案例或处罚决定替代法条，法条缺失时须写明「无直接成文法规定，参照以下标准 / 规范」；安全审查须同时引用技术依据（OWASP Top 10、GB/T 标准）和法律依据（PIPL、DSL）；许可证引用须注明完整许可证文本来源。

05不做什么

  • 不自动安装任何未经用户确认的技能
  • 不绕过安全审查流程
  • 不保证第三方技能的质量或安全性
  • 不替代用户对技能适用性的独立判断
  • 安全审查只针对提交时的代码快照，不替代运行时安全监控；技能更新后须重新审查（配置模板审查者注释块）
