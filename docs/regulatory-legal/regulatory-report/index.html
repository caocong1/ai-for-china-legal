01概要

帮助企业及其律师、合规官、法务依法起草向监管机关报送的五类报告（定期报告、专项报告、重大事项报告、整改报告、自查报告），立足事实准确、合规声明有据、如实报送。开始前读取 regulatory-legal/CLAUDE.md 的所属行业、主管监管机关、服务立场、监管关系、合规严格度、监管报告风格、风险校准与升级矩阵；配置缺失时以临时模式运行（监管报告起草立场、律师角色、合规严格度保守）。流程分四步：按行业—报告映射表与五类报告对照表识别报送义务的来源、频率、时限、格式与触发事件；按数据收集清单、溯源五要素与来源可靠性分级核实数据，构建事实时间线并做五项一致性校验；按十章通用结构起草正文，做术语规范与七项客观性自查；最后强制先做虚假报告法律风险提示，再出合规声明、签章要素、报送清单与归档清单。全程拒绝瞒报、漏报、伪造，报送期限不足 3 个工作日即标紧急，行刑衔接时暂停报送并强制升级律师；非律师角色在报告定稿报送、合规声明签署、整改报告报送前须经执业律师确认。

02适用与边界

适用场景

  • 企业须按法定周期报送年度、半年度、季度、月度等定期报告
  • 发生重大安全事故、数据泄露、产品质量事件、环境污染事件等，须报送专项报告
  • 发生重大诉讼、重大行政处罚、重大股权变更、重大关联交易、经营许可证变更等，须报送重大事项报告
  • 收到处罚决定、整改通知或监管约谈要求后，须在整改期限届满前报送整改报告（衔接行政处罚应对流程）
  • 监管机关要求或企业主动开展合规自查后，须形成自查报告或合规评估报告（衔接合规体系建设流程）
  • 新规改变报送口径、频率、渠道或新增报告义务时，须重新识别报送义务（衔接监管动态监控流程）

不做什么

  • 不提供瞒报、漏报、伪造或篡改数据、规避报送义务、隐瞒已知问题的方法；识别即拒绝并标 [合规边界 — 拒绝]
  • 不以估算、推测替代无法获取的实际数据，不编造日期或事实
  • 不伪造签章，不在合规声明中使用模糊表述
  • 不替代刑事辩护：报告虚假且情节严重可能构成犯罪时暂停报送、强制升级律师并提示刑事合规插件（criminal-compliance）
  • 不硬写行业规章文号、报送天数、罚款数额、国家标准号；具体报告类型、频率、格式须到各监管机关官网核实
  • 不替非律师角色定稿：报告定稿报送、合规声明签署、整改报告报送前须经执业律师确认

03输入与产出

需要律师提供

  • regulatory-legal/CLAUDE.md 实践配置必需
    我们是谁（所属行业、主管机关、业务模式、规模、重点监管风险领域、历史受罚情况）、合规与监管立场、文书风格中的监管报告风格、谁在使用（角色）、风险校准、升级矩阵；不存在或含 [PLACEHOLDER] 时进入临时模式
  • 所属行业与主管监管机关（中央·地方）必需
    决定适用的报告类型与报送义务范围；不得猜测行业后静默进行
  • 报告类型或触发事件说明、监管通知或检查文书可选
    个案文书中责令限期报送的义务标 [用户提供]
  • 报告所需原始数据与凭证：财务记录、内部系统导出、第三方机构报告、监管文书、公开信息必需
    每项数据须能指向具体文件编号、页码、行次和责任人；无法获取的标 [数据不可获取]
  • 上期同类报告可选
    用于跨报告同期数据与口径一致性校验；口径变更须说明原因与影响
  • 合规体系建设与处罚应对流程的产出可选
    合规风险识别结果、合规制度文件、合规评估结果、整改闭环记录；处罚决定中的责令改正义务、陈述申辩中确认的事实、从轻减轻事由中的整改措施
  • 监管机关固定报告模板、报送指南可选
    有模板时以模板为准调整结构 [待验证 — 模板须核实现行版本]
  • 签章授权书、报送渠道信息、监管机关联系人可选
    第 4 步签章与报送确认使用

产出

  • 监管报告类型与报送义务识别报告给律师内部
    行业与监管机关 → 五类报告识别表（是否适用、具体名称、义务来源、频率/时限、格式）→ 报送义务来源分层追溯（法律·行政法规 / 部门规章 / 规范性文件 / 地方）→ 触发事件清单 → 下一步建议
  • 数据收集与事实梳理报告给律师内部
    数据收集清单 → 数据溯源表 → 事实时间线 → 数据一致性校验 → 数据不可获取 / 矛盾说明 → 下一步建议
  • 监管报告草稿给监管机关（定稿前为律师内部草稿）
    封面（报告名称、报送单位与统一社会信用代码、报送机关、报告期间、报送日期）→ 概述 → 基本情况 → 事实陈述 → 合规说明 → 问题与不足 → 整改措施与计划 → 结论 → 附件清单
  • 合规声明与报送完成报告给律师内部 / 企业；其中合规声明面向监管机关
    虚假报告法律风险提示与告知确认日期 → 合规声明 → 签章记录 → 报送记录（方式、日期、回执编号）→ 归档清单 → 后续事项

04开始前

前置条件

  • 读取 regulatory-legal/CLAUDE.md 七项配置：执业角色与企业画像、服务立场、监管关系、合规严格度、监管报告风格、行政违法风险校准、升级矩阵（强制升级条件与角色权限表）
  • 配置不存在或含 [PLACEHOLDER] 时，提示运行 /regulatory-legal:cold-start-interview，或由用户说明服务立场与所属行业后以临时模式继续：监管报告起草立场 / 律师角色 / 合规严格度保守 / 所属行业与主管监管机关按用户陈述逐案判断 / 识别重大处罚或行刑衔接即强制升级；输出标 [临时模式 — 请运行冷启动访谈完成配置]；监管报告风格缺失时默认客观准确、不夸大、如实陈述
  • 确认已读取所属行业与主管监管机关；画像缺失时提示补充，不得猜测行业后静默进行
  • 明确告知当前服务立场；缺失时默认监管报告起草，并按用户陈述逐案判断
  • 读取引用规范（legal-basis-conventions.md）、行政法引用库（administrative-law-citations.md）与配置契约（practice-profile-schema.md）
  • 后一步以前一步产出为输入：数据梳理读取报告类型识别结果，起草读取识别结果与数据梳理结果，合规声明与报送在报告定稿后进行

硬性规则

企业画像与所属行业确认
行业决定适用的报告类型与报送义务范围，画像缺失时显式提示用户补充
服务立场决定起草侧重
监管报告起草：各类报告，侧重事实准确、合规声明、如实报送；行政处罚应对：侧重整改报告，衔接处罚应对流程；合规体系建设：侧重自查报告与合规评估报告，衔接合规体系建设流程；监管动态监控：侧重新规驱动的报告义务更新，衔接监管动态监控流程
监管报告文书风格
客观准确、不夸大、如实陈述；术语规范；数据口径一致；合规声明有据可查
监管合规边界
绝不提供瞒报漏报方法、伪造或篡改数据与事实的建议、规避报送义务的方法、在报告中隐瞒已知问题的建议，或任何以「合规」为名实质虚假报送的方法；识别即拒绝并标 [合规边界 — 拒绝]，提示依法合规、如实报送
行刑衔接升级
报告内容虚假且情节严重可能构成犯罪，或行政违法可能升格刑事时：强制升级执业律师、标 [强制升级 — 行刑衔接]、暂停报送流程、提示刑事合规插件；本护栏凌驾于服务立场与合规严格度之上，不可被配置覆盖
报送时限
识别报送义务后必须确认截止日并评估剩余天数；不足 3 个工作日标「紧急」，已过期标「紧急 — 报送期限已逾期」；具体期限天数须核实 [待验证]，不写裸数字
律师审查
非律师角色（合规官、法务、当事人）在监管报告定稿报送、合规声明定稿与签署、整改报告定稿报送前必须暂停并升级执业律师确认
目的地 / 特权检查
面向监管机关的监管报告、自查报告、整改报告、合规声明可能影响特权保护，须提供内部律师工作草稿与对外提交正式版两套选项；对外材料须真实准确，虚假报送构成违法
地方差异与引用纪律
涉及具体地区标 [地方 flagged — 需核实地方性法规与地方裁量基准]；行政处罚法只用 2021 修订后新条号并标「建议复核」；行业规章、规范性文件、裁量基准描述规则加 [待验证]；国家标准号与案例案号一律 [待验证]，不臆造标准号

05执行步骤

共 4 步，按执行顺序。每步旁边（窄屏在步骤说明之后）是请律师核对的内置假设，可逐条复制。页面里的英文标记见首页「标记与术语」。

  1. 报告类型与监管要求识别

    /regulatory-legal:report-type-requirement-identification可单独运行

    根据所属行业与主管机关，识别企业须报送的报告类型，追溯每项报送义务的法定来源，明确报送频率、截止日期、格式要求与接收机关，并识别触发专项报告、重大事项报告、整改报告的事件。

    请律师核对

    • 核对 1.19 个行业的典型报告清单是否覆盖贵方客户？是否有遗漏的高频报告？
    • 核对 1.2以行政处罚法第4条（处罚法定）作为「报送义务须有法定依据」的总原则，这一类推是否妥当？
    • 核对 1.3重大事项报告的五类触发事件中「重大」如何认定，原文未规定，是否需要补充标准？

    做法

    1. 读取配置中的所属行业（核心变量）、主管监管机关（中央·地方）、业务模式、规模、重点监管风险领域、服务立场、合规严格度、监管关系、角色与升级矩阵；含占位符时以临时模式运行（合规严格度保守，行业与机关按用户陈述逐案判断），所属行业为占位符时提示用户确认，不得猜测。
    2. 按行业—报告映射表确定典型主管机关与典型报告类型；跨行业混合业务按主要行业与次要行业分别识别，确保不遗漏。
    3. 按五类报告对照表逐一判断是否适用：定期报告（按法定周期，无论是否发生特定事项均须报送，频率为年度、半年度、季度、月度）；专项报告（针对特定事项或领域，触发事件发生后规定时限内）；重大事项报告（知悉重大事项后规定时限内）；整改报告（整改期限届满前报送整改完成情况）；自查报告（监管机关要求或企业主动自查，要求时限内）。
    4. 对每项义务分层追溯来源：法律、行政法规（到 https://flk.npc.gov.cn 核实）、部门规章（报告格式、渠道、具体时限）、规范性文件（通知、指南、模板）、地方性法规与地方规章（标 [地方 flagged]）、监管通知或检查文书（个案义务，标 [用户提供]）。
    5. 列出触发事件：专项报告——重大安全事故、数据泄露、产品质量事件、环境污染事件（部分行业要求立即报告 [待验证]）；重大事项报告——重大诉讼、重大行政处罚、重大股权变更、重大关联交易、经营许可证变更（部分事项须事前报告 [待验证]）；整改报告——收到行政处罚决定、监管检查整改通知、监管约谈要求。
    6. 报送频率、截止日期、格式一律以规则描述记录并标 [待验证]；用户口述截止日期或文号的标 [待验证]，提示核实现行版本，不写入裸数值。
    7. 监管关系为被动应对时优先识别整改报告义务并检查是否已逾期；发现逾期未报的标「紧急 — 报送时限已过」，提示逾期后果并建议立即联系执业律师。
    8. 按模板输出识别报告，建议下一步进入数据收集与事实梳理，或转监管动态监控、合规体系建设流程。

    内置规则

    • 行业—报告映射（均 [待验证]）：制造业——安全生产定期报告、排污许可执行报告、产品质量报告；互联网平台——数据安全报告、个人信息保护合规报告、算法备案报告；金融机构——定期监管报告、重大事项报告、风险事件报告；药品医疗器械——不良反应报告、生产经营年度报告、召回报告；食品饮料——食品安全自查报告、生产许可年度报告；房地产建设——建设工程质量报告、环保验收报告；能源化工——安全生产报告、排污报告、重大危险源报告；广告传媒——广告经营年度报告、内容安全报告；贸易——进出口合规报告、产品质量报告。
    • 典型主管机关：制造业为市场监管总局、应急管理部、生态环境部；互联网平台为网信办、市场监管总局；金融机构为金融监管总局、人民银行、证监会；房地产建设为住建部、生态环境部、应急管理部；贸易为市场监管总局、海关总署。
    • 格式要求：定期报告、整改报告通常有固定格式模板，专项报告通常有规定格式，重大事项报告通常无固定模板但须载明事项要素，自查报告通常有自查清单模板（均 [待验证]）。
    • 报送义务必须有法定依据；无法确认来源的标 [待验证 — 义务来源须核实]，不得臆造文号或条文；监管机关信息不完整时标注缺失维度（如「地方监管机关未确认，地方性报告义务待补充」），不静默填补；规章信息不足的标 [待补充 — 须核实监管规章]。
    • 整改报告的义务来源之一为行政处罚法第28条（责令改正，建议复核）；用户使用旧版条号时提醒 2021 修订已重排。
    • 用户要求瞒报漏报或伪造识别结论的拒绝并标 [合规边界 — 拒绝]；识别到虚假报告可能构成犯罪的标 [强制升级 — 行刑衔接]。

    法律依据

    • 《行政处罚法》第28条 — 责令改正，整改报告义务来源之一（已核实锚点（中度把握），建议复核）
    • 《行政处罚法》第4条 — 处罚法定，用作报送义务须有法定依据的总原则（建议复核）
    • 各行业前置法律与国务院条例 — 定期、专项、重大事项报告的义务来源 [待验证]
    • 市场监管、网信、金融、药监、生态环境、应急管理六领域报告规章 — [待验证 — 行业监管规章快速演进，须核实现行版本]
    • 各监管机关报告模板与填报指南、各地地方性法规与地方监管通知 — [待验证] [地方 flagged]
    • 企业合规管理体系国家标准（GB/T [待验证]）— 应包含监管报告义务的识别与管理机制；学说一项（报送义务源于法律、法规、规章的明确规定，无法律义务不得强加报送要求）[待验证]

    产出

    《监管报告类型与报送义务识别报告》：工作产物标题（律师版 / 非律师版）与审查者注释块；抬头列编制日期、适用主体、主管机关、服务立场、合规严格度；第一节行业与监管机关；第二节五类报告识别表（是否适用、具体名称、义务来源、频率/时限、格式）；第三节报送义务来源分层追溯；第四节触发事件清单；第五节下一步建议。

  2. 数据收集与事实梳理

    /regulatory-legal:data-fact-gathering可单独运行

    确保报告依据的数据与事实真实、准确、完整、可追溯：定义每项数据的口径，核实来源与责任人，构建有证据支撑的事实时间线，并做交叉一致性校验；绝不捏造、篡改、虚构数据或事实。

    请律师核对

    • 核对 2.1来源可靠性分级（当事人陈述为「低」、内部系统数据为「中」）是否同意？
    • 核对 2.2禁止估算的唯一例外是「行业规范允许合理估算且已注明」，是否足够？
    • 核对 2.3平衡型、务实型的核验标准原文未规定，是否需要补充？
    • 核对 2.4以行政处罚法第54条（行政机关调查取证）作为企业数据收集须符合法定程序的依据，是否妥当？

    做法

    1. 读取配置（所属行业、主管机关、业务模式、规模、重点监管风险领域、服务立场、合规严格度、监管关系、角色、升级矩阵）与上一步的报告类型识别结果，据此列出本报告需要的数据项目。
    2. 填写数据收集清单：每项数据写明口径定义（计算口径或统计方法）、统计范围、时间区间、数据来源与来源状态（已确认 / 待确认 / 不可获取）；同一报告中同名数据项必须使用同一口径，不得在不同章节使用不同口径。
    3. 逐项建立溯源链五要素：原始来源文件（具体到文件编号、页码、行次）、数据生成时间（须与报告时间区间一致）、数据责任人（具体人员或部门）、提取方式（系统导出 / 手工摘录 / 计算得出）、核验状态（已核验 / 未核验 / 存在矛盾）。
    4. 按来源可靠性分级确定核验要求（见规则）；当事人陈述须以书面记录或客观证据印证。
    5. 构建事实时间线（序号、时间节点、事件描述、证据或来源、涉及主体、法律意义），遵守五条规则：客观性（只记可证实的事件，不记推测、传言、主观判断）、完整性（不遗漏影响结论的关键事件）、精确性（精确到日，不能确定的标 [日期待确认]）、关联性（标注与报告主题的关联）、证据对应（无证据的标 [待补充证据]）。
    6. 执行五项一致性校验：同一数据在不同章节是否一致（数值对比）、时间序列是否连续（趋势检查）、合计与分项是否一致（加总验证）、与其他报告同期数据是否一致（横向对比）、数据与时间线事实是否一致（逻辑验证）。
    7. 按不一致类型处理：口径差异——统一口径后重算并注明口径调整；数据错误——以原始凭证为准更正并注明原因与依据；数据缺失——标 [数据不可获取] 并评估对完整性的影响；无法解释的矛盾——标「数据矛盾 — 须查明后方可入报告」，不得写入报告；时间线逻辑矛盾标「时间线矛盾」并核查证据。
    8. 按模板输出数据收集与事实梳理报告；所有数据须由数据责任人确认后才能写入正式报告，需要律师审核数据结论的升级执业律师。

    内置规则

    • 来源可靠性分级：企业正式财务记录（经审计的财务报表、银行对账单）高，须核对原始凭证；监管机关文书（处罚决定书、检查通知、许可证书）高，以原件为准；第三方机构报告（审计、检测、鉴定报告）中-高，须核实机构资质与报告有效期；企业内部系统数据（ERP、CRM、生产管理系统）中，须核实完整性与准确性；公开信息（企业公示信息、行业统计数据）中，须核实来源与时效；当事人陈述（口头陈述、未经证实的说明）低。
    • 无法核验的数据一律标注 [未发明]，不得以推测、估计替代实际数据；不可获取的数据标 [数据不可获取 — 须说明原因并评估对报告完整性的影响]；用户要求以估算替代时标 [数据不可获取 — 须以实际数据为准]，除非行业规范允许合理估算且已注明。
    • 原始记录已灭失的标 [数据不可获取 — 原始记录灭失]；数据来源有多个版本的，以最新、最权威的为准并注明版本差异与选取理由。
    • 口径与上期报告不一致的标 [口径变更 — 须说明变更原因与影响]，确保可比性。
    • 数据涉及商业秘密或敏感信息的，提醒数据保护义务，向监管机关报送时评估是否需要保密处理。
    • 合规严格度影响核验标准：保守型要求全部数据交叉核验。
    • 用户要求篡改、虚构数据或伪造事实的拒绝并标 [合规边界 — 拒绝]，提示虚假报送的法律后果；识别到行刑衔接风险立即标 [强制升级 — 行刑衔接]。

    法律依据

    • 《行政处罚法》第28条 — 责令改正，整改报告的事实基础须以事实为依据（已核实锚点（中度把握），建议复核）
    • 《行政处罚法》第4条 — 处罚法定，报告内容须以事实为依据、不得虚构（建议复核）
    • 《行政处罚法》第54条 — 行政机关调查取证的法定程序，原文据此要求数据收集须符合法定程序（原文标已核实锚点，建议复核）
    • 各行业数据报告规章、企业数据管理与记录保存规章 — 口径、来源、格式、保存期限与可追溯性要求 [待验证 — 行业监管规章快速演进，须核实现行版本]
    • 各监管机关数据填报指南 — 口径与格式的直接依据 [待验证]
    • 企业合规管理体系国家标准与数据管理国家标准（GB/T [待验证]）— 数据记录、保存、报告机制与数据质量、可追溯规范；学说一项（数据真实性义务是行政法上的法定义务，虚假报送构成独立违法行为并可能构成刑事责任）[待验证]

    产出

    《数据收集与事实梳理报告》：工作产物标题与审查者注释块；抬头列编制日期、适用主体、报告类型、服务立场、合规严格度；第一节数据收集清单；第二节数据溯源表（原始来源文件、来源编号/页码、生成时间、责任人、提取方式、核验状态）；第三节事实时间线；第四节数据一致性校验；第五节数据不可获取 / 矛盾说明；第六节下一步建议（进入起草、补充数据清单与责任人、升级律师审核）。

  3. 报告结构与起草

    /regulatory-legal:structure-drafting可单独运行

    把已核实的数据与事实转化为结构完整、内容准确的报告正文：按通用结构搭框架，逐章起草，统一术语与数据口径，并做客观性自查，消除夸大、缩小与主观评价。

    请律师核对

    • 核对 3.1十章结构与贵所常用监管报告体例是否一致？
    • 核对 3.2把「可能」等表述一律列为主观表述是否过严？对尚未查清的事项应如何措辞？
    • 核对 3.3「问题与不足」以风险识别结果为准，是否要求把全部已识别风险都写入报告？披露范围如何把握？

    做法

    1. 读取配置（所属行业、主管机关、业务模式、规模、服务立场、合规严格度、监管关系、监管报告风格、角色、升级矩阵）以及前两步产出；监管报告风格含占位符时默认客观准确、不夸大、如实陈述，术语规范，数据口径一致，合规声明有据可查。
    2. 按十章通用结构搭建框架；监管机关有固定模板的以模板为准调整并注明依据 [待验证 — 模板须核实现行版本]；按报告类型调整重心：定期报告多用规定的固定结构，专项报告按专项事项特点调整，整改报告突出整改措施与完成情况，自查报告突出自查发现的问题与整改计划。
    3. 逐章起草：概述交代报送义务的法律依据与报告期间、范围；事实陈述按上一步时间线叙述并附数据来源；合规说明以制度文件索引与执行记录为准；问题与不足以合规体系建设流程的风险识别结果为准；整改措施每项附具体时限与责任人；结论须有前文事实支撑。
    4. 只使用已核验数据起草；数据梳理结果不完整的章节标 [待补充数据]；数据与时间线有未解决矛盾的，暂停相关章节，标「数据矛盾未解决」，返回上一步核实。
    5. 术语规范化：法律术语用法定表述，监管术语用规章术语，数据写成「截至[日期]的[口径]数据」，时间写明确起止日期，主体用法定全称或经备案的简称。
    6. 逐项完成七项客观性自查（逐段、逐条核查），发现夸大、缩小或主观评价的立即修正并记录修正前后对比，修正后方可进入下一步。
    7. 按模板输出报告草稿，提示非律师角色定稿前须升级执业律师确认，定稿后进入合规声明与报送。

    内置规则

    • 十章结构与起草原则：封面（报告名称、报送单位、报送机关、报告期间、报送日期、密级；部分机关有固定封面模板 [待验证]）；目录（篇幅较短可省略）；概述/前言（须注明报送义务的法律依据 [待验证]）；基本情况（客观陈述，不夸大不缩小）；事实陈述（以事实为依据，附证据来源）；合规说明（有据可查，附制度文件索引）；问题与不足（如实陈述，不回避、不夸大，不得隐瞒已知问题）；整改措施与计划（具体、可验证、附时限）；结论（客观审慎，结论有事实支撑）；附件（完整、编号、与正文对应）。
    • 常见错误与避免方法：概述遗漏报送依据、范围不清——引用法定义务来源并写明起止日期；基本情况夸大规模或合规水平——以工商登记、财务数据等客观来源为准；事实陈述时间线混乱、来源不明——引用事实时间线；合规说明虚构制度、夸大效果——以制度索引与执行记录为准；问题与不足隐瞒或淡化——以风险识别结果为准；整改措施空泛、无时限无责任人；结论超出事实支撑。
    • 术语示例：用「责令改正」不用「让改」，用「行政处罚」不用「被罚」，用「合规管理体系」不用「守规矩的制度」，用「2025年1月1日至2025年12月31日」不用「去年」，用「[企业全称]」不用「我司」。
    • 客观性自查七项：是否夸大事实（有无证据支撑、形容词堆砌）；是否缩小或淡化问题（问题描述是否完整、有无弱化措辞）；是否以「我认为」「应该」「可能」等主观表述代替客观陈述；数据是否有来源、口径一致、表述精确；每项合规声明能否在合规说明或附件中找到依据；结论是否引入前文未涉及的事实或判断；法律条文引用是否准确、是否为 2021 修订后新条号。
    • 须披露不利事实时如实披露，标 [合规边界 — 不得隐瞒已知问题]；用户要求夸大合规成果、隐瞒问题或伪造报告内容的拒绝并标 [合规边界 — 拒绝]，提示虚假报送的法律后果。
    • 用户口述行业规章文号的标 [待验证]，不写裸文号；用户要求使用旧版行政处罚法条号的提醒改用新条号并标「建议复核」；报告涉及行刑衔接风险的标 [强制升级 — 行刑衔接]。

    法律依据

    • 《行政处罚法》第28条 — 责令改正，整改报告起草的义务来源之一（已核实锚点（中度把握），建议复核）
    • 《行政处罚法》第4条 — 报告内容须有事实与法律依据（建议复核）
    • 各行业国务院条例、报告格式与内容规章、报告模板与填报指南 — 结构与格式要求的直接依据 [待验证 — 行业监管规章快速演进，须核实现行版本]
    • 各监管机关报告编写指南、各地地方报告结构要求 — [待验证] [地方 flagged]
    • 企业合规管理体系国家标准（GB/T [待验证]）— 合规管理体系中的报告与沟通机制；学说一项（报告须客观、真实、完整，不得作虚假陈述或重大遗漏）[待验证]

    产出

    监管报告草稿（标题注明「草稿」）：工作产物标题；抬头列编制日期、报送单位、报送机关、报告期间、服务立场、合规严格度；封面（含统一社会信用代码）、概述、第一节基本情况、第二节事实陈述、第三节合规说明、第四节问题与不足、第五节整改措施与计划、第六节结论、附件清单（名称、编号、对应正文章节）；文末提示非律师角色定稿前须经律师确认，定稿后进入合规声明与报送。

  4. 合规声明与报送

    /regulatory-legal:compliance-statement-submission可单独运行

    报告定稿报送前，先强制告知虚假报告的法律后果并取得知悉确认，再完成合规声明、签章、报送渠道确认、回执获取与归档。

    请律师核对

    • 核对 4.1合规声明第一条的固定措辞，以及第四条在对外声明中写入「刑事责任」，是否适合提交监管机关？
    • 核对 4.2风险提示表的严重程度分级与刑事罪名举例（提供虚假证明文件罪、妨害公务罪）是否需要调整？
    • 核对 4.3第48条（处罚信息公开）被标为「已核实锚点」，但不在引用规范列出的锚点之内，请核实条号与表述。
    • 核对 4.4签章四要素（部门章不得替代公章、骑缝章 [待验证]）是否符合贵所经验？

    做法

    1. 读取配置（所属行业、主管机关、业务模式、规模、服务立场、合规严格度、监管关系；「谁在使用」的角色决定标题、升级路由与签章权限；升级矩阵与角色权限表）。
    2. 强制前置：向报送主体逐项告知虚假报告法律风险提示表的八类后果，并确认其已知悉；用户要求跳过的拒绝，此步不可省略。
    3. 列明行政处罚法第9条六类处罚种类，提示均可能因虚假报告而适用，具体以行业规章为准 [待验证]；识别到虚假且情节严重可能构成犯罪的，立即标 [强制升级 — 行刑衔接] 并暂停报送流程。
    4. 按模板起草合规声明：报送单位与统一社会信用代码、报告名称、报告期间、报送机关，四条声明内容，法定代表人或授权代表人签字、单位盖章、日期；非律师角色在合规声明定稿前必须暂停并升级执业律师确认。
    5. 确认签章四要素：法定代表人或书面授权代表人签字（授权书留存备查）；单位公章（不得用部门章替代，部分机关要求加盖多枚印章 [待验证]）；多页报告骑缝章（部分机关要求 [待验证]）；签署日期须在报送期限前。
    6. 逐项确认报送流程清单七项：报送机关与具体处室；报送方式（线上系统 / 邮寄 / 现场提交 / 电子邮件）[待验证]；正副本份数 [待验证]；纸质版、电子版或两者兼有 [待验证]；报送期限 [待验证]；报送地址或系统名称；监管机关联系人与联系方式。渠道不确定的标 [待验证 — 报送渠道须核实]，建议通过监管机关官网确认。
    7. 检查报送期限：不足 3 个工作日标「紧急 — 报送期限临近」并建议立即报送；已过标「紧急 — 报送期限已逾期」，提示逾期后果并建议立即联系执业律师评估补救途径。
    8. 报送后获取回执并按六项归档清单归档；回执未获取的标 [待获取 — 报送回执] 并跟进。
    9. 按模板输出合规声明与报送完成报告；后续事项包括保存回执与签收凭证、跟踪监管机关审查反馈、如有整改要求转合规体系建设流程启动整改闭环、如需更新配置重新运行冷启动访谈。

    内置规则

    • 合规声明四条：一、本报告所载内容真实、准确、完整，不存在虚假记载、误导性陈述或重大遗漏；二、所依据的数据均来源于可追溯的原始记录，数据口径一致，计算方法符合[行业监管规章名称/标准名称] [待验证]；三、本报告已经本单位[内部审核程序]审核；四、本单位知悉提供虚假报告、重大遗漏、伪造数据将承担相应法律责任，包括但不限于行政处罚、信用惩戒、刑事责任。
    • 归档清单六项：报告定稿（签章版）、合规声明、报送回执或签收凭证、附件材料、内部审核记录、虚假报告法律风险提示确认记录。
    • 报送主体拒绝签署合规声明的，提示不签署的后果（无法完成报送义务）；若是知悉后果后仍坚持虚假内容，标 [合规边界 — 拒绝]。
    • 发现报告内容可能存在虚假时立即暂停报送并标 [合规边界 — 报告内容存疑]，查明后再决定是否报送；审核中发现错误的，返回起草步骤修正后重新进入本步骤。
    • 要求在合规声明中使用模糊表述（声明须明确、具体、无歧义）、隐瞒已知问题后报送、伪造签章（本身构成违法）、瞒报漏报的，一律拒绝并标 [合规边界 — 拒绝]；用户口述罚款数额或文号的标 [待验证]，不写裸数值。

09何时暂停或升级

  • 报告内容虚假且情节严重可能构成犯罪，或行政违法可能升格刑事：暂停报送流程，标 [强制升级 — 行刑衔接]，升级执业律师并提示刑事合规插件
