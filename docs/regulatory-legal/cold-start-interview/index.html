01概要

通过四段结构化访谈（共 37 问），把企业画像与主管监管机关、服务立场与合规严格度、监管关系、风险等级与升级规则、文书风格与监管资源写入 regulatory-legal/CLAUDE.md，完成监管合规实践配置的初始化或增量更新；之后监管动态监控、行政处罚应对、合规体系建设、监管报告起草四条流程都从这份文件读取配置。访谈按「身份与企业画像 → 合规立场与服务范围 → 风险与升级 → 文书风格与监管资源」顺序进行：先检查配置文件是否存在（不存在则从模板创建、全部字段为 [PLACEHOLDER]；已存在则读取现有值作为默认值进入增量更新），每步按问卷提问、按写入映射表写入对应章节、展示写入摘要经确认后再进入下一步，全部完成后输出更新摘要并建议提交 git。对用户口述的条号、文号、罚款数额、程序时限、国家标准号一律做合理性检查并标 [待验证]，不写裸数字；行刑衔接强制升级与行政程序时限护栏是不可协商护栏，访谈只允许补充触发场景、不允许关闭。README 估计首次访谈约 10-15 分钟；律师、合规官、法务也可直接编辑配置文件，无需重跑访谈。

02适用与边界

适用场景

  • 首次使用监管合规插件，regulatory-legal/CLAUDE.md 仍是带 [PLACEHOLDER] 的模板
  • 其他监管合规流程检测到配置缺失或关键字段（执业角色、所属行业与主管监管机关、整体服务立场、监管关系、使用者角色）含占位符，提示运行冷启动访谈或进入临时模式时
  • 企业进入新行业、主管监管机关变化、团队角色变动、服务立场转变后需要全量更新（参数「更新」进入增量更新模式）
  • 只需更新某一章节：参数「身份与企业画像」「合规立场与服务范围」「风险与升级」「文书风格与监管资源」分别只运行对应步骤
  • 企业从主动合规转为被动应对（收到处罚决定或检查通知）时，更新监管关系字段以触发更强的程序时限护栏

不做什么

  • 不做任何具体事项的合法性审查、监管动态分析、制度起草或报告起草，只收集并写入配置
  • 不生成独立 YAML 或 JSON 配置文件；regulatory-legal/CLAUDE.md 是所有流程读取立场与配置的唯一来源
  • 不修改「输出」「事项工作区」「审查过的种子文档」等非配置章节，这些章节不由访谈写入
  • 不代替律师核实口述的条号、文号、罚款数额、程序时限天数与国家标准号，只做合理性检查并加 [待验证] 标注
  • 不能用来关闭行刑衔接强制升级或行政程序时限护栏，用户提出此类要求一律拒绝
  • 小改动（更新联系人、调整某个默认值）不需要重跑访谈，直接编辑配置文件即可，编辑后各流程自动读取

03输入与产出

需要律师提供

  • regulatory-legal/CLAUDE.md 现有内容（模板或已部分填写）必需
    总流程先检查是否存在：不存在则从模板创建（全部字段 [PLACEHOLDER]），存在则读取并进入增量更新；每步再读取目标章节现有内容作为默认值展示
  • 律师、合规官或法务对 37 个访谈问题的回答必需
    身份与企业画像 13 问、合规立场与服务范围 4 问、风险与升级 5 问、文书风格与监管资源 15 问；多数问题给出选项、追问与默认值，拒答字段写 [PLACEHOLDER] 不阻塞
  • 运行参数：首次运行 / 更新 / 身份与企业画像 / 合规立场与服务范围 / 风险与升级 / 文书风格与监管资源可选
    留空或「首次运行」执行完整四步；「更新」只改用户选择的章节；章节名只运行对应步骤
  • 已收到的处罚决定、检查通知的送达日期与文书编号可选
    监管关系选「被动应对」时在第 2 步追问，用于计算程序时限；文书编号标 [待验证]；未提供送达日期则附 [待补充 — 送达日期未提供，程序时限待计算]
  • 行业特殊风险触发情形、团队额外角色、内部额外升级场景、常用程序时限速查表、额外时限触发节点可选
    第 3 步追问时提供，只能作为法定护栏的补充写入
  • 特定法院或复议机关的文书格式要求、特定监管机关的报告模板、所在地裁量基准与地方性法规信息可选
    第 4 步追问时提供，用于定制文书风格与地方差异提示

产出

  • 更新后的 regulatory-legal/CLAUDE.md给律师内部
    替换 [PLACEHOLDER] 后的章节：我们是谁（组织名称、实体类型、执业角色、主要服务事项、企业画像 11 项）/ 谁在使用（角色、律师联系人）/ 合规与监管立场（整体服务立场、合规严格度与保守型重点、监管关系、侧重方面补充说明）/ 行政违法风险校准（四级表确认或调整版）/ 升级矩阵（角色权限表、补充强制升级触发条件、补充时限节点与计算规则说明）/ 文书风格（四类风格与存放位置）/ 可用集成（中央与地方监管机关、复议机关、审判法院、行业协会、法规数据库、鉴定检测审计机构、文档存储、企业微信/钉钉）/ 共享护栏 → 地方性法规与裁量基准提示（所在地、裁量基准差异、地方性法规差异）
  • 每步写入内容摘要给律师内部
    每个步骤写入后向用户展示本步写入的字段与取值，确认无误后进入下一步；口述数字带 [待验证]、[待验证 — 地方 flagged]、[待验证 — 标准号须核实] 等标注
  • 完成后的配置更新摘要给律师内部
    列出所有已填写或更新的字段；提示可直接编辑 CLAUDE.md 微调、可重跑访谈更新特定章节；建议执行 git add regulatory-legal/CLAUDE.md 与 git commit -m "更新监管合规实践配置" 以追溯配置变更

04开始前

前置条件

  • 开始前检查 regulatory-legal/CLAUDE.md 是否存在：不存在则从模板创建（入口称使用 references/ 目录下的模板或内嵌默认结构），所有字段为 [PLACEHOLDER]；已存在则读取现有内容进入增量更新模式
  • 配置文件格式异常（章节缺失）时，先识别已有章节，对缺失章节用 [PLACEHOLDER] 补充并告知用户，再开始访谈
  • 第 2 步前须完成第 1 步或「我们是谁」章节已填写（服务立场推荐依赖其中的主要服务事项与痛点）
  • 第 3 步前须完成第 1、2 步：执业角色、服务立场与合规严格度已确定
  • 第 4 步前须完成第 1、2 步：所属行业、主管监管机关与服务立场已确定；未完成时基于行业默认值推荐监管机关与法规数据库，经确认后写入
  • 每步开始先读取目标章节现有内容，作为默认值展示给用户确认或修改

硬性规则

唯一真相来源
访谈结果写入 regulatory-legal/CLAUDE.md 各章节，不生成独立 YAML 文件；配置文件是所有监管合规流程读取立场与配置的唯一来源
写入前确认
不覆盖用户未确认的内容：每个步骤写入前须经用户确认，写入后展示摘要
不动非配置章节
「输出」「事项工作区」「审查过的种子文档」等章节不由访谈写入，不修改、不删除
法律事实验证
用户口述的条号、文号、罚款数额、时限、标准号一律标 [待验证]，不写入裸数字：行政处罚法旧版（2021 修订前）条号提醒更新为新条号并以规则描述方式记录；罚款数额与地方裁量基准标 [待验证 — 地方 flagged]；国家标准编号标 [待验证 — 标准号须核实]；程序时限天数提示以正式送达文书日期为起算点核实
不可协商护栏
行刑衔接强制升级与行政程序时限护栏不可通过配置关闭，仅可补充触发场景；增量更新时法定护栏部分只允许补充不允许删除；强制升级护栏凌驾于服务立场与合规严格度之上，即使选「务实型」仍须升级
增量更新只改确认字段
增量更新模式仅替换用户确认修改的字段，其余保留原值；单章节更新只运行对应步骤、只改对应章节
中断可恢复
访谈中用户中断时，已写入的内容保留，下次运行从断点继续或重新运行该步骤
拒答不阻塞
用户拒绝回答某字段时写入 [PLACEHOLDER]，不阻塞后续访谈；无法确定主管监管机关时按行业列出候选供选择，仍未确定写 [待确认]

05执行步骤

共 4 步，按执行顺序。每步旁边（窄屏在步骤说明之后）是请律师核对的内置假设，可逐条复制。页面里的英文标记见首页「标记与术语」。

  1. 身份与企业画像访谈

    /regulatory-legal:identity-enterprise-profile可单独运行

    采集组织与执业角色、企业画像（所属行业与主管监管机关为核心变量）和实际使用者信息，写入「我们是谁」与「谁在使用」两章，使后续流程能据此识别行业规则源、确定处罚决定来源与复议机关、选择裁量基准版本、按角色选择工作产物标题与升级路由。

    请律师核对

    • 核对 1.1执业角色七选项（监管合规律师 / 企业合规官 / 企业法务 / 当事人本人有或无律师 / 非律师有或无律师联系人）是否覆盖贵所实际？配置文件「谁在使用」章节的角色选项只列了六项，缺「非律师且无律师可咨询」，两处宜统一。
    • 核对 1.2重点监管风险领域预设八项（反垄断 / 数据安全与个人信息保护 / 广告 / 产品质量 / 安全生产 / 环保排污 / 食品药品安全 / 金融业务许可），是否要补充价格、反不正当竞争、海关与外汇、劳动用工、消费者权益等领域？
    • 核对 1.3写入映射表含「服务事项（初步）」写入「主要服务事项」字段，但 13 个问题中没有一问采集它，而第 2 步的立场推荐又依赖它——SKILL.md 未规定如何取值，建议补一问。
    • 核对 1.4「强监管行业」的追问举例为金融·医药·食品·危化品·能源，是否符合贵所对强监管行业的判断？
    • 核对 1.5历史受罚只分「警告或小额罚款」与「重大处罚」两档，SKILL.md 未定义「小额」与「重大」的界线，是否以配置文件的「较大数额罚款」为界？

    做法

    1. 确认 regulatory-legal/CLAUDE.md 存在（不存在则提示由总流程先从模板创建，本步暂停）；增量更新时读取「我们是谁」「谁在使用」现有内容作为默认值展示供确认或修改。
    2. 第一部分基本信息：Q1 组织/律所/企业名称，追问实体类型（律所合规/争议业务部 / 企业合规部 / 企业法务部 / 个人当事人）；Q2 主要执业角色七选一（监管合规律师 / 企业合规官 / 企业法务 / 当事人本人（有律师可咨询）/ 当事人本人（无律师可咨询）/ 非律师但有律师联系人 / 非律师且无律师可咨询），非律师追问律师联系人姓名与联系方式，并告知角色决定输出标题格式（律师工作产物 vs 研究笔记）、升级路由与风险提示强度。
    3. 第二部分企业画像：Q3 所属行业 [核心变量]，追问是否跨行业经营（列出全部相关行业）、是否属强监管行业（金融·医药·食品·危化品·能源等）；向用户说明所属行业决定适用的行业监管规章体系、规则源识别方向与裁量基准适用范围。
    4. Q4 主管监管机关（中央级）[核心变量]，追问是否有多个中央级主管机关（如互联网平台可能同时受市场监管总局与网信办监管）以及地方级主管机关（如 XX 省市场监管局、XX 市网信办）；说明主管监管机关决定处罚决定来源、行政复议机关、规则源官网与裁量基准适用版本。
    5. Q5 企业规模（员工人数、年营业额大致范围；民营 / 国有 / 上市）；Q6 主要业务模式（追问是否有跨境业务或部分涉外）；Q7 是否涉外（是（跨境业务）/ 否 / 部分涉外，默认否），涉外时追问涉及国家或地区、是否涉及出口管制或制裁合规。
    6. Q8 历史受罚情况四选一（无历史处罚 / 曾受警告或小额罚款 / 曾受重大处罚 / 待评估，默认待评估），曾受处罚时追问处罚种类、处罚机关、大致时间；用户提供具体处罚条号或罚款数额时标 [待验证] 并提示核实。
    7. Q9 重点监管风险领域，可从八项选择或补充（反垄断合规 / 数据安全与个人信息保护 / 广告合规 / 产品质量 / 安全生产 / 环保排污 / 食品药品安全 / 金融业务许可）；Q10 当前主要痛点（监管规则变化快跟不上 / 收到行政处罚决定不知如何应对 / 合规体系缺失 / 监管报告规范不清楚）；Q11 团队规模（负责监管合规的律师、合规官、法务各几人）；Q12 负责人/联系人。
    8. 第三部分使用者信息：Q13 谁在使用本插件，追问实际使用者角色与 Q2 是否一致（不一致则分别说明）、非律师使用者是否有律师联系人供审查；默认与 Q2 一致。
    9. 按写入映射表写入 17 个字段：「我们是谁」的组织名称、实体类型、执业角色、主要服务事项（初步）及企业画像 11 项（所属行业、中央与地方主管监管机关、规模、业务模式、是否涉外、历史受罚、重点监管风险领域、主要痛点、团队规模、负责人/联系人）；「谁在使用」的角色与律师联系人。角色为「非律师且无律师可咨询」时在「谁在使用」附加特别提示：所有输出为合规研究，不替代律师意见。
    10. 走检查清单（所属行业与中央主管机关非 PLACEHOLDER、地方机关已填或标不适用、执业角色已确认并告知输出格式与升级路由、非律师已告知研究笔记定性与律师审查要求、受罚条号/数额已标待验证、其余字段已填或明确跳过），向用户展示写入摘要确认。

    内置规则

    • 所属行业与主管监管机关是监管合规工作的核心变量，须在访谈中重点确认，检查清单要求两者不得留 PLACEHOLDER（地方级可标不适用）
    • 执业角色决定输出标题格式（律师工作产物 vs 研究笔记）、升级路由与风险提示强度
    • 用户拒绝回答某字段：写入 [PLACEHOLDER]，不阻塞后续访谈
    • 用户无法确定主管监管机关：根据所属行业列出可能的监管机关供选择，仍未确定则写入 [待确认]
    • 用户提供的处罚条号为 2021 修订前旧版：提醒更新为新条号，标 [待验证]，以规则描述方式记录
    • 用户提供罚款数额但无法确认地方裁量基准：标 [待验证 — 地方 flagged]，不写入裸数字
    • 用户口述国家标准编号：标 [待验证 — 标准号须核实]
    • 增量更新模式仅替换用户确认修改的字段，其余保留原值

    法律依据

    • 《行政处罚法》（2021 修订）— 条号已重排，用户口述的处罚条号须核实是否为 2021 修订后新条号，旧条号提醒更新并标 [待验证]

    产出

    「我们是谁」（组织名称、实体类型、执业角色、主要服务事项、企业画像 11 项）与「谁在使用」（角色、律师联系人）两章的写入摘要，确认后写入 regulatory-legal/CLAUDE.md；非律师且无律师可咨询时附特别提示

  2. 合规立场与服务范围访谈

    /regulatory-legal:compliance-stance-scope可单独运行

    采集整体服务立场（核心变量）、合规严格度、监管关系与分析侧重，写入「合规与监管立场」章节（含「合规严格度」「监管关系」两小节），决定后续各流程的侧重方向、输出格式、时限护栏强度与升级路由。

    请律师核对

    • 核对 2.1访谈默认合规严格度为平衡型，而实践配置契约的临时模式默认保守型——两处默认值不一致是否有意？
    • 核对 2.2保守型的适用场景写为「高风险行业、曾受重大处罚、上市企业」，是否同意把上市企业一律归入保守型？
    • 核对 2.3「有正在进行的处罚事项则行政处罚应对自动提升为高优先级」是否符合贵所对立场排序的做法？
    • 核对 2.4被动应对只以「处罚决定或检查通知」送达为触发，未提及责令改正通知、立案告知、调查询问通知等文书，是否需要扩展触发文书范围？

    做法

    1. 前置检查：第 1 步已完成或「我们是谁」已填写，否则提示先运行身份与企业画像，或跳过前置仅更新本章节；读取「合规与监管立场」现有内容作为默认值。
    2. Q1 整体服务立场 [核心变量] 五选一：监管动态监控（跟踪新规·修订·废止·征求意见稿，输出动态简报与合规义务台账，侧重规则源识别与影响评估）/ 行政处罚应对（已收到处罚决定·检查通知·责令改正，侧重合法性审查·陈述申辩听证·从轻减轻不予处罚争取·复议与诉讼，行政程序时限护栏最强）/ 合规体系建设（以预防行政违法为目标设计制度·流程·组织架构·培训考核，参照企业合规管理体系国家标准）/ 监管报告起草（定期·专项·重大事项·整改·自查报告，侧重事实准确·合规声明·如实报送）/ 混合多类型。
    3. Q1 追问：选混合多类型须按优先级排序主要立场；询问当前是否有正在进行的行政处罚事项，如有则行政处罚应对自动提升为高优先级。默认值：主动合规情形取监管动态监控，被动应对情形取行政处罚应对。向用户说明服务立场决定各流程侧重、输出格式、时限护栏强度与升级路由。
    4. Q2 合规严格度三选一并说明适用场景与效果：保守型（一切疑点从严标红并升级；适用高风险行业、曾受重大处罚、上市企业；效果为任何监管规则疑点即标红、裁量基准疑点零容忍、监管报告每条陈述须可核验）/ 平衡型（重大监管风险标红升级，一般风险提示整改路径；适用一般企业合规管理）/ 务实型（仅拦截明显高风险，一般风险提供可行控制建议；适用小微企业、低风险领域）；选保守型追问特别关注的保守重点领域。默认平衡型。
    5. Q3 监管关系二选一：主动合规（事前主动跟踪与合规建设，无现实处罚风险）/ 被动应对（已收到处罚决定或检查通知，须依法应对）；选被动应对追问处罚决定或检查通知的送达日期（用于计算程序时限）、是否已收到处罚文书及文书编号（标 [待验证]）。默认主动合规。
    6. 被动应对时向用户说明：行政程序时限护栏自动加强——须识别处罚决定送达日期，强标陈述申辩期、听证申请期、复议申请期、起诉期，不得静默放任时限流逝。
    7. Q4 分析侧重多选：行业监管规章变化跟踪与影响评估 / 行政处罚合法性审查与应对策略 / 合规制度设计与流程建设 / 监管报告起草与合规声明核验 / 陈述申辩·听证·复议·诉讼程序支持 / 合规培训与考核体系；默认按 Q1 立场推荐对应侧重。
    8. 按写入映射写入：整体服务立场；「合规严格度」小节的合规严格度与保守型重点；「监管关系」小节；侧重方面写入补充说明。说明服务立场与角色权限的交互影响，走检查清单后展示写入内容确认。

    内置规则

    • 整体服务立场是核心变量：同一企业在不同服务立场下侧重截然不同，须准确选择
    • 有正在进行的行政处罚事项时，行政处罚应对自动提升为高优先级
    • 用户无法确定服务立场：根据第 1 步的主要服务事项与痛点推荐，确认后写入
    • 混合多类型但无法排序：按全部类型等优先级处理，各流程独立判断适用性
    • 主动合规与被动应对可后续切换：允许更新监管关系字段，触发相应护栏强度调整
    • 被动应对但未提供送达日期：写入被动应对状态并附 [待补充 — 送达日期未提供，程序时限待计算]
    • 用户口述处罚条号：标 [待验证]，核实是否为行政处罚法 2021 修订后新条号；口述罚款数额：标 [待验证 — 地方 flagged]，提示核实当地裁量基准
    • 增量更新模式仅替换用户确认修改的字段

    法律依据

    • 《行政处罚法》（2021 修订）— 口述处罚条号须核实是否为 2021 修订后新条号并标 [待验证]
    • 企业合规管理体系国家标准（GB/T）— 合规体系建设立场的参照，标准号在配置文件中标 [待验证]

    产出

  3. 风险与升级访谈

    /regulatory-legal:risk-escalation可单独运行

    确认或调整行政违法风险四级定义、角色权限表、强制升级触发条件与行政程序时限护栏偏好，写入「行政违法风险校准」与「升级矩阵」两章；行刑衔接强制升级与程序时限护栏为不可协商护栏，只能补充触发场景，不能关闭。

    请律师核对

    • 核对 3.1默认「届满前 3 天提醒」是否够用？贵所惯例是否为 5 至 7 天，或按节点类型区别设置？
    • 核对 3.2预设风险四级表把「监管机关已开始检查或问询」「近期同行业执法案例密集」归为高级而非关键级，是否同意？
    • 核对 3.3强制升级五情形中「较大数额罚款」不写数值，留 [待验证 — 地方 flagged]；引用库 H 节已记录政府采购领域为 200 万元以上（财库〔2022〕3 号，已核实 2026-09-13）——是否按贵方行业预填数值？
    • 核对 3.4角色权限表把「企业合规官/法务」合并为一行，是否需要区分合规官与法务、资深与初级？
    • 核对 3.5时限触发升级表四个节点的天数全部 [待验证]，而引用库 I 节已记录法释〔2026〕3号（2026-05-01 施行）的 6 个月/1 年起诉期限、复议决定后 15 日、不作为满 2 个月等已核实期限，以及《行政复议法实施条例》2026 修订后条号全部变化——是否由律师核实后预填入配置，而不是每次留白？

    做法

    1. 前置检查：第 1、2 步已完成（执业角色、服务立场与合规严格度已确定），否则提示先完成或基于默认值运行；读取两章现有内容。
    2. Q1 展示配置文件现有风险等级表并询问是否调整：关键 = 重大行政处罚风险或行刑衔接风险（吊销许可·责令停产停业·较大数额罚款·行刑衔接·行政拘留）；高 = 重大监管风险敞口（无许可经营·监管机关已检查·同行业执法密集）；中等 = 合规制度缺失或不完善（合规义务未落实·规章已更新但措施未跟进）；低 = 已有合规控制且有效执行（制度完善·自查无重大发现）。追问是否增加等级或调整触发情形、行业是否有特殊触发情形（如环保行业在线监测超标、金融行业资本充足率预警）。默认采用现有定义。
    3. Q2 展示配置文件现有角色权限表（当事人本人·企业合规官/法务·助理律师·主办律师·合伙人）询问是否调整：追问团队中未列出的角色（外部顾问、实习律师等）、是否收窄某些角色权限（如企业要求合规官所有输出须经律师审核）、是否放宽（如资深法务可独立处理一般合规事项）。默认采用现有权限表。
    4. Q3 [不可协商护栏] 向用户明确说明五类法定强制升级情形必须升级执业律师、不可通过配置关闭：吊销许可证件（行政处罚法第9条·第63条范围内的较重处罚）；责令停产停业·责令关闭·限制从业（行政处罚法第9条）；较大数额罚款（具体数额标准由地方·行业规章规定）；行刑衔接风险（违法所得数额·情节达刑事追诉标准、监管机关移送公安）；责任人人身自由风险（行政拘留、可能被采取刑事强制措施）。
    5. Q3 追问：除法定情形外企业或团队是否有额外内部强制升级场景（如任何监管机关现场检查即升级、任何罚款超过特定金额即升级），描述并确认后作为补充写入；并说明监管合规边界——强制升级护栏凌驾于服务立场与合规严格度之上，即使选「务实型」仍须升级，这是基于行政处罚法与刑法的制度要求。
    6. Q4 [不可协商护栏] 说明行政程序时限护栏强制执行规则：处罚决定送达后须强标陈述申辩期；拟处罚告知后须强标听证申请期；行政行为作出后须强标行政复议申请期与行政诉讼起诉期；不得静默放任时限流逝。展示配置文件现有行政程序时限触发升级表（四个节点天数均 [待验证]）；追问是否有常用程序时限速查表需集成（如特定行业的复议期限规定）、是否补充时限触发节点（如责令改正期限届满提醒、整改报告提交期限提醒）。默认采用现有时限表。
    7. Q5 时限计算偏好：是否以文书送达日期为起算点（推荐，符合法律规定）；是否设置提前提醒天数。默认以送达日期为起算点、届满前 3 天提醒。
    8. 按写入映射写入：「行政违法风险校准」的风险等级表；「升级矩阵」的角色权限表、强制升级触发条件的补充触发条件、行政程序时限触发升级表的补充时限节点与计算规则说明；走检查清单（含用户已确认理解两项护栏不可关闭、护栏说明已展示并获确认）后展示摘要确认。

    内置规则

    • 用户要求关闭行刑衔接强制升级：拒绝，说明这是法定要求不可通过配置覆盖
    • 用户要求关闭行政程序时限护栏：拒绝，说明逾期将丧失救济权利
    • 用户要求增加更多强制升级场景：允许，作为法定条件的补充写入；团队角色不在现有表中：允许新增角色行
    • 增量更新模式：法定护栏部分仅允许补充不允许删除
    • 配置文件预设角色权限表（本步展示供确认）：当事人本人（无律师）全部实质性法律行动前须升级；当事人本人（有律师联系人）在陈述申辩书定稿、听证申请提交、复议申请提交、起诉前及监管报告定稿报送前升级；企业合规官/法务可做合规制度草稿、合规风险初判、台账初建，制度定稿须律师审核，处罚应对、复议诉讼、监管报告定稿报送、重大处罚或行刑衔接须升级
    • 配置文件预设角色权限表（续）：助理律师可做材料整理、初步合法性分析、制度草案，在陈述申辩书、听证陈述、复议申请、起诉状定稿及重大处罚或行刑衔接决策时升级；主办监管合规律师可定稿合法性审查报告、起草陈述申辩书、定稿复议申请，行刑衔接情形须合伙人或刑事律师确认、重大处罚的诉讼策略须升级；合伙人/高级律师无上限
    • 用户口述处罚条号作为升级触发条件：标 [待验证]；口述地方罚款数额标准：标 [待验证 — 地方 flagged]，提示核实当地现行裁量基准
    • 用户无法确认程序时限天数：写入 [待验证]，提示以正式送达文书日期为起算点核实

    法律依据
