给律师看的 skill 说明

AI for China Legal 是一套面向中国大陆律师的法律 AI 工作流。这里按律师能读的方式讲清每个 skill 能做什么、怎么做到、分几步、内置了哪些法律判断，并把可以提意见的地方逐条标出来。

所有 skill 的输出都是供律师审查的草稿，不是法律意见，也不替代执业律师的判断。本站只讲工具怎么工作。

13个领域73个 skill309个步骤

01一个事项怎么走

不论哪个领域，每个法律事项都经过同样的外层流程。专项流程在第 4 步。

  1. 自动接管法律事项

    律师发来任务或文件，AI 按内容判断进入法律工作流，不需要说口令；默认按资深大陆律师的工作产物标准办，但不代替签字律师。 详细说明

  2. 开工前先问清

    读完全部材料，列出会改变成果的问题，分成必须确认、建议确认、可按默认、材料请求四档；在回复里写明开工前确认结论，然后直接提问，或生成问卷文档发给律师。 详细说明

  3. 先检索、后结论

    每个法律问题都同时找支持依据、反向依据和程序上的陷阱；来源分五级，法条逐字核对官方文本，核对不了的标「待律师复核」。 详细说明

  4. 进入专项流程

    按要交付的文书进入具体领域的流程（合同审查、答辩状、尽调、备案……）。每个流程的步骤、规则和内置判断见各 skill 页。

  5. 交付前检查与复核说明

    不覆盖原件；修订可以逐条接受或拒绝；版式逐页检查后交付。高风险事项写明是否由另一个 AI 模型独立复核。

  6. 律师意见回流

    律师的评价和修改意见按 skill 归类，只做小范围、可核对的修改，并记成脱敏案例。本站每条「核对」都是为这一步准备的。 详细说明

03怎么读一个 skill 页

概要、适用与边界、输入与产出

先判断这个流程是不是您要评的那个：它接什么材料、出什么文书、给谁看。

开始前

流程开始前一定会做的事（读实践配置、开工前确认、研究闸门），以及不能绕过的硬性规则。

执行步骤

主体。每一步写明怎么做、内置了哪些判断标准和阈值、引用哪些法条、产出什么。技术细节已略去，法律上的数字和清单照原文保留。

请律师核对（朱砂色）

每一步旁边标出的内置判断，以及页末的审阅清单。每条都可以一键复制成带编号的引用，粘到微信发给操作员。

法律依据与共用规则

法条照原文保留书名号与条号；「待验证」是 skill 原文自己的标记。共用规则是多个流程共享的法条库和口径，点名称可以看它收录了什么。

04常用说法

skill 页里反复出现的几个说法，意思如下。

请律师核对 / 审阅清单
本站加的批注：前者在每个步骤旁，后者在页末汇总；两者说的是同一件事时，审阅条目下会提示「相关批注」。条目里「供核对」之后的内容，是本站整理时对照现行条文补充的提示，不是 skill 原文。
操作员
把律师的需求交给 AI、转发问题和答复的人。可能是律师本人，也可能是助理或负责操作软件的人员。
[待验证] [待律师复核] [模型知识 — 需验证]
skill 原文自己的核验标记，本站原样保留：前两个表示依据未核验或需要律师判断；「模型知识」表示 AI 凭记忆写出、尚未检索核实的依据。
实践配置 / 临时模式
每个领域一份实践配置，记录贵所的立场、审查尺度和文书习惯，律师可以直接修改。还没有配置时按通用默认值办理（临时模式），并在成果上注明。
冷启动访谈
每个领域首次使用前的配置访谈：问清贵所的立场和习惯，答案写进实践配置。
护栏 / 升级 / 强制升级
护栏是 skill 里不能绕过的硬性规则（实践配置里的「共享护栏」一章对本领域所有流程生效）。升级是停下来交给指定的人决定，通常是执业律师或合伙人；实践配置里的「升级矩阵」规定什么情况交给谁。强制升级是不能经配置关闭的情形，如涉嫌犯罪、人身安全风险。
风险等级 [红] [橙] [黄] [绿]
关键、高、中等、低四级；各领域的具体口径写在本领域的实践配置里。
开工前确认结论
开工前写在回复里的一段说明：直接开工、先问再写还是暂停等答复，理由是什么；四档问题各几个、怎么问；按什么执行强度办；哪些事项暂缓确认。
文字版待确认问题清单 / 问卷文档
开工前提问的两种书面形式：前者是按编号列出、可以直接粘到微信的清单；后者是 Word 文件，由操作员转给承办律师填写。
必须确认 / 建议确认 / 可按默认 / 材料请求
开工前确认给问题分的四档。只有「必须确认」的问题没有答复时，受影响的部分才暂停起草。
执行强度：常规 / 加强 / 最高
按事项风险定的办理方式：常规由 AI 自查；加强由另一个 AI 模型独立复核；最高把材料提取、检索、起草、复核分开做，最后由律师人工审核。
复核情况说明
按加强或最高强度办理的事项，交付时写明：是否由另一个 AI 模型独立复核、还有几处分歧未解决、没做的原因；复核意见本身写在《成稿说明》里。
《成稿说明》
交付文书时另附给承办律师的内部说明，不随文书发给客户：形成方式、核心结论、客户材料中的问题、发送前请律师关注或确认的事项、法律依据核验情况、检索到但未采用的依据、建议客户补充的材料、复核情况等。
来源一级至五级
研究闸门给来源分的等级：法律与司法解释、入库案例与指导性案例、普通裁判文书、监管文件、实务文章；五级只作线索。
律师复核稿 / 律师工作产物
成果上的标注，表示这是供律师复核的草稿，不是定稿。部分领域的标题写「受律师-当事人特权保护」，沿用了普通法的说法；中国法下对应的是律师的保密义务，本站照录原文，是否改写请律师提意见。
常见缩写
CIIO：关键信息基础设施运营者；PIA：个人信息保护影响评估；DPO：个人信息保护负责人；FTO：自由实施（不侵权）分析；API、SDK：软件接口与开发工具包；LPR：贷款市场报价利率；IRAC：问题—规则—适用—结论的分析方法；PDCA：计划—执行—检查—改进的循环。

05怎么提意见

对任何一条规则：复制页面上的引用，写上「同意 / 反对 / 应改为」和依据，发给操作员或在 GitHub 提 issue。意见会按律师反馈精炼流程转成有边界的 skill 修改。格式与示例见怎么提意见。

本站把 AI for China Legal 项目里的 skill 规则改写成给律师看的说明，与 skill 原文不一致时以原文为准。所有 skill 的输出都是供律师审查的草稿，不是法律意见。说明站版本 1.8.0，生成日期 2026-11-03。

发现说明与 skill 的实际表现不一致，或对 skill 的规则有意见：见怎么提意见。
