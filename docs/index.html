给律师看的 skill 说明

ai-for-china-legal 是一套面向中国大陆律师的法律 AI 工作流。这里按律师能读的方式讲清每个 skill 能做什么、怎么做到、分几步、内置了哪些法律判断，并把可以提意见的地方逐条标出来。

所有 skill 的输出都是供律师审查的草稿，不是法律意见，也不替代执业律师的判断。本站只讲工具怎么工作。

01一个事项怎么走

不论哪个领域，每个法律事项都经过同样的外层流程。专项流程在第 4 步。

  1. 自动接管法律事项（总路由）

    律师发来任务或文件，工具按内容进入法律工作流，不用说口令；默认按资深大陆律师的工作产物标准，但不代替签字律师。 详细说明

  2. 开工前先问清（动态 intake）

    读完全部材料后列出会改变成果的问题，分成必须确认、建议确认、可按默认、材料请求四档；在回复里写出开工决定，然后直接问，或生成问卷文档发给律师。 详细说明

  3. 先检索、后结论（研究闸门）

    对每个法律问题同时找支持依据、反向依据和程序陷阱；来源分 L1–L5 五级，法条逐字核验，不能核验的标「待律师复核」。 详细说明

  4. 进入专项流程

    按交付物进入具体领域的流程（合同审查、答辩状、尽调、备案……）。每个流程的步骤、规则和内置假设见各 skill 页。

  5. 交付前检查与复核声明

    不覆盖原件，修订可接受、可拒绝，结构与渲染检查后交付；高风险事项写明是否做了不同模型的独立复核。

  6. 律师意见回流

    律师的评价与文字意见按 skill 聚类，只做有边界的修改，并沉淀为脱敏案例。本站每条「核对」都是为这一步准备的。 详细说明

03怎么读一个 skill 页

概要、适用与边界、输入与产出

先判断这个流程是不是您要评的那个：它接什么材料、出什么文书、给谁看。

开始前

流程开始前必须发生的事（读实践配置、动态 intake、研究闸门）和不可绕过的硬性规则。

执行步骤

主体。每一步写明做法的先后顺序、内置的判断规则与阈值、引用的法条、产出什么。这是源文件里最厚的部分，已按原文顺序保留数字与清单。

请律师核对（朱砂色）

每一步旁边标出的内置假设，以及页末的「请律师重点核对」清单。每条都可以一键复制成带编号的引用，粘到微信给操作员。

法律依据、共享规则、源文件

法条照原文保留《》与条号；「待验证」是源文件自己的标记。源文件链接到 GitHub，便于核对原文。

04标记与术语

skill 页照录源文件，保留了少量英文标记。它们的意思如下。

请律师核对 / 审阅清单
本站加的批注：前者在每个步骤旁，后者在页末汇总；两者对应时，审阅条目会写「对应 核对 n.k」。
[待验证] [待律师复核]
源文件自己标出的未核验引用或需要律师判断的点，本站原样保留。
INTAKE_DECISION
动态 intake 在开工前写在回复里的决定：是否暂停、各档问题几题、用哪种方式问。
[CLARIFY:]
没有提问工具时，交给律师按编号回复的待确认清单。
REVIEW_STATUS
高风险事项交付前写明的复核状态：是否做了不同模型的独立复核、有无未消解的分歧。
执行档 standard / high / critical
按风险定的执行强度：单模型自检；强模型起草加不同模型复核；材料提取、检索、起草、复核分角色执行，最后律师人审。
必须确认 / 建议确认 / 可按默认 / 材料请求
intake 给问题分的四档。只有必须确认未答复时，受影响部分才暂停起草。
来源分级 L1–L5
研究闸门的来源层级：法律与司法解释、入库与指导案例、普通判决、监管文件、实务文章；L5 只作线索。
实践配置文件 / 临时模式
每个领域的 CLAUDE.md 记录贵所立场与习惯，由冷启动访谈填写；没有配置时可用临时模式按通用默认值运行，并在输出上标注。

05怎么提意见

对任何一条规则：复制页面上的引用，写上「同意 / 反对 / 应改为」和依据，发给操作员或在 GitHub 提 issue。意见会按律师反馈精炼流程转成有边界的 skill 修改。格式与示例见怎么提意见。

本站把 ai-for-china-legal 仓库里的 skill 文件改写成给律师看的说明。所有 skill 的输出都是供律师审查的草稿，不是法律意见。页面由 scripts/build-docs-site.py 从 docs/data/skills/parts/ 生成；生成日期 2026-11-02。

发现说明与源文件不一致、或对 skill 的规则有意见：见怎么提意见。
