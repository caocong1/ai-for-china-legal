怎么提意见

意见要能对回 skill 里的某一条规则，才能变成修改。页面上的每条「核对」和「审阅」都带编号，复制就是现成的引用。

01提什么

  • 内置假设不对或不全：某个阈值、分级、清单、默认立场与贵所实践不符。
  • 法条有误：条号、文号、生效情况、适用范围写错了，或漏了关键司法解释。
  • 步骤顺序或缺步：实务上先后应当颠倒，或少了一个必须做的核查。
  • 该问没问：开工前应当向律师确认的事项，没有列进开工前确认的问题里。
  • 措辞与文书体例：产出文书的结构、口吻、落款与贵所模板不一致。
  • 说明与实际表现不一致：本站是摘要；skill 实际交出的成果与这里写的不一样，请一并指出。

02怎么写

三行即可：引用、结论、依据。引用从页面复制；结论写「同意 / 反对 / 应改为……」；依据写法条、案号或实务经验。

【商事合同／合同审查 · 第1步 风险识别 · 核对 1.2】风险等级把「超出备选范围」定为高风险……

反对。我所实践中……应改为……
依据：《民法典》第585条第2款；（2023）京03民终××××号。

一次可以发多条；不同 skill 的意见请分开，每条带自己的引用。不要把客户材料或案情原文写进意见。

03发到哪里

  • 微信发给操作员：最常用。操作员按律师反馈精炼流程处理。
  • GitHub：每个 skill 页末尾有「在 GitHub 提 issue」按钮，会自动带上页面地址（需要 GitHub 账号）：项目的意见列表。
  • 墨律桌面端：对单次成果点 👍/👎 并留言，会随同步服务汇总。

04之后会发生什么

意见按 skill 归类，找到对应的规则，每次只做 1–3 处小范围的替换或追加，每处写明对应哪条意见；不删研究闸门的强制步骤，不编造法条，拿不准的新规则标「待律师复核」。改完至少对照一个真实场景核对，再发布新版本，律师端下次启动时自动更新。来自真实任务的经验脱敏后进入案例库。

本站把 AI for China Legal 项目里的 skill 规则改写成给律师看的说明，与 skill 原文不一致时以原文为准。所有 skill 的输出都是供律师审查的草稿，不是法律意见。生成日期 2026-11-03。

发现说明与 skill 的实际表现不一致，或对 skill 的规则有意见：见怎么提意见。
