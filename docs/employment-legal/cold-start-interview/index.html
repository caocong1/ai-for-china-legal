01概要

通过四段结构化访谈（身份与团队 → 审查立场 → 风险与升级 → 文书风格与地方性规定），把律师或 HR 的执业立场、风险偏好、升级矩阵与文书风格写入 employment-legal/CLAUDE.md 对应章节，使全部劳动人事流程按个性化配置运行。整体约 5–10 分钟，也可单独重跑任一段只更新对应章节。每段开始先读现有配置，发现非占位符内容时逐字段确认是否覆盖；用户口述的条款号、金额、期限写入前按 practice-profile-schema.md 第六节做合理性检查，并以 labor-law-citations.md 的已核实条文（第19、23–24、47、87条，仲裁时效第27条）为基准。产出只是更新后的 CLAUDE.md，不生成独立 YAML 或 JSON 文件。

02适用与边界

适用场景

  • 首次安装劳动人事工具后初始化实践配置（README 将本命令列为安装步骤）
  • 服务对象发生变化（如从专做用人单位方转为兼做劳动者方）→ 单独重跑 /employment-legal:review-stance
  • 更换主要工作地点 → 单独重跑 /employment-legal:style-local-rules
  • 升级矩阵人员变动 → 单独重跑 /employment-legal:risk-escalation
  • 其他流程运行时提示配置含 [PLACEHOLDER]

不做什么

  • 不审查具体劳动合同、解雇方案或争议案件，那是其他六条流程的工作
  • 不生成独立的 YAML / JSON 配置文件，只填充 employment-legal/CLAUDE.md 的占位符
  • 只改一两个字段时不必走访谈：律师可直接编辑 CLAUDE.md，用 git log / git diff 查看历史与变更
  • 不想运行访谈时可在任何流程中说「临时模式」，按 practice-profile-schema.md §3.3 的默认值运行

需要律师提供

  • 现有 employment-legal/CLAUDE.md必需
    每段开始前读取，检查对应章节是否已有非 [PLACEHOLDER] 内容
  • employment-legal/skills/_shared/practice-profile-schema.md必需
    字段映射契约（§2.1–2.8）与 §6 合理性检查规则
  • employment-legal/skills/_shared/labor-law-citations.md A 组核心条文可选
    审查立场段用作合理性检查基准：试用期第19条、竞业第23–24条、经济补偿第47条、违法解除第87条

产出

  • 更新后的 employment-legal/CLAUDE.md给律师内部
    对应章节的 [PLACEHOLDER] 被替换：第一段写「我们是谁」「谁在使用」「可用集成」；第二段写「审查立场」（雇佣审查 / 解雇审查）；第三段写「风险校准」「升级矩阵」；第四段写「文书风格」「输出」「共享护栏 → 地方性规定识别」。含 [前提 flagged — 需验证] 的字段写入前须经用户确认；未回答的问题保留占位符

04开始前

前置条件

  • 每段开始前读取 employment-legal/CLAUDE.md，若目标章节已有非 [PLACEHOLDER] 内容，提示「这些字段已有配置，是否覆盖更新？」并逐字段确认，不整体覆盖
  • 读取 practice-profile-schema.md 对应小节（§2.1–2.8）的字段映射，确定每个答案写入哪个章节的哪个字段
  • 第三段读取第一段已填的「最终升级联系人」用于确认升级矩阵人员；第四段读取「主要工作地点」用于预填地方性规定勾选
  • 写入目标固定为 employment-legal/CLAUDE.md，不反复询问输出格式与保存位置；只有用户要求写入其他配置文件或目标不明时，才按 shared/legal-document-intake/SKILL.md 确认

硬性规则

写入前法律事实合理性检查
每段把用户口述的法律事实写入前，对照 practice-profile-schema.md §6 校验：竞业限制期限不超过 2 年（《劳动合同法》第24条，已核实）；经济补偿 2N 仅适用于违法解除（第87条，已核实）；仲裁时效为 1 年（《劳动争议调解仲裁法》第27条，已核实）；其他用户口述条款号 / 金额 / 期限标注 [前提 flagged — 需验证]
只更新本段章节
每段只覆写自己负责的章节，其他章节不受影响；写入时保留其他未提交的配置改动
不生成独立配置文件
产出是更新后的 CLAUDE.md 章节内容，不生成独立 YAML 或 JSON 文件
临时模式
用户不想运行完整访谈时，可在任何劳动人事流程中说「临时模式」，按 practice-profile-schema.md §3.3 的默认值运行，输出标 [临时模式 — 配置你的档案以获得定制输出]
先检索、后结论
给出任何法律结论、条款建议或风险判断前，优先用检索工具核对现行有效的法律法规、司法解释及指导性案例（注意修订、修正与废止）；无法核实时在结论处标「未经检索核实，请以现行有效文本为准」；禁止凭记忆断言法条编号、发文文号或生效日期

05执行步骤

共 4 步，按执行顺序。每步旁边（窄屏在步骤说明之后）是请律师核对的内置假设，可逐条复制。页面里的英文标记见首页「标记与术语」。

  1. 身份与团队访谈

    /employment-legal:identity-team可单独运行

    收集公司 / 律所身份、团队规模、工作地点、使用者角色与系统集成情况，写入「我们是谁」「谁在使用」「可用集成」三章，让后续流程能选对工作产物标题、触发地方性规定识别并确定升级路由

    请律师核对

    • 核对 1.1角色选项中「HR（无法律背景，无律师可咨询）」仍可运行全部流程，仅加提示语；贵所是否接受非律师无监督使用
    • 核对 1.2工作地点选项只预设北京 / 上海 / 广州 / 深圳，其他城市靠「其他」自填
    • 核对 1.3「独立承包人（非劳动关系）」被列为雇佣类型选项，是否符合贵所分类口径

    做法

    1. 读取 CLAUDE.md 三个目标章节，已有非占位符内容时提示是否覆盖
    2. Q1 公司 / 律所名称与实体类型，可选：企业（国有 / 私营 / 外资）/ 律所 / 政府法务 / 其他
    3. Q2 HR / 劳动法团队规模，参考量级：1-3 人（小团队）/ 4-10 人（中型）/ 10 人以上（大型）/ 外部法律顾问（无内部团队）
    4. Q3 最终升级联系人，格式「姓名 + 职位 + 联系方式」
    5. Q4 每月处理雇佣 / 劳动事务数量，用于理解工作量和提示频率
    6. Q5 主要雇佣类型，可多选：全职劳动合同 / 兼职 / 劳务派遣 / 实习 / 独立承包人（非劳动关系）/ 混合
    7. Q6 主要工作地点（北京 / 上海 / 广州 / 深圳 / 其他 / 多地点），同步写入「共享护栏 → 地方性规定识别」勾选对应地区；多地点时逐一勾选
    8. Q7 最大劳动用工痛点（开放式，如频繁争议、合规文件管理、绩效辞退流程、竞业执行难、多地点合规差异）
    9. Q8 主要使用者角色：劳动法律师 / HR 法务（有律师可咨询）/ HR（无法律背景、无律师可咨询）/ 法务人员 / 混合团队，决定工作产物标题与是否在法律后果步骤前暂停
    10. Q9 律师联系人；使用者本人是律师填「本人」
    11. Q10 集成情况：HR 系统 / 文档存储 / 企业微信或钉钉 各填 已连接 / 未连接 / 不适用；未连接时核心功能仍可用，需手动粘贴文档
    12. 按写入映射表把 10 个答案替换到对应 [PLACEHOLDER]；不想回答的问题保留占位符并记录（后续流程遇到占位符时会提示）

    内置规则

    • 律师角色：所有输出标「律师工作产物 — 受律师-当事人特权保护 / 保密」
    • 非律师但有律师可咨询：输出标「研究笔记 — 非法律建议，供律师审查」，在签署文件、发出解除通知等具有法律后果的步骤前暂停
    • 非律师且无律师可咨询：同上，额外添加「建议在重大决定前咨询执业律师」提示
    • 主要工作地点触发的地方性规定识别范围：社保基数、竞业限制补偿指引、产假奖励假天数、陪产假天数、婚丧假标准
    • 用户口述「当地竞业限制补偿要求是 Y%」时只记录并标 [前提 flagged — 需验证当地规定]；口述月工资标准只记录，留给后续流程处理
    • 律师与 HR 混合团队默认按律师角色，提示不同使用者可单独重跑本段设置角色
    • 已有配置而用户想部分更新时显示当前值并逐字段确认，不整体覆盖
    • 工作地点填写不清（如「北方几个城市」）时请求列出具体省市；角色选择矛盾（自称 HR 却询问「律师意见」）时追问「您是 HR 法务还是执业律师？」

    产出

    更新后的 CLAUDE.md「我们是谁」「谁在使用」「可用集成」三章，以及「共享护栏 → 地方性规定识别」中的地区勾选；未回答字段保留 [PLACEHOLDER]

  2. 审查立场访谈

    /employment-legal:review-stance可单独运行

    明确代表用人单位方还是劳动者方，以及试用期、工时、社保、竞业与解雇的标准立场和经济补偿倾向，写入「审查立场」章

    请律师核对

    • 核对 2.1竞业补偿「5% 以下」被当作过低的提示阈值，但补偿比例无全国统一标准，文件仅标 [待验证]
    • 核对 2.2标准工时制「每日不超过 8 小时、每周不超过 40 小时」未标验证状态，直接作为基准
    • 核对 2.3用人单位方试用期典型立场是「倾向约定至上限」，是否符合贵所对客户的惯常建议
    • 核对 2.4非过失性辞退「提前 30 天或额外一个月工资」与裁员「20 人或 10%」都只标为 [前提 flagged / 待验证]，未列为硬检查

    做法

    1. 读取 CLAUDE.md「审查立场」章与 practice-profile-schema.md §2.2–2.4；读取 labor-law-citations.md A 组核心条文（第19、23–24、47、87条）作为合理性检查基准
    2. Q1 服务对象：用人单位方（合规与风险预防视角：条款是否暴露用人单位于争议风险）/ 劳动者方（权益主张视角：无效条款识别、可主张的权利与救济路径）/ 双方（依事项，运行时每次询问）；写入「谁在使用 → 服务对象」（若第一段未填）
    3. Q2 试用期标准立场与特殊情况，按第19条分档校验用户口述：合同 3 个月以上不满 1 年 → 最长 1 个月；1 年以上不满 3 年 → 最长 2 个月；3 年以上及无固定期限 → 最长 6 个月
    4. Q3 工时制度：标准工时制（每日不超过 8 小时、每周不超过 40 小时）/ 综合计算工时制 [待验证] / 不定时工时制 [待验证]，后两者须劳动行政部门批准
    5. Q4 社保标准立场与公积金立场，校验基准：「自愿放弃社保」约定无效、以「社保补贴」代替缴纳无效、缴纳基数不低于法定下限
    6. Q5 竞业限制四项配置（适用人员范围 / 经济补偿标准 / 期限 / 范围），按第23–24条校验：人员限于高管、高级技术人员和其他负有保密义务人员，不得扩大到全体员工；期限不超过 2 年；须按月支付补偿（标准参照地方指引 [管辖 flagged]）；范围限于有竞争关系的业务
    7. Q6 过失性辞退内部认定标准（须依据已生效并公示的规章制度，不得事后补充 [前提 flagged — 需验证]）
    8. Q7 非过失性辞退（医疗期满 / 不胜任 / 客观情况变化）处理流程（须提前 30 天书面通知或额外支付一个月工资 [前提 flagged — 需验证]）
    9. Q8 经济性裁员审批流程（裁员 20 人以上或占 10% 以上须提前向工会或全体职工说明并听取意见 [第41条，待验证]）
    10. Q9 经济补偿倾向：法定 N / N+1 / 2N / 高于法定（填具体标准），并校验 12 年与三倍封顶规则及 N 与 2N 互斥
    11. Q10 交易破坏者：用人单位方问「绝不接受的劳动者主张或条款风险」，劳动者方问「必须主张权利的违法条款」，写入对应章节末尾
    12. 含 [前提 flagged — 需验证] 的字段写入前经用户确认（§6.3），然后只覆写「审查立场」章

    内置规则

    • 试用期上限分档（《劳动合同法》第19条，已核实）：3 个月以上不满 1 年 → 1 个月；1 年以上不满 3 年 → 2 个月；3 年以上及无固定期限 → 6 个月；典型立场：用人单位方「按合同期限在法定上限内约定，倾向约定至上限」，劳动者方「核实是否超过法定上限，超过部分无效，另支付工资差额」
    • 竞业限制期限上限 2 年（第24条，已核实）；用户口述 3 年时提示超出部分无效，并询问按 2 年写入还是保留 3 年并标 [前提 flagged]
    • 竞业补偿比例口述过低（如 5% 以下）时提示：补偿过低可能被认定为无效或劳动者有权单方解除竞业义务（具体标准参照地方指引 [待验证]）
    • 经济补偿：法定 N 每满一年一个月工资（第47条，已核实）；N+1 常见于非过失性辞退代通知；2N 为违法解除赔偿金（第87条，已核实），N 与 2N 互斥
    • 「高于三倍平均工资部分，经济补偿年限封顶 12 年，月工资按三倍封顶」（第47条，已核实）
    • 用户口述「2N 用于合法解除」或「违法解除也支付 N 就够了」时纠正：合法解除付 N 或 N+1，违法解除须付 2N，不可选低标准
    • 用户把「社保补贴」作为标准立场时警告其无效，建议改为「按法定标准缴纳，不约定补贴代缴」
    • 未经批准自行约定综合 / 不定时工时的，加班费计算仍按标准工时制处理 [前提 flagged — 需验证]
    • 经济补偿倾向不明（「视情况而定」）时记录为「依法定标准，具体情形具体判断」，后续流程按法定 N 计算并提示确认
    • 用户不清楚代表哪方时追问：是帮公司合法用工、降低争议风险，还是帮员工主张权利、索取赔偿

    法律依据

    • 《劳动合同法》第19条 — 试用期按合同期限分档上限（已核实）
    • 《劳动合同法》第23–24条 — 竞业限制人员范围、2 年期限、按月经济补偿（已核实）
    • 《劳动合同法》第41条 — 经济性裁员 20 人或 10% 以上须向工会或全体职工说明 [待验证]
    • 《劳动合同法》第47条 — 经济补偿 N、12 年与三倍封顶（已核实）
    • 《劳动合同法》第87条 — 违法解除赔偿金 2N（已核实）
    • 《劳动合同法》第39条、第40条 — 过失性与非过失性辞退（仅作为配置项标题引用，条文内容未在本步骤展开）

    产出

    更新后的 CLAUDE.md「审查立场」章：雇佣审查（试用期 / 工时制度 / 社会保险 / 竞业限制四字段）、解雇审查（法定解除情形三项 / 经济补偿）及章节末尾的交易破坏者说明；必要时补填「谁在使用 → 服务对象」

  3. 风险偏好与升级矩阵访谈

    /employment-legal:risk-escalation可单独运行

    确认四级风险等级含义、各角色可独立处理的事项与升级条件、自动升级触发场景和高时效场景，写入「风险校准」「升级矩阵」两章

    请律师核对

    • 核对 3.1默认把「解雇或终止劳动合同（非常规离职）」整体列为自动升级到最高层，对解雇量大的企业是否过严
    • 核对 3.2[红] 示例把「未付经济补偿 2N」与「三期解雇」「医疗期内违法解除」并列为几乎肯定败诉
    • 核对 3.3「进取型」偏好允许把 [橙] 高风险降为提醒项
    • 核对 3.4不服裁决 15 日与撤销 30 日在本段标 [待验证]，而本插件劳动争议处理流程的描述称第47条「已核实」，验证口径不一致

    做法

    1. 读取 CLAUDE.md「风险校准」「升级矩阵」章、practice-profile-schema.md §2.5–2.6，以及第一段已填的最终升级联系人
    2. Q1 逐级确认默认风险定义（[红] 关键 / [橙] 高 / [黄] 中等 / [绿] 低）并记录调整；跟进问「有没有默认定义未包含、但你们视为必须升级不可自行处理的问题」，记为额外触发条件
    3. Q2 收集团队角色与各自可独立处理范围，提供四级参考表供修改：HR 专员 / 助理（日常入职文件签署、常规假期审批、社保登记）→ HR 经理 / 法务助理（一般劳动合同审查、常规离职手续、病假医疗期管理）→ 主办律师 / 法务经理（解雇方案审查、经济补偿计算、竞业限制执行评估）→ 法务总监 / 合伙人（无上限）
    4. Q3 收集每个角色的升级触发条件，建议至少含：HR 专员涉及解雇、竞业限制、劳动争议申诉即升级；主办律师遇集体性争议、超出 X 万元的经济补偿决策、诉讼立案风险即升级；群体性争议、媒体关注风险、监管调查升级至法务总监 / 合伙人
    5. Q4 逐项确认六类自动升级触发场景的默认设置（见规则）
    6. Q5 记录需「立即响应」的时效场景：仲裁时效 1 年（第27条，已核实）接近到期；不服裁决起诉收到裁决书后 15 日内 [待验证]；一裁终局用人单位申请撤销裁决书送达后 30 日内 [待验证]
    7. 对用户口述的时效数字与风险定级做合理性检查（见规则），然后只覆写两章，并在「升级矩阵」末尾追加自动升级触发与时效提醒说明

    内置规则

    • [红] 关键：明显违反强制性规定，几乎肯定败诉；例：医疗期内违法解除、三期解雇、未付经济补偿 2N
    • [橙] 高：有较大法律风险，可能败诉；例：竞业补偿明显过低、规章制度未经民主程序
    • [黄] 中等：存在争议空间，取决于证据和仲裁员 / 法官裁量；例：过失认定证据不充分、日工资基数计算方式有争议
    • [绿] 低：合规或有充分依据；法定标准完全符合
    • 默认自动升级：竞业限制纠纷（违约金主张或协议有效性争议）、解雇或终止劳动合同（非常规离职）、群体性劳动事件（多人同时主张权益、集体停工风险）、仲裁 / 诉讼立案、监管检查 / 劳动局稽查 → 自动升级；媒体 / 社交媒体曝光风险 → 确认后升级
    • 口述「仲裁时效 3 年」→ 纠正为 1 年（《劳动争议调解仲裁法》第27条，已核实），非民法典 3 年时效，记录并标 [前提 flagged — 需验证]；口述「不服裁决有 1 个月起诉」→ 提示一般 15 日、一裁终局用人单位撤销 30 日 [待验证]，确认具体情形
    • 口述「群体性纠纷自己处理」→ 建议列为自动升级 [前提 flagged — 建议确认]；设置「任何事项都自己处理」→ 保留记录但提示至少保留群体性事件 / 仲裁立案为自动升级
    • 把「违法解除」定为 [黄] → 提示违法解除（2N 赔偿金，第87条已核实）通常为 [红]，设为 [黄] 可能导致风险提示不足，确认是否调整
    • 团队只有 1-2 人时升级矩阵简化为「独立处理」与「须外部法律建议」两层；无明确升级联系人时记「未配置，升级时询问」；角色职位不清（如「某人」）时追问头衔
    • 风险偏好「保守型」：[黄] 中等提升为需关注项，建议修改而不仅提示；「进取型」：[橙] 高降为提醒项，但 [红] 关键始终保持升级触发

    法律依据

    • 《劳动争议调解仲裁法》第27条 — 仲裁时效 1 年（已核实）
    • 《劳动合同法》第87条 — 违法解除 2N 作为 [红] 关键定级的校验基准（已核实）
    • 不服裁决起诉 15 日 / 一裁终局用人单位申请撤销 30 日 — 原文 [待验证]，未写条号
