01概要

面向上市公司自查、投资方尽调、集团对子公司或外包用工的合规调查，把「指令文件 + 报告模板 + 底稿资料包」做成可恢复、可溯源的调查报告：每个结论回到底稿文件编号与页码，每个未核实事实以条件句进正文并出现在附录。流程四步：先把花名册、社保公积金表、考勤表统一到同一人员键和统计日，固化用工口径表与差异清单；再对直签、派遣、外包、劳务、实习、退休返聘、关联公司交叉用工、异地代缴、代发薪逐类定性并识别「名为外包实为派遣」；再以法释〔2025〕12号和工作地点年度地方标准为基准逐条审查合同范本与规章制度中的废止规则与旧数字；最后按指令文件章节写正文、倒推重大问题汇总、装配「待核实事项及待补充资料」附录，以客户模板包成稿并完成覆盖审计、渲染 QA、隐私检查与 REVIEW_STATUS。依赖共享的尽调 playbook、文档交付 QA、研究闸门，以及本插件的引用库、派遣 / 外包定性对照表与北京地方标准。

02适用与边界

适用场景

  • 上市公司本部用工合规自查
  • 投资方或贷款人对目标公司的劳动用工尽调
  • 集团对子公司或外包用工群体的合规调查
  • 任务形态为「指令文件 + 报告模板 + 底稿资料包」，需要整家公司或一个用工群体的调查报告
  • 指令文件点名「假外包真派遣」「社保委托代缴」等重点关注项

不做什么

  • 单份劳动合同、单份竞业协议的审查仍用 hiring-review / non-compete-review 等流程；本流程面向整家公司或一个用工群体
  • 不下质量结论：固化的是案例库 LWC-2026-0006（116 份底稿、125 页报告）与 LWC-2026-0005 劳动章节的流程与检查清单，两案均为律师复核稿、人审待回填
  • 不凭推测填写 OCR 识别不清的金额、日期、人名
  • 不代替律师做「需律师决定」项的法律判断，此类项在附录以「【律师决定】」开头
  • 默认不联网做企业信用、裁判文书、执行信息等外部核验；未执行须在报告中声明

03输入与产出

需要律师提供

  • 指令文件（章节结构、资料夹对应、重点关注项、受众与立场）必需
  • 报告模板 DOCX（客户或律所模板）可选
    无模板时用 shared/references/document-structures.md 的意见书 / 报告结构 + 中文 reference.docx
  • 底稿资料包：花名册 / 劳动合同台账、社保公积金缴费表、考勤表、工资表、合同范本、专项协议、机构协议、规章制度、协商解除协议、案件与处罚文件必需
    扫描件 OCR 后台执行，结果只用于定位
  • employment-legal/CLAUDE.md 的审查立场与「输出」工作产物标题必需
    缺失或含 [PLACEHOLDER] 时按临时模式：风险偏好平衡型、被调查公司合规视角、工作地点按资料确认
  • 工作地点年度地方标准文件（local-rules-beijing.md 或同结构的其他城市文件）必需
    取当年度社保基数上下限、最低工资、生育假现行值
  • 统计日可选
    三表尽量取同一月份

产出

  • 报告正文（第三部分）给客户（公司管理层 / 投资方），经律师复核后交付
    按指令文件章节，通常：组织架构与用工概况（主体、关联公司、人数口径表、整页组织架构图）/ 劳动人事（用工分类汇总表 → 劳动合同与专项协议评析 → 规章制度评析 → 社保公积金 → 工时与休假 → 离职协商解除协议表）/ 诉讼、仲裁与行政处罚（案件表、稽核处罚通知、信用报告交叉）；成稿恒标「律师复核稿」
  • 重大问题汇总（第二部分）给客户
    表格：# / 重大问题 / 风险 / 正文位置 / 待核实或待补；从正文倒推，不新增正文没有的结论；[红] → [橙] → [黄] 排序，同级按涉及人数
  • 附录「待核实事项及待补充资料」给客户 / 律师
    表格：序号 / 待核实事项 / 需提供的资料或说明；「需律师决定」项以「【律师决定】」开头；条件句结论对应项放前列；与正文【待核实】计数一致
  • 交付说明与 REVIEW_STATUS给律师内部
    占位符清单（出具日期、尽调期间、释义表待填）、目录域刷新提示、未执行事项（外部检索、独立模型复核）、结构指标（页数、表格数、待核实数）；REVIEW_STATUS 未做独立复核时写 independent_review: skipped 与原因
  • 内部工作目录给律师内部
    资料清单（file_id、sha256、extraction、chapter、contains_pii）、分章事实底稿、比对脚本与中间表、含个人信息的底稿；留在仓库外，不进发送包

04开始前

前置条件

  • 读取 employment-legal/CLAUDE.md；配置缺失或含 [PLACEHOLDER] 时按 hiring-review 的临时模式规则：风险偏好平衡型、被调查公司合规视角、工作地点按资料确认；报告立场由指令文件决定（公司自查 / 投资方 / 集团管理），不得从模板旧稿沿用
  • 执行 shared/legal-document-intake/SKILL.md，按 shared/references/due-diligence-playbook.md 第 1 节判定必答项：受众与立场（决定措辞确定性与附录口径）、重点关注项（指令文件列明的优先，无则按默认清单）、章节与资料夹对应（通常「第三部分按资料夹分章、第二部分从正文归纳」）；尽调期间、出具日期、释义表简称、3 份以内文件的金额 / 日期识别不清列为 deferred_items 进附录并在交付说明点名
  • 开工前必须输出 INTAKE_DECISION；本类任务为正式对外报告，execution_profile 默认 critical；指令文件 + 模板 + 资料包齐备时通常为 ready + draft_mode: conditional，不必澄清
  • 步骤顺序固定：先固化人数与用工类型口径（否则后面每个比例都会变）→ 再定性 → 再审文本（定性结果决定哪些合同重点看）→ 最后装配；单独触发第 2 步须先提供第 1 步的口径表

硬性规则

司法解释二基准
2025-09-01 之后的用工审查以法释〔2025〕12号重判混同用工、变换主体续签、二倍工资、竞业限制范围与补偿、社保约定无效与补贴返还；旧结论不得沿用
地方标准版本
最低工资、社保基数、生育假天数按年度版本核对；客户文本中的旧数字是发现项，不是背景
OCR 只定位
扫描件 OCR 后台执行；识别不清的金额、日期、人名不得按推测填写，标【待核实】并进附录
个人信息
底稿含身份证号、住址时放内部目录；报告与附录只用工号或脱敏称谓；发送包做正则检查
条件性表述
代发薪人员是否构成派遣、外包人员此前是否已直接用工等推断性结论，正文用条件句并放附录前列
覆盖审计
装配前核对资料包每个文件是否被引用（playbook 第 4 节）；未做覆盖审计的报告不得写「资料已全部审阅」
模板永不覆盖
模板 DOCX 永不覆盖，成稿另存新文件；指令文件已明确模板、章节与资料夹对应、保存位置时直接执行不重复询问；只有受众 / 立场、参考稿排除规则等会改变成果的必须项缺失，或写入目标可能覆盖模板原件时，才输出 [CLARIFY:] 并暂停
先检索、后结论
每一处法条、司法解释条号、地方标准数字在写入前经 shared/research-gate/SKILL.md 联网核对现行版本；无法核对的标 [待律师复核]，不凭记忆写条号或金额
独立复核可观察
交付前按 shared/legal-document-intake/SKILL.md 输出 REVIEW_STATUS；未做不同模型独立复核时写 independent_review: skipped 并给出原因，不得沉默

05执行步骤

共 4 步，按执行顺序。每步旁边（窄屏在步骤说明之后）是请律师核对的内置假设，可逐条复制。页面里的英文标记见首页「标记与术语」。

  1. 资料清点与三表交叉比对

    /employment-legal:headcount-reconciliation可单独运行

    把花名册 / 劳动合同台账、社保公积金缴费表、考勤表（及工资表）统一到同一人员键和同一统计日，输出可复算的用工口径表和差异清单；只产出事实口径，不下法律结论。LWC-2026-0006 中 54 名「代发薪」人员不在花名册、2 人花名册记劳务而考勤记劳动合同、实习人数两表不一致（1 对 3），都只有交叉比对才会浮现

    请律师核对

    • 核对 1.1花名册被设为人员总数与用工类型的基准，社保表为参保主体基准，考勤表为在岗基准；贵所是否同意这一基准分配
    • 核对 1.2「基数 = 下限 / 上限的人数与中位数」被用作社保基数偏低的线索，未设比例阈值
    • 核对 1.3人员键不用身份证号，无工号时用「姓名 + 入职日期」，同名同日入职会撞键，文件未规定处理方式

    做法

    1. 读 due-diligence-playbook.md 第 2、3 节按其 schema 建资料清单与分章底稿；读工作地点地方标准文件取当年度社保基数上下限
    2. 按文件类型选提取路径：xlsx / csv 本地脚本直读，保留原列名另建标准化列；docx / doc 文本提取（doc 先转 docx）；有文本层 PDF 用 pdftotext 直取；扫描 PDF / 图片 OCR 作为后台任务，结果只用于定位
    3. 每份文件登记 file_id、sha256、extraction、chapter（按指令文件的资料夹对应）；contains_pii 为 true 的进内部目录
    4. 识别四张基础表并确定各自基准：花名册 / 劳动合同台账（工号、姓名、用工类型、合同主体、合同期限、签订日期、工作地点、岗位）= 人员总数与用工类型的基准；社保公积金缴费表（参保单位自管户 / 代缴机构、缴费基数、险种、公积金金额）= 参保主体与基数分布的基准；考勤表（工号、姓名、用工类型、出勤天数）= 实际用工在岗的基准；工资表（应发、实发、发放主体）= 代发薪识别与社保基数合理性
    5. 固化口径：统计日三表尽量取同一月份，不同月份时写明并解释差异；人员键优先工号，无工号用姓名 + 入职日期，不以身份证号为键输出
    6. 用工类型标准化为 11 类（直签-固定 / 直签-无固定 / 直签-完成任务 / 派遣 / 外包 / 劳务 / 实习 / 返聘 / 代缴 / 代发薪 / 未知），原始表述保留旁列；合同主体标准化为 被调查公司 / 关联公司 A、B… / 人力资源机构 X、Y… / 未知
    7. 跑 9 项差异矩阵（见规则），每条差异记录人数、人员键清单（内部）、来源 file_id、候选定性、需补资料
    8. 输出用工口径表（统计日 YYYY-MM；口径 / 人数 / 来源）与差异清单（# / 差异 / 人数 / 候选定性 / 需补资料 / 来源）；数字必须能由脚本重算，脚本与中间表留在仓库外工作目录，报告只引用结果

    内置规则

    • 在社保表、不在花名册 → 代发薪 / 代缴人员不在用人单位名册 → 候选定性：劳动合同主体不明、派遣或委托代缴 → 需补劳动合同样本、机构服务协议附件
    • 在花名册、不在社保表 → 未参保、异地参保、劳务 / 实习 → 未参保风险或劳务关系定性 → 需补异地参保凭证、劳务协议
    • 在考勤表、不在花名册 → 外包 / 派遣人员受用工方考勤 → 「名为外包实为派遣」线索 → 需补外包合同及补充协议
    • 花名册类型 ≠ 考勤类型 → 劳务 vs 劳动合同记载冲突 → 事实劳动关系风险 → 需补两份原件；实习人数两表不一致 → 需补实习协议、在校证明
    • 合同主体 ≠ 参保主体 → 关联公司交叉用工 / 代缴 → 混同用工、变换主体续签 → 需补签订日期批次、调动文件；签订日期成批次 → 关联公司集中转签 → 变换主体连续订立固定期限合同 → 需补原合同、工龄承继约定
    • 基数 = 下限 / 上限人数、中位数 → 基数偏低或集中下限 → 社保基数合规 → 需补工资表；公积金为零 → 未缴或法定例外 → 需补例外证明（残疾、退休返聘等）
    • 只有花名册、无社保表 → 口径表注明「参保情况未核验」，列入补充资料首项
    • 三表月份不同 → 分别标注月份，剔除月份间入离职人员后再比较
    • 花名册含多家关联公司 → 按合同主体分列，不合并计算派遣比例
    • 资料超 100 份 → 清点与提取并行处理，比对口径由主笔固化

    产出

    Markdown 用工口径表（示例：花名册劳动合同记录 252（直签 248 / 派遣 4）来源 F-0012；劳务 / 实习 15 / 1；社保自管户 / 代缴 / 代发薪 / 派遣 175 / 26 / 54 / 3 来源 F-0031；考勤记录 215 来源 F-0045）与差异清单；资料清单已去重、skipped 文件写明原因、OCR 文件标 extraction: ocr；输出不含身份证号、住址

  2. 用工形态分类定性

    /employment-legal:workforce-classification可单独运行

    把每个用工群体落到一个法律定性和一个风险等级，带置信度，说明证据来自哪份文件、还缺什么证据；定性错误会让后续比例、补缴和补偿结论全部失真。单独触发须附第 1 步的口径表

    请律师核对

    • 核对 2.1「两项以上呈派遣特征即高置信度」的判定门槛是否符合贵所对「名为外包实为派遣」的主张标准
    • 核对 2.2代发薪 54 人在示例中直接标 [红]，尽管结论仍是条件句
    • 核对 2.3协商解除协议审查范围默认「近 12 个月」
    • 核对 2.4超龄用工按 2026-07-01 施行的令第56号审查，对此前签订的返聘安排如何过渡，文件未规定

    做法

    1. 读口径表与差异清单、dispatch-vs-outsourcing-checklist.md、labor-law-citations.md G 节（法释〔2025〕12号）、H 节（劳务派遣）、A.2 / A.3（无固定期限、二倍工资）与 legal-basis-conventions.md；条号未核实一律 [待验证]
    2. 按 11 种形态逐类审查定性要件、典型风险、法源与需补证据：直签-固定 / 直签-无固定 / 关联公司交叉用工 / 派遣 / 外包 / 超龄退休返聘 / 劳务（兼职、非全日制）/ 实习 / 异地委托代缴 / 代发薪 / 挂靠
    3. 对外包群体按对照表 12 要素逐项填「本案证据」列；LWC-2026-0006 的典型组合：商业合同名为《服务外包合同》，补充协议按人头计费，用工方决定工资与社保基数、考勤与加班费、退回机制，用工方还直接与人员签《派遣补充协议》约定试用期与工资，三方主体错位（外包合同对方为省外关联公司、劳动合同用工单位为北京机构、解除协议用上海机构）
    4. 判定「名为外包实为派遣」：计价 / 选人 / 指挥管理三项中两项以上呈派遣特征 → 高置信度；否则条件句；定性为派遣的人数计入派遣比例，并检查许可证与派遣协议是否提供
    5. 关联公司交叉用工：从签订日期批次（如同一日成批转签）识别集中转签；逐个列出连续订立固定期限合同、满 10 年工龄仍签固定期限的人员；检查工龄是否书面承继、原主体是否支付经济补偿；以法释〔2025〕12号变换主体 / 混同用工条文为基准（条号见 G 节），不沿用 2025-09-01 前的裁判口径
    6. 协商解除协议：对调查期间内（通常近 12 个月）的协议逐份列表：补偿金额与基数、是否含奖金、是否含「社保公积金补偿款」、是否含「不投诉承诺 + 违约金」、是否涉及董事 / 高管；与同期公积金投诉、社保稽核通知相互印证时合并写入重大问题；金额或日期识别不清 → 【待核实】
    7. 输出分类汇总表（形态 / 人数 / 定性 / 置信度 / 风险 / 证据 / 待核实）；每个条件句结论同时写入附录「待核实事项」前列；派遣比例按定性后口径重算并写明分子分母

    内置规则

    • 直签-固定：连续两次固定期限后未签无固定、满 10 年仍签固定 → 《劳动合同法》第14条（已核实），需补历次合同
    • 关联公司交叉用工：合同主体与实际用工 / 参保主体不一致、签订日期成批次 → 混同用工责任、变换主体规避连续订立、工龄承继、二倍工资（第82条已核实；法释〔2025〕12号 G 节），需补原合同、调动 / 转签文件、工龄约定
    • 派遣：定性要件为派遣协议 + 许可证 + 三性岗位；风险为超 10% 比例、无许可、连带责任（H 节），需补派遣协议、许可证
    • 外包：按对照表 12 要素；外包合同未提供只有制度与考勤时，以制度与履行证据定性、置信度中，补充资料首项为合同；多家派遣 / 外包机构逐机构分表、许可证逐一核对
    • 超龄 / 退休返聘：先看是否已享受养老保险待遇（法释〔2025〕12号第16条）；2026-07-01 起须签书面「用工协议」、不低于最低工资、单位缴工伤保险（人社部等令第56号第6、11、15条，I 节）；典型风险：未签用工协议、未缴工伤保险、按旧 60 周岁直接终止、延迟退休到龄人员误按退休处理；无退休证明时条件句「若未领取养老金则可能构成劳动关系」
    • 劳务（兼职、非全日制）：是否受考勤 / 制度管理、工时是否超非全日制上限 → 被认定全日制劳动关系（《劳动合同法》第68–72条 [待验证]）；实习：在校身份、实习协议、三方协议，毕业后继续用工 → 劳动关系
    • 异地委托代缴：劳动合同主体 = 用人单位、社保以机构名义参保 → 参保主体不一致、待遇申领与工伤认定、约定效力（法释〔2025〕12号第19条口径，条号已核实），需补机构服务协议、员工同意书
    • 代发薪：先查劳动合同主体——与机构签约 → 按派遣；否则回代缴（对照表第三节）；未问清不写定性结论
    • 挂靠：无劳动关系却参保 → 骗取待遇风险（《社会保险法》第88条 [待验证]），看考勤与费用承担
    • 「不投诉承诺 + 违约金」「社保公积金补偿款」条款效力对照法释〔2025〕12号第19条口径 [待律师复核]；调查对象为多实体集团时按实体分列比例，跨实体交叉用工单列

    法律依据

    • 《劳动合同法》第14条 — 无固定期限合同触发（已核实）
    • 《劳动合同法》第82条 — 未签书面合同二倍工资（已核实）
    • 《劳动合同法》第68–72条 — 非全日制用工 [待验证]
    • 法释〔2025〕12号第16条 — 超龄人员是否已享受养老保险待遇
    • 法释〔2025〕12号第19条 — 社保约定无效、变更缴纳主体安排的效力（条号已核实）
    • 法释〔2025〕12号 G 节相关条文 — 混同用工、变换签约主体连续订立固定期限合同
    • 《超龄劳动者基本权益保障暂行规定》（人社部等令第56号）第6、11、15条 — 书面用工协议、不低于最低工资、单位缴工伤保险（2026-07-01 施行）
    • 《社会保险法》第88条 — 挂靠参保骗取待遇 [待验证]
    • 劳务派遣规则（labor-law-citations.md H 节） — 三性岗位、10% 比例、许可、连带责任

    产出

  3. 劳动合同文本与规章制度审查

    /employment-legal:contract-policy-review可单独运行

    找出客户文本沿用的已废止规则与旧数字、制度之间及制度与合同之间的冲突、缺民主程序与公示证据的制度；负责全量文本的横向一致性与版本陷阱，单份合同的深度审查复用雇佣 / 竞业 / 解雇审查流程的检查项。这些发现不依赖访谈，直接可核

    请律师核对

    • 核对 3.1旧数字沿用（如病假基数 2,420 元）的示例被定为 [橙] 高风险
    • 核对 3.2考勤制度与合同工时约定冲突时「以合同优先」
    • 核对 3.3法释〔2026〕14号在引用库中标「发布已核实 / 内容为二手来源」，却被用作学历教育服务期的审查口径
    • 核对 3.4第39–41、43条、第4条等高频条文仍标 [待验证]，每份报告都需律师复核条号

    做法

    1. 读第 2 步的分类汇总（决定哪些合同范本、哪些机构协议是重点）、labor-law-citations.md A–H 节、工作地点地方标准文件
    2. 建四类文本清单：合同范本（固定 / 无固定期限 / 完成任务合同：必备条款、期限、工作地点与调岗、解除条款、仲裁时效表述）；专项协议（保密、竞业限制、培训服务期、派遣补充、医疗期、协商解除、实习、劳务：适用人员范围、补偿、违约金、旧最低工资数字）；机构协议（派遣协议、外包合同及补充协议、代缴 / 代发薪服务协议，与对照表联动）；规章制度（员工手册、考勤与休假、薪酬与绩效、奖惩、外包服务管理、保密与信息安全、差旅等：民主程序、公示签收、与合同冲突）
    3. 每份文件记录 file_id、版本 / 生效日期、适用范围、是否有签收或公示证据
    4. 以司法解释二为基准跑 17 项逐条检查（仲裁时效、社保转移、社保约定、竞业限制、连续订立 / 无固定、二倍工资、最低工资 / 病假工资、生育假、工时、加班费基数、解除条款、违约金、民主程序、超龄用工、服务期、制度冲突等），每项比对客户文本与现行规则锚点
    5. 所有年度数字（最低工资、病假工资基数、生育假天数、社保基数）与地方标准现行值比对，旧数字写入评析并标现行值
    6. 每份文件出一段「文本评析」：问题 / 现行规则（带验证状态）/ 风险 / 建议
    7. 规章制度另出「制度清单」表：名称 / 版本 / 民主程序证据 / 公示证据 / 主要问题数
    8. 制度与合同冲突交叉引用：考勤制度与合同工时约定不一致时以合同优先并写入评析；外包管理制度体现用工方选人 / 考勤的作为派遣定性证据回传第 2 步

    内置规则

    • 仲裁时效：仍写「六十日内申请仲裁」→ 现行 1 年（《劳动争议调解仲裁法》第27条，已核实）；社保转移写「三十日内办理转移」等废止规则 → 按现行社保转移接续办法 [待验证]
    • 社保约定：「自愿放弃」「社保补贴代缴」「异地参保视为已履行」→ 法释〔2025〕12号第19条约定无效、补缴后可请求返还补贴（条号已核实）
    • 竞业限制：全员竞业、无补偿、范围 / 期限超法定 → 法释〔2025〕12号关于不负保密义务人员竞业条款、补偿与范围的条文（G 节）；《劳动合同法》第23–24条（已核实）
    • 连续订立 / 无固定：变换关联主体续签、第三次仍固定 → 第14条（已核实）+ G 节变换主体条文；二倍工资：未签合同期间补签倒签 → 第82条（已核实）+ G 节二倍工资计算条文
    • 最低工资 / 病假工资：医疗期协议、病假制度沿用旧年度数字 → 地方规则文件第一、二节；生育假：制度写 128 天 → 现行 158 天（北京）[管辖 flagged]
    • 工时：销售 / 高管按不定时工时但无审批、综合工时批复过期 → 审批办法 + 地方规定 [待验证]，批复文号与有效期入附录；加班费基数以基本工资为基数 → 《劳动法》加班费三档（规则已核实）
    • 解除条款：把「不能胜任」「严重违纪」写成单方即时解除且无程序 → 《劳动合同法》第39–41、43条 [待验证]，工会通知；违约金：服务期 / 竞业之外约定违约金 → 第25条（规则已核实）
    • 民主程序：制度无职工代表大会 / 工会讨论、无公示签收 → 《劳动合同法》第4条 [待验证]；超龄用工：退休返聘仍用劳动合同范本或无书面协议、无工伤保险安排 → 人社部等令第56号第6、15条（2026-07-01，I 节）
    • 服务期：以学历教育为由约定服务期 / 违约金 → 法释〔2026〕14号（2026-07-30）：不得仅以第22、25条主张无效，超出合理比例部分综合判断（G 节配套）
    • 边界：制度只有扫描件且 OCR 不清 → 逐条意见写到可识别条款，其余【待核实】；合同范本多版本并存 → 分版本评析并列明各版本适用人员批次；工作地点多城市 → 按城市分别核对，无对应地方文件标 [管辖 flagged — 需验证地方性规定]

    • 法释〔2025〕12号第19条 — 社保约定无效、补贴返还（条号已核实）

  4. 报告装配

    /employment-legal:dd-report-assembly可单独运行

    交给律师一份结构与版式和律所既有报告一致、每个结论可回溯、每个缺口有去处的复核稿，而不是一篇需要重排的长文

    请律师核对

    • 核对 4.1重大问题排序规则「[红] → [橙] → [黄]，同级按涉及人数」
    • 核对 4.2「需律师决定」项混在同一附录表中，仅靠「【律师决定】」前缀区分
    • 核对 4.3外发版默认只去除内部评级与【律师决定】说明；是否还需去除置信度与条件句标记，文件未规定
    • 核对 4.4独立模型复核允许写 skipped 并给原因即可交付

    做法

    1. 读 due-diligence-playbook.md 第 4–8 节与 document-delivery-qa.md 第 2、4、5 节；确认前三步输出已落盘为分章内容文件（防止上下文压缩丢失）；读 CLAUDE.md「输出」取工作产物标题
    2. 写正文（第三部分）：按指令文件章节顺序——组织架构与用工概况 / 劳动人事 / 诉讼、仲裁与行政处罚；事实以底稿为准每条可回 file_id；推断性结论用条件句并标【待核实】；法条与地方数字只写已核实或 [待验证] 的版本；释义表新增简称与正文一致
    3. 从正文倒推重大问题汇总（第二部分），不新增正文没有的结论；每项注明风险、正文位置、待核实 / 待补；排序 [红] → [橙] → [黄]，同级按涉及人数（LWC-2026-0006 为 13 项，全部可回溯）
    4. 装配附录「待核实事项及待补充资料」：来源为 deferred_items、各步骤的【待核实】与「需补资料」；「需律师决定」项以「【律师决定】」开头；条件句结论对应项放前列；与正文【待核实】计数核对一致
    5. 模板包成稿：以模板 DOCX 为包，删除旧正文（另一客户旧稿不得残留），克隆标题 / 编号 / 表格样式，用标记语言生成正文；释义表补充简称；日期留【 】占位；目录域设 updateFields；表格不用固定行高，三列表按 38 / 62 等比例设宽
    6. QA 与覆盖审计：资料包每个文件是否被引用，未引用者逐个解释；LibreOffice 渲染逐页检查表格截断、列宽、组织架构图、空白页、页眉页脚；OOXML 校验；【待核实】计数与附录条目核对；发送包正则检查身份证号、手机号，含个人信息的底稿留内部目录
    7. 交付说明：占位符（出具日期、尽调期间、释义表待填）、目录域刷新、未执行事项（外部检索：企业信用 / 裁判文书 / 执行信息；独立模型复核）、结构指标（页数、表格数、待核实数，仅作解释）；随后输出 REVIEW_STATUS，未做独立复核写 skipped 与原因
    8. 案例库：成稿时先登记资料聚合指纹、覆盖率与结构指标；律师反馈到达后按 shared/feedback-refinement/SKILL.md 第 0 节在 docs/legal-ops/case-library/ 记录脱敏案例

    内置规则

    • 先正文后摘要：重大问题汇总从正文倒推，摘要不得出现正文没有的结论；指令要求先写第二部分时仍先写正文草稿再归纳，并向律师说明原因
    • 劳动人事章内部顺序：用工分类汇总表 → 劳动合同与专项协议评析 → 规章制度评析 → 社保公积金（参保主体、基数分布、公积金、稽核与投诉）→ 工时与休假（审批、年休假、产假）→ 离职（协商解除协议表）

    • 重大问题表列：# / 重大问题 / 风险 / 正文位置 / 待核实或待补；示例：「54 名代发薪人员劳动合同主体不明，若由机构签约则派遣比例约 18%」[红]，第三部分 2.1，附录 1、2
    • 附录按 playbook 第 5 节三分类（补充资料 / 待说明（事实矛盾）/ 需律师决定）；劳动用工类可把前两类合并为「待核实事项及待补充资料」一表，但「需律师决定」项仍须可识别
