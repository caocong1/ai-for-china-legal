# 报告装配（dd-report-assembly）

> **前置**：
> 1. 读取 `shared/references/due-diligence-playbook.md` 第 4–8 节与 `shared/references/document-delivery-qa.md` 第 2、4、5 节；发包方外包用工调查另读 `employment-legal/skills/_shared/outsourcing-compliance-playbook.md` 第二、五节；
> 2. 前三个子技能的输出已落盘为分章内容文件（防止上下文压缩丢失）；
> 3. 读取 `employment-legal/CLAUDE.md` → `## 输出` 取工作产物标题。
>
> 可被 `workforce-compliance-dd/SKILL.md` 编排入口调用，也可通过 `/employment-legal:dd-report-assembly` 单独触发。

---

## 目的

让律师拿到的是一份结构与版式和律所既有报告一致、每个结论可回溯、每个缺口有去处的成果，而不是一篇需要重排的长文。交付模式在 intake 时确定：律师工作稿带内部标记与附录；客户成稿可原样转发，内部内容另出《成稿说明》。

---

## 详细步骤

### 步骤 1：正文（第三部分）

按指令文件章节顺序写，通常：

1. **组织架构与用工概况**：主体、关联公司、人数口径表、组织架构图（整页，留白为已知代价）；
2. **劳动人事**：用工分类汇总表 → 劳动合同与专项协议评析 → 规章制度评析 → 社保公积金（参保主体、基数分布、公积金、稽核与投诉）→ 工时与休假（审批、年休假、产假）→ 离职（协商解除协议表）；
3. **诉讼、仲裁与行政处罚**：案件表、稽核 / 处罚通知、信用报告交叉。

发包方外包用工调查改用「第一部分 前言 / 第二部分 现状评析（八章，每节事实 + 法律评析）/ 第三部分 操作指引（八章，不写法律评析）/ 附件：审阅材料清单」，标题写「合规调查报告及操作指引」（外包作业手册第二节）。

规则：

- 事实以底稿为准，每条可回到 `file_id`；
- 推断性结论用条件句；工作稿另标【待核实】，客户成稿不标，核实项进《成稿说明》；
- 法条与地方数字只写已核实或 `[待验证]` 的版本；
- 释义表新增的简称与正文一致。

### 步骤 2：重大问题汇总（第二部分）

从正文倒推，不新增正文没有的结论。每项：

```markdown
| # | 重大问题 | 风险 | 正文位置 | 待核实 / 待补 |
|---|---|---|---|---|
| 1 | 54 名代发薪人员劳动合同主体不明，若由机构签约则派遣比例约 18% | 🔴 | 第三部分 2.1 | 附录 1、2 |
```

排序：🔴 → 🟠 → 🟡；同级按涉及人数。LWC-2026-0006 为 13 项，全部可回溯。

客户成稿：是否设这一部分、是否标等级，按框架、模板或实践配置（`document-delivery-qa.md` 5.4 B 类）。未定的，正文用文字描述风险（「法律风险较高」「存在……的较大风险」），等级表放《成稿说明》第四节供律师选用。

### 步骤 3：附录

「待核实事项及待补充资料」一表：序号 / 待核实事项 / 需提供的资料或说明。

- 来自 `deferred_items`、各子技能的【待核实】与「需补资料」；
- 「需律师决定」项在事项列以「【律师决定】」开头，保持可识别；
- 条件句结论对应的核实项放前列；
- 与正文【待核实】计数核对一致。

客户成稿默认不附本表：内容写进《成稿说明》第七节，措辞可直接转给客户；实践配置或律师要求作附件的，照附。凭证核对明细、统计表等底稿同理。LWC-2026-0010 中律师删去了这三份附件，属偏好（5.4 B 类）。结论依赖的缺失材料，正文对应位置仍用来源句写明。

### 步骤 4：模板包成稿

按 `document-delivery-qa.md` 第 2 节：以模板 DOCX 为包，删除旧正文（另一客户旧稿不得残留），克隆标题 / 编号 / 表格样式，用标记语言生成正文；释义表补充简称（不收内部称谓，如材料批次）；表格不用固定行高、三列表按 38 / 62 等比例设宽。工作稿日期留【 】占位、目录域设 `updateFields`；客户成稿日期写「二〇××年×月　日」，目录域不设 `updateFields`，渲染后回填页码。

### 步骤 5：QA 与覆盖审计

1. 覆盖审计（playbook 第 4 节）：资料包每个文件是否被引用，未引用者逐个解释；
2. LibreOffice 渲染逐页检查：表格截断、列宽、组织架构图、空白页、页眉页脚；
3. OOXML 校验；工作稿核对【待核实】计数与附录条目；客户成稿核对内部标记计数为 0，删除附件后检索悬空引用（「见附件×」）与空表格；
4. 发送包正则检查身份证号、手机号；含个人信息的底稿留内部目录。

### 步骤 6：交付说明与复核状态

交付说明列：占位符（出具日期、尽调期间、释义表待填）、目录域刷新、未执行事项（外部检索：企业信用 / 裁判文书 / 执行信息；独立模型复核）、结构指标（页数、表格数、待核实数，仅作解释）。客户成稿按 `document-delivery-qa.md` 5.2 出《成稿说明》九节，并在第四节列出 5.4 B 类偏好项本稿的处理、另一种做法和可插入的文本。

随后按 `shared/legal-document-intake/SKILL.md` 输出 `REVIEW_STATUS`；未做独立复核写 `skipped` 与原因。

### 步骤 7：案例库

律师反馈到达后，按 `shared/feedback-refinement/SKILL.md` 第 0 节在消费者项目 `docs/legal-ops/case-library/` 记录脱敏案例；本次成稿时先登记资料聚合指纹、覆盖率与结构指标。律师返回定稿的，按第 0.1 节做定稿比对。

## 检查清单

- [ ] 正文每章事实可回到 `file_id`
- [ ] 重大问题全部可回溯到正文位置
- [ ] 工作稿：附录与正文【待核实】计数一致，「律师决定」项可识别
- [ ] 客户成稿：内部标记为 0；5.4 A 类规范已落实；B 类偏好项已按配置处理，或在《成稿说明》第四节给出选项；影响认定的答复与证据不一致已在事实段中性写明；无悬空的附件引用
- [ ] 模板旧正文无残留；释义表与正文简称一致
- [ ] 渲染逐页检查完成；表格无截断
- [ ] 发送包无身份证号 / 手机号
- [ ] 交付说明与 `REVIEW_STATUS` 已输出

## 边界条件

| 情形 | 处理 |
|---|---|
| 无客户模板 | 用 `shared/references/document-structures.md` 的意见书 / 报告结构 + 中文 reference.docx（QA 清单第 3 节） |
| 指令要求先写第二部分 | 仍先写正文草稿再归纳，向律师说明原因 |
| 上下文压缩发生 | 从分章内容文件续写，不重做比对 |
| 律师要求外发版或可直接发客户 | 按客户成稿交付（`document-delivery-qa.md` 第 5 节，取舍见 5.4） |
| 发包方外包用工调查 | 骨架、证据层级与依据按 `outsourcing-compliance-playbook.md`；第三部分操作指引不写法律评析 |
